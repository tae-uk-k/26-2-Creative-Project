# 가상 식당 지도 정비 예시

모든 상호·소개·메뉴·가격·메뉴판·주소·영업시간은 설명을 위한 가상 설정이다. 실제 식당의 미흡 사례나 추천 측정 결과로 사용하지 않는다.

## 보기

- `index.html`: 카카오 / Google 전환, 소개 / 메뉴 전환, 원자료와 스토리.
- `images/kakao_story_before_after.png`: 온담식탁의 소개와 메뉴 전후 비교.
- `images/google_story_before_after.png`: 소담면가의 소개와 메뉴 전후 비교.
- `정비스토리.md`: 원래 상태 → 사용한 자료 → 정비 결과.
- `cases.json`: 수정 전후 문구와 가상 원자료 8건.
- `sources/*_board_*.svg`: 읽을 수 있도록 직접 만든 가상 메뉴판 4장.
- `fact_ledger.json`: 정비 문구와 자료 ID 연결.

## 이번 예시가 보여 주는 절차

1. 빈 설명 칸만 보고 끝내지 않고 기존 소개·텍스트 메뉴·메뉴판 두 장을 모두 확인한다.
2. 음식 종류·재료·조리 특징·가격·인분·구성·시간·추가금을 항목별로 추출한다.
3. 소개에는 음식과 조리 특징을, 메뉴 설명에는 단위·구성·선택·추가금·판매 시간을 배치한다.
4. 기존 브랜드 첫 문장을 보존하고, 메뉴명은 같은 메뉴의 정확한 이름으로 명확하게 한다.
5. 가격 6개는 모두 유지한다. 주차·예약·전체 알레르기처럼 자료에 없는 값은 작성하지 않는다.

온담 2인 세트의 평일 주문 시간을 전체 영업시간으로 바꾸지 않는다. 소담면가의 우동 곱빼기 1,500원과 점심세트 우동 변경 500원을 구분한다.

## 화면 구성과 검수

- 카카오: 이전에 보존한 원본 CSS, 헤더, 탭, 소개 카드와 메뉴 설명 클래스를 재사용했다.
- Google: 이전 원본 지도 캡처의 바깥 틀을 사용하고, 가상 정보 패널을 원본 메뉴의 글자·간격에 맞춰 재구성했다. 왼쪽 실제 상호·내용은 가상 내용으로 전부 교체했다.
- 실제 매장 사진은 사용하지 않았다. 출처 메뉴판 자체도 가상 원자료다.
- `static_qa.json`: 메뉴 가격 유지, 화면 8개와 메뉴판 4장 생성 확인.
- 실제 브라우저에서 소개 4개 화면과 메뉴 4개 화면의 문구·줄바꿈을 확인하고 캡처했다. 보기 전환과 자료 펼치기 동작도 확인했다.
- 기존 실제 식당 시안 폴더는 수정하지 않았다.

## 다시 생성

`python build_virtual.py`로 가상 자료·원본 UI 자산에서 화면을 생성한다. CSS 출처는 보존된 형제 폴더 `지도UI_실제정비_2예시_20261106`이다. 보존한 최종 브라우저 캡처에서 `python compose_previews.py`로 비교 PNG를 생성한다. `export_renders.py`는 이 대화의 CUA 캡처를 처음 파일로 보존할 때 사용한 스크립트다.
