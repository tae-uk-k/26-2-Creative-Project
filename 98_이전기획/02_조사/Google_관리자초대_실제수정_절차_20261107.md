# Google 관리자 초대와 실제 가게 정보 수정 절차

- 확인일: 2026-11-07
- 목적: 사업자등록이 없는 프로젝트 팀이 고객 매장의 관리 권한을 받아 정비할 수 있는지, 화면 수정과 API 자동화를 구분해 확인.
- 검증 범위: Google 공식 문서 확인. 실제 고객 계정의 초대 수락·정보 저장·공개 반영·API 신청은 이번 조사에서 실행하지 않음.

## 1. 우리 팀의 사업자등록과 고객 매장 인증

일반 관리자 초대의 공개 요건은 초대받을 Google 계정과 소유자의 권한 부여다. 이 절차에 초대받는 사람의 별도 사업자등록증 제출 단계는 없다. 따라서 고객의 기존 프로필을 관리하는 시험을 위해 우리 이름의 식당 프로필이나 가상 사업장을 만들 필요가 없다. 이는 플랫폼의 일반 관리자 접근 절차에 대한 판단이다.

고객 매장은 실제 운영되는 지점이어야 하며, 정비를 충분히 수행하려면 소유자가 프로필을 인증해 두는 것이 출발점이다. 인증 방법은 Google이 해당 프로필에 제시하는 방식에 따른다. 사업자등록증을 내는 한 가지 방식으로 고정하거나 우리가 원하는 인증 수단을 임의로 고르는 구조로 설명하지 않는다. [관리자 계정 요건](https://support.google.com/business/answer/3403100?hl=ko), [매장 인증](https://support.google.com/business/answer/7107242?hl=ko)

## 2. 우리 팀 준비

1. 담당자가 사용할 업무용 Google 계정을 준비한다. Gmail 또는 Google 계정으로 등록된 다른 이메일을 사용할 수 있다.
2. 사장님에게 정확한 초대 대상 이메일을 전달한다. 회사 도메인 이메일은 일반 초대의 필수 조건으로 두지 않는다.
3. 계정의 담당자를 정하고 2단계 인증을 설정하는 것을 프로젝트 운영 기준으로 삼는다. 여러 담당자는 각자 계정으로 권한을 받도록 설계한다.
4. 사업자등록, 별도 식당 프로필 생성, API 신청을 일반 초대의 선행 조건으로 묶지 않는다.

계정 사용 방식은 일반 관리자 시험용 제안이다. 별도의 대행사 조직 등록은 7절에서 구분한다. [Google 계정과 이메일](https://support.google.com/business/answer/7107242?hl=ko), [관리 권한](https://support.google.com/business/answer/3403100?hl=ko)

## 3. 사장님이 할 일

사장님 소유자 계정으로 [비즈니스 프로필](https://business.google.com/)을 열고 해당 지점의 설정에서 사용자 권한 관리로 이동한다. 우리 이메일을 추가하고 관리자 역할을 지정해 초대한다. 기본 소유권은 사장님에게 남긴다.

우리 쪽은 초대받은 계정으로 수락한 뒤 지점명·주소가 맞는지 대조한다. 이는 이미 소유자가 있는 프로필의 공동 관리 절차이므로, 새 가게 등록이나 소유권 교체 요청과 구분한다. [초대 절차](https://support.google.com/business/answer/3403100?hl=ko)

## 4. 실제 수정 화면

PC에서는 우리 계정으로 로그인한 Google 검색/비즈니스 프로필에서 가게를 연다. 휴대전화에서는 Google 지도 앱의 비즈니스 관리 영역을 사용한다.

| 우리 정비 대상 | 관리 화면에서 할 일 | seelo의 작성 원칙 |
|---|---|---|
| 소개 | 프로필 편집의 설명 항목에서 기존 값 확인·수정·저장 | 정상 원문 보존, 필요한 음식 특징만 짧게 작성 |
| 영업시간 | 기본 시간과 특별 시간의 실제 값을 확인하고 해당 항목 수정 | 메뉴 한정 판매 시간과 가게 영업시간 구분 |
| 메뉴 | 메뉴 편집에서 기존 메뉴를 골라 이름·가격·설명을 수정 | 가격·단위·구성·필수 조건을 연결, 다른 메뉴 보존 |
| 편의·서비스 | 해당 지점에 제공되는 속성 선택지 수정 | 확인된 실제 서비스만 선택 |
| 기존 공식 링크 | 사이트·메뉴 URL 등 지원되는 항목 수정 | 현재 사이트 연결만 수정, 새 외부 페이지 제작과 구분 |

메뉴 편집은 식음료 업종 및 해당 계정의 지원 화면을 확인해야 한다. 특정 편집 버튼이 없으면 실제 지원 여부를 확인하고 다른 이름의 칸에 억지로 넣지 않는다. [프로필 편집](https://support.google.com/business/answer/3039617?hl=ko), [음식 메뉴 편집](https://support.google.com/business/answer/9455840?hl=ko)

프로젝트는 관리 권한 전체 중 정비안에서 승인된 칸만 사용한다. 가게 이름·주소·업종 변경과 리뷰 답글은 현재 정비 범위에서 제외한다. 일반 관리자에게 프로필 정보 편집 권한은 있지만 사용자 관리·프로필 삭제는 제한된다. 신규 권한의 첫 7일 제한은 삭제·사용자 제거·기본 소유권 이전 등의 작업에 적용되며 일반 정보 수정의 일괄 대기 기간으로 설명하지 않는다. [관리자 권한과 신규 제한](https://support.google.com/business/answer/3403100?hl=ko)

## 5. 저장 후 확인

1. 우리 서비스에는 변경 대상과 승인 값을 기록하고, 해당 칸의 수정 전 값을 보존한다.
2. 관리 화면에서 저장한 결과와 검토 상태를 확인한다.
3. 공개 Google 지도에서 같은 지점·같은 칸을 다시 열어 승인 값과 비교한다.
4. 저장 성공, 검토 대기, 공개 반영 확인을 구분해 기록한다. 검토 중인 값을 재차 덮어쓰지 않는다.

일반 프로필 수정은 보통 10분 이내 검토되지만 최대 30일까지 걸릴 수 있다고 안내된다. 메뉴 수정 안내의 공개 반영 시간은 24~48시간이다. 서로 다른 안내를 단일 고정 시간으로 합치지 않는다. [프로필 수정 검토](https://support.google.com/business/answer/3038311?hl=ko), [메뉴 반영](https://support.google.com/business/answer/9455840?hl=ko)

## 6. 우리 서비스에 적용할 시험 순서

권장하는 첫 시험은 **실제 고객 매장 1곳의 일반 관리자 초대 + 담당자 수동 수정**이다. AI가 정비안을 만들고 사장님이 승인하는 단계는 우리 서비스에서 수행하며, 저장은 우리 담당자가 Google 관리 화면에서 처리하고 공개 값을 확인한다. 이 시험에는 API 승인이 필요하지 않다.

브라우저 자동화는 현재 기획에 있으나, 초대가 수락된다는 사실만으로 자동 로그인·편집·저장이 작동한다고 판단하지 않는다. 자동화 작동 여부는 별도 시험 대상이다. 이번 조사에서는 기존 기획·코드를 임의로 변경하지 않았다.

아직 수행하지 않은 확인:

- [ ] 실제 사장님 계정에서 우리 이메일을 관리자로 초대
- [ ] 우리 계정의 초대 수락과 정확한 지점 접근
- [ ] 소개·메뉴 등 해당 지점의 편집 칸 확인
- [ ] 사장님이 승인한 작은 변경 1건 저장
- [ ] 공개 지도 반영과 전후 증거 확보

위 항목은 지인/고객 매장의 동의와 실제 초대가 확보된 뒤 수행한다. 가상 매장 시안으로 성공 여부를 대체하지 않는다.

## 7. 일반 초대·대행사 조직·API 자동화 구분

| 경로 | 용도 | 추가 준비 |
|---|---|---|
| 일반 관리자 초대 | 지점별로 우리 계정을 초대해 화면에서 관리 | 우리 Google 계정, 고객 소유자의 초대 |
| 대행사 조직 | 여러 고객과 여러 담당자의 접근 권한을 체계적으로 운영 | 회사 이메일과 연결된 적합한 계정, 대행사 웹사이트, 조직 등록 절차 |
| Business Profile API | 승인된 프로그램으로 프로필 읽기·수정 | API 프로젝트·접근 승인·OAuth·각 기능 지원 확인 |

대행사 등록 안내는 등록에 사용할 계정이 기존 프로필을 소유·관리하지 않는 상태여야 한다고 명시한다. 일반 시험에 사용한 계정을 나중에 그대로 대행사 등록에 쓸 수 있다고 단정하지 않는다. 일반 초대와 별도로 운영 계정·그룹 구성을 정한다. [대행사 등록](https://support.google.com/business/answer/7353903?hl=ko)

API 신청 공개 요건에는 인증되고 활성 상태로 60일 이상인 프로필을 관리하는 것과 그 프로필의 사업체 웹사이트가 포함된다. 해당 프로필은 신청자 본인 사무실 또는 관리하는 고객 매장일 수 있다. 60일 조건은 우리 계정이 초대받은 뒤 60일을 기다리라는 뜻으로 해석하지 않는다. 신청에는 프로필의 소유자/관리자로 등록된 이메일과 Google Cloud 프로젝트 번호를 사용한다. [API 신청 조건](https://developers.google.com/my-business/content/prereqs)

API 호출에는 OAuth 2.0 인증이 추가로 필요하며 현재 권한 범위는 `https://www.googleapis.com/auth/business.manage`다. 관리자 초대를 받는 것만으로 API 프로젝트가 승인되거나 토큰이 자동 생성되지 않는다. 실제 API 지원 필드와 메뉴 API 사용 가능 여부도 개별 확인한다. [OAuth 안내](https://developers.google.com/my-business/content/implement-oauth)

## 8. 승인 흐름과 자료 보존

고객의 관리 동의, 정비안 승인, 수정 내용 전달을 남긴다. 고객이 소유권을 유지하고 관리 중단 시 권한을 회수할 수 있게 한다. 실제 API 도입 시 고객의 명시적 동의와 변경 안내를 기존 S13·F-10 흐름에 연결한다. [서드 파티 운영 기준](https://support.google.com/business/answer/7353941?hl=ko), [API 운영 기준](https://developers.google.com/my-business/content/policies)

이 문서는 조사 결과다. 사업자등록 없는 초대 계정의 실제 수정 성공, 우리 계정의 API 승인, OAuth 동작 완료를 증명하는 실행 기록은 아니다.
