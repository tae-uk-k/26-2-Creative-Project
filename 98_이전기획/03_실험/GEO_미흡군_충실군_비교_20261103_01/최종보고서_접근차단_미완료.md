# GEO 정보 미흡군과 충실군의 CLI 추천 등장률 비교

2026-11-03 / 회차01 / **연구 미완료: 지도 상세 조사 접근 차단**

## 실제 수행·차단 사유

새 폴더에서 A=0~3점, B=5~6점, 4점·필수 항목 미확인 제외 기준을 고정했다. 후보 확대 단계, 매칭 기준, 9개 한국어 질문·90셀 무작위 실행 순서, 모델·검색 설정, 새 세션 실행 도구와 재계산 코드를 저장했다. 기존 연구 결과는 합산하지 않았다.

실제 지도 조사 도구를 호출했으나 브라우저 인벤토리에서 `Local browser use is disabled in Work settings`가 반환됐다. 웹 도구로 카카오 상세 2곳과 Google 상세 1곳을 직접 열어도 접근 불가였다. 제3자 검색 결과로 후보 탐색을 시도했으나 이 정보를 지도 상세 원문·지도 검색 순위·GEO 채점으로 대체하지 않았다. 해당 후보는 표본에 편입하지 않았다.

별도 중립 CLI 점검을 **2회 실제 실행**했다. 식당·실험 지역·가설·후보 이름 없이 서울특별시청의 양 지도 주소 확인만 요청했다.

| 점검 | 프로세스 결과 | 원시 이벤트·응답 검수 | 식당 추천 실험 포함 |
|---|---|---|---|
| 1차, KST 03:12:31~03:12:45 | 종료코드1 | Selected model is at capacity | 제외 |
| 2차, KST 03:13:35~03:14:00 | 종료코드0 | 양 지도의 실제 open_page 이벤트 결과가 모두 Internal Error. 최종 응답도 양 지도 접근 실패로 명시 | 제외 |

요청 모델 `gpt-6.1-sol`, CLI `0.166.0-alpha.5.1`, 내장 live web_search, reasoning low, read-only, ephemeral, ignore-user-config, project_doc_max_bytes=0를 사용했다. 내부 모델 스냅샷 ID는 반환되지 않아 미확인이다. 새 빈 외부 폴더에서 독립 프로세스로 실행했으며 조사 파일을 질문에 전달하지 않았다. 실제 식당 추천에는 아직 사용하지 않았다.

브라우저 기능 복구가 필요하다고 사용자에게 요청했다. 설정을 임의로 변경하거나 다른 경로로 우회하지 않았다. **집단 확정 전 추천을 측정하지 말라는 순서를 유지했으므로 90회 식당 추천은 시작하지 않았다.** 이 차단을 표본 부족, 실패90회, 미노출90회 또는 차이 없음으로 보고하지 않는다.

## ① 두 집단의 기본 검색 노출 수준은 얼마나 비슷한가?

**미확인.** 이번 회차는 실제 지도의 동일 검색어·정렬 결과 순위를 수집할 수 없었으며 확정 집단도 없다. 준비된 수치 기준은 양 지도 같은 검색어 내 상위60위·각 순위 차이 최대20, 평점 차이 최대0.6, 리뷰 수 비율 최대8, 같은 판매 단위 식사 가격 비율 최대1.75, 기본 필드6개 이상·차이 최대1이다. 같은 세부 주력 음식군을 요구한다. 이 값은 측정 전 설계 기준이며 실제로 균형이 달성됐다는 결과가 아니다.

확대는 세 지역 모두 음식점 일반 검색60개 → 돈까스·국수·파스타·백반 각30개 → 필요 시31~60위로 순서와 검색어를 고정했다. 자세한 내용은 `사전규약.md`에 있다. 지도 접근 복구 후 실행해야 한다.

## ② 실제로 어떤 GEO 정보 특성이 달랐는가?

**이번 회차에서 판정하지 못했다.** 새 지도 상세에서 메뉴·가격·판매 단위, 실제 서비스 조건, 동일 지점의 채널 간 정보 일관성을 검증하지 못했으므로 점수나 집단을 만들지 않았다. 접근 실패를0점으로 바꾸지 않았다. 사용하지 않는 서비스를 설명하지 않았다는 이유로 감점하지 않았으며, 제3자 결과의 가격을 지도 확인 가격으로 기록하지 않았다.

## ③ 추천 등장률은 각각 얼마였는가?

**A: 산출 불가 / B: 산출 불가 / B-A: 산출 불가.** 분모0이며 0%가 아니다. 지역·질문·매장 쌍별 차이, 평균 추천 순서, 불확실성 구간도 미산출이다. 요청된 발표용 등장률 문장은 생성하지 않았다.

분석 코드는 실제 빈 원장으로 실행했다. 분모0은null, 동일 응답의 중복 언급은1회, 실패 제외, 셀별 최초 유효 응답만 채택, 매장별 비율 평균 및 쌍별 동일 분모를 적용한다. 계산 검증에 사용한 메모리 내 테스트 자료는 연구 파일에 저장하지 않았으며 실제 측정 수치로 사용하지 않았다.

## ④ 추천 답변은 어떤 정보를 근거로 삼았는가?

**식당 추천 응답이 없어 미확인.** 중립 점검에서 확인한 것은 지도 접근 오류이며, 이 응답을 식당 추천으로 분류하지 않았다. 출처 본문 확인 없이 모델 자기보고나 URL 출력만으로 성공을 판정하지 않는다. 추천 이유·지도 출처 사용률·사실 오류·조건 누락은 실제 응답 확보 후 검수해야 한다.

## ⑤ 어떤 정보부터 정비할 필요가 있는가?

**이번 실측 결과에 근거한 우선순위는 아직 정할 수 없다.** 가격·단위 연결, 실제 조건 연결, 지점 정보 일관성은 이번 조사 항목이며, 아직 추천 등장률과의 관계가 확인된 항목이 아니다. 실제 지도 정보는 수정하지 않았다. 정보 정비의 전후 효과를 측정했다는 표현도 사용하지 않았다.

## 보존·검수·재개 지점

기존 연구의 해시 목록에 있던 **85개 파일 모두 원본 해시 일치**를 확인했다. 이번 도구는 새 폴더에만 기록했다.

`tools/verify_current.py`의 11개 현재 상태 검수는 90셀 고유성, 후보·분류 없는 질문, 집단 미확정 시 실행 차단, 준비성 원문 해시, 실제 호출2회, 기존 파일 보존, 중복·분모0·실패 처리 계산을 확인했다. **코드·현재 상태 검증이며 실험 완료 검증이 아니다.**

원시 CLI JSONL·stderr·질문·시각·설정·해시는 `readiness/`에, 도구 접근 오류는 `evidence/`에 있다. `raw/`는 실제 식당 추천 원문이 들어갈 곳으로 현재 비어 있다. `analysis/현재상태/`에는 빈 실제 원장으로 산출한 null 결과와 원시 도구 이벤트 검수가 있다.

재개 지점은 **지도 상세 접근 복구 → 규약대로 후보 확대 조사 → 동일 지점·점수·A/B 매칭 확정 → cohort_lock 해시 고정 → 90회 새 CLI 실행 → 실패·지점·출처 검수 → 분석**이다. 표본을 임의로 만들거나 실제 측정 없이 완료 처리하지 않았다.
