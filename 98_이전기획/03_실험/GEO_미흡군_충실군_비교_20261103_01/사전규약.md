# GEO 정보 미흡군과 충실군의 CLI 추천 등장률 비교

2026-11-03, 회차01. 기존 연구 파일·결과는 변경하지 않는다. 이전 추천 결과를 합산하지 않는다. 기존 매장 상태의 관찰 비교이며 매장 정보를 수정하지 않는다.

## 고정 집단 기준

세 항목별 0/1/2/미확인, 합계 0~3=A, 5~6=B, 4 또는 필수 항목 미확인=주 분석 제외. 목표 지역별4쌍, 총12쌍24매장. 추천 결과를 보기 전에 항목 점수·지점 식별·매칭·질문 적합성·파일 해시를 확정한다.

1. 메뉴·가격·단위 연결: 실제 같은 메뉴 항목에서 인분·세트·정식·개수·중량과 가격이 연결됨=2. 메뉴와 가격은 연결되나 판매 단위 일부만 명확=1. 확인된 누락 또는 어떤 메뉴/단위의 가격인지 관계 불명확=0. 접근하지 못한 메뉴 사진·상세는 미확인.
2. 이용 조건: 실제 제공 메뉴·서비스에 적용되는 주문 시간·인원·최소 주문·포함 구성 등이 해당 항목에 명확히 연결=2. 실제 안내 중 적용 범위 일부만 명확하거나 일반 이용 시간과 메뉴 조건의 연결이 부분적=1. 실제 적용 조건이 확인되지만 관련 항목 연결이 누락·불명확=0. 서비스·제한 존재 자체가 불명확하면 미확인으로 남기며, 제공하지 않는 서비스를 설명하지 않았다는 이유로 감점하지 않는다. 맛·식감 등의 홍보 수사를 이용 조건으로 채점하지 않는다.
3. 지점 일관성: 같은 지점의 연락처·영업시간·공식 연결이 대조 가능한 채널에서 일치=2. 일부 시간 차이·연결번호 의미 미해결 등=1. 확인된 다른 지점 연결·불일치=0. 필요한 채널에 접근하지 못하거나 지점 식별 불가=미확인. 공식 채널이 없다는 이유만으로 감점하지 않는다. 공식 브랜드의 공통 시간과 특정 지점 시간을 무조건 같은 범위의 값으로 취급하지 않는다.

각 점수에 실제 짧은 문구·정확한 출처·관측 일시·확인 범위·판정 이유를 붙인다. 사진·텍스트, 메뉴 항목 수, 기본 사실 필드 수, 업주·플랫폼·사용자 작성 여부를 별도 기록한다. 사업자 인증이나 AI 추천 라벨을 메뉴 문구 전체의 업주 작성 증거로 삼지 않는다. 서로 다른 출처 가격·시간은 병기하고 임의로 현재 정답을 선택하지 않는다.

## 후보 조사 확대

브라우저 접근 복구 후 아래 순서로 두 지도에 동일한 질의·기본 정렬·필터 없음·한국어를 적용한다. 카카오는 정확도순, Google은 기본 관련성순. 광고는 별도 기록하고 장소 ID별 첫 자연 검색 위치를 쓴다. 서로 다른 질의의 순위를 한 순위처럼 합치지 않는다.

- 1차: 서울 명동 음식점 / 서울 성수동 음식점 / 서울 망원동 음식점, 각 지도 첫60개. 기존 후보는 조사 출발점으로만 참고하고 새 조사 확인 시각·실제 확인 범위를 기록한다.
- 2차 확대: 각 지역에 동일하게 돈까스·국수·파스타·백반을 결합한 질의12개, 각 지도 첫30개. 두 지도 모두 실제 서울 해당 지역인지를 주소로 확인한다.
- 3차 확대: 부족한 지역은 같은 4개 음식 질의의31~60위를 양 지도에서 추가 수집한다. 쌍 부족 여부만 보고 확대하고, 추천 결과를 보고 확대하지 않는다.
- 정식 상세 확인은 이름·도로명/지번의 동등성·층수·전화 및 가능한 공식 지점 안내로 대조한다. 주소 차이는 해소 전까지 동일 지점 미확인. 폐업·장기 휴업 표시는 제외하고, 공개 영업 안내 기준 확인과 현장 확인을 구분한다.

## 매칭 기준

지난 연구의 같은20위 구간+순위차15+리뷰비율3 제약은 이번 설계에 이월하지 않는다. 아래 기준은 새 추천 결과를 보기 전 고정한 수치다.

- 동일 지역, 같은 세부 주력 음식군. 단순히 모두 한식이라는 이유나 공통 부수 메뉴 하나만으로 같은 음식군으로 묶지 않는다.
- 두 지도에서 **같은 검색어**로 표시된 순위로 비교한다. 양쪽 모두 해당 질의 상위60위, 각 지도 순위 차이 최대20. 음식점 일반 질의의 짝을 우선하고 음식별 확대 질의의 짝은 별도 층으로 보고한다.
- 같은 판매 단위 대표 식사의 가격 비율 최대1.75. 중량 단가를 식사 총액으로 임의 환산하지 않는다. 가격 충돌로 비교 총액을 결정할 수 없으면 매칭 제외.
- Google 평점 차이 최대0.6, 리뷰 수 비율 최대8. 리뷰 수는 양수. 플랫폼별 평점과 리뷰 수를 섞지 않는다.
- 기본 사실 필드(상호·주소·전화·영업시간·업종·대표메뉴가격·공식연결) 중 6개 이상 존재, 쌍별 차이 최대1. 양쪽 대표 메뉴·가격은 필수. 읽지 못한 사실을 존재/부재로 임의 코딩하지 않는다.
- 위치 차이는 확인된 도로명·공개 좌표로 설명한다. 실제 좌표 없이 거리 숫자를 만들지 않는다. 같은 동/인접 도로·역 접근권인지 근거를 기록한다.
- 적합한 A-B 조합 중 음식군→가격 차이→두 지도 순위 차이→로그 리뷰 수 차이 순으로 가까운 쌍 우선. 매장 중복 없이 지역별 최대4쌍. 동률은 장소ID 사전순으로 고정.
- 부족하면 위 확대 단계까지 조사하고 실제 확보 수를 보고한다. 점수·집단 기준은 변경하지 않는다. 데이터 미접근을 후보 부족으로 혼동하지 않는다.

## 고정 질문

예산·점심·인원·국적 조건을 추가하지 않는 세 유형을 사용한다. 정식 표본은 매장에서 한 끼 식사가 가능한 음식점으로 확인한다. 주류 전용·디저트 전용은 제외한다.

1. [지역]에서 한 끼 식사하기 좋은 음식점 5곳을 추천해줘.
2. [지역]을/를 처음 방문하는 사람에게 추천할 음식점 5곳을 알려줘.
3. [지역]에서 대표 메뉴를 먹어볼 만한 식당 5곳을 추천해줘.

모두 다음을 붙인다: 카카오맵과 구글 지도의 공개 정보를 확인하고, 정확한 지점명, 추천 이유, 대표 메뉴·가격, 실제로 확인한 출처 링크를 제시해줘. 확인되지 않은 사실은 추측하지 마.

측정 세션에는 이 추천 질문만 전달한다. 조사 목록·분류·점수·가설·프로젝트 파일·이전 응답은 전달하지 않는다. JSON 형식 지시 등 별도 질문도 추가하지 않고 자연어 원문을 사후 추출한다.

## CLI 측정·실패·분석

Codex CLI 0.166.0-alpha.5.1, 요청 모델 gpt-6.1-sol, 내장 live web search, reasoning low, read-only, ephemeral, ignore-user-config, project_doc_max_bytes=0, 새 빈 외부 폴더. 중립 도구 준비성 질문과 실제90회는 별도 저장한다. 실행 순서는 난수2026110301로 90셀을 무작위화한다. 각각 별도 프로세스·새 세션, resume/fork 미사용. 실행 시각·CLI명·설정·원문·도구 이벤트 보존. 내부 모델 스냅샷 ID가 반환되지 않으면 요청 모델명과 구분한다.

지도 접근 실패·모델 오류·권한 거절·시간 초과는 측정 실패. 지도 링크만 출력했다고 실제 지도 접근 성공으로 분류하지 않는다. 소스 본문 및 도구 원문 증거 없이 모델 자기보고만으로 접근 성공 판정하지 않는다. 로컬 조사 파일·프로젝트를 읽었거나 지시 외 도구를 사용하면 절차 이탈로 제외한다. 출처나 지점 불명확은 검수 대상으로 남긴다.

자동 유효 판정은 하지 않는다. 원문·도구 이벤트를 검수해 각 시도 상태를 valid/failure/protocol_deviation/review로 확정한다. 실패 시도는 분모에 포함하지 않는다. 최초 유효 시도 1개만 셀별 선택한다. 기본90셀 후 실패 셀별 최대1회 재시도 가능하며 따로 기록한다. 설정을 바꾸어 재시도하지 않는다.

매장 등장률=같은 지역·질문 조건 유효 응답 중 등장 응답 수/동일 유효 응답 수. 응답별 같은 매장은1회. 쌍 A/B에 같은 분모 사용. 집단은 매장별 비율 평균, B-A는 %p. 지역·질문·쌍별 결과와 노출 시 평균 순서를 병기한다. 분모0은null. 반복90응답을 독립90매장으로 취급하지 않는다. 불확실성 구간을 계산하면 매장쌍 재표집으로 한다.

관찰 비교와 실제 정보 정비 효과를 구분한다. 결과를 실제 정보 정비 전후 개선 효과로 부르지 않는다. 발표용 등장률 문장은 검수된 실제 측정 수치가 있을 때만 만든다.
