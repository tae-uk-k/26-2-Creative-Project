# GEO 정보 정리 상태와 AI 추천 노출: 매장 쌍 관찰 연구

고정일 2026-11-03 KST. 과거 실험과 합산하지 않는다. 매장 정보 수정은 하지 않는다.

## 순서와 후보 틀

1. 명동·성수·망원 각각 `[지역] 음식점`을 카카오맵과 Google 지도에서 검색한다. 카카오 정확도순, Google 기본 관련성순, 한국어·로그아웃 브라우저, 추가 가격/평점/영업 필터 없음. 광고를 별도 기록하고 순위에서 제외한다. 지도 중심이나 현위치를 수동 조정하지 않는다.
2. 같은 질의의 첫 60개 자연 검색 결과를 수집한다. 사이트가 더 적게 제공하면 실제 수만 기록한다. 노출 순위는 이 환경의 한 시점 표시 순위이며 API 결과 순서로 대체하지 않는다.
3. 두 지도에서 이름·도로명 주소·지점/층수를 대조한다. 장소 ID와 직접 상세 URL을 기록한다. 동명이점·주소 불명·휴폐업 표시는 제외/검수 대상으로 남긴다.
4. 두 지도 상세와 확인 가능한 공식 안내를 읽어 대표 메뉴·가격·판매 단위·이용 조건·시간·전화·정보량을 수집한다. API·검색 결과에 없는 필드는 상세 화면을 확인한다. 접근 불가는 미확인이다.
5. 추천 측정 전 점수·매장 쌍·질문·설정을 파일 해시로 고정한다. 조사 내용이 없는 새 CLI 세션에서만 측정한다.

## 점수 판정

항목별 0/1/2/미확인과 짧은 실제 문구·URL·관측 시각을 함께 남긴다. 원문 확인 범위를 기록한다.

- **메뉴·가격·단위 연결**: 2=같은 메뉴 항목에 가격과 인분/정식/세트/수량/중량 등 판매 단위가 명시됨. 1=메뉴와 가격은 연결되나 단위가 암묵적이거나 일부 메뉴만 명확함. 0=가격 자체는 존재하지만 어떤 메뉴/단위에 해당하는지 확인된 화면에서 연결이 불명확함. 접근하지 못한 가격/사진은 미확인이다.
- **이용 조건 연결**: 2=확인한 적용 조건(인원·최소 주문·포함 구성·주문 시간 등)이 해당 메뉴/서비스에 명확히 붙어 있음. 1=일반 영업 안내나 일부 조건만 확인되고 메뉴별 적용 범위가 일부 불명확함. 0=확인된 제한·구성이 어느 메뉴/서비스에 해당하는지 불명확하거나 관련 화면에서 연결이 누락됨. 존재 여부조차 확인할 수 없는 제한은 만들어 채점하지 않는다.
- **지점 일관성**: 2=동일 지점의 연락처·주간 영업시간·공식 연결이 대조 가능한 채널에서 일치함. 1=주소는 일치하나 시간 등 일부 차이가 있거나, 연락처 연결번호 차이의 의미를 확인하지 못함. 0=다른 지점 연결 등 확인된 불일치. 필요한 상세에 접근하지 못하면 미확인이다. 공식 채널이 없다는 이유만으로 0점 처리하지 않는다.

사진/텍스트, 메뉴 개수, 설명 길이, 기본 필드 수, 작성자 확인 여부를 별도로 기록한다. 사업자 인증이나 플랫폼 AI 요약을 업주 작성 소개로 코딩하지 않는다.

## 매칭: 추천 결과를 보기 전 적용

- 지역별 최대 4쌍, 총 최대 12쌍. 두 지도 동일 지점 확인·운영 안내·기본 정보·대표 메뉴 가격이 모두 확인된 후보만 사용한다.
- 같은 지역, 같은 세부 음식군. 위치는 도로명과 공개 좌표로 비교하고 근접성 근거를 적는다. 좌표를 못 확인한 경우 거리 숫자를 추정하지 않는다.
- 같은 판매 단위의 대표 식사/세트 가격 비율 최대 1.5. 중량 단가와 한 끼 총액을 혼합하지 않는다.
- 각 지도의 순위 차이 최대 15, 순위 구간 1–20/21–40/41–60이 같아야 한다.
- Google 평점 차이 최대 0.4, 리뷰 수 비율 최대 3. 리뷰 수는 양수이며 숫자 원문을 기록한다.
- 기본 정보 필드 수(상호·주소·전화·시간·업종·메뉴 가격·공식 링크) 차이 최대 2. 양쪽 모두 메뉴·가격 필수.
- 세 항목 모두 점수가 확인된 매장만 주 비교에 사용한다. 합계가 낮은 매장을 A, 높은 매장을 B로 두고, 합계 차이는 최소 2점으로 정한다. 점수 동률은 짝지을 수 없다.
- 가능한 쌍 가운데 같은 세부 업종, 가격 차이, 두 지도 순위 차이, Google 리뷰 로그 차이, 평점 차이가 작은 쌍을 우선하고 중복 매장을 쓰지 않는다. 선정 이유와 남은 차이를 공개한다.
- 위 조건을 만족하는 쌍이 부족하면 수를 줄인다. 점수·조건·질문을 결과에 맞춰 수정하지 않는다.

## 질문과 조건 적합성

특정 예산·시간·인원·국적 조건을 부여하지 않아 두 집단에 같은 식사 질문을 적용한다. 점심 전용·주류 전용 가게 등은 질문 적합성을 별도 기록한다.

지역별 세 문구:
1. `[지역]에서 한 끼 식사하기 좋은 음식점 5곳을 추천해줘.`
2. `[지역]을 처음 방문하는 사람에게 추천할 음식점 5곳을 알려줘.`
3. `[지역]에서 대표 메뉴를 먹어볼 만한 식당 5곳을 추천해줘.`

공통 요청은 모두 같다: `카카오맵과 구글 지도의 공개 정보를 확인하고, 정확한 지점명, 추천 이유, 대표 메뉴·가격, 확인한 출처 링크를 제시해줘. 확인할 수 없는 사실은 추측하지 마.`

JSON 응답 형식을 공통으로 지시하되 후보명·집단·점수·가설·과거 추천·프로젝트 문서는 전달하지 않는다. 새 빈 작업 폴더, 새 독립 세션, 고정 CLI 모델 1개와 검색 설정을 사용한다. 실행 순서는 고정 난수로 섞는다. 3지역×3질문×10반복=90개 고유 측정 셀이다.

## 성공·실패·검수

- 원문·도구 이벤트·모델/CLI/검색 설정·시작/종료 시각·실패·재시도 모두 보존한다.
- 지도 도구 실패·권한 거부·오류·시간 초과는 실패다. 정상 추천이었으나 표본이 없을 때만 0회다. 접근 여부 자기보고와 실제 도구 결과를 구분한다.
- 응답 안의 같은 식당은 1회. 이름만으로 지점을 특정할 수 없으면 식별 불가로 별도 검수한다.
- A/B는 동일한 유효 응답 집합으로 비교한다. 질문별로 분리하고 매장별 분모를 남긴다. 실패 재시도는 성공을 중복 집계하지 않는다.
- 집단 노출률은 매장별 노출률 평균, 쌍별 차이는 B−A. 신뢰 구간/재표집은 매장 쌍 단위로 한다. 90응답을 90개 독립 매장으로 세지 않는다.
- 추천된 가격·단위·지점·조건과 실제 인용 내용이 맞는지 검수한다. 사실 오류를 발견해도 질문·점수·표본을 사후 변경하지 않는다.
- 본 비교는 기존 매장의 관찰 차이를 측정한다. 정보 정비의 전후 효과를 측정한 실험과 구분한다.
