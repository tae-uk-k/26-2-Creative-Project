# 랜딩 모션 개선 · 2026-10-28

대상: 03_city_scroll, 04_neumorphic, 05_shop_windows, 07_kinetic, 08_window_stage.

## 코드에서 확인한 원인

- 멀티 윈도: 매 프레임 left/top/width와 글자 크기를 바꿨다. 줄바꿈과 카드 높이가 계속 재계산됐다.
- 키네틱: 장면 페이드와 개별 글자·배경 가림막의 시간이 달랐다. 가림막은 전환 경계에서 갑자기 초기화됐다.
- 시내: 별도의 스크롤 당김과 카메라 지연을 중첩했다. 화면이 정지해도 RAF는 계속 돌았다.
- 입자 가게: 스크롤 상태와 별도로 3D 루프가 계속 돌고, DOM보다 한 프레임 늦게 요청됐다.

## 적용

- 큰 창은 고정된 레이아웃으로 만들고, translate/scale/opacity로만 전환한다. 원래 작은 창의 위치는 리사이즈 때만 측정한다.
- 시간 기반 보간을 하나의 스케줄러로 관리한다. 읽기 위치에서는 장면이 완전히 표시된다. 초기 복원 위치는 바로 반영한다.
- 타이포 확대·글자별 지연과 갑자기 초기화되는 가림막을 제거했다.
- 시내의 자동 당김은 정지 위치 근처 2.5% 이내, 진행 방향일 때만 작동한다. 연속 루프를 필요할 때만 실행한다.
- 입자 모델은 처음 모이는 동안과 스크롤·리사이즈 등 상태가 변할 때만 그린다. DOM과 같은 프레임에 렌더링한다.
- 기존 시안은 스톤·구리색 / 아이보리·클레이 / 화이트·블루로 변경했다. 자연물의 재질색은 남겼다.

## 검수

- JS 6개 문법 검사 통과.
- verify-scroll.cjs: 빠른 역방향 이동, 읽기 구간, 스크롤 중 geometry 읽기 없음, 정지·숨김 시 RAF 종료 통과.
- verify-shop.cjs: 모델 행렬, 카드 분리, 비교 막대, 정지 시 렌더 중단, 모션 줄이기 통과.
- 연결된 브라우저에서 시내·가게·키네틱·멀티 윈도 장면 이동을 확인했다. 콘솔 오류 없음.
- 멀티 윈도의 실제 창 너비와 글자 크기가 전환 중에도 고정됨을 확인했다. 460px 및 데스크톱 화면 가로 넘침 없음.
- 모든 기기의 고정 FPS나 정량적 성능 향상 비율을 측정한 것은 아니다.
