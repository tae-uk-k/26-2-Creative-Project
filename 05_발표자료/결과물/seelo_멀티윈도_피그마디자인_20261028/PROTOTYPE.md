## 주요 경로

랜딩 → 회원가입·로그인 → 가게 등록 → 후보 선택 → 진단 진행 → 결과 → 정비 신청 → 지도 연결 → 정비안 확인 → 승인 팝업 → 정비 진행 → 전후 비교 → 완료 상태의 내 가게.

회원가입의 Google 버튼으로 바로 가게 등록 전 화면에 진입할 수 있다. 이메일 가입은 입력칸이나 동의를 클릭하면 입력 완료 상태로 전환되고 가입 버튼이 활성화된다. 인증 안내에서 ‘인증을 완료했어요’를 눌러 계속한다.

등록 화면은 입력칸 클릭으로 입력 완료 상태를 확인하거나 ‘가게 찾기’를 눌러 후보 선택으로 진행한다.
정비안은 영업시간 입력칸 또는 확인 체크를 눌러 완료 상태로 전환한다. ‘정비 시작’에서 팝업이 열리고, ‘다시 확인’이나 × 또는 배경을 누르면 원래 화면으로 돌아온다.

모바일도 가게 등록·진단·지도 연결·정비안·승인·전후 비교를 한 기기 크기 안에서 이어 볼 수 있다.

## 전환과 스크롤

- 일반 화면 전환: 220ms Dissolve / Ease out
- 입력·확인 상태: 180ms Smart animate / 스크롤 위치 유지
- 진단 진행: 2400ms 뒤 결과로 전환
- 신청 접수: 2200ms 뒤 연결 화면으로 전환
- 정비 진행: 2600ms 뒤 보고서로 전환
- 모바일 진행: 2000~2200ms 뒤 다음 단계
- 데스크톱 뷰포트: 1440×900
- 모바일 뷰포트: 390×844
- 긴 본문: 세로 스크롤
- 상단 메뉴: 고정
- 오버레이: 화면 중앙, 배경·닫기·취소로 닫기

Figma의 지연 트리거는 밀리초, 전환 시간은 초 단위로 저장했다. 일반 화면이 과하게 움직이지 않도록 좌우 밀기나 큰 확대는 적용하지 않았다.

## 검수

52개 프레임에는 원래 32개 화면의 미리보기 복제본, 입력 완료·연결 완료·정비 완료 상태와 팝업이 포함된다.

- 저장된 반응 329개, 그중 클릭 324개·시간 지연 5개
- 끊긴 목적지 0개
- 같은 화면으로 잘못 이동하는 연결 0개
- 데스크톱·모바일 핵심 경로 도달 누락 0개
- 자동 레이아웃 자식의 넘침 0개
- 시작점 5개: 전체 이용·모바일·관리자·측정 실패·정상 0%
- 팝업 5개 모두 배경·취소 또는 확인·×로 닫기 가능
- 실제 Figma 렌더링으로 첫 화면·확인 완료·승인 팝업·모바일 보고서 점검

브라우저 조작은 Work 설정상 비활성이라 실제 플레이어에서 클릭하며 재생하는 검수는 하지 못했다. 연결 그래프·뷰포트·스크롤·고정 헤더·팝업·전환 설정을 Figma API에서 읽어 검증했다.

이것은 입력과 처리 과정을 시연하는 디자인 프로토타입이다. 자유로운 키보드 입력이나 실제 가입·메일·AI 측정·지도 수정·데이터 저장은 연결하지 않았다. 일부 목록 필터나 후보별 데이터 변경은 실제 기능이 아니며, 주요 서비스 경로를 중심으로 구성했다.
