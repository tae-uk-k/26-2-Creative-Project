# seelo 지도 정보 정비 기준

- 작성·출처 확인: 2026-10-28
- 같은 날 보완: 정보 추가보다 선별·전용 칸 배치·분량 제한·모바일 가독성을 우선하는 편집 기준 추가.
- 추가 보완: 메뉴판 사진·리뷰·출처 충돌·수정 실행의 실제 상황 36가지를 11장에 정리. 문구 길이보다 정보의 출처·현재성·편집 권한·최소 변경량으로 판단한다.
- 목적: 어떤 지도 정보를 어떤 근거로 바꾸고, 무엇을 완료로 볼지 정한다.
- 적용 범위: 현재 기획서의 Google 지도·카카오맵 정비. 네이버·웹사이트·SNS는 비교 자료로만 사용한다.
- 문서 성격: 연구에 근거한 운영 기준 제안. 현재 개발 기준은 계속 `01_기획/한눈_기획서.md`, `01_기획/한눈_명세서.md` 두 문서다. 아래 보완 제안은 아직 두 문서에 반영하지 않았다.
- 검증 범위: 논문 본문·도구 공식 도움말·지도 공식 가이드를 확인했다. 유료 도구 사용 시험이나 실제 매장 정보 수정은 하지 않았다.

## 1. 채택할 기준

**사장님이 정한 소개는 보존하고, 부족한 사실을 적합한 칸에서 최소한으로 보완한다.** 소개가 없을 때는 가게를 구별하는 핵심으로 짧게 작성한다. 정보가 많다는 이유로 좋은 정비라고 평가하지 않는다.

판단이 충돌하면 **정확성·필수 이용 조건 → 사장님이 선택한 표현·브랜드 의도 → 전용 칸 배치 → 가독성 → AI 질문 관련성** 순서로 결정한다. 지도 페이지의 글꼴·카드 순서·접힘 동작은 플랫폼이 정하므로, seelo는 입력 내용·분량·지원되는 정렬만 관리한다.

### 기존 소개가 있을 때: 원문 보존 우선

**2문장·400자 등의 자체 편집 상한은 소개를 처음 작성하거나 사장님이 전체 재작성을 요청한 경우에만 적용한다.** 기존 소개가 더 길거나 감성적인 표현이라는 이유만으로 축약·교체하지 않는다. 플랫폼 공식 제약은 별도로 확인한다.

| 현재 상태 | 처리 | 원문 변경 범위 |
|---|---|---|
| 소개가 없음 | 사장님이 원하는 말투·핵심 표현을 확인할 수 있으면 반영해 새 소개 제안 | 새 문구 전체를 승인받음 |
| 사장님 소개가 있고 사실 오류·이용상 문제가 없음 | 그대로 유지. GEO 사유만으로 재작성하지 않음 | 변경 없음 |
| 소개에 대표 음식·가격·시간 등 필요한 사실이 없음 | 메뉴·가격·영업시간·서비스 전용 칸부터 보완 | 원문 유지가 기본. 다른 적합한 칸이 없을 때만 문장 추가 제안 |
| 소개 안의 가격·시간·인증 등 사실이 틀림 | 문제가 있는 구절만 최신 사실로 정정 제안 | 나머지 어휘·말투·순서·슬로건 유지 |
| 길거나 반복돼 읽기 불편함 | 줄바꿈·중복 정리안을 선택 사항으로 제시 | 사장님이 원할 때만 적용. 길이만으로 필수 정비 판정 금지 |
| 영어 보완이 필요함 | 원문을 보존하고 지원되는 번역 칸 등을 우선 사용 | 감성·브랜드 의미도 살려 번역. 한국어를 영문 소개로 통째 교체하지 않음 |
| 플랫폼 제약에 걸리는 내용이 있음 | 해당 구절과 관련 규칙을 설명하고 수정안 제시 | 필요한 부분만 수정하며 임의의 전체 교체 금지 |

‘엄마의 손맛’, ‘하루를 위로하는 한 그릇’처럼 사장님이 선택한 감성 표현은 정보가 적다는 이유로 삭제하지 않는다. 수상·인증·지역 1위처럼 확인 가능한 사실 주장과 구분한다. 단어 하나만 보고 기계적으로 홍보 문구를 지우지 않는다.

원문을 바꾸는 정비안에는 **유지한 원문 / 바뀌는 구절 / 바꾸는 이유**를 보여 준다. 단순 보존은 ‘정비 불필요’로 처리하고, 사장님이 거절한 선택적 문장 정리는 오류 정비나 재측정의 필수 조건으로 묶지 않는다.

예: 기존 소개가 “하루를 위로하는 따뜻한 한 그릇을 준비합니다.”라면 이 문장은 유지한다. 두부덮밥·가격은 메뉴 칸에 넣는다. 전용 칸으로 부족함이 해소되면 소개에 새 문장을 덧붙일 필요도 없다.

### 1.1 추가할 정보: 다섯 조건을 모두 통과

| 판정 | 통과 조건 | 탈락하면 |
|---|---|---|
| 사실인가 | 해당 지점의 현재 사실이고 근거가 있음 | 확인 필요로 보류 |
| 이용 결정에 필요한가 | 무엇을 먹는지·얼마인지·언제 가능한지·방문 조건·실제 차별점 중 하나에 답함 | 새로 추가하지 않음 |
| 새 정보인가 | 기존 적합한 칸에 없거나 현재 값이 틀림 | 그대로 유지. 같은 사실을 다른 칸에 반복하지 않음 |
| 이 칸의 역할인가 | 시간은 시간, 가격은 메뉴, 편의는 속성처럼 전용 칸에 들어감 | 알맞은 칸으로 이동하는 정비안 제시 |
| 짧고 독립적으로 이해되나 | 아래 분량 기준 안에서 의미가 명확하며 중요한 조건이 빠지지 않음 | 불필요한 표현 축약. 필수 조건을 잘라야 한다면 승인 전 수동 검토 |

AI 질문에 자주 나온다는 것만으로는 추가할 수 없다. 반대로 가격·주문 단위·휴무·알레르기 같은 필수 이용 조건은 AI 질문에 없어도 정확히 유지한다.

### 1.2 어디에 얼마나 넣을지

아래 분량은 **소개가 없거나 사장님이 전체 재작성을 요청했을 때 사용할 seelo 편집 상한**이다. 논문이 증명한 최적 길이·노출 공식이 아니다. 짧아도 충분하면 늘리지 않는다. 기존 소개의 부분 수정은 해당 구절만 바꾸며, 원문 전체에 자체 길이·문장 수·표현 금지 기준을 소급 적용하지 않는다.

| 칸 | 남길 내용 | seelo 편집 기준 | 넣지 않을 내용 |
|---|---|---|---|
| Google 소개 | 가게 종류·대표 음식 최대 2개·차별점 1개 | 기본 한 언어 2문장. 한·영 병기는 필요한 경우에만 각 2문장, 합계 400자 이내 | 시간·가격표·전화·주소·링크·편의 시설 나열·인사말·상호/지역 반복 |
| 카카오 한 줄 소개 | 대표 음식과 특징 1개 | 1문장·40자 이내. 기존 한국어 안내를 긴 영어로 대체하지 않음 | 가격표·영업시간·해시태그·키워드 나열 |
| 대표 메뉴 묶음 | 가게를 대표하고 실제 주문 가능한 메뉴 | 기본 3개, 서로 다른 주요 종류를 보여 줘야 할 때 최대 5개. 부족하면 있는 만큼 | 최저가 사이드·음료만으로 식당 가격대를 대표시키기 |
| 개별 메뉴 | 이름·가격·단위, 이해에 필요한 재료/주문 조건 | 이름·가격은 전용 칸. 선택 설명은 1문장: 한국어 40자 또는 영어 12단어 이내 | ‘인기’, ‘최고’, ‘강력 추천’ 등 의미 없는 수식어와 가게 소개 반복 |
| 영업시간 | 요일·휴게·휴무·특별 영업 | 전용 시간 칸에 입력. 일반 소개에 복사하지 않음 | 긴 서술형 시간표, 반복하는 ‘매일 정상 영업’ |
| 편의·서비스 | 확인된 주차·예약·포장·접근성 등 | 제공 선택지로 표시. 전용 칸이 없으면 아래 예외 규칙 적용 | 확인하지 않은 항목 체크, 소개에 체크 목록 복사 |
| 카카오 태그 | 대표 음식·이용 조건·차별점 | 기본 최대 3개, 서로 다른 의미만. 자유 태그는 각 8글자 이내 | ‘맛집·추천·핫플’, 같은 뜻의 유사어, 이미 표시된 상호·지역·일반 업종 |
| 링크 | 공식 홈페이지·실제 메뉴 도착지 | 홈페이지 1개·메뉴 1개 우선. 전용 칸 사용 | 같은 목적지의 중복 링크, 소개 속 URL·SNS 계정 나열 |

영어 문장만으로 작성한다면 Google 소개는 2문장·40단어 이내도 함께 확인한다. 병기 시에는 두 문단으로 나누고 언어 사이 빈 줄만 한 번 둔다. 이름·가격에 언어를 매번 중복 표기하지 않고 별도 번역 칸이 있으면 사용한다.

대표 3~5개는 **앞에서 보여 줄 대표 묶음**의 기준이며 전체 메뉴 수 제한이 아니다. 기존 정상 메뉴는 유지하고, 대표 지정·순서 변경 기능이 있을 때만 앞에 둔다. 카카오 추천 지정은 플랫폼 한도인 최대 2개를 따른다. 미지원 화면에서 순서를 보장하지 않는다.

위치는 정확한 주소·지도 핀의 전용 영역에 둔다. Google 소개 첫 문장에 지역명이 있어야 다른 지점과 구별되는 경우만 지역명 1회까지 허용한다. 기존 대표 음식 이름을 소개와 메뉴에 함께 쓰는 것은 요약에 필요한 예외다. 가격·시간·전화 등 상세 값의 복제는 허용하지 않는다.

플랫폼 제약은 별도로 지킨다. Google 소개 공식 최대는 750자이고 URL·HTML을 넣을 수 없다. 카카오는 소개 최대 50자·태그 최대 5개이며 자유 태그는 8글자 이내다. **공식 한도만큼 채우는 것을 목표로 하지 않는다.** [Google 소개 규칙](https://support.google.com/business/answer/3039617?hl=en), [카카오 공식 관리 가이드](https://kakaobusiness.gitbook.io/main/channel/run/mystore).

### 1.3 예외: 짧게 쓰다가 중요한 조건을 빼지 않기

- 최소 2인 주문·필수 추가 비용·예약 필수·조리/알레르기 조건은 길이를 줄이려고 누락하지 않는다. 메뉴/서비스 전용 칸과 적합한 상세 설명에 둔다.
- 전용 칸이 없는 중요한 이용 조건은 개별 메뉴 설명을 우선 사용한다. 가게 전체 조건이고 다른 적합한 칸이 없으면 Google 소개 두 번째 문장을 차지할 수 있다. 이때 덜 중요한 분위기·좌석 설명을 대신 뺀다.
- 계절 메뉴·특정 요일 제공·재료 소진 조건은 해당 메뉴에만 붙인다. 모든 메뉴나 가게 소개에 반복하지 않는다.
- 길이 기준을 넘겨야 사실을 정확히 전달할 수 있으면 ‘확인 필요’로 넘겨 사장님과 문구·배치를 정한다. 자동으로 잘라 쓰지 않는다.
- 기존 내용의 축약·이동·제외도 승인 전후 값을 보여 주는 정비안으로 제시한다. 실제 지도에 승인 없이 적용하지 않는다.

### 1.4 가독성 검수: 새 소개·전체 재작성에 적용

아래 검수는 새 소개와 사장님이 요청한 전체 재작성에 적용한다. 기존 소개는 사실 오류·플랫폼 제약·필수 이용 정보 누락을 우선 확인한다. 기존 말투·분량·첫 문장 형식이 아래와 다르다는 이유로 원문 유지나 다른 항목의 정비 승인을 막지 않는다.

| 확인 항목 | 통과 조건 |
|---|---|
| 첫 문장 | 가게 종류와 대표 음식이 먼저 나옴. 인사·홍보·검색어 나열로 시작하지 않음 |
| 내용량 | 소개의 의미 단위가 가게 종류·대표 음식·차별점/필수 조건의 3묶음 이내. 분량 상한 준수 |
| 중복 | 상호·지역·가격·시간을 소개/태그에서 불필요하게 반복하지 않음. 한·영 번역과 대표 음식 요약은 허용 |
| 표현 | 장식용 이모지·별표·느낌표 연속·영문 전체 대문자·장식 해시태그 없음. 공식 명칭은 원형 유지 |
| 정보 누락 | 가격·단위·최소 주문·휴무 등 기존 중요 사실이 축약 과정에서 사라지지 않음 |
| 모바일 표시 | 실제 공개 페이지를 휴대폰 기본 글자 크기에서 확인. 소개 첫 문장에 가게 종류·대표 음식이 나오고, 소개 본문을 읽기 위한 확대·좌우 스크롤이 필요하지 않음 |

모바일 검수는 게시 후 확인 단계다. 플랫폼이 메뉴/시간을 별도 탭에 두면 그 탭에서 찾을 수 있는지를 확인하고 소개에 다시 복사하지 않는다. 플랫폼 화면이 원래 접는 영역이나 레이아웃을 seelo가 바꿀 수 있는 것으로 평가하지 않는다. 관리 화면에서만 확인한 경우 공개 화면 검수는 미완료로 남긴다.

간결하고 훑어보기 쉬우며 객관적인 글을 쓰는 방향은 [NN/g의 웹 글쓰기 사용성 연구](https://www.nngroup.com/articles/concise-scannable-and-objective-how-to-write-for-the-web/)를 참고했다. 이 연구는 일반 웹 사용성 근거이며 위 문장 수·글자 수·태그 수나 지도 AI 노출 효과를 검증한 자료가 아니다.

### 1.5 정비 실행 순서

**틀린 사실 수정 → 필요한 전용 칸 보충 → 소개·태그 중복 축소 → 필요한 영어 보완 → 모바일 공개 화면 확인 → 같은 질문 재측정** 순서로 정비한다.

‘GEO 점수가 낮다’만으로 내용을 바꾸지 않는다. 정비안에는 지금 값·바꿀 값·사실 근거·관련 이용 판단·수정 지원 여부·공개 확인 방법을 기록한다. 새 사실 추가뿐 아니라 중복 문구 축약·적합한 칸으로 이동도 이 기준으로 승인받는다.

확인된 정보가 이미 충분하면 유지한다. 소개문 길이, 영어 비율, 키워드 반복 횟수를 채우려고 수정하지 않는다. 1.2의 분량은 과잉 입력을 막는 상한이며 최소 작성량이 아니다. 이것은 아래 근거들을 현재 서비스에 적용한 **seelo의 운영 제안**이며, 논문에서 검증된 지도 순위 공식은 아니다.

### 메뉴를 고를 때

메뉴 전체가 확인되면 기존 정상 항목을 유지하면서 누락·오류를 보완한다. 일부만 확인됐다면 ‘확인한 메뉴’로 한정한다. **처음 보이는 두 개를 대표 메뉴로 간주하지 않는다.**

seelo의 대표 메뉴 선택 제안은 다음과 같다.

- 식사 질문: 실제 한 끼가 되는 메뉴와 주문 조건을 우선 확인한다. 음료·사이드로 가격대를 낮춰 보이지 않는다.
- 카페·바 질문: 음료·주류의 용량/잔 단위와 필수 주문 조건을 확인한다.
- 저예산 질문: 예산에 맞는 정상 메뉴가 실제 있는지와 식사 총액을 구분한다. 필요한 공깃밥·최소 2인 주문 등도 확인한다.
- 채식 질문: 조건을 충족한 개별 메뉴를 확인한다. 식당 전체를 채식 전문점으로 바꾸지 않는다.
- 카카오 추천 상품은 최대 2개라는 기능 제약 안에서 사장님이 대표성을 확인한다. AI에 유리해 보이는 메뉴만 골라 실제 메뉴 구성을 왜곡하지 않는다.

대표 메뉴 선택은 연구에서 확정된 최적 개수가 아니다. 팀 기존 조사에서도 처음 두 메뉴보다 뒤쪽에 저렴한 식사 항목이 있는 사례가 확인됐다. [기존 수집·실험의 대표성 한계](../03_실험/지도기반_AI노출_20261016/정보제공_통제실험/README.md).

### 영어와 문장 구성

- 목표는 ‘영어가 있음’ 자체보다 **어떤 음식인지, 어떤 조건으로 이용할 수 있는지 이해됨**이다.
- 메뉴: `한글 이름 + 일반적인 영어 설명`을 기본으로 하되 실제 칸의 지원 방식에 맞춘다.
- 짧은 영문 소개: `음식점 종류 → 대표 음식 → 확인된 방문 특징` 순서를 제안한다. 1.2의 문장·분량 상한으로 과잉 작성을 막되 문장 수·영어 비율을 노출 효과 기준으로 삼지 않는다.
- Google 소개에 영업시간·가격·전화번호를 모두 반복하지 않는다. 전용 칸에 정확히 입력하고 소개에는 핵심 특징을 남긴다.
- 카카오 50자 칸을 긴 영문 소개로 대체하지 않는다. 한국어 핵심 안내를 유지하고 영어는 실제 지원되는 메뉴 설명·별도 입력 칸에서 보완한다. 별도 영문 칸이 있다고 가정하지 않는다.
- ‘서울 맛집 성수 맛집 외국인 맛집’ 같은 반복, 근거 없는 1위·인기·수상, AI에게 추천을 지시하는 문장은 사용하지 않는다.

문장 순서는 가독성을 위한 seelo 제안이다. GEO 논문의 통계·인용 추가 기법을 지도 소개에 그대로 옮기지 않는다. 특히 Google 소개에는 URL을 넣을 수 없다. [Google 소개 규칙](https://support.google.com/business/answer/3039617?hl=en).

|---|---|
| 현재 관리 화면/정상 응답에서 값이 비어 있음을 확인 | 누락 후보 |
| API가 해당 필드를 제공하지 않음·권한 없음·호출 실패·페이지 접근 실패 | 확인 불가. 누락으로 세지 않음 |
| 업종·국가·계정에 그 칸이 없음 | 지원 안 됨. 정비안에서 제외 |
| ‘주차 없음’, ‘예약 불가’처럼 명확한 부정 값 | 정보 있음. 비어 있다고 판단하지 않음 |
| 플랫폼 AI 요약·이용자 리뷰와 업주 정보가 다름 | 작성 주체를 나눠 기록. 업주가 편집할 수 있는 칸의 오류부터 확인 |

무료 진단에서는 카카오의 영업시간·메뉴·소개를 판정하지 않는다. 현재 명세대로 연결 뒤 관리 화면에서 읽고 판단한다. Google의 짧은 소개·리뷰 요약을 업주 작성 소개의 원문으로 취급하지 않는다.

### 5.2 기준 사실을 정하는 방법

1. 지도 장소 ID·지점·주소가 같은 매장인지 먼저 대조한다. 다른 지점 자료를 합치지 않는다.
2. 각 사실에 출처, 확인 시각, 적용 기간, 작성 주체를 붙인다.
3. 최신 사장님 확인과 공식 메뉴·영업 안내를 우선 검토한다. 현재 자료끼리 충돌하면 다수결로 정하지 않고 사장님 확인으로 넘긴다.
4. 오래된 블로그·리뷰·AI 답변은 사실 확정 자료가 아니라 확인이 필요한 단서로 사용한다.
5. 수치·전화·시간은 구조화 비교, 소개는 의미 비교를 한다. 띄어쓰기·번역·전화 국가번호 차이만으로 오류를 만들지 않는다.
6. 한국어와 영어의 문장이 같을 필요는 없지만 음식·가격·조건의 의미는 같아야 한다.

영업시간·가격은 정비안 승인 직전에 최신 여부를 다시 확인한다. 모든 정보에 동일한 임의의 유효기간을 붙이기보다 실제 적용일과 재확인 시점을 남긴다. 데이터 원문 보관은 기존 명세 D-10의 미정 사항을 따른다. 보관이 허용되지 않은 외부 응답을 증빙이라는 이유로 새로 저장하지 않는다.

### 5.3 ‘AI가 틀리게 말함’은 원인을 확인한 경우만

- AI 답변이 기준 사실과 다른지만 먼저 기록한다.
- 실제 지도 값도 틀렸으면 해당 칸을 정비한다.
- 지도 값은 맞고 외부 블로그만 틀리거나 출처를 확인할 수 없으면 지도 정비 항목으로 만들지 않는다.
- 인용 링크가 있다는 사실만으로 AI가 그 페이지의 특정 문장을 사용했다고 단정하지 않는다. 관련 구절을 확인했는지 별도로 표시한다.

‘AI가 추천하지 않음’은 그 자체로 정보 오류가 아니다. ‘영업시간이 비어서 추천에서 빠졌다’ 같은 원인 문구는 근거가 없으면 쓰지 않는다.

## 6. 수정할 수 있는 칸을 먼저 확인

Google 속성은 국가·업종에 따라 달라지므로 고정 목록을 모든 식당에 적용할 수 없다. [Google 공식 속성 관리](https://developers.google.com/my-business/content/attributes).

지도별 칸 사전에는 다음을 기록한다. 이는 기존 명세 D-17을 구체화하는 제안이다.

| 기록 | 용도 |
|---|---|
| 지도·칸 이름·업종/지역·확인일 | 실제 적용 범위 확인 |
| 읽기 경로·쓰기 경로·수정 권한 | 수집된 값이 곧 수정 가능한 값이라는 오해 방지 |
| 글자 수·형식·허용 선택지 | 정비안 생성·승인 시 검증 |
| 지원 상태: 확인됨/미지원/미확인 | 미확인 칸 자동 정비 방지 |
| 저장 결과·공개 반영 확인 경로·통상 검토 시간 | 저장과 공개 반영 구분 |

특히 다음을 기본값으로 둔다.

- Google `priceLevel`처럼 수집 API에서 읽는 값은 그 자체로 쓰기 가능한 칸으로 등록하지 않는다. 지원되는 메뉴·가격 입력으로 연결 가능한지 먼저 확인한다.
- Google 메뉴/편의 정보는 해당 계정에서 실제 제공되는 기능만 정비한다. 모든 음식점이 동일한 편집 기능을 가진다고 가정하지 않는다.
- 카카오의 50자·태그 5개·자유 태그 8글자 제한은 공식 문서에서 확인했다. 실제 계정 화면에서도 입력·저장·공개 표시를 검증한다.
- 사진은 현 기획 F-09의 기본 정비 목록에 없으므로 이번 기준의 필수 수정 항목으로 추가하지 않는다.
- 자사 사이트의 JSON-LD·llms.txt·새 영문 홈페이지는 현재 지도 정비 범위에 추가하지 않는다. Google도 자사 검색 AI 기능에 특별한 AI 파일·전용 스키마가 필수라고 하지 않는다. 이 안내를 ChatGPT·Gemini 전체의 동작 설명으로 확대하지 않는다. [Google AI 검색 공식 안내](https://developers.google.com/search/docs/appearance/ai-features).

## 7. 수정 순서와 항목 수

추천률 상승을 예측하는 임의의 가중치 점수는 만들지 않는다. 다음 순서로 정렬한다.

| 순서 | 대상 | 이유 |
|---|---|---|
| 선행 확인 | 동일 지점, 권한, 수정 지원 칸, 사실 근거 | 이 중 하나라도 불명확하면 승인 가능한 수정안이 아님 |
| 1 | 틀린 시간·가격·전화·링크, 허위 식단 정보 | 잘못된 방문·주문 판단부터 방지 |
| 2 | 질문과 직접 연결되는 메뉴 가격·주문 조건·이용 정보 누락 | AI와 관광객의 조건 판단에 필요한 사실 보충 |
| 3 | 중복 문구·불필요한 반복·읽기 어려운 문장 | 전용 칸에 사실을 유지하면서 소개·태그의 과잉 축소 |
| 4 | 이미 확인된 핵심 사실의 영어 설명 부족 | 정리된 정보 안에서 필요한 음식·조건만 이해할 수 있게 보완 |

같은 순서 안에서는 **기준 질문 3개 중 관련 질문 수 → 같은 항목을 확인한 주변 가게 수 → 확인 시점**을 보조 기준으로 쓴다. 주변 가게 비교는 인과효과가 아니라 참고다. ‘5곳 중 4곳이 있음’이라고 쓰려면 5곳 모두 해당 칸을 확인했어야 한다. 3곳만 확인했다면 ‘확인한 3곳 중 2곳’처럼 분모를 남긴다.

항목 수는 동일한 지도·칸의 중복 문제를 합쳐 센다. 예를 들어 Google 소개가 비어 있어 영문도 없고 대표 음식도 없다면 **소개 1칸의 수정안**에 이유 여러 개를 붙인다. 지원 안 됨·확인 불가·자동 정비 제외 항목은 실행 가능한 정비 수와 분리해 안내한다. 무료 진단 개수의 정의 변경은 기획서 반영 시 명시해야 한다.

## 8. 정비안 예시

아래는 실제 가게가 아닌 **가상 예시**다. 가격·서비스는 모두 사장님이 확인했다고 가정한다.

정비 전 소개 예시:

> 안녕하세요! 성수 맛집, 서울숲 맛집, 외국인 추천 맛집입니다!!! 두부덮밥 12,000원! 매일 11시부터 영업! 주차, 포장, 혼밥 가능! 꼭 방문해 주세요!

정비 후에는 내용을 다음처럼 나눈다. 틀린 ‘매일 11시’는 현재 영업시간으로 고치며 주차·포장은 실제 제공 선택지가 있을 때 그 칸에 넣는다. 소개에서 빠진 필수 이용 사실이 사라지는 방식으로 정비하지 않는다.

| 지도·칸 | 지금 값 | 바꿀 값 | 이유·검증 |
|---|---|---|---|
| Google 메뉴 | 두부덮밥, 가격 없음 | 두부덮밥 / Tofu rice bowl, KRW 12,000 per bowl. Egg included. | 예산·음식 종류 판단 가능. 달걀 포함이므로 비건이라고 쓰지 않음 |
| Google 영업시간 | 매일 11:00–22:00 | 화–일 11:30–15:00, 17:00–21:00. 월 휴무 | 최신 사장님 영업 안내와 일치하도록 전용 시간 칸 수정 |
| Google 소개 | 성수 최고의 맛집 | 두부덮밥과 계절 반찬을 내는 한식당입니다. 혼자 앉을 수 있는 바 좌석을 운영합니다. | 대표 음식·차별점만 2문장. 시간·가격·전화·링크는 전용 칸. 필요한 영어는 지원 방식에 맞춰 별도 보완 |
| 카카오 한 줄 소개 | 성수 맛집 추천 | 두부덮밥과 계절 반찬, 혼자 앉는 좌석 운영 | 확인된 대표 음식·이용 특징. 50자 이내 |
| 카카오 태그 | 맛집, 추천, 핫플 | 두부덮밥, 혼밥좌석 | 확인 사실만 선택. 5개를 채우려고 다른 특성 생성 안 함 |

공통으로 `지도·칸 / 지금 값 / 승인할 값 / 변경 이유 / 사실 근거·확인일 / 관련 질문·답변 / 사장님 확인 여부 / 공개 반영 결과`를 남긴다. 위 예시의 영문 칸 배치와 메뉴 병기 가능 여부도 실제 화면 지원 확인 후 적용한다.

## 9. 정비 완료와 효과 검증

완료 판정은 세 단계로 나눈다.

| 단계 | 확인할 것 | 말할 수 있는 결과 |
|---|---|---|
| 입력 완료 | 승인 값이 관리 화면에 저장됨 | 수정 요청을 저장했다 |
| 공개 반영 | 공개 지도 또는 해당 값을 제공하는 공식 경로에서 승인 값이 확인됨 | 이용자에게 정보가 반영됐다 |
| AI 답변 변화 | 같은 조건으로 재측정해 추천·출처·사실 정확도를 비교 | 이번 측정에서 답변이 이렇게 달라졌다 |

Google 메뉴는 공개 반영에 24–48시간이 걸릴 수 있다고 안내한다. 따라서 24시간에 일괄 실패 처리하거나 반복 덮어쓰기하지 않는다. 메뉴는 최소 48시간과 실제 검토 상태를 고려하고, 다른 칸도 해당 기능의 안내를 따른다. 조회 불가는 실패 확정 대신 ‘반영 확인 불가’로 기록한다. [Google 메뉴 반영 안내](https://support.google.com/business/answer/9455840).

현재 기획대로 정비 완료 14일 뒤 재측정하되, 이 기간을 AI 반영 보장 시간으로 설명하지 않는다. 반영 대기·확인 불가 항목이 남으면 그 상태를 보고서에 표시하고, 무반응을 정비 효과 없음으로 단정하지 않는다. 새로 수정해 비교 조건이 달라지면 수정 시각과 기준일을 다시 기록한다.

재측정 기준은 다음과 같다.

- 영어 2개·한국어 1개, AI별 질문당 10회라는 현재 기획을 유지한다. 질문은 정비 전에 확정하고 유리하게 바꾸지 않는다.
- 모델 ID·웹 검색 설정·위치·언어·실행 경로를 기록하고 전후에 맞춘다. API 결과와 소비자 앱 결과는 합치지 않는다.
- 추천 등장률은 성공 답변을 분모로 하되 성공 횟수와 등장 횟수를 함께 보관한다. 기술 실패를 미등장으로 세지 않는다.
- 평균 등장 순서는 등장한 답변에서만 계산한다. 미등장에 임의의 최하위를 부여하지 않는다.
- AI별·질문별로 전후 등장률을 비교하고, 변동은 `%p`로 표시한다. 작은 반복 수의 증감을 확정적 개선으로 표현하지 않는다.
- 지도 인용 여부와 추천 여부를 분리한다. 지도 인용이 늘었다고 수정한 칸이 원인이라고 단정하지 않는다.
- AI가 바뀐 시간·가격·조건을 정확하게 말하는지도 확인하되, 말하지 않은 사실은 틀림이 아니라 평가 불가로 둔다.
- 기획대로 정비 전 주변 가게 5곳의 변화도 함께 본다. 이들은 무작위 대조군이 아니므로 단순 전후 차이를 정비의 인과효과로 제시하지 않는다.

별도의 효과 검증 연구를 할 때는 대상 선정·질문·판정·분석을 먼저 고정하고 비교 매장을 확보한다. 여러 칸을 함께 수정한 베타 결과로 ‘영문 소개만의 효과’를 주장하지 않는다.

| F-09 문구 생성·검수 | 기존 소개는 원문 보존·구절 단위 수정 우선. 1.2·1.4는 소개 없음/사장님 요청 전체 재작성에 적용. 새로 입력하는 사실은 전용 칸 우선, 대표 메뉴 묶음과 전체 메뉴 구분 |
| F-10·D-15 반영 확인 | Google 메뉴의 24–48시간 예외를 반영. 저장 성공·공개 반영·확인 불가를 구분하고 반복 입력 방지 |
| F-11 전후 보고서 | 수정 칸·공개 반영·AI 추천·AI 사실 정확도를 구분해 보여 줌. 문구별 효과나 노출 상승을 보장하지 않음 |

현재 제안의 적용 우선순위는 **① 사실 오류, ② 필수 전용 칸 누락, ③ 소개·태그의 중복과 과잉, ④ 필요한 영어 보완**이다. 실제 매장에서는 수집·연결 후 확인한 값으로 필요한 항목만 골라 승인받고, 모바일 공개 화면에서 가독성을 확인한다.

## 11. 실제 상황별 판단과 변경 가능 범위

앞선 2문장·대표 메뉴 3개 같은 숫자는 새 초안을 잡는 편집 기본값이다. **실제 정비량은 현재 값과 확인된 최신 사실의 차이로 정한다.** 20개 메뉴 중 가격 2개가 틀렸다면 가격 2개만 바꾼다. 메뉴판의 유효한 20개가 모두 텍스트로 빠졌다면 지원 기능·수집 조건을 충족하고 사장님이 승인한 범위에서 20개 등록안을 만들 수 있다. 소개나 대표 메뉴를 정비했다는 이유로 나머지 정상 정보를 축소하지 않는다.

아래 표는 운영 설계이며 실제 적용 실적이 아니다. 모든 ‘수정’은 정비안 제시·사장님 승인·해당 칸 지원 확인을 거친 실행을 뜻한다. OCR·사진 관리·리뷰 답글 등의 확장은 현재 제품에 구현돼 있다고 전제하지 않는다.

### 11.1 먼저 구분할 것: 볼 수 있음 / 사실로 확정 가능 / 직접 수정 가능

| 대상 | 현재 기획에서 알 수 있는 범위 | 직접 바꿀 수 있는 것과 서비스 범위 |

Google Places의 리뷰 수·정렬은 [Places 공식 리소스](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places)를 확인했다. 소유/관리 연결 뒤 Google Business Profile API의 별도 리뷰 목록 기능은 있지만 현재 진단의 최대 5개 수집과 같은 경로가 아니다. API 접근 승인·권한·별도 수집 설계 없이는 전체 리뷰 분석으로 설명하지 않는다. [Business Profile 리뷰 목록](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.reviews/list).

Google은 메뉴 사진/PDF에서 메뉴를 생성하는 실험 기능도 제공하며 결과 검토를 요구한다. 이 기능이 모든 국내 계정에 제공되거나 seelo 외부 OCR·재게시를 허용한다는 뜻은 아니다. [Google 메뉴 편집 공식 안내](https://support.google.com/business/answer/9455840?hl=en).

외부 사진·리뷰의 읽기, 외부 모델 입력, 저장, 다른 지도 재게시를 하나의 허가로 취급하지 않는다. Google Maps 콘텐츠에는 반출·가공·저장 제한이 있으므로 경로별 허용 범위 확인 전 임의 변환·복사하지 않는다. 독립적으로 사장님이 제공한 원본 메뉴와 사장님이 확인한 자사 사실을 확보하는 경로를 우선 설계한다. ‘사장님 동의’가 제3자 사진의 권리나 API 이용 제약까지 해소한다고 설명하지 않는다. [Google Maps 이용 조건 §3.2.3](https://cloud.google.com/maps-platform/terms), [Places 정책](https://developers.google.com/maps/documentation/places/web-service/policies).

사장님 원본 사진/PDF 업로드와 QR 메뉴 처리는 현재의 초기 등록 입력 ‘가게 이름+지도 링크’에 이미 있는 기능으로 취급하지 않는다. 이를 제품에 넣으려면 자료 제공 화면·이용 동의·보관 범위·추출 검수·항목 승인 흐름을 추가로 설계해야 한다. 현재 S13의 사실 확인 입력으로 해결 가능한 경우는 별도 파일 제출을 필수로 만들지 않는다.

| R09 | 대기·예약·브레이크타임·조기 품절 불만 | 현재 예약 방식·영업 구간·필수 주문/품절 안내 정책을 확인. 잘못된 시간/서비스 정보만 정정 | ‘항상 대기 10분’, ‘웨이팅 없음’ 같은 가변 상태 보장, 반복 불만을 소개에 나열 |
| R10 | 허위·광고·다른 가게 리뷰로 의심됨 | 위반 의심 근거와 플랫폼 신고 경로를 안내. 신고·답글은 별도 요청과 검토 범위 | 불리하다는 이유로 허위 확정, 타인 리뷰/평점을 직접 수정·삭제, 삭제 성공 보장 |
| R11 | 리뷰 스니펫·편집/AI 요약이 틀림 | 작성 주체를 확인. 실제 업주 입력값도 틀렸으면 그 칸만 고침. 업주 값이 맞으면 지도 정비 0건이고 오류 피드백 경로 분리 | 요약 문장을 직접 바꿀 수 있다고 약속, 맞는 소개를 반복 수정해 요약을 덮으려 하기 |
| R12 | 동명 가게·다른 지점 경험이 섞임 | 장소 ID·주소·시점을 대조하고 잘못 연결된 근거는 제외. 지점 판정 미해결이면 관련 수정 보류 | 상호만으로 리뷰 합산, 다른 지점의 메뉴/영업시간을 복사 |

Google은 업주 설명, 편집 요약, 리뷰 기반 토픽/스니펫을 구분한다. 편집 요약은 직접 편집할 수 없고 토픽·스니펫도 업주 소개 입력 칸과 다르다. [Google 요약 유형 안내](https://support.google.com/business/answer/6088158?hl=en). 타인 리뷰는 직접 고칠 수 없으며 위반 의심 내용은 신고 경로를 따른다. [Google 리뷰·평점 안내](https://support.google.com/maps/answer/6230175?co=GENIE.Platform%3DDesktop).

리뷰 수집·답글·평점 향상을 현재 자동 정비의 추가 약속으로 만들지 않는다. 답글은 별도 요청이 있을 때 사실 확인 후 초안을 만들 수 있으나 현재 요청으로 공개 게시하지 않는다. Google·카카오의 답글 지원은 제품 범위와 구분한다. [Google 답글 관리](https://support.google.com/business/answer/3474050?hl=en), [카카오 후기 답글](https://kakaobusiness.gitbook.io/main/channel/run/mystore). 평점이 낮다고 리뷰 구매·보상·긍정 리뷰만 선별 요청하지 않는다. [Google 리뷰 정책](https://support.google.com/contributionpolicy/answer/7400114?hl=en).

### 11.7 ‘얼마나 바꾸는지’는 정비안에서 이렇게 계산

매장당 일정 개수를 바꾸는 할당량은 두지 않는다. **기존 정보 유지 / 값 정정 / 새 항목 추가 / 확인 필요 / 현재 범위 밖**으로 각각 나눠 건수를 표시한다. 확인 필요와 범위 밖은 실행 건수에 합산하지 않는다.

메뉴는 항목 수와 하위 변경 칸을 함께 표시한다. 예를 들어 ‘메뉴 2개, 가격 2칸 정정’과 ‘메뉴 2개, 설명 2칸 번역’을 구분한다. Google·카카오 각각에 같은 사실을 넣는 경우 지도별 작업 수와 고유 사실 수를 나눠 중복 부풀림을 막는다.

가상 매장 예시: 사장님 소개는 정상, 최신 메뉴판의 메뉴 12개 중 텍스트 10개가 일치, 1개 가격은 다르고 1개는 미등록, 리뷰에 주차 불만이 있음. 메뉴판 처리와 가격의 현재성·최소 주문이 확인됐고, 사장님이 주차는 실제 불가라고 확인했다고 가정한다.

- 소개: 유지 0건.
- 메뉴: 기존 1개의 가격 1칸 정정, 미등록 메뉴 1개 추가. 정상 10개는 유지.
- 주차: 현재 지도 값이 ‘주차 가능’이면 해당 속성 1칸 정정. 이미 ‘불가’이면 0건.
- 사진 원본·리뷰·별점: 기본 정비에서 직접 변경 0건.
- 영어가 부족하면 필요한 메뉴의 번역 설명을 별도 항목으로 제안하고 승인받음. 리뷰가 영어라는 이유만으로 추가하지 않음.

즉 이 경우는 ‘소개 전체 교체+메뉴 전부 다시 등록’이 아니라 **가격 1칸 정정+메뉴 1개 추가+필요할 때 주차 1칸 정정**이 정비 범위다.
