# 스마트스토어·카페24 수정 API와 GEO 적용 범위

확인일: 2026-11-24. 공식 문서, 기존 실계정 수정 기록, 오늘의 인증 응답을 대조했다. 이번 확인에서는 상품을 수정하지 않았다.

## 결론

**두 플랫폼 모두 수정용 API를 발급·연결할 수 있으며 상품 상세 HTML을 통한 GEO 콘텐츠 정비가 가능하다.**

| 구분 | 스마트스토어 | 카페24 |
|---|---|---|
| API | 네이버 커머스API | 카페24 Admin API |
| 본인 몰 인증 | 내 스토어 애플리케이션, SELF 토큰 | 개발자 앱, 해당 몰 OAuth 동의 |
| 상세 수정 | `PUT /v2/products/origin-products/{originProductNo}` | `PUT /api/v2/admin/products/{product_no}` |
| 본문 필드 | `originProduct.detailContent` | `request.description` |
| 관련 필드 | `detailAttribute.seoInfo`, 상품 속성·고시 | `mobile_description`, `summary_description`, `simple_description`, 상품 SEO 별도 API |
| 실계정 증거 | 본문 수정·재조회·원복 성공. 추가 상품 2종 등록 후 본문·SEO 일치 확인 | 관리자 UI 저장·공개 반영 성공. Admin API 토큰 발급·상품 쓰기는 미수행 |
| 현재 남은 것 | 호출 허용 IP 확인 | 앱·OAuth 연결과 읽기·쓰기·복구 시험 |

상품 상세의 요약, 원료·용량·활용·보관·주의, 질문과 답변을 읽을 수 있는 텍스트와 HTML로 정리하는 방식은 양쪽 모두 적용 대상이다. 전용 ‘GEO 켜기’ API가 있는 방식이 아니라, seelo가 만든 정비안을 상품 수정 API에 전달하는 방식이다.

## 1. 스마트스토어 확인

### 발급·수정 가능 여부

1. 스마트스토어 통합매니저 권한이 있는 계정으로 커머스API센터를 이용한다.
2. 본인 몰 실험은 ‘내 스토어 애플리케이션’을 등록한다.
3. 상품 API 권한과 호출 허용 IP를 설정한다.
4. Client ID·Secret으로 SELF 인증 토큰을 발급받는다.
5. 원상품번호로 상품을 조회하고 상세 HTML을 수정한다.

공식 문서에 원상품 수정 경로와 `detailContent`, `detailAttribute.seoInfo.pageTitle`, `metaDescription`, `sellerTags`가 명시돼 있다. [API센터 안내](https://apicenter.commerce.naver.com/ko), [원상품 수정](https://apicenter.commerce.naver.com/docs/commerce-api/current/update-origin-product-product), [원상품 구조체](https://apicenter.commerce.naver.com/docs/commerce-api/current/schemas/%EC%9B%90%EC%83%81%ED%92%88-%EC%A0%95%EB%B3%B4-%EA%B5%AC%EC%A1%B0%EC%B2%B4)

### 실제 검증과 오늘 접속 상태

- 2026-11-19: 본인 앱 발급과 SELF 인증을 완료했다. 벌꿀 상세를 A안→B안으로 바꿔 재조회한 뒤 A안으로 복구했다. 가격·재고·배송 등의 보존도 확인했다. [당시 실행 결과](../03_실험/쇼핑몰_API_상품수정_20261119/실행결과.md)
- 2026-11-24 등록 기록: 수박씨·사차인치를 API로 신규 등록했다. 각 상품의 본문·SEO 저장 일치와 구매수량 조건을 재조회로 확인했다. [수박씨 API 검증](../03_실험/쇼핑몰_API_상품수정_20261119/단백질2종_네이버_20261124/watermelon_API검증.json), [사차인치 API 검증](../03_실험/쇼핑몰_API_상품수정_20261119/단백질2종_네이버_20261124/sacha_API검증.json)
- 이번 확인: 새 토큰 발급 요청은 HTTP 403, `GW.IP_NOT_ALLOWED`, ‘호출이 허용되지 않은 IP입니다.’로 거부됐다. 따라서 오늘 이 확인 작업의 신규 상품 읽기 요청은 실행되지 않았다. Secret 오류나 수정 API 미지원으로 해석하지 않는다. 호출 환경의 공인 IP와 앱 허용 IP의 일치 여부를 확인해야 한다.

인증 원문은 Git 제외 `.local/geo-token-diagnostic-20261124.json`에 보관했다. 공개 문서에는 키·토큰·IP를 쓰지 않는다.

### GEO 적용 경계

- 상품 상세 HTML과 상품 정보·SEO 필드의 정비는 가능하다.
- 기존 스마트에디터 ONE 본문에 `detailContent`를 보내면 HTML 작성 방식으로 바뀐다. 따라서 기존 고객 상품은 원본 형식과 공개 레이아웃을 확인한 뒤 변경한다. 현재 seelo 예시 상품은 HTML 방식으로 등록했다. [네이버 공식 안내](https://github.com/commerce-api-naver/commerce-api/discussions/26)
- 일부 HTML 태그·속성·속성값은 필터링된다. 일반 본문 구조의 저장 가능과 임의 스크립트·JSON-LD의 실행 가능을 같은 것으로 취급하지 않는다. 이번에는 새 JSON-LD의 저장·실행을 시험하지 않았다. [공식 필터링 답변](https://github.com/commerce-api-naver/commerce-api/discussions/3585)
- 확인한 상품 API는 상품 상세·정보 범위다. 네이버 페이지 전체의 `<head>`나 플랫폼이 생성하는 Product 데이터를 직접 편집하는 수단으로 사용하지 않는다.

## 2. 카페24 확인

### 발급 과정

1. 카페24 개발자센터에서 앱을 등록하고 Client ID·Secret을 받는다.
2. 앱의 Redirect URI와 필요한 상품 읽기·쓰기 권한을 설정한다.
3. 본인 쇼핑몰에 테스트 설치하고 운영자가 OAuth 사용 권한에 동의한다.
4. Authorization Code를 Access Token·Refresh Token으로 교환한다.
5. Admin API로 상품을 조회하고 수정한다.

상품 작업의 최소 권한은 `mall.read_product`, `mall.write_product`다. 관리자 로그인·부운영자 권한과 앱 OAuth 동의는 각각 별도 절차다. 앱 테스트 설치와 API 호출 경로도 공식 안내에 있다. [API 시작하기](https://apidocs.cafe24.com/en/docs/guide/intro), [상품 Scope](https://developers.cafe24.com/app/front/app/develop/api/scope), [OAuth](https://apidocs.cafe24.com/en/docs/guide/oauth2-authentication), [자체몰 테스트 설치](https://developers.cafe24.com/app/front/common/concepts/sellapp/newbuildapp)

### 수정 가능한 항목

| 대상 | 공식 경로·필드 | 용도 |
|---|---|---|
| 상세 본문 | `PUT /api/v2/admin/products/{product_no}`의 `request.description` | 상세 HTML의 구성·문구 정비 |
| 모바일 본문 | `mobile_description`, `separated_mobile_description` | 모바일 별도 본문 또는 PC 본문 공통 사용 설정 |
| 요약·간략 설명 | `summary_description`, `simple_description` | 짧은 상품 정보 정비 |
| 상품 SEO | `PUT /api/v2/admin/products/{product_no}/seo` | 브라우저 제목·메타태그·검색 노출 설정 |

공식 Scope 안내는 상품 생성·수정·삭제 권한으로 `mall.write_product`를 명시한다. 최신 SEO 수정 문서는 이를 `WRITE_PRODUCT`로 표시한다. 최신 상품 수정 페이지의 공식 메타 정보에서도 상세·모바일·요약·간략 설명 필드를 확인했다. 구버전 공식 필드 설명에서는 상세 HTML 입력을 명시한다. [상품 수정](https://apidocs.cafe24.com/docs/admin/put-products-by-product-no), [SEO 수정](https://apidocs.cafe24.com/docs/admin/put-products-by-product-no-seo), [공식 필드 설명](https://developers.cafe24.com/docs/en/api/admin/?version=2023-03-01)

상품 API 권한으로 쇼핑몰 전체 스킨·공통 `<head>` 편집까지 완료되는 것으로 보지 않는다. 디자인·페이지 작업은 `mall.read_design`·`mall.write_design` 등 별도 범위다. JSON-LD를 어디에 넣고 어떤 스킨에서 유지되는지는 별도 검증한다. [권한 범위](https://developers.cafe24.com/app/front/app/develop/api/scope)

### 우리 계정의 검증 상태

- 카페24 상품 5종은 관리자 UI로 등록·수정하고 공개 PC·모바일 반영을 확인했다.
- 이것은 Admin API 쓰기 성공의 증거가 아니다.
- 현재 실험 폴더에는 카페24 앱·토큰 파일이 없다. 기존 기록도 Admin API OAuth·쓰기를 미수행으로 표시한다.
- 따라서 **공식 API가 지원하는 것은 확인했으나, 우리 몰의 발급·동의·쓰기·복구 성공은 아직 확인하지 않았다.**

## 3. 다른 고객 쇼핑몰에 제공할 때

- 카페24: 고객 몰마다 앱 설치와 OAuth 동의를 받아 해당 몰 토큰으로 수정한다.
- 스마트스토어: 본인 몰 SELF 시험과 별도로 커머스솔루션 구독에 따른 SELLER 인증 또는 공식 API 대행 연결 경로를 확보한다. 매니저 초대와 API 연결을 구분한다. [네이버 솔루션 인증](https://apicenter.commerce.naver.com/docs/solution-doc/3000/%EA%B8%B0%EB%B3%B8-%EC%97%B0%EB%8F%99-%EC%9A%94%EC%86%8C-%EA%B0%80%EC%9D%B4%EB%93%9C), [등록 대행사 연결 안내](https://github.com/commerce-api-naver/commerce-api/discussions/3679)

## 4. 다음 기술 검증

1. 네이버 호출 허용 IP를 확인해 현재 호출 환경에서 인증을 복구한다.
2. 카페24의 상품 읽기·쓰기 전용 앱과 OAuth 연결을 준비한다.
3. 카페24 별도 비공개 상품에서 원본 조회→짧은 상세 변경→재조회·관리자 미리보기→원본 복구를 수행한다. 구매자 공개 반영은 구매 제한을 설정한 별도 검증 상품에서 구분해 확인한다.
4. 기존 노출 실험 4개 URL의 기준선은 유지한다. 실제 GEO 개선은 기준선 측정 후에 적용한다.
5. 검증 완료 후 seelo의 정비안을 플랫폼별 필드에 매핑한다. UI 도구 시험, 직접 API 시험, 서비스 자동 연동 결과를 각각 기록한다.
