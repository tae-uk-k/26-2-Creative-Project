# seelo: GEO 관점의 추가 정비 방법

- 조사일: 2026-10-29.
- 질문: SEO와 겹치는 지도 정비에 더해, AI 추천·인용을 위해 무엇을 다르게 고르고 쓰고 검증할 것인가.
- 이 문서는 조사·제안이다. 기획서·명세서, 실제 지도, 기존 비포·애프터 HTML은 변경하지 않았다.
- 현재 개발 범위는 Google·카카오 정비다. 웹사이트 정비·공개 영문 페이지·JSON-LD·영어 외 다국어·외부 변경 감지는 현재 기획의 P2다. 아래 확장안을 이미 제공하는 기능으로 해석하지 않는다.

## 1. 이번에 확인한 근거와 한계

| 근거 | 확인한 내용 | 식당 서비스에 적용할 때의 한계 |
|---|---|---|
| Google AI 검색 공식 문서 [S1] | 기존 SEO 원칙, 텍스트로 제공한 핵심 정보, 관련 하위 검색을 함께 다루는 방식 | Google AI Overviews/AI Mode 설명이다. 모든 ChatGPT·Gemini 소비자 응답의 내부 동작을 설명하지 않는다. 특수 GEO 마크업을 요구하지 않는다. |
| GEO 원 논문 [R1] | 고정된 검색 후보를 제공한 실험에서 출처·수치·인용·문장 개선을 비교 | 원 연구의 주 평가와 별도 Perplexity 실험을 구분해야 한다. 식당 지도에서 동일 상승률을 보장하지 않으며, 통계·권위자 인용을 억지로 추가할 이유가 되지 않는다. |
| SAGEO Arena v2 [R2] | 검색·재정렬·답변 생성까지 평가하면 본문만 고친 전략의 효과가 달라지고 악화될 수도 있음 | 구성한 실험 파이프라인의 결과다. 상용 서비스 전체나 특정 음식점의 인과 효과가 아니다. |
| What Drives AI Citations? v1 [R3] | 실제 응답 수집·API 재현에서 질문과 페이지의 의미 일치, AI 자체 검색에서 발견되는 단계를 중시 | 2026-10-10 arXiv 사전공개 연구. 미국 영어 통신·B2B 시장이며 한국 식당 실험이 아니다. 관찰 연관성과 제한된 통제 실험을 구분한다. FAQ·스키마의 보편적 인용 상승을 입증하지 않는다. |
| Peec 공식 도움말 [V1] | 질문별 응답·인용 URL·경쟁 출처의 빈틈을 조사하고 작업으로 연결하는 기능 | 업체가 제공하는 기능·방법을 확인한 자료다. 효과를 독립 검증한 연구가 아니다. |
| Yext 공식 제품 자료 [V2] | 지점별 사실 관리, 지점 페이지, 여러 채널 배포와 측정의 결합 | 제품 구성의 참고 사례다. 데이터 그래프나 인증 표식만 있으면 AI가 인용한다는 주장은 채택하지 않는다. |

따라서 ‘SEO는 키워드, GEO는 FAQ’처럼 나누지 않는다. 차이를 만들 지점은 **어떤 질문의 어떤 정보가 부족한지, 어느 출처를 고쳐야 하는지, AI가 무엇을 잘못 연결하는지**다. 아래 편집안은 이 근거를 식당에 적용한 제안이며, 각각의 추천 상승 효과는 실험해야 한다.

## 2. 정비 대상을 고르기 전에 구분할 네 상태

| 관측 상태 | 필요한 작업 |
|---|---|
| 가게·관련 페이지가 출처에서 관측되지 않음 | 발견 경로·검색 접근·관련 출처부터 점검. 소개 문장만 고쳐서 해결됐다고 하지 않음 |
| 관련 페이지는 출처에서 관측되지만 가게 추천은 없음 | 페이지가 질문의 조건을 실제로 충족하는지, 비교에 쓸 사실이 있는지 확인 |
| 가게가 추천되지만 지점·가격·시간을 틀리게 설명함 | 틀린 주장과 연결된 사실·출처를 대조하고 그 범위만 정정 |
| 가게가 올바르게 추천됨 | 정상 정보를 유지. 수정량을 만들기 위한 문구 추가 금지 |

인용 링크가 없다는 이유로 ‘검색되지 않음’을 확정하지 않는다. 소비자 화면은 전체 검색 후보를 공개하지 않을 수 있다. 검색 로그가 보이는 API 실험은 별도 표본으로 기록하고 소비자 앱 결과와 합산하지 않는다. Google Maps grounding API 실험 역시 소비자 Gemini 앱의 노출 증거와 구분한다. [R3][S6]

## 3. 지도 안에서 더 할 수 있는 다섯 작업

### G1. 질문 조건을 실제 사실에 연결하기

- ‘채식 맛집’ 같은 태그를 늘리는 대신, 어느 메뉴가 어떤 조리 조건에서 해당하는지 확인한다.
- ‘1인 2만원 이하’에는 메뉴 하나의 최저가보다 판매 단위·최소 주문·필수 추가금이 필요하다.
- ‘늦은 저녁 식사’에는 영업 종료와 별도로 주방 주문 마감이 필요한지 확인한다. 종료 시각만 보고 마감을 만들지 않는다.
- 적용: 해당 메뉴 설명, 실제 지원되는 편의 속성, 정규·특별 영업시간. 적합한 칸이 없으면 확인 필요로 남긴다.
- 새로운 가치를 만드는 것은 이미 질문에 맞는 가게의 빠진 근거를 보완하는 일이다. 조건에 맞지 않는 가게를 맞는 것처럼 바꾸지 않는다.

### G2. 메뉴 한 항목을 따로 읽어도 오해하지 않게 쓰기

- 메뉴명·가격·판매 단위·주요 구성·적용 조건을 해당 항목에서 함께 이해하게 한다.
- 전체 소개에 메뉴별 조건을 복사하지 않는다. 각 정상 메뉴도 통째로 재작성하지 않는다.
- 예: ‘39,900원’만으로 끝내지 않고 해당 설명에 ‘2인용 세트 총액’과 구성을 명확히 한다. 가격 칸은 실제 세트 가격을 유지한다.
- 예: 특정 런치에만 해당하는 평일 제한을 다른 메뉴나 식당 전체 조건으로 확대하지 않는다.
- 목적: AI가 일부 문장만 사용하더라도 단위·조건을 잃지 않게 하는 편집 가설. 특정 형식의 노출 상승은 아직 검증되지 않았다.

### G3. 음차에 음식 설명을 붙이기

- 로마자 메뉴명만 있는 경우 필요한 항목에 짧은 음식 종류·먹는 방식을 영어로 보완한다.
- 예시 형식: `Tsukemen — noodles served with a separate dipping broth.` 실제 메뉴와 표현을 확인한 뒤 사용한다.
- 주재료·육수·맵기·추가금은 확인된 사실만 쓴다. 영문 메뉴와 영어 직원 응대는 다른 정보다.
- 상호에 임의 검색어를 추가하지 않는다. 기존 공식 명칭과 사장님 브랜드 표현은 유지한다.
- Google 메뉴 설명 등 지원되는 칸에 우선 적용한다. 카카오에 같은 설명 칸이 있다고 가정하거나 짧은 소개에 장문을 밀어 넣지 않는다.
- 번역 자체는 SEO·현지화와 겹친다. 질문에서 필요한 의미가 실제 메뉴 사실로 연결되는지를 검수하는 방식으로 구체화한다.

### G4. 브랜드 홈페이지보다 해당 지점·해당 메뉴 링크 연결하기

- 지도 웹사이트·메뉴 링크가 브랜드 공통 홈으로 가는 경우, 공식 지점 전용 페이지·메뉴 URL이 더 적합한지 검토한다.
- 예: 플랜트 연남 안내는 이태원 회사 연락처와 구분되는 지점 정보가 있다. 연남 페이지를 연결하면 해당 지점의 사실을 찾기 쉬워지는지 검수할 수 있다.
- ‘현재 지도의 링크가 실제로 공통 홈인지’와 관리자 입력 칸을 확인한 뒤만 변경안을 확정한다.
- Google 소개에 URL을 넣지 않는다. 웹사이트·메뉴용 지원 칸을 사용한다. 카카오 사이트 링크도 실제 관리자 칸과 업주 의도를 확인한다.
- 같은 브랜드의 지점 정보가 합쳐지는 문제를 줄이는 목적이다. 상호·주소·업종 수정은 현재 자동 정비 범위 밖이다.

### G5. AI가 틀리게 말하는 사실을 정비의 우선순위로 삼기

- ‘이 가게는 예약 불가’, ‘2인 세트 가격이 1인 가격’, ‘비건이면 모든 알레르기에 안전’처럼 실제 발생한 잘못된 답변을 항목별로 기록한다.
- 위 문장들은 점검할 오류 유형의 예시다. 이번 조사에서 각 오류가 실제 발생했다고 주장하지 않는다.
- 원본 출처가 잘못됐는지, 최신 값이 아직 반영되지 않았는지, AI가 조건을 빠뜨렸는지 나눈다.
- 잘못된 지도 값이 있으면 해당 칸을 정정한다. 지도는 맞고 AI만 틀리면 지도 전체를 고치지 않는다.
- 외부 블로그·공식 사이트가 문제의 출처라면 ‘현재 정비 범위 밖’으로 표시한다. AI를 직접 수정하거나 학습시켰다고 표현하지 않는다.

| X3. 지점·메뉴 사실 관리와 구조화 데이터 | 사실마다 지점·근거·확인일·판매 단위·적용 조건을 관리하고, 공개 본문과 Restaurant/MenuItem/Offer 등의 값을 일치시킴 | 내부 관리와 실제 공개 배포를 구분. JSON-LD는 관리 가능한 웹사이트에만 적용. Google·카카오에 임의 코드를 삽입하지 않음. 공식 스키마 지원이 추천 상승의 증거는 아님 |
| X4. 검색용 AI 접근 점검 | 소유 사이트의 공개 텍스트, 로그인 필요 여부, 색인 제한, robots/WAF의 검색 봇 접근 설정을 점검한 기록 | 사이트 소유자가 관리하는 영역에 한정. OAI-SearchBot 검색 접근과 GPTBot 학습 허용은 별개. 모든 봇 허용이나 보안 해제를 기본값으로 하지 않음 |

## 6. 검증 방법도 바꿔야 한다

질문별로 다음 연결을 보존한다.

`사용자 질문 → 필요한 사실 → 현재 공개 값 → 관측한 AI 답변/출처 → 확인된 누락·오류 → 승인한 수정 → 공개 반영 → 반복 재측정`

추가로 구분할 수치는 다음과 같다.

1. **출처 관측**: 해당 지점/공식 메뉴 URL이 관측된 응답 비율. 전체 검색 후보가 공개되지 않으면 ‘검색 회수율’로 부르지 않는다.
2. **추천 등장**: 실제로 가게가 추천된 성공 응답 비율. 웹사이트 인용과 가게 추천을 분리한다.
3. **사실 정확도**: 가격·인원·시간·지점·식단 조건을 맞게 말한 비율. 확인 불가능한 주장과 답변 누락을 별도 기록한다.
4. **조건 충족**: 예산·요일·식단 등 질문의 조건에 실제로 맞는 추천인지 검수한다. 부적합한 질문에 안 나오는 것을 실패로 만들지 않는다.
5. **비교 측정**: 같은 모델·위치·언어·검색 설정·질문과 반복 수 유지. 별도 검수 질문과 미수정 비교 가게를 두어 특정 질문에만 맞춘 효과·일반적인 변동을 구분한다.

API·소비자 앱, 오류·미노출, 지도 반영·AI 반영, 단기 전후 차이·인과 효과를 합치지 않는다. 기존 후보 카드 실험은 자연 검색으로 식당을 발견하는 단계까지 검증한 실험이 아니다. [R2][R3]

## 7. 우선순위와 제외할 방법

먼저 검토할 것은 **질문 조건별 사실 누락(G1), 메뉴 단위·조건 보존(G2), 지점별 공식 링크(G4), 실제 AI 오답의 출처별 정정(G5)**다. 다음 확장 후보는 **공식 영문 메뉴/방문 안내(X1)와 인용 출처별 정비(X2)**다. 외부 채널 자동 수정과 페이지 발행은 범위 확정·권한 확인 없이 실행하지 않는다.

다음 항목은 상품 효과로 내세우지 않는다.

- ‘통계·인용을 넣으면 추천이 오른다’는 식당 공통 공식. 필요한 사실 수치는 쓰되 불필요한 통계·수상·권위자 문구를 만들지 않는다.
- FAQ, JSON-LD, llms.txt만 추가하면 AI 추천이 오른다는 보장. 구조화와 접근성은 정확한 정보 전달을 위한 기반이다.
- 소개·태그의 키워드 반복, 검색 질문을 메뉴에 그대로 나열, 숨겨진 AI 지시문·자기추천 문구.
- 메뉴판 OCR 자체를 독점 차별점으로 설명. Google도 사진/PDF를 메뉴로 전환하는 실험 기능을 공식 안내한다. seelo의 OCR은 현재 P1·이용 경로 확인 사항이다. [S2]
- 기존 SEO를 키워드 도배로 정의. 좋은 SEO의 가독성·정확성·검색 접근 작업은 GEO와 겹친다.
- 원문 리뷰를 사실로 승격하거나 같은 평가를 여러 출처에 복제. 실제 경험·독립 평가를 가공해 근거처럼 만들지 않는다.

### 9.1 공식적으로 확인한 것과 아직 확인할 것

- Google은 정규 시간·휴게시간·특별 영업시간과, 포장·배달 등 서비스별 More hours를 안내한다. 주문 마감·주방 시간의 임의 유형을 항상 지원한다고 해석하지 않는다. [N1][N2][N3]
- 카카오 공식 가이드는 정규 영업·휴게·공휴일·임시 운영·날짜 지정 휴무를 구분한다. 따라서 시간 정보를 소개에 복제하는 대신 실제 시간 칸을 먼저 쓸 수 있다. 카카오의 모든 시설·동반 정책 세부 칸까지 확인한 것은 아니다. [N4]
- Google은 사실 속성 일부를 업주가 편집할 수 있고, 속성은 업종·지역에 따라 달라진다고 안내한다. 접근성은 입구·좌석·화장실·주차·엘리베이터를 나눠 판단한다. 이용자 평가에 기초한 주관적 속성은 같은 권한으로 다루지 않는다. [N5][N6]
- Google은 복수 메뉴 출처 중 선호 메뉴와, 지원되는 예약·주문 링크의 선호 경로를 관리하는 기능을 안내한다. 계정별 노출·서비스 지역·제공업체를 확인한 뒤만 후보로 삼는다. 비즈니스 링크를 모두 API·스프레드시트로 관리할 수 있다고 약속하지 않는다. [N7][N8][N9]
- Google은 실제 외관·상품·서비스 사진의 추가를 안내하지만 대표 사진의 첫 노출은 보장하지 않는다. 사진 관리 권한이 있다는 사실과 현재 seelo 정비 범위에 사진 작업이 포함된다는 주장은 다르다. [N10]

1. 영업시간: 정규·휴게·특정 날짜 운영을 정확하게 표시.
2. 정보 탭: 해당 가게가 제공하는 결제·서비스·접근성 사실을 지원 속성에 반영.
3. 예약·주문: 올바른 지점·행동 경로와 필요한 조건을 정비.
4. 메뉴: 최소 주문·특정 시간 제공·확인된 차별적 조리 사실을 필요한 항목에 반영.
5. 확장안: 실제 입구·좌석 사진이나 기간 있는 소식은 별도 권한·작업 범위로 검토.

설명 문장을 길게 늘리지 않고, 정상 값은 그대로 둔다. 특정 방향을 시안에 넣기 위해 확인되지 않은 시설·정책을 실제 가게에 덧붙이지 않는다. 지원되지 않는 칸의 정보를 짧은 소개에 전부 몰아 넣지 않는다.

각 후보는 ‘어떤 조건의 질문에서, 어느 사실이 부족해 잘못된 추천·설명이 생겼는가’와 연결해 검증한다. 플랫폼이 이 항목을 지원한다는 근거와 해당 항목이 AI 추천을 늘린다는 근거는 별개다. 현재 확인한 공식 문서는 주로 전자를 뒷받침한다.
