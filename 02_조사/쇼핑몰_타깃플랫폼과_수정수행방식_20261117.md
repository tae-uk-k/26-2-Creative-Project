# 쇼핑몰 진행 대상·가입·관리 권한

기준일: 2026-11-24.

**진행 대상은 네이버 스마트스토어와 카페24다.** 가입, 상품 정비, API 개발은 이 두 플랫폼만 진행한다. 이 문서를 같은 경로에서 갱신한다.

2026-11-19 스마트스토어 seelo의 가입 승인을 확인했다. 상품 등록과 API 본문 수정·재조회·복구를 검증했다. 2026-11-23 두 플랫폼에 벌꿀·귀리분말·서리태분말 3종을 공개했다. 카페24는 사용자 로그인 완료 및 등록 지시로 보류를 해제했다. 카페24 관리자 편집과 공개 반영은 완료했고 Admin API 인증·쓰기는 아직 수행하지 않았다. 실제 결과는 [스마트스토어 상품·API 수정 실험](../03_실험/쇼핑몰_API_상품수정_20261119/실행결과.md), [상품 3종 실행 결과](../03_실험/쇼핑몰_API_상품수정_20261119/상품3종_20261123/실행결과.md), [카페24 등록 결과](../03_실험/쇼핑몰_API_상품수정_20261119/상품3종_20261123/카페24_실행결과.md)에서 관리한다.

## 1. 사업자 필요 여부

| 플랫폼 | 개설 조건 |
|---|---|
| 카페24 | 테스트몰 개설에는 사업자등록이 필요하지 않다. |
| 스마트스토어 | 개인판매자 가입에는 사업자등록이 필요하지 않다. 사업자판매자 가입에는 사업자등록이 필요하다. |

페이지 개설과 실제 판매 개시를 구분한다. 주문·입금·결제를 받지 않는 기능 시험을 먼저 진행한다. 실제 판매를 시작하면 기존 사업자의 업종 정정과 통신판매업 신고 대상 여부를 별도로 확인한다.

근거: [카페24 개설 조건](https://support.cafe24.com/hc/ko/articles/8471034757529-%EC%82%AC%EC%97%85%EC%9E%90-%EB%93%B1%EB%A1%9D%EC%9D%84-%ED%95%B4%EC%95%BC-%EB%AC%B4%EB%A3%8C-%EC%87%BC%ED%95%91%EB%AA%B0%EC%9D%84-%EB%A7%8C%EB%93%A4-%EC%88%98-%EC%9E%88%EB%82%98%EC%9A%94), [스마트스토어 판매자 유형](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15949), [국세청 사업자 정정](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7779&mi=2234), [정부24 통신판매업 신고](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=11300000006).

## 2. 쇼핑몰 가입

### 카페24

1. 카페24 회원가입을 진행한다.
2. 본인 명의 휴대전화로 인증한다.
3. 사업자회원으로 가입하면 사업자등록번호를 인증한다.
4. 쇼핑몰을 생성한다.
5. 관리자에서 상품을 등록한다.

기본 쇼핑몰 주소가 제공된다. 이번 무주문 공개 실험은 **진열함·판매함·모두에게 표시**로 설정했다. 구매는 회원이 없는 검증 전용 등급만 허용한다. 일반 가입자의 기본 등급은 일반회원으로 유지한다. 공개 화면과 직접 주문 링크의 차단을 확인한다.

근거: [가입·쇼핑몰 생성](https://support.cafe24.com/hc/ko/articles/13991865226777-%EC%B9%B4%ED%8E%9824%EC%99%80-%ED%95%A8%EA%BB%98%ED%95%98%EB%8A%94-%EC%87%BC%ED%95%91%EB%AA%B0-%EB%A7%8C%EB%93%A4%EA%B8%B0), [상품 표시·판매 상태](https://support.cafe24.com/hc/ko/articles/7738873859737--%EB%8F%99%EC%98%81%EC%83%81%EA%B0%80%EC%9D%B4%EB%93%9C-%EC%83%81%ED%92%88-%EC%9D%BC%EB%B0%98-%EB%93%B1%EB%A1%9D).

### 스마트스토어

1. 네이버 커머스 ID를 만든다.
2. 본인에게 맞는 판매자 유형을 선택한다.
3. 스토어와 판매 상품 정보를 입력한다.
4. 배송·반품 주소를 입력한다.
5. 정산계좌와 담당자 정보를 입력한다.
6. 해당 유형의 서류를 제출한다.
7. 고객확인을 완료한다.
8. 가입 심사를 받는다.

사업자 유형은 사업자등록 서류 등이 필요하다. 개인사업자와 법인의 제출 서류를 구분한다. 본인 인증과 예금주 조건에 따라 일부 서류가 생략될 수 있다. 가입 화면의 요구 서류를 기준으로 준비한다.

필요 서류를 모두 제출하면 가입 심사는 **영업일 3일 이내**에 진행된다. 통신판매업 신고를 위해 가입하는 경우에는 공식 안내에 따라 미신고 상태로 신청한 뒤 구매안전서비스 이용확인증을 발급받는 순서를 확인한다.

근거: [가입 순서·심사](https://help.sell.smartstore.naver.com/faq/content.help?faqId=15949), [유형별 제출 서류](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3664).

## 3. 상품 편집 권한 부여

소유자 계정과 seelo 작업 계정을 구분한다. 연결 전에 대상 스토어와 담당 계정을 확인한다.

2026-11-24 외부 고객 위임 재확인: 관리자 초대만으로 API 인증이 완료되지는 않는다. 스마트스토어 대행사 매니저는 상품 UI를 수정할 수 있지만, 고객용 API 서비스는 등록 대행사·솔루션 경로를 준비해야 한다. 카페24 부운영자는 앱을 설치할 수 없으므로 대표운영자의 최초 앱 설치·동의가 필요하다. 고객의 개발자 가입·키 발급 부담을 줄이는 방식은 [관리 위임과 간편 API 연결](쇼핑몰_관리위임과_간편API연결_20261124.md)에서 관리한다.

### 카페24: 부운영자

1. 소유자가 **쇼핑몰 설정 → 운영자 설정 → 운영자 관리 → 운영자 계정 관리**를 연다.
2. 소유자가 보안 인증 후 **등록**을 누른다.
3. 소유자가 seelo 전용 부운영자 계정을 만든다.
4. 소유자가 대상 쇼핑몰 접근을 허용한다.
5. 소유자가 상품 메뉴 접근과 **상품 수정** 권한을 부여한다.
6. seelo 담당자가 관리자 로그인 화면의 **부운영자** 탭으로 접속한다.

분류 변경이 필요하면 **상품 분류 관리 등록/수정** 권한을 추가한다. 디자인 권한은 해당 작업이 필요할 때 별도로 요청한다.

근거: [부운영자 등록·로그인](https://support.cafe24.com/hc/ko/articles/7673792789145--%EB%8F%99%EC%98%81%EC%83%81%EA%B0%80%EC%9D%B4%EB%93%9C-%EC%9A%B4%EC%98%81%EC%9E%90-%EB%93%B1%EB%A1%9D-%EC%A1%B0%ED%9A%8C), [메뉴·상세 권한](https://support.cafe24.com/hc/ko/articles/17498047886233-%EB%B6%80%EC%9A%B4%EC%98%81%EC%9E%90-%EA%B3%84%EC%A0%95-%EA%B6%8C%ED%95%9C-%EA%B4%80%EB%A0%A8-%EC%9E%90%EC%A3%BC-%EB%AC%BB%EB%8A%94-%EC%A7%88%EB%AC%B8).

### 스마트스토어: 대행사 매니저

1. seelo가 담당자 이름과 SMS 수신 휴대전화를 안내한다.
2. 통합매니저 또는 계정 주매니저가 **판매자정보 → 판매자 관리 → 매니저 관리**를 연다.
3. 소유자가 **매니저 초대**를 누른다.
4. 소유자가 담당자 이름과 휴대전화를 입력한다.
5. 소유자가 **대행사** 권한으로 초대한다.
6. seelo 담당자가 SMS의 초대 링크를 연다.
7. seelo 담당자가 네이버 커머스 ID로 로그인해 수락한다.

대행사 역할은 상품 등록·수정과 통계 등의 기능을 제공한다. 스토어 전체 관리자 권한을 기본 요청으로 사용하지 않는다.

근거: [매니저 초대·대행사 역할·SMS 수락](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3733).

## 4. API 자동 연동

관리자 초대와 API 인증은 별개다. 초대를 수락했다고 API 연결 완료로 표시하지 않는다.

**2026-11-24 후속 결정:** 기본 상품 수정은 **관리자 위임 → 브라우저 자동화**로 진행한다. API 발급·앱 설치를 기본 이용 절차에 넣지 않는다. 원본 수집·저장·재조회·복구를 관리 화면에서 수행하며, API 방식은 별도 선택 경로로 유지한다. 현재 개발 기준은 [관리자 화면 자동화](../01_기획/개발/쇼핑몰_관리자화면자동화.md)다. 아래 API 조건은 API 방식을 선택했을 때 적용한다.

2026-11-24 최신 재확인: 두 플랫폼 모두 상품 상세 HTML 수정 API를 제공한다. 스마트스토어는 기존 실계정 수정·복구와 신규 2종 등록을 검증했다. 이번 재접속은 `GW.IP_NOT_ALLOWED`로 인증이 거부됐다. 카페24는 상품 상세·모바일·요약 및 별도 SEO 수정 경로와 OAuth 상품 권한을 공식 문서에서 확인했으며, 우리 몰의 Admin API 발급·쓰기는 아직 미수행이다. 자세한 필드·발급 절차·증거는 [수정 API와 GEO 적용 범위 확인](쇼핑몰_수정API와_GEO적용범위_확인_20261124.md)을 따른다.

| 플랫폼 | 연결 순서 | 상품 수정 경로 |
|---|---|---|
| 카페24 | 개발자 앱 생성 → 자체몰 테스트 설치 → 상품 쓰기 OAuth 동의 → 토큰 발급 | `PUT /api/v2/admin/products/{product_no}` |
| 스마트스토어 | 커머스솔루션마켓 또는 API 대행사 공식 경로 확보 → 판매자 연결 → 인증 | `PUT /v2/products/origin-products/{originProductNo}` |

**본인 소유 테스트 스토어의 자체 실험**은 별도다. 2026-11-19 본인 계정에서 스마트스토어 전용 개발업체 계정을 만들고 `내 스토어 애플리케이션`의 상품/N배송 그룹으로 SELF 인증을 검증했다. 상품 상세본문의 수정·복구에 성공했다. 이 키를 외부 판매자에게 넘겨받는 서비스 방식으로 확대하지 않는다. 매니저 초대·본인 스토어 SELF 실험·외부 고객 SELLER 연결을 구분한다.

카페24는 출시 전 테스트 설치를 지원한다. 외부 고객용 앱 배포에는 필요한 심사 절차를 적용한다. 공개 앱 심사는 평균 영업일 3~5일이다. 개발과 보완 시간은 별도다.

스마트스토어의 **매니저 대행사 역할**과 **API 대행사 등록**을 구분한다. API 대행사 방식은 판매자가 **스토어관리 → 스토어 설정 → API 관리**에서 등록 대행사를 선택하는 흐름을 확인한다. 개인용 ‘내 스토어’ 앱 키를 넘겨받는 방식은 사용하지 않는다.

근거: [카페24 테스트 설치](https://developers.cafe24.com/app/front/common/concepts/sellapp/newbuildapp), [OAuth](https://developers.cafe24.com/app/front/app/develop/oauth/process), [상품 수정](https://apidocs.cafe24.com/docs/admin/put-products-by-product-no), [앱 심사](https://developers.cafe24.com/app/front/app/launch/examine/Quick-examine), [네이버 공식 대행 연결 안내](https://github.com/commerce-api-naver/commerce-api/discussions/3679), [원상품 수정](https://apicenter.commerce.naver.com/docs/commerce-api/current/update-origin-product-product).

## 5. 정비 범위와 타깃

AI는 같은 상품·모델·옵션의 자료를 먼저 수집한다. 확인한 누락 정보를 보완한다. 자료로 확인되지 않은 사양은 추가하지 않는다. 판매자에게는 필요한 누락만 묻는다.

| 플랫폼 | 정비 대상 | 먼저 확인할 항목 |
|---|---|---|
| 카페24 | 상세·모바일 설명, 요약, 상품 속성, 필요한 SEO 항목 | 기존 편집기·스킨·외부 상품 관리 도구와 실제 전송 필드 |
| 스마트스토어 | 상세설명, 상품 속성, 승인받은 상품 정보 | 스마트에디터의 기존 구성과 API 수정 후 HTML 전환 동작 |

초기 고객은 기본 기능이나 기존 대행으로 해결되지 않은 상품 정보 문제가 있는 판매자다. 카페24 PRO·기본 AI 검색 기능·GEO 앱과 중복되는 작업부터 확인한다.

카페24의 Google 연동은 요약 설명이나 SEO 값을 사용할 수 있다. 상세 본문만 수정한 뒤 전송 완료로 판단하지 않는다. 실제 필드와 수신 값을 대조한다.

근거: [카페24 PRO](https://www.cafe24.com/commerce/service/cafe24pro.html), [Google 전송 항목](https://shopnotice.cafe24.com/view?bbs_no=12&no=349182), [네이버 상세 편집기 안내](https://github.com/commerce-api-naver/commerce-api/discussions/1539).

효과 연구와 실험 설계는 [상세페이지 효과 검토](쇼핑몰상세페이지_효과와플랫폼검토.md)에서 관리한다.

## 6. 1주 실험 계획

첫 기술 검증은 **카페24 테스트몰 1개·상품 1~3개**로 진행한다. 스마트스토어는 가입 준비와 매니저 초대를 병행한다. 두 플랫폼의 외부 고객용 API 배포 완료를 1주 목표로 잡지 않는다.

| 일정 | 실행할 작업 |
|---|---|
| 1~2일차 | 카페24 테스트몰 생성. 스마트스토어 가입 유형·서류 준비. |
| 3~4일차 | 전용 작업 계정 연결. 원본 상품과 AI 정비안 작성. |
| 5~7일차 | 저장·재조회·PC/모바일 반영·복구 확인. 카페24 자체몰 API 시험. |
| 후속 | 스마트스토어 공식 API 연결 경로 확보. 상품 수정 시험. |

| 상태 | 완료 증거 |
|---|---|
| 계정 접근 | 전용 계정으로 정확한 스토어에 로그인하고 상품을 조회했다. |
| 편집 | 승인된 상품 변경을 저장하고 다시 조회했다. |
| 공개 반영 | 공개 상세페이지의 PC·모바일 표시를 확인했다. |
| API 연결 | 별도 인증과 상품 읽기·쓰기 시험을 통과했다. |

주문 없는 테스트몰에서는 구매전환을 측정하지 않는다. 실제 판매 실험은 방문·주문 데이터를 확보한 뒤 진행한다. 위 일정은 계획이며 완료 결과가 아니다.

## 7. 2026-11-19 실행 상태와 무주문 노출 실험
