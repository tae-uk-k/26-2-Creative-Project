# 쇼핑몰 타깃 플랫폼과 수정 수행 방식

권한 절차 확인일: 2026-11-18. 기존 타깃·경쟁 기능 조사일: 2026-11-17.

**쇼핑몰 정비 진행 대상은 카페24·아임웹·Shopify·WooCommerce·네이버 스마트스토어 5곳으로 한정한다.** 쿠팡·메이크샵·고도몰은 이번 권한 신청·정비·자동화 개발 대상에서 제외한다. 현재 Google 지도·카카오맵 베타의 범위는 별도로 유지한다.

이 문서는 공식 권한 위임 경로를 확인한 실행 지침이다. 실제 판매자 초대 수락·로그인·상품 저장·공개 반영 시험은 아직 수행하지 않았다. 이 문서를 계속 갱신하며 권한 안내의 최신 기준으로 사용한다.

## 1. 어디를 먼저 대상으로 삼을 것인가

**국내 첫 실험은 카페24 자사몰 중 상품 정보에 실제 누락·불일치가 있고, 기본 AI 검색 설정·기존 GEO 앱·운영대행으로 그 문제가 해결되지 않은 판매자에게 제안한다.** PRO 미이용 여부만으로 선정하면 부족하다. 아임웹은 수동 정비 대상으로 함께 검토한다. 미국에 판매하는 브랜드를 확보할 수 있다면 Shopify를 별도 실험 대상으로 삼는다.

이는 수정 권한, 편집 범위, 공식 상품 데이터 전달 경로를 비교한 사업 판단이다. 플랫폼별 유료 수요나 고객 획득 비용을 측정한 순위는 아니다. 돈을 내는 고객은 플랫폼 회사가 아니라 해당 플랫폼을 사용하는 판매자다.

| 플랫폼 | 우리가 대상으로 삼을 판매자 | 권한을 받고 수정하는 방식 | 우선 판단 |
|---|---|---|---|
| **카페24** | 기본 기능·GEO 앱·운영대행으로 해결되지 않은 상품 정보 문제가 있는 자사몰 판매자 | 사장님이 전용 **부운영자** 생성 → 상품 편집 권한 부여 → 상품 수정의 상세설명·요약·전용 항목 편집. 자동화는 별도 앱 설치·OAuth 동의 | **국내 첫 실험 후보.** PRO뿐 아니라 기본 AI 검색 기능·GeoDocs 등과 업무 중복 확인 |

| **Shopify** | 미국 고객에게 판매하며 Catalog에 전달되는 상품 정보·옵션 묶음에 문제가 있는 브랜드 | **Partner 협업자** 요청을 사장님이 승인 → 상품 설명·메타필드 수정 → Shopify Catalog의 필드 연결 확인·수정. 자동화는 별도 앱 설치 | **해외 판매 브랜드 별도 후보.** ChatGPT 연결은 적격 스토어에 이미 기본 제공 |
| **WooCommerce / WordPress** | 자사몰을 직접 운영하고 사이트별 개발 작업을 수용하는 판매자 | 제품 편집 권한이 있는 별도 사용자 → 상품 편집. API는 해당 사용자의 읽기·쓰기 키로 연동 | **개별 구축형 후보.** 테마·플러그인 차이로 작업량 편차 큼 |

## 2. 플랫폼별 실제 수행 경로

연결 전에 우리는 담당자 이름·업무용 이메일·휴대전화, 플랫폼별 전용 계정과 요청할 상품 권한을 준비한다. 사장님에게는 이미 확인한 쇼핑몰 정보를 다시 입력하게 하지 않고, 아래의 계정 추가·초대·승인 절차만 안내한다. Shopify의 협업 요청 코드는 필요한 연결 정보로 별도 받는다.

관리자 화면의 상품 편집 권한과 API 자동 수정 권한은 각각 관리한다. 전용 계정으로 상품을 편집할 수 있다는 사실을 API 연동 완료로 표시하지 않는다.

### 카페24: 부운영자 계정으로 직접 정비부터 시작

**권한 받기**

1. 우리는 전용 운영자 ID·담당자명과 필요한 상품 메뉴를 안내한다.
2. 사장님은 **쇼핑몰 설정 → 운영자 설정 → 운영자 관리 → 운영자 계정 관리**에서 보안 인증 후 **등록**을 누른다.
3. 전용 부운영자를 만들고, 대상 멀티쇼핑몰의 접근을 허용한다. **PC어드민 권한설정 → 상품 메뉴 접근·상품 수정**을 설정한다. 분류 변경이 필요한 작업만 **상품 분류 관리 등록/수정**을 추가한다.
4. 저장한 뒤 우리는 쇼핑몰 관리자 로그인 화면의 **부운영자** 탭으로 접속한다. 담당 계정의 초기 비밀번호는 플랫폼 절차에 따라 변경한다.

공식 근거: [운영자 등록·로그인](https://support.cafe24.com/hc/ko/articles/7673792789145--%EB%8F%99%EC%98%81%EC%83%81%EA%B0%80%EC%9D%B4%EB%93%9C-%EC%9A%B4%EC%98%81%EC%9E%90-%EB%93%B1%EB%A1%9D-%EC%A1%B0%ED%9A%8C), [메뉴·상세 권한 설정](https://support.cafe24.com/hc/ko/articles/17498047886233-%EB%B6%80%EC%9A%B4%EC%98%81%EC%9E%90-%EA%B3%84%EC%A0%95-%EA%B6%8C%ED%95%9C-%EA%B4%80%EB%A0%A8-%EC%9E%90%EC%A3%BC-%EB%AC%BB%EB%8A%94-%EC%A7%88%EB%AC%B8).

**받은 권한으로 정비하기**

1. 상품 관리에 필요한 권한으로 작업한다. 디자인 변경이 필요한 경우에만 그 권한을 추가한다.
2. 대상 상품의 현재 상세설명·모바일 설명·이미지·옵션·사용 중인 편집 방식을 읽는다. 외부 상품 관리 도구에서 덮어쓰는지도 확인한다.
3. 상품 수정 화면의 상세설명에서 **직접 작성 → `<>` HTML 소스**로 편집할 수 있다. 기존 이미지·브랜드 문구를 보존하면서 검증한 사양표·사용 조건·질문과 답 등을 필요한 위치에 넣는다.
4. 상품명·브랜드·모델·옵션 등은 가능한 전용 필드에 반영한다. PC와 모바일 공개 페이지를 각각 확인한다.
5. 구조화 데이터나 공통 템플릿 변경은 상품 설명 편집과 별개 작업이다. 기존 출력 내용을 먼저 확인하고, 필요한 디자인 권한 또는 기존 제작업체 협업을 확보한다.

**이미 있는 전달 경로도 확인한다.** 카페24의 구글 & 유튜브 연동은 설명에 상품 요약 설명을 우선 사용하고, 없으면 SEO 값을 활용한다고 안내한다. 따라서 긴 상세 본문만 수정하고 끝내면 실제 전송 설명이 바뀌지 않을 수 있다. 소재·색상·사이즈 추출 원본, 옵션 그룹, 품목별 GTIN도 함께 확인한다. 상품 설명서 PDF 전송은 해당 공지에서 준비 중인 기능이다.

카페24는 `@Cafe24` 앱을 호출하는 ChatGPT 쇼핑 경로도 안내한다. 이 앱의 검색 결과와 앱을 호출하지 않은 ChatGPT 일반 질문 결과를 구분해 기록한다. 판매자별 상품 포함 조건과 실제 검색 결과는 별도 확인 대상이다.

**자동 연동:** 개발자 앱을 만들고 필요한 출시·배포 절차를 거친 뒤 **판매자의 앱 설치·상품 쓰기 OAuth 동의 → 인증 코드 수신 → 토큰 발급**으로 연결한다. 상품 수정 API 경로는 `PUT /api/v2/admin/products/{product_no}`다. 현행 요청 필드와 테스트 상품 반영은 구현 단계에서 확인한다.

공식 근거: [HTML 입력 방법](https://support.cafe24.com/hc/ko/articles/31319599080729), [상품 수정 API](https://apidocs.cafe24.com/docs/admin/put-products-by-product-no), [OAuth 인증](https://developers.cafe24.com/app/front/app/develop/oauth/process), [앱 권한 동의](https://developers.cafe24.com/app/front/app/develop/api/scope), [앱 출시 심사](https://developers.cafe24.com/app/front/app/launch/examine/Quick-examine), [2026-10-13 Google 전송 항목·원본 안내](https://shopnotice.cafe24.com/view?bbs_no=12&no=349182), [Cafe24 ChatGPT 앱 안내](https://shopnotice.cafe24.com/view?bbs_no=5&no=348670).

### 아임웹: 운영진 편집은 가능, SaaS 자동 연동은 별도

**권한 받기**

1. 우리는 담당자 이름·업무용 이메일과 사용할 사이트 회원 계정을 준비한다. **Starter 이상** 사이트인지 확인한다.
2. 사장님은 관리자 **고객 → 운영진 → 새 운영진 그룹 만들기**에서 쇼핑 상품의 **조회·편집** 권한을 설정하고 그룹을 저장한다. SEO나 코드 편집이 필요하면 해당 메뉴의 권한을 별도로 검토한다.
3. 담당자가 기존 사이트 회원이면 **고객 → 고객 목록 → 회원 선택 → 그룹지정**으로 방금 만든 운영진 그룹에 넣는다. 회원이 아니면 **고객 → 운영진 → 운영자 추가**에서 전용 계정을 추가한다.
4. 우리는 해당 계정으로 관리자에 접속해 **쇼핑 → 상품**의 접근·편집 범위를 확인한다.

공식 근거: [운영진 생성·기존 회원 지정·신규 운영자 추가](https://www.imweb.me/qna?mode=faq&q=71161).

**받은 권한으로 정비하기:** 상품 편집기에서 상세설명·속성·SEO를 필요한 범위에서 수정한다. 본문과 사이트 공통 코드의 권한을 구분하고, 초기에는 운영진 방식으로 소수 상품부터 진행한다.

**자동 연동:** 앱 생성 → 사용할 API 선택 → 개발자 소유 사이트 테스트 → 앱 승인 요청·제휴 절차 → 앱스토어 게시 → 판매자 설치·API 동의 순서로 검토한다. 현행 `PATCH /products/{prodNo}`, `PATCH /products/{prodNo}/seo`의 상세 요청 스키마는 구현 전 확인한다. 운영진으로 초대받았다는 이유만으로 외부 고객용 앱 배포가 승인된 것은 아니다.

공식 근거: [운영진 설정](https://www.imweb.me/qna?mode=faq&q=71161), [상품 편집기 안내](https://imweb.me/qna?mode=faq&q=72653), [현행 API](https://developers-docs.imweb.me/reference), [앱 개발·승인 과정](https://developers-docs.imweb.me/guide/프로세스-확인하기).

### Shopify: 상품 설명과 Catalog 데이터 연결을 함께 정비

**권한 받기**

1. 우리는 **Shopify Partner 계정·안전한 로그인 방식**을 준비한다. Shopify가 요청하면 Partner 본인 확인을 완료한다.
2. 사장님은 **Settings → Users → Security**에서 **4자리 협업 요청 코드**를 확인해 전달한다. 조직 구성에 따라 Users 또는 Users & permissions를 한 번 더 선택하는 화면이 있다.
3. 우리는 **Dev Dashboard → Stores**에서 대상 스토어의 협업 접근을 요청한다. 상품의 **View + Create and edit**를 기본으로 요청하고, 이미지 작업 시 필요한 Files 권한을 함께 확인한다.
4. 사장님은 **Settings → Users → Requests → 우리 요청 → Roles 검토 → Accept request**로 승인한다.
5. 우리는 Dev Dashboard의 해당 스토어에 접속해 상품 편집과 상품 메타필드 권한을 확인한다. Catalog나 테마 변경은 필요한 추가 권한을 별도 확인한다.

공식 근거: [판매자 승인·협업 코드](https://help.shopify.com/en/manual/your-account/users/security/collaborator-accounts), [Partner 접근 요청](https://help.shopify.com/en/partners/manage-clients-stores/working-on-client-stores), [Dev Dashboard의 Stores](https://help.shopify.com/en/partners/manage-clients-stores/client-transfer-stores), [상품·메타필드·파일 권한](https://help.shopify.com/en/manual/your-account/users/roles/permissions/store-permissions).

**받은 권한으로 정비하기**

1. 상품 설명 HTML·제품 메타필드를 정비한다.
2. **Sales channels → Agentic → Sources의 Shopify Catalog → Review product data mapping**을 연다.
3. 제목·설명의 원본 필드와 필요한 옵션 묶음을 조정하고, 누락 값·수신 미리보기를 확인해 저장한다.

**차이가 나는 기능은 온라인몰의 상품 구성·화면을 유지하면서 Catalog가 사용할 제목·설명 원본을 지정할 수 있다는 점이다.** 같은 상품 사실을 정리한 메타필드로 연결할 수 있다. Catalog 미리보기는 수신 데이터 확인이며, ChatGPT 화면 자체의 확인은 별도로 한다.

ChatGPT 판매 대상은 미국 고객에게 판매하는 등 적격 조건을 충족한 스토어다. 해당 스토어에는 기본 연결이 제공되어 별도 ChatGPT 판매 채널이나 상품 피드를 다시 만드는 작업이 필요하지 않다. 따라서 우리의 작업 범위는 **연결된 데이터의 누락·불일치 정비와 검증**으로 잡는다.

**자동 연동:** 앱 배포 유형을 정하고 필요한 심사를 거친 뒤 판매자가 상품 쓰기 접근을 승인한다. `productUpdate`로 `descriptionHtml`·메타필드 등을 수정하고, 품목 가격 등은 해당 품목 API로 구분한다. 여러 독립 판매자를 위한 앱 배포와 단일 판매자용 맞춤 앱은 절차를 구분한다.

공식 근거: [협업자 계정](https://help.shopify.com/en/manual/your-account/users/security/collaborator-accounts), [Catalog 매핑](https://help.shopify.com/en/manual/shopify-catalog/mapping), [ChatGPT 판매 요건·기본 연결](https://help.shopify.com/en/manual/online-sales-channels/agentic-storefronts/chatgpt), [상품 수정 API](https://shopify.dev/docs/api/admin-graphql/latest/mutations/productUpdate), [입력 필드](https://shopify.dev/docs/api/admin-graphql/latest/input-objects/ProductUpdateInput), [앱 배포 유형](https://shopify.dev/docs/apps/launch/distribution).

### WooCommerce: 편집 자유도는 크지만 사이트별 작업

**권한 받기**

1. 우리는 전용 사용자명·업무용 이메일을 안내한다.
2. 사장님 또는 사이트 관리자는 WordPress 관리자 **사용자 → 새로 추가**에서 전용 사용자를 만든다.
3. 역할은 상품을 편집할 수 있도록 설정한다. 기본 **Shop Manager**는 상품 생성·수정·게시가 가능하다. 다만 주문·환불 등도 포함하므로 기존에 상품 편집 전용 역할이 있으면 우선 사용하고, 없으면 판매자에게 기본 역할의 범위를 안내해 합의한다.
4. 우리는 전용 사용자로 접속해 **상품 → 대상 상품 편집**에서 허용된 범위를 확인한다.

공식 근거: [사용자 추가](https://wordpress.org/documentation/article/users-add-new-screen/), [WooCommerce 역할과 권한](https://woocommerce.com/document/roles-capabilities/).

**받은 권한으로 정비하기:** 설명·짧은 설명·속성을 수정한다. 구조화 데이터는 사이트의 테마·SEO 플러그인·WooCommerce 출력을 함께 확인한다.

**자동 연동:** 기본 설계는 공식 **`/wc-auth/v1/authorize` 접근 승인 링크**를 사용한다. 판매자가 해당 쇼핑몰에서 로그인해 `read_write` 접근을 승인하면 API 키가 우리 서버의 HTTPS 콜백으로 전달된다. 키의 실제 권한은 연결된 WordPress 사용자의 역할을 따른다. 이 연결 기능은 앞으로 구현·검증할 대상이다.

직접 키를 발급하는 대체 경로는 **WooCommerce → 설정 → 고급 → REST API → 키 추가 → 전용 사용자 선택 → Read/Write → API 키 생성**이다. 상품 수정은 `PUT /wp-json/wc/v3/products/{id}`를 사용한다.

공식 근거: [역할과 권한](https://woocommerce.com/document/roles-capabilities/), [API 키 발급](https://woocommerce.com/document/woocommerce-rest-api/), [API 인증과 사용자 권한](https://developer.woocommerce.com/docs/apis/rest-api/authentication/), [상품 수정 API](https://woocommerce.github.io/woocommerce-rest-api-docs/#update-a-product).

### 네이버 스마트스토어: 매니저 초대와 서비스 API 등록을 구분

**권한 받기**

1. 우리는 담당자 이름·SMS를 받을 휴대전화·네이버 커머스 ID를 준비해 안내한다.
2. 통합매니저 또는 계정 주매니저가 **판매자정보 → 판매자 관리 → 매니저 관리 → 매니저 초대**를 누른다.
3. 우리 담당자의 **이름·휴대전화**를 입력하고 **대행사** 권한을 선택해 초대한다. 공식 안내에서 대행사는 **상품 등록/수정·통계 등**을 이용할 수 있는 역할이다.
4. 우리는 수신한 **SMS 초대 링크 → 네이버 커머스 ID 로그인**으로 수락한다. 커머스 ID가 없다면 초대 화면에서 가입한다.
5. 대상 스토어의 상품 조회·수정 화면에 접근되는지 확인한다.

공식 근거: [매니저 초대·대행사 권한·SMS 수락](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3733).

**받은 권한으로 정비하기:** 상품명·상세설명·속성·옵션 중 승인받은 내용을 수정한다. 플랫폼 공통 HTML·구조화 데이터 변경은 이 상품 편집 권한에 포함하지 않는다.

**자동 연동:** 우리 사업자가 **커머스솔루션마켓 또는 API 대행사** 공식 경로를 먼저 갖춘다. API 대행사 방식은 판매자가 **스토어관리 → 스토어 설정 → API 관리**에서 등록된 우리 대행사를 선택하는 흐름을 확인한다. 매니저의 ‘대행사’ 역할과 API 대행사 등록은 별개다. 담당자의 2026-08-04 답변에 따라 개인용 ‘내 스토어’ 앱 키를 넘겨받는 방식은 사용하지 않는다.

API 상품 수정 경로는 `PUT /v2/products/origin-products/{originProductNo}`다. 상세설명 전달에 따른 에디터 전환 문제도 확인 대상이다. 2024년 담당자 답변에는 `detailContent` 전달 시 HTML 에디터로 바뀐다고 되어 있어, 현재 판매자의 편집기에서 테스트한 뒤 처리한다.

공식 근거: [매니저 관리](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3733), [2026년 공식 대행 연동 답변](https://github.com/commerce-api-naver/commerce-api/discussions/3679), [현행 상품 수정 API](https://apicenter.commerce.naver.com/docs/commerce-api/current/update-origin-product-product), [2024년 에디터 전환 답변](https://github.com/commerce-api-naver/commerce-api/discussions/1539).

## 4. 첫 고객에서 실제로 수행할 일

1. **문제 있는 상품을 선정한다.** 예: 이미지 안에만 있는 규격, 설명·옵션의 호환 모델 불일치, 자사몰·마켓의 상충 정보, Catalog에 전달되지 않는 상세 사양.
2. **AI 노출·답변을 먼저 기록한다.** 상품 비교 질문, 정확한 모델 질문, 사용 조건 질문을 고정하고 언급·인용·사실 오류를 분리한다.
3. **전용 계정을 받아 상품 1개부터 작업한다.** 현재 값과 공개 화면을 기록하고 제조사 자료·판매자 원본으로 사실을 확인한다. AI가 추측한 사양은 넣지 않는다.
4. **실제 편집 필드에 수정안을 반영한다.** 상품 전용 정보 → 필요한 본문 설명 → 별도 코드·Catalog 연결 순으로 필요한 범위만 수행한다.
5. **저장 결과와 공개·수신 결과를 확인한다.** 관리자 재조회, PC·모바일 상세페이지, 기존 디자인, 옵션, 사용 중인 Catalog·피드의 수신 값을 점검한다.
6. **같은 질문으로 재측정한다.** 수정하지 않은 비교 상품도 두고 기술적 반영과 AI 답변 변화를 별도로 기록한다.

초기 서비스는 **부운영자·운영진·협업자 계정으로 직접 수행**하고, 반복되는 필드가 확인되면 플랫폼별 정식 앱/API 연동으로 전환한다. 관리자 초대만으로 여러 고객 자동 연동까지 완성되는 구조로 기획하지 않는다.

### 연결 완료의 판단 기준

| 상태 | 확인할 증거 |
|---|---|
| 권한 요청 준비 | 플랫폼·스토어 주소·전용 담당 계정·필요한 상품 권한을 확정했다. |
| 권한 요청 중 | 계정 생성 안내 또는 협업·매니저 초대를 발송했다. |
| 계정 접근 확인 | 우리 전용 계정으로 정확한 스토어에 로그인하고 대상 상품을 조회했다. |
| 편집 가능 확인 | 승인된 대상 상품 1개의 변경을 저장하고 다시 조회했다. 편집 버튼이 보이는 것만으로 완료하지 않는다. |
| 공개 반영 확인 | PC·모바일 공개 상세페이지와 필요한 상품 데이터 수신 결과를 대조했다. |
| API 연결 확인 | 해당 플랫폼의 별도 인증과 필요한 읽기·쓰기 시험을 통과했다. 관리자 로그인 완료와 따로 기록한다. |

기본 요청은 상품의 조회·설명·속성 편집에 맞춘다. 디자인·주문·정산 등 추가 범위가 필요한 경우에는 작업 목적과 권한을 따로 제시한다. 권한이 부족하면 그 메뉴만 보완 요청하고 이미 가능한 정비안을 계속 준비한다.

## 5. 접근·검증이 남은 자료

- **아임웹 AI 검색 진단:** 공식 연결 주소는 확인했지만 텍스트 접근 결과 본문이 없어 진단 항목·실제 결과는 확인하지 못했다.
- **카페24·아임웹 현행 API 요청 상세:** 상품 수정 경로는 읽었으나 동적 요청 스키마가 텍스트에 노출되지 않았다. 현재 필드·편집기 보존 동작을 구현 전 확인해야 한다.
- **모든 플랫폼:** 고객 계정 접근, 앱 설치 승인, 실제 상품 변경, 수신 데이터 반영 시험은 아직 수행하지 않았다.

## 6. 1주 안에 진행할 범위

**기술 검증의 첫 목표는 카페24 테스트몰 1개·상품 상세 1~3개·전용 부운영자 1개다.** 직접 만든 HTML 페이지는 설명 정비 결과를 보여 주는 데 쓸 수 있지만, 카페24·아임웹 등의 권한 연결과 저장 동작은 그 플랫폼 안에서 시험해야 한다.

| 작업 | 1주 계획에 포함할 범위 |
|---|---|
| 본인 소유 테스트몰 개설·상품 등록 | 카페24 1개부터 진행. 실제 주문·결제를 받지 않도록 설정 |
| 별도 계정에 상품 편집 권한 부여 | 소유자와 작업자 계정을 분리해 초대·로그인·수정·공개 반영을 시험 |
| AI가 만든 설명의 반영 | 관리자 화면에서 먼저 저장·재조회·공개 화면을 확인 |
| API 자동 수정 | 카페24 자체 테스트몰에서 상품 1개의 읽기·쓰기 연동을 시험하는 목표. 개발 완료 상태로 간주하지 않음 |
| 5개 플랫폼의 외부 고객용 자동 연동 | 1주 완료 범위에서 제외. 앱 등록·권한 심사·배포·제휴 절차를 각각 진행해야 함 |
| 구매 성과 실험 | 주문 없는 테스트몰에서는 측정하지 않음. 실제 판매자·방문·주문 데이터가 있는 다음 실험에서 진행 |

카페24는 출시 전 쇼핑몰에 앱을 테스트 설치하는 공식 절차를 제공한다. 개발자 어드민에서 쇼핑몰 ID를 입력하고 설치 동의로 연결한다. 반면 공개 앱 심사는 **심사 요청 이후 평균 영업일 3~5일**이며, 개발·반려 보완 시간은 별도다. 아임웹의 외부 배포에는 앱 승인·제휴 절차가 있고, 스마트스토어의 서비스 API는 공식 대행 연동 경로가 필요하다. 따라서 5개 자동 연동을 1주 일정에 한꺼번에 넣지 않는다. [카페24 테스트 설치](https://developers.cafe24.com/app/front/common/concepts/sellapp/newbuildapp), [카페24 앱 심사](https://developers.cafe24.com/app/front/app/launch/examine/Quick-examine)

아래 일정은 계정과 상품 원자료가 준비된 경우의 작업 계획이다. 아직 수행한 결과가 아니다.

| 4~5일차 | 관리자 저장·재조회·PC/모바일 반영 확인, 자체몰 API 테스트 착수 |

## 7. 직접 테스트몰을 만들 때 필요한 것

### 7.1 지금 권장하는 방법: 판매하지 않는 테스트몰

**기존 사업자의 판매 업종 추가부터 시작할 필요 없이, 주문을 받지 않는 테스트몰을 먼저 개설한다.** 카페24 공식 안내는 사업자등록이 없어도 쇼핑몰 생성이 가능하다고 설명한다. 통신판매의 법적 정의는 판매 정보를 제공하고 소비자의 청약을 받아 판매하는 행위다. 따라서 이번 기능 실험은 주문·입금·결제를 받지 않는 상태로 구분한다. [카페24 개설 조건](https://support.cafe24.com/hc/ko/articles/8471034757529-%EC%82%AC%EC%97%85%EC%9E%90-%EB%93%B1%EB%A1%9D%EC%9D%84-%ED%95%B4%EC%95%BC-%EB%AC%B4%EB%A3%8C-%EC%87%BC%ED%95%91%EB%AA%B0%EC%9D%84-%EB%A7%8C%EB%93%A4-%EC%88%98-%EC%9E%88%EB%82%98%EC%9A%94), [전자상거래법 제2조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1032361201)

| 준비할 것 | 이번 테스트의 사용 목적 |
|---|---|
| 본인 계정·이메일·플랫폼이 요구하는 본인 확인 | 쇼핑몰 소유 계정 개설 |
| 테스트몰 이름과 접속 주소 | 작업 대상 식별. 카페24 기본 제공 주소부터 사용 가능 |
| 상품명·사진·검증 가능한 규격·설명 | 상품 원본 1~3개 등록. 사용할 수 있는 자료로 준비 |
| 별도 담당 계정 | 소유자와 다른 계정의 상품 편집 권한 시험 |
| 주문 차단 상태 | 기능 시험용임을 표시하고 실제 주문 접수가 되지 않는지 확인 |
| API 테스트를 할 경우 개발자 계정·앱·HTTPS 인증 콜백 | 자체 테스트몰의 OAuth·상품 읽기·쓰기 시험 |

카페24는 상품을 **진열함·판매 안함**으로 설정하면 품절로 표시한다. 이를 사용한 테스트는 ‘판매 중인 상품’의 성과 실험과 구분한다. 아임웹은 공식 **제품 브로셔 사이트** 방식으로 가격·구매 버튼을 숨길 수 있어 소개 페이지 시연의 대안이 된다. [카페24 상품 표시·판매 상태](https://support.cafe24.com/hc/ko/articles/7738873859737--%EB%8F%99%EC%98%81%EC%83%81%EA%B0%80%EC%9D%B4%EB%93%9C-%EC%83%81%ED%92%88-%EC%9D%BC%EB%B0%98-%EB%93%B1%EB%A1%9D), [아임웹 브로셔 설정](https://imweb.me/qna?mode=faq&q=71627)

### 7.2 실제 상품을 판매하기 시작하는 경우

사업자등록이 이미 있다고 해서 판매 업종과 통신판매업 신고까지 완료된 것은 아니다. 기존 사업자에 실제 판매 내용에 맞는 업종을 추가·정정할 수 있는지 먼저 확인한다. 일반 온라인 상품 소매의 국세청 분류는 **전자상거래 소매업(525101)**이지만, 정확한 업종은 상품·판매 방식·현재 사업자 내용에 따라 정한다. 국세청은 홈택스를 통한 사업자등록 정정을 안내한다. [업종·사업자 정정](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7779&mi=2234), [전자상거래 업종 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7804)

실제 판매 단계에서 준비할 항목은 다음과 같다.

- 사업자 정보·대표자 본인 확인, 실제 취급 품목에 맞는 업종.
- 상호·연락처·사업장 주소·반품 주소와 정산 계좌.
- 상품·가격·재고·배송·교환/반품 정보와 품목별 필수 고지·인허가.
- 통신판매업 신고 대상 여부 확인과 필요한 신고. 선지급식 통신판매에 해당하면 구매안전서비스 이용 확인증을 준비한다.
- 카드 결제를 받을 경우 PG 계약·심사·계좌 등 해당 결제수단의 요건.

통신판매업 신고의 정부24 안내 처리기간은 국내 소재 기준 **총 3일**이다. 국세청 업종 변경 안내는 **신청일로부터 2일 이내**다. 서류 준비·보완·결제사 심사는 별도이므로, 이번 1주 기능 검증과 실제 판매 개시 일정을 합치지 않는다. [정부24 신고 안내](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=11300000006), [국세청 정정 처리 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7779&mi=2234)

스마트스토어는 커머스 ID 외에도 스토어·상품·배송·정산·담당자 정보를 입력하고 고객확인을 진행한다. 사업자 유형에는 사업자등록 서류 등이 필요하며, 공식 안내의 가입 심사는 필요 서류 제출 완료 후 **영업일 3일 이내**다. 주문 없는 첫 기술 실험을 위해 스마트스토어까지 동시에 개설할 필요는 없다.
