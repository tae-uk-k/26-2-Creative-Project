# 지도 정비의 근거와 판단 사례

이 문서는 기존 조사에서 확인한 도구·논문과 가상 예시·현장 판단 사례를 모은 참고 자료입니다. 현재 정비 동작은 [지도정보 정비 기준](../01_기획/지도정보정비기준.md), 질문은 [AI 수집과 최소 질문](../01_기획/AI수집과최소질문.md)에서 관리합니다. 아래 사례의 미확인은 내부 검토 상태이며 모두 사장님 질문이 되는 것은 아닙니다. 과거의 질문·확인 방식과 현재 운영 기준이 다르면 현재 기준을 따릅니다.

## 1. 기존 도구에서 가져올 방식

| Peec AI Gap Analysis | 경쟁사는 언급되지만 우리 브랜드는 없는 출처를 찾고 모델별로 나눠 본다 | ChatGPT·Gemini 출처 차이를 기록한다. 인용된 지도에서 고칠 칸이 확인되면 우선 검토한다 | 출처에 등장하는 것과 추천되는 것은 다른 관측값이다 |

따라서 ‘경쟁 가게가 많이 쓰는 표현을 복사’하는 방식보다 **우리 가게의 확인된 사실 중 질문에 필요한 것이 빠졌는지** 확인하는 방식을 채택한다. 외부 기사·커뮤니티 언급 부족은 분석 메모에 남기되 현재 상품의 지도 정비 항목으로 세지 않는다.

## 2. 논문에서 가져올 것과 가져오지 않을 것

| 근거 | 본문에서 확인한 결과·범위 | 채택할 해석 | 적용하면 안 되는 해석 |
|---|---|---|---|
| Aggarwal 외, GEO, KDD 2024 | 웹 문서의 인용·통계·표현을 바꾸고 생성 답변에서 출처 기여도를 비교. 키워드 반복은 좋은 결과를 내지 못함 | 근거 있는 구체적 사실과 읽기 쉬운 설명을 사용하고 반복을 목표로 삼지 않는다 | 지도 소개에 통계·인용문을 추가하면 식당 추천률이 40% 오른다 |
| Kim 외, SAGEO Arena, 2026 arXiv v1 | 검색→재정렬→답변 생성을 포함한 실험에서 본문 수정이 앞단 검색 성능을 떨어뜨리는 경우를 확인 | 내용을 잘 써도 실제 검색·접근 단계가 별도로 필요하다. 공개 반영과 답변 변화를 따로 확인한다 | 특정 문체·스키마가 현재 ChatGPT·Gemini 지도 추천을 보장한다 |
| Pitenin, Invisible to the Machine, 2026 arXiv v1 | 발리 음식점·카페·바 4,776곳, 검색 연결 API 답변 2,208개 감사. 웹사이트·가격 표시·리뷰량·외부 언급과 추천 진입의 연관을 보고 | 실제 메뉴 가격과 공식 링크는 우선 실험할 가치가 있다 | 가격을 추가하면 추천될 확률이 반드시 오른다. 해외 API 결과가 한국 소비자 앱에도 그대로 적용된다 |

출처: [GEO 논문 본문 §3–6](https://arxiv.org/html/2311.09735v3), [SAGEO Arena 본문 §3–5](https://arxiv.org/html/2602.12187v1), [식당 감사 논문 본문 §5.3·7](https://arxiv.org/html/2608.07069v1). 뒤 두 자료는 여기서 확인한 arXiv 판본 기준이며 학회 채택 여부는 이 문서에서 판단하지 않는다.

식당 감사 논문의 영업시간 변수에는 수집 경로에 따른 누락 문제가 있다. 이 논문을 근거로 ‘영업시간을 지우면 유리하다’고 해석하지 않는다. 영업시간 정비는 아래 Google 공식 지침과 정확한 방문 안내의 필요를 근거로 한다.

팀의 [기존 96회 통제 실험](../03_실험/지도기반_AI노출_20261016/정보제공_통제실험/README.md)도 같은 방향의 참고 자료다. 메뉴·가격을 제공한 후보가 더 많이 선택됐지만 정보량·메뉴·가격·길이가 함께 달라졌다. 같은 사실의 항목 정리는 지역별 결과가 달랐고 반복의 일관된 이점도 없었다. **후보 카드 선택 결과를 자연 검색 노출 개선으로 바꾸어 설명하지 않는다.**

근거는 다음처럼 표시한다. 하나의 ‘신뢰 점수’로 합치지 않는다.

| 표시 | 의미 | 예 |
|---|---|---|
| 공식 기능·규칙 | 입력 가능 여부·제약·반영 방식에 대한 플랫폼 설명 | Google 소개 750자 제한 |
| 통제 실험 | 실험 안에서의 정보·표현 변경 비교 | GEO, SAGEO, 팀 후보 카드 실험 |
| 관찰 연관 | 다른 조건을 통제해도 남는 연관. 정비 효과는 미확정 | 식당 감사 연구의 가격 표시 |
| 제품 참고 | 상용 도구의 기능·운영 방식 | 출처 차이 분석 |
| seelo 제안 | 위 자료를 서비스에 적용한 규칙. 별도 검증 필요 | 아래 수정 우선순위·대표 메뉴 선택 |

## 3. 정비안 예시

아래는 실제 가게가 아닌 **가상 예시**다. 가격·서비스는 모두 사장님이 확인했다고 가정한다.

정비 전 소개 예시:

> 안녕하세요! 성수 맛집, 서울숲 맛집, 외국인 추천 맛집입니다!!! 두부덮밥 12,000원! 매일 11시부터 영업! 주차, 포장, 혼밥 가능! 꼭 방문해 주세요!

정비 후에는 내용을 다음처럼 나눈다. 틀린 ‘매일 11시’는 현재 영업시간으로 고치며 주차·포장은 실제 제공 선택지가 있을 때 그 칸에 넣는다. 소개에서 빠진 필수 이용 사실이 사라지는 방식으로 정비하지 않는다.

| 지도·칸 | 지금 값 | 바꿀 값 | 이유·검증 |
|---|---|---|---|
| Google 메뉴 | 두부덮밥, 가격 없음 | 두부덮밥 / Tofu rice bowl, KRW 12,000 per bowl. Egg included. | 예산·음식 종류 판단 가능. 달걀 포함이므로 비건이라고 쓰지 않음 |
| Google 영업시간 | 매일 11:00–22:00 | 화–일 11:30–15:00, 17:00–21:00. 월 휴무 | 최신 사장님 영업 안내와 일치하도록 전용 시간 칸 수정 |
| Google 소개 | 성수 최고의 맛집 | 두부덮밥과 계절 반찬을 내는 한식당입니다. 혼자 앉을 수 있는 바 좌석을 운영합니다. | 대표 음식·차별점만 2문장. 시간·가격·전화·링크는 전용 칸. 필요한 영어는 지원 방식에 맞춰 별도 보완 |
| 카카오 한 줄 소개 | 성수 맛집 추천 | 두부덮밥과 계절 반찬, 혼자 앉는 좌석 운영 | 확인된 대표 음식·이용 특징. 50자 이내 |
| 카카오 태그 | 맛집, 추천, 핫플 | 두부덮밥, 혼밥좌석 | 확인 사실만 선택. 5개를 채우려고 다른 특성 생성 안 함 |

공통으로 `지도·칸 / 지금 값 / 승인할 값 / 변경 이유 / 사실 근거·확인일 / 관련 질문·답변 / 사장님 확인 여부 / 공개 반영 결과`를 남긴다. 위 예시의 영문 칸 배치와 메뉴 병기 가능 여부도 실제 화면 지원 확인 후 적용한다.

## 4. 실제 상황별 판단과 변경 가능 범위

앞선 2문장·대표 메뉴 3개 같은 숫자는 새 초안을 잡는 편집 기본값이다. **실제 정비량은 현재 값과 확인된 최신 사실의 차이로 정한다.** 20개 메뉴 중 가격 2개가 틀렸다면 가격 2개만 바꾼다. 메뉴판의 유효한 20개가 모두 텍스트로 빠졌다면 지원 기능·수집 조건을 충족하고 사장님이 승인한 범위에서 20개 등록안을 만들 수 있다. 소개나 대표 메뉴를 정비했다는 이유로 나머지 정상 정보를 축소하지 않는다.

아래 표는 운영 설계이며 실제 적용 실적이 아니다. 모든 ‘수정’은 정비안 제시·사장님 승인·해당 칸 지원 확인을 거친 실행을 뜻한다. OCR·사진 관리·리뷰 답글 등의 확장은 현재 제품에 구현돼 있다고 전제하지 않는다.

### 4.1 먼저 구분할 것: 볼 수 있음 / 사실로 확정 가능 / 직접 수정 가능

| 대상 | 현재 기획에서 알 수 있는 범위 | 직접 바꿀 수 있는 것과 서비스 범위 |
|---|---|---|
| Google 기본 매장 정보 | Places API의 요청·반환 필드. 관리 연결 뒤 실제 편집 칸 확인 | 현재 F-09 허용 칸의 승인된 값. 읽기 전용 가격대·평점 등은 별개 |
| Google 리뷰 | 진단은 Places API 관련성순 최대 5개. 최신 전체 리뷰라는 뜻이 아님 | 다른 사람의 리뷰·별점은 직접 수정 못 함. 답글은 별도 기능·요청 범위 |
| 카카오 메뉴·시간 | 로컬 API로는 못 얻음. 연결 뒤 허용된 매장정보 화면에서 확인 | F-09의 가격 정보·시간·소개·서비스·태그 등. 연결 전에는 상세 결측 판정 안 함 |
| 카카오 리뷰 | 로컬 API 수집 대상 아님. 후기 관리 화면 접근 가능성과 허용 사용을 별도 확인해야 함 | 후기 답글은 권한 기능과 현재 정비 상품을 구분. 자동 답글 게시로 확대하지 않음 |
| 메뉴판 사진 OCR | 현재 P1이며 약관·처리 경로 확인 전 비활성 | 판독 결과를 곧바로 사실·최신 가격으로 확정하지 않음 |
| 사진 업로드·교체 | 권한표에는 사진 관리가 있으나 F-09 기본 정비 목록에는 없음 | 별도 기능·사장님 요청·권리 확인 후 검토. 현재 기본 상품에서 일괄 교체 약속 금지 |
| 편집 요약·리뷰 토픽·플랫폼 AI 요약 | 업주 작성 소개와 작성 주체를 구분해서 관측 | 직접 편집 가능한 칸이라고 가정하지 않음. 오정보의 실제 수정 경로 별도 확인 |

Google Places의 리뷰 수·정렬은 [Places 공식 리소스](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places)를 확인했다. 소유/관리 연결 뒤 Google Business Profile API의 별도 리뷰 목록 기능은 있지만 현재 진단의 최대 5개 수집과 같은 경로가 아니다. API 접근 승인·권한·별도 수집 설계 없이는 전체 리뷰 분석으로 설명하지 않는다. [Business Profile 리뷰 목록](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.reviews/list).

Google은 메뉴 사진/PDF에서 메뉴를 생성하는 실험 기능도 제공하며 결과 검토를 요구한다. 이 기능이 모든 국내 계정에 제공되거나 seelo 외부 OCR·재게시를 허용한다는 뜻은 아니다. [Google 메뉴 편집 공식 안내](https://support.google.com/business/answer/9455840?hl=en).

외부 사진·리뷰의 읽기, 외부 모델 입력, 저장, 다른 지도 재게시를 하나의 허가로 취급하지 않는다. Google Maps 콘텐츠에는 반출·가공·저장 제한이 있으므로 경로별 허용 범위 확인 전 임의 변환·복사하지 않는다. 독립적으로 사장님이 제공한 원본 메뉴와 사장님이 확인한 자사 사실을 확보하는 경로를 우선 설계한다. ‘사장님 동의’가 제3자 사진의 권리나 API 이용 제약까지 해소한다고 설명하지 않는다. [Google Maps 이용 조건 §3.2.3](https://cloud.google.com/maps-platform/terms), [Places 정책](https://developers.google.com/maps/documentation/places/web-service/policies).

사장님 원본 사진/PDF 업로드와 QR 메뉴 처리는 현재의 초기 등록 입력 ‘가게 이름+지도 링크’에 이미 있는 기능으로 취급하지 않는다. 이를 제품에 넣으려면 자료 제공 화면·이용 동의·보관 범위·추출 검수·항목 승인 흐름을 추가로 설계해야 한다. 현재 S13의 사실 확인 입력으로 해결 가능한 경우는 별도 파일 제출을 필수로 만들지 않는다.

### 4.2 메뉴판·음식 사진: 12가지

| ID | 상황 | 할 일과 바꿀 수 있는 양 | 하지 않을 일 |
|---|---|---|---|
| M01 | 사장님의 최신 메뉴판 사진만 있고 텍스트 메뉴가 없음 | P1/처리 조건 충족 후 메뉴명·가격·단위·조건을 항목별 추출. 최신 적용일을 확인하고 승인한 항목만 텍스트 메뉴로 추가. 소개는 유지 | 사진 등록일을 메뉴 적용일로 간주, OCR 숫자를 무검토 확정, 메뉴 전체를 소개에 복사 |
| M02 | 사진과 텍스트 메뉴가 모두 있고 이름·가격·조건이 일치 | 기본 변경 0건. 영어가 필요한 항목만 번역안 제안 | 사진이 있다는 이유로 텍스트 메뉴가 불필요하다고 판단하거나 정상 메뉴 재작성 |
| M03 | 사진은 10,000원, 텍스트는 12,000원으로 다름 | 최신 적용 가격·홀/배달·사이즈가 같은 조건인지 확인. 확정 뒤 틀린 가격 칸만 정정 | 최신 업로드 사진이나 다수 출처를 무조건 정답으로 선택 |
| M04 | 흐림·반사·잘림으로 일부 금액/각주를 못 읽음 | 불확실한 부분은 보류. 판독 가능한 항목도 잘린 최소 주문·단위 각주의 영향을 받지 않는지 확인 후 제안 | 8,000/9,000 등을 추측, 잘린 ‘2인 이상’을 무시하고 가격만 등록 |
| M05 | 점심·저녁·주말·크기별로 같은 메뉴 가격이 다름 | 이름이 같아도 조건을 보존해 지원되는 변형·설명으로 구분. 구분 불가하면 사장님과 입력 방식 결정 | 최저가 하나로 통합, 평균 가격 계산, 낮은 가격만 대표로 선택 |
| M06 | 100g 가격·2인 세트·공깃밥 별도·최소 2인 주문이 있음 | 금액과 기준 단위·최소 주문·필수 추가 비용을 함께 입력. 메뉴별 해당 조건만 수정 | g당 가격을 한 끼 가격으로 표시, 2인 세트를 1인 가격처럼 표시 |

| M08 | 시가·중량별·계절별 변동 가격 | 플랫폼이 지원하는 변동가격 방식과 현재 주문 조건을 사용. 고정 가격을 확정할 수 없으면 확정 금액 보류 | 가격을 0원·임의 최저가로 채움, 오래된 고정 금액 재사용 |
| M09 | 이용자가 올린 오래된 메뉴판이 남아 있음 | 타인 사진 자체는 직접 수정 대상으로 만들지 않음. 사장님 최신 원본으로 텍스트 메뉴를 확인. 사진 관리 확장 시 본인 원본 추가와 신고 경로 별도 검토 | 타인 사진을 다운로드해 수정·재게시, 오래됐다는 이유만으로 삭제 보장 |
| M10 | 음식 사진만 있고 메뉴명·가격·성분이 없음 | 음식 종류를 추정하더라도 확인 요청의 단서로만 사용. 판매 메뉴와 구성은 사장님 자료로 확정 | 사진만으로 메뉴명·가격·중량·알레르기·비건/할랄 판정 |
| M11 | 메뉴가 공식 PDF·웹페이지·QR 뒤에 있음 | 정상 접근 가능한 공식 메뉴 도착지를 확인해 지원 링크 칸에 연결. 본문 추출은 허용 경로와 OCR/PDF 처리 범위를 별도 확인 | QR 이미지 자체를 메뉴 텍스트라고 간주, 로그인·접근 차단 우회, 외부 메뉴판 임의 변경 |
| M12 | 계절·품절·판매 종료 메뉴가 섞임 | 한시 품절과 영구 종료를 사장님에게 구분 확인. 지원 시 상태 표시, 영구 종료는 해당 항목 제외/삭제안을 별도 승인 | 리뷰 한 건의 ‘품절’을 근거로 메뉴 삭제, 일시 품절을 영구 종료로 처리 |

메뉴판 사진은 정보 형식이고, 유효한 판매 사실인지 여부는 별도다. 카카오는 변동가격·상품 설명과 추천 최대 2개를 지원한다. 추천 지정 수가 전체 메뉴 수 제한은 아니다. [카카오 가격·매장 관리](https://kakaobusiness.gitbook.io/main/channel/run/mystore).

### 4.3 리뷰·평판·플랫폼 요약: 12가지

리뷰는 **확인할 질문을 찾는 단서**로 사용한다. 현재 판매 사실·시설·서비스를 확정하거나 사장님의 소개를 대체하는 자료로 바로 승격하지 않는다. 아래 리뷰 분석은 허용된 경로로 실제 확인한 범위에 한정한다.

| ID | 상황 | 할 일과 바꿀 수 있는 양 | 하지 않을 일 |
|---|---|---|---|
| R01 | ‘맛있다·친절하다·분위기 좋다’는 칭찬이 많음 | 기본 수정 0건. 이미 드러난 주관 평가를 소개에 재생산할 필요 없음 | ‘지역 최고’, ‘모두가 인정한’으로 바꾸기, 리뷰 문구를 사장님 소개처럼 복사 |
| R02 | 특정 메뉴가 여러 리뷰에 등장하나 지도 메뉴에 없음 | 현재 판매·정식 명칭·가격·사장님이 보는 대표성을 확인. 실제 빠진 메뉴/영문 설명만 추가 | 몇 건 언급됐다는 이유로 ‘판매 1위·시그니처’ 확정, 재고 없는 메뉴 추가 |
| R03 | ‘주차 가능’과 ‘주차 못 했다’는 리뷰가 섞임 | 전용/제휴/인근 유료, 시간·요금·차량 조건을 확인. 틀린 서비스 선택지와 필요한 조건만 정정 | 리뷰 다수결로 주차 가능 결정, 인근 주차장을 무료 전용 주차로 표시 |
| R04 | 불친절·맛·위생·양에 대한 부정 평가 | 정보 오류와 실제 운영 불만을 구분. 운영 불만이면 지도 수정 0건, 사장님에게 개선 과제로 전달 | ‘친절·청결·푸짐’ 같은 반대 문구를 넣어 문제 해결로 포장 |
| R05 | 리뷰가 없거나 적음, API로 일부만 확인됨 | 미확보/0건/관측 소수를 구분. 관측 범위만 기록하고 정비 가능한 사실 항목을 별도로 점검 | 리뷰를 만들기, 낮은 평점/적은 리뷰만으로 소개 재작성, ‘전체 고객 다수’라고 표현 |
| R06 | 최근 리뷰와 오래된 리뷰가 충돌·이전 운영자 시절 리뷰가 남음 | 적용 시기와 현재 운영 사실을 확인해 현행 메뉴/서비스만 갱신. 오래된 리뷰 자체 변경은 0건 | 운영자 변경을 이유로 이전 리뷰 삭제 약속, 리뷰 내용을 최신 경험처럼 사용 |
| R07 | 외국인이 영어 메뉴·의사소통·외국 카드 문제를 언급 | 메뉴 번역과 직원 응대 언어·카드 지원을 분리 확인. 실제 부족한 번역/지원 선택지만 보완 | 영어 메뉴가 생겼다고 ‘영어 응대 가능’, 카드 결제가 된다고 모든 외국 카드 지원 표시 |

| R09 | 대기·예약·브레이크타임·조기 품절 불만 | 현재 예약 방식·영업 구간·필수 주문/품절 안내 정책을 확인. 잘못된 시간/서비스 정보만 정정 | ‘항상 대기 10분’, ‘웨이팅 없음’ 같은 가변 상태 보장, 반복 불만을 소개에 나열 |
| R10 | 허위·광고·다른 가게 리뷰로 의심됨 | 위반 의심 근거와 플랫폼 신고 경로를 안내. 신고·답글은 별도 요청과 검토 범위 | 불리하다는 이유로 허위 확정, 타인 리뷰/평점을 직접 수정·삭제, 삭제 성공 보장 |
| R11 | 리뷰 스니펫·편집/AI 요약이 틀림 | 작성 주체를 확인. 실제 업주 입력값도 틀렸으면 그 칸만 고침. 업주 값이 맞으면 지도 정비 0건이고 오류 피드백 경로 분리 | 요약 문장을 직접 바꿀 수 있다고 약속, 맞는 소개를 반복 수정해 요약을 덮으려 하기 |
| R12 | 동명 가게·다른 지점 경험이 섞임 | 장소 ID·주소·시점을 대조하고 잘못 연결된 근거는 제외. 지점 판정 미해결이면 관련 수정 보류 | 상호만으로 리뷰 합산, 다른 지점의 메뉴/영업시간을 복사 |

Google은 업주 설명, 편집 요약, 리뷰 기반 토픽/스니펫을 구분한다. 편집 요약은 직접 편집할 수 없고 토픽·스니펫도 업주 소개 입력 칸과 다르다. [Google 요약 유형 안내](https://support.google.com/business/answer/6088158?hl=en). 타인 리뷰는 직접 고칠 수 없으며 위반 의심 내용은 신고 경로를 따른다. [Google 리뷰·평점 안내](https://support.google.com/maps/answer/6230175?co=GENIE.Platform%3DDesktop).

리뷰 수집·답글·평점 향상을 현재 자동 정비의 추가 약속으로 만들지 않는다. 답글은 별도 요청이 있을 때 사실 확인 후 초안을 만들 수 있으나 현재 요청으로 공개 게시하지 않는다. Google·카카오의 답글 지원은 제품 범위와 구분한다. [Google 답글 관리](https://support.google.com/business/answer/3474050?hl=en), [카카오 후기 답글](https://kakaobusiness.gitbook.io/main/channel/run/mystore). 평점이 낮다고 리뷰 구매·보상·긍정 리뷰만 선별 요청하지 않는다. [Google 리뷰 정책](https://support.google.com/contributionpolicy/answer/7400114?hl=en).

### 4.7 ‘얼마나 바꾸는지’는 정비안에서 이렇게 계산

매장당 일정 개수를 바꾸는 할당량은 두지 않는다. **기존 정보 유지 / 값 정정 / 새 항목 추가 / 확인 필요 / 현재 범위 밖**으로 각각 나눠 건수를 표시한다. 확인 필요와 범위 밖은 실행 건수에 합산하지 않는다.

메뉴는 항목 수와 하위 변경 칸을 함께 표시한다. 예를 들어 ‘메뉴 2개, 가격 2칸 정정’과 ‘메뉴 2개, 설명 2칸 번역’을 구분한다. Google·카카오 각각에 같은 사실을 넣는 경우 지도별 작업 수와 고유 사실 수를 나눠 중복 부풀림을 막는다.

가상 매장 예시: 사장님 소개는 정상, 최신 메뉴판의 메뉴 12개 중 텍스트 10개가 일치, 1개 가격은 다르고 1개는 미등록, 리뷰에 주차 불만이 있음. 메뉴판 처리와 가격의 현재성·최소 주문이 확인됐고, 사장님이 주차는 실제 불가라고 확인했다고 가정한다.

- 소개: 유지 0건.
- 메뉴: 기존 1개의 가격 1칸 정정, 미등록 메뉴 1개 추가. 정상 10개는 유지.
- 주차: 현재 지도 값이 ‘주차 가능’이면 해당 속성 1칸 정정. 이미 ‘불가’이면 0건.
- 사진 원본·리뷰·별점: 기본 정비에서 직접 변경 0건.
- 영어가 부족하면 필요한 메뉴의 번역 설명을 별도 항목으로 제안하고 승인받음. 리뷰가 영어라는 이유만으로 추가하지 않음.

즉 이 경우는 ‘소개 전체 교체+메뉴 전부 다시 등록’이 아니라 **가격 1칸 정정+메뉴 1개 추가+필요할 때 주차 1칸 정정**이 정비 범위다.
