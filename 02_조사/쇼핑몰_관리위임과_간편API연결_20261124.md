# 스마트스토어·카페24 관리 위임과 간편 API 연결

확인일: 2026-11-24. 외부 고객 쇼핑몰에 seelo가 상품 정비를 제공하는 상황을 조사했다. 공식 문서와 운영팀 답변을 확인했다. 이번에는 고객 초대, 앱 설치, 권한 변경, 상품 수정을 실행하지 않았다.

**같은 날 후속 사용자 결정:** 초기 고객 수정은 위임받은 관리자 화면을 코드로 자동 조작하는 방식으로 진행한다. 이 문서의 API 경로 비교는 조사 기록으로 유지한다. 현재 개발 기준은 [쇼핑몰 관리자 화면 자동화](../01_기획/개발/쇼핑몰_관리자화면자동화.md)다.

## 결론

**관리자 위임만으로 고객 몰의 API 권한까지 자동으로 생기지는 않는다. 정식 앱·API 연결을 갖추면 관리자 계정 초대 없이도 상품을 수정하는 구조를 만들 수 있다.**

| 확인 항목 | 스마트스토어 | 카페24 |
|---|---|---|
| 관리자 화면 수정 위임 | 매니저 관리에서 seelo 담당자를 ‘대행사’ 역할로 초대 | 상품 메뉴와 수정 권한을 가진 부운영자 생성 |
| 위임만 받은 상태에서 고객 API 발급 | 대행사 역할 초대가 내 스토어 앱 발급 권한을 주지는 않음 | 부운영자 계정으로 앱 설치 불가 |
| 고객 서비스용 API 연결 | 등록 API 대행사 또는 커머스솔루션 | seelo 개발자 앱을 고객 몰에 설치하고 OAuth 동의 |
| 사장님의 필수 작업 | API 대행사 선택·연동 또는 솔루션 사용 신청 | 대표운영자 로그인 → 앱 설치 → 권한 동의 |
| 사장님의 개발자 가입·키 생성 | 정식 대행사·솔루션 연결에서는 요구하지 않음 | seelo 앱을 이용하면 요구하지 않음 |
| seelo가 먼저 할 일 | 법인 자격 확인, 해당 유형 신청·개발·심사 | 개발자 앱·인증 서버·토큰 관리·앱 심사 준비 |

아래 간편 연결 흐름은 공식 기능에 근거한 **서비스 설계안**이다. seelo 고객용 연동이 구현·승인됐다는 뜻은 아니다.

## 1. 스마트스토어 관리자 위임 확인

### 초기 고객을 관리자 화면에서 수정하는 절차

1. seelo가 초대받을 담당자 이름과 휴대전화 번호를 안내한다.
2. 사장님의 통합매니저 또는 계정 주매니저가 **판매자정보 → 판매자 관리 → 매니저 관리 → 매니저 초대**를 연다.
3. 담당자 정보를 입력하고 **대행사** 권한을 선택한다.
4. seelo 담당자가 SMS 초대 링크에서 본인 네이버 커머스 ID로 로그인하고 수락한다.
5. seelo가 해당 스토어의 상품 등록·수정 화면에서 작업한다.

공식 안내에서 대행사 역할은 상품 등록·수정과 통계 등 일부 기능을 이용할 수 있다. 판매·정산·정보 변경 등은 제한된다. ‘매니저 대행사 역할’과 ‘API 대행사 입점’은 다른 자격이다. [매니저 초대·권한 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3733)

### 위임받으면 API도 얻을 수 있는가

- 대행사 매니저 초대만으로는 안 된다. 커머스API센터 가입은 통합매니저 조건을 두고 있다. [마켓 입점 프로세스](https://apicenter.commerce.naver.com/docs/solution-doc/1000/마켓-입점-프로세스)
- 고객이 ‘내 스토어 애플리케이션’을 만들어 ID·Secret을 seelo에 전달하는 흐름을 고객 서비스 방식으로 사용하지 않는다. 공식 FAQ는 이 위탁 운영을 허용하지 않는다. 2026-08-31 답변에서도 판매자 본인 운용과 제3자 솔루션을 구분한다. [공식 FAQ](https://github.com/commerce-api-naver/api-agency/discussions/6), [2026년 공식 재확인](https://github.com/commerce-api-naver/commerce-api/discussions/3771)
- 우리 소유 테스트몰의 SELF 수정 성공과 외부 고객 서비스 승인은 별개다.

### 사장님의 작업을 줄이는 정식 경로

| 경로 | seelo 준비 | 사장님 작업 | 판단 |
|---|---|---|---|
| API 대행사 | 국내 법인 사업자, 대행사 신청·승인, 전용 애플리케이션, 연동 시험, 라이브 전환 | **스토어관리 → 스토어 설정 → API 관리**에서 상품 API 대행사로 seelo 선택·저장. 서비스 연결에 필요한 판매자 식별정보 입력은 별도로 설계 | 기존 seelo 서비스에 상품 수정을 붙일 때 우선 검토 |
| 커머스솔루션마켓 | 법인 입점 동의, 솔루션 개발·테스트·심사 | 솔루션 페이지에서 사용 신청·구독 연결 | 플랫폼 내 유입·구독까지 함께 운영할 때 검토 |

2026-07-15 공식 답변은 API 대행사 신청을 국내 법인 사업자로 한정한다. 승인 후 대행사 애플리케이션을 발급하며, 라이브 전환 후 판매자센터의 명단에 표시된다. 등록 업체를 판매자가 설정하는 연결 흐름도 공식 답변에서 확인했다. [자격·승인·라이브 전환](https://github.com/commerce-api-naver/api-agency/discussions/1003), [판매자 연결](https://github.com/commerce-api-naver/commerce-api/discussions/3679)

API 대행사는 상품 API 그룹만 사용하는 신청 사례가 공식 답변에 있다. 주문 권한을 함께 요구할 이유는 없다. 국내 호출 IP와 사업자 정보가 보이는 서비스 URL 등은 seelo 쪽에서 준비한다. [상품 그룹·IP·서비스 URL 조건](https://github.com/commerce-api-naver/api-agency/discussions/906)

솔루션 방식은 구독 고객의 판매자 UID로 `SELLER` 토큰을 받아 상품 관리 API를 호출하는 구조다. 솔루션 가입·구독과 개발사 내부 매니저 초대도 구분한다. [솔루션 인증](https://apicenter.commerce.naver.com/docs/solution-doc/3000/기본-연동-요소-가이드)

## 2. 카페24 관리자 위임 확인

### 초기 고객을 관리자 화면에서 수정하는 절차

1. 대표운영자가 **쇼핑몰 설정 → 운영자 설정 → 운영자 관리 → 운영자 계정 관리**를 연다.
2. seelo 전용 부운영자 ID를 만든다.
3. 해당 쇼핑몰 접근, 상품 메뉴, 필요한 상품 수정 권한을 부여한다.
4. seelo는 관리자 로그인의 **부운영자** 탭에서 접속한다.

작업에 필요한 상품 권한을 부여하고, 분류·디자인은 해당 작업이 있을 때 추가한다. 메뉴 권한을 가진 부운영자의 UI 수정과 앱 OAuth 권한을 같은 것으로 표시하지 않는다. [운영자 등록 가이드](https://support.cafe24.com/hc/ko/articles/7673792789145), [운영자 등록·권한 설명](https://serviceguide.cafe24.com/IN/ko_KR/SG.OM.OT.html)

### 위임받으면 API도 얻을 수 있는가

**부운영자 위임만으로는 앱을 설치할 수 없다. 최초 설치는 대표운영자가 해야 한다.** 현행 스토어 FAQ는 대표운영자 로그인과 사용 권한 동의를 안내한다. 공식 Help Center는 부운영자 설치 불가를 명시한다. [현행 스토어 설치 FAQ](https://store.cafe24.com/kr/support/faq), [대표운영자만 설치 가능](https://mighelp.cafe24.com/hc/ko-kr/articles/7780235400345)

개발자 앱의 Client ID·Secret은 seelo가 준비한다. 사장님이 설치·동의하면 seelo 서버가 인증 코드를 해당 몰의 토큰으로 교환한다. 대표 계정 비밀번호나 고객별 개발자 키를 seelo 입력창에 받을 필요가 없다. [OAuth 인증](https://apidocs.cafe24.com/en/docs/guide/oauth2-authentication)

### 사장님의 작업을 줄이는 권장 경로

1. seelo가 앱과 HTTPS 인증 수신 주소를 준비한다.
2. 사장님은 seelo의 **카페24 연결**에서 몰 ID를 입력한다. 앱스토어에서 시작한 경우 전달받은 몰 정보를 이용해 중복 입력을 줄인다.
3. 카페24 공식 화면에서 대표운영자로 로그인하고 앱 설치·권한에 동의한다.
4. seelo 서버가 토큰을 발급·갱신하고 상품을 수집한다.
5. 이후 정해진 수정 범위의 작업은 API로 처리한다. 관리자 UI 확인이 필요한 경우에만 부운영자를 추가한다.

상품 권한은 `mall.read_product`, `mall.write_product`를 우선 사용한다. 앱 설치 관리에 필요한 기본 권한은 별도로 확인한다. `mall.write_product`는 상품 생성·수정·삭제를 포함하므로, 플랫폼 권한이 ‘상세페이지 편집만’으로 제한된다고 안내하면 안 된다. seelo 내부에서 허용 API·필드를 제한하는 설계가 필요하다. [공식 Scope](https://developers.cafe24.com/app/front/app/develop/api/scope), [필수 권한 설정](https://developers.cafe24.com/app/front/app/develop/oauth/put)

토큰 갱신을 서버에서 정상 처리하면 만료 때마다 사장님에게 로그인을 요구할 필요가 없다. 권한 추가·철회·갱신 실패 시의 재연결은 별도로 처리한다. 앱 실행 시 부운영자 권한 정보도 전달되므로 앱 내부의 사람별 작업 권한을 따로 적용할 수 있다. [토큰 갱신](https://apidocs.cafe24.com/en/docs/guide/oauth2-authentication), [앱 실행 권한](https://developers.cafe24.com/app/front/app/develop/manage/runappauth)

자체몰 테스트 설치와 고객용 출시는 구분한다. 먼저 우리 몰에서 인증·상품 수정·원복을 시험하고 고객 배포에 필요한 앱 심사를 진행한다. [테스트 설치](https://developers.cafe24.com/app/front/common/concepts/sellapp/newbuildapp), [출시 심사 가이드](https://developers.cafe24.com/app/front/app/launch/examine/Quick-examine)

## 3. 사장님의 입력과 판단을 줄이는 서비스 흐름

아래는 조사 결과에 따른 제안이다. 현재 구현 완료 항목으로 취급하지 않는다.

1. **연결:** 플랫폼 선택 후 공식 로그인·설치·권한 동의로 이동한다. API 키, IP, Redirect URI, 개발자 계정 설정은 seelo가 처리한다.
2. **진단:** 연결 후 상품과 공개 페이지를 자동으로 읽는다. 상품 URL·HTML·원료 정보를 반복 입력받지 않는다. 공개 URL만으로 가능한 사전 진단은 연결 전에 제공할 수 있다.
3. **작업 범위:** 최초에 상세 본문·SEO 등 자동 수정 범위를 정한다. 가격·재고·배송·판매 상태·삭제는 초기 허용 범위에서 제외한다. 플랫폼 권한과 seelo의 실제 작업 제한을 구분해 안내한다.
4. **질문:** AI가 기존 상품 정보와 자료를 먼저 확인한다. 실제 영양성분표처럼 확인되지 않은 필수 사실만 묻는다. 근거 없는 수치와 효능을 만들지 않는다.
5. **수정:** 근거와 허용 범위가 확인된 항목은 자동으로 정비한다. 이미 정한 범위의 매 작업마다 API 설정이나 관리자 승인을 반복 요구하지 않는다.
6. **확인:** 저장 응답, 재조회, 공개 페이지를 확인한다. 실패·상품 충돌·추가 정보가 필요한 경우를 별도로 알린다. 변경 전후 기록으로 복구할 수 있게 한다.

## 4. 지금 적용할 운영 순서

| 단계 | 스마트스토어 | 카페24 |
|---|---|---|
| 자체 기술 검증 | 기존 SELF 실험을 외부 고객 권한과 구분해서 유지 | 우리 몰에서 앱 설치·OAuth·쓰기·원복 시험 |
| 정식 API 연결 전 초기 고객 | 대행사 매니저 초대를 받아 담당자가 관리자 화면에서 수정 | 상품 권한 부운영자로 담당자가 수정 |
| 고객 부담을 줄이는 목표 방식 | 상품 API 대행사 등록을 우선 검토. 법인 자격이 없으면 이 경로가 선행 과제 | 앱 심사 후 사장님의 설치·동의 중심 연결 |

등록 대행사와의 제휴는 대안 후보이나, 해당 업체의 상품 상세 수정 기능·재위임 조건·계약과 실제 연결 검증이 필요하다. 특정 업체가 seelo 대신 연결을 제공한다고 아직 확인하지 않았다. 대행사 키를 빌려 쓰는 방식으로 설명하지 않는다.

## 5. 확인된 범위와 미확인 항목

- **공식 확인:** 양 플랫폼의 관리자 위임, 네이버 고객 서비스용 연결 유형과 법인 조건, 카페24 대표운영자 앱 설치·OAuth·상품 Scope.
- **이번 미수행:** 실제 외부 고객 초대·설치·API 수정. 기존 자체몰 수정 성공은 고객 위임 성공의 증거가 아니다.
- **다음 실증:** 별도 판매자 계정의 위임 수락, 카페24 대표운영자 설치 후 seelo 토큰 수정, 권한 철회 시 접근 차단, 고객이 수행한 화면·입력 수 측정.
- **추가 확인 필요:** seelo의 국내 법인·대행사 승인 상태, 심사 전 고객 파일럿 허용 범위, 대행사 연결 시 판매자 식별정보의 전달 방식, 스마트에디터 ONE 기존 본문 보존.

상품 수정 필드와 GEO 적용 경계는 [수정 API와 GEO 적용 범위 확인](쇼핑몰_수정API와_GEO적용범위_확인_20261124.md)을 따른다. 기존 AI 노출 전후 비교 상품은 이번 조사에서 변경하지 않았다.
