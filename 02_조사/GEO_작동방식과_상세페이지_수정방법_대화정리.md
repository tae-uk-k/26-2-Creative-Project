## 2. AI가 상품 정보를 이용하는 흐름

당시 공식 설명과 조사 결과를 다음 흐름으로 정리했다. 모든 AI 서비스가 같은 내부 순서나 같은 자료를 쓴다는 뜻은 아니다.

```text
공개 상품 페이지·상품 데이터·외부 콘텐츠
→ 검색 또는 지원되는 상품 데이터 경로를 통해 후보 확보
→ 같은 상품·모델·옵션인지 식별
→ 질문의 용도·규격·가격 등 조건과 대조
→ 상품을 추천하거나 근거 URL을 제시
→ 사용자가 방문·비교·구매
```

각 단계에서 확인할 내용은 다르다.

| 단계 | 확인할 것 | 상세페이지 정비와의 관계 |
|---|---|---|
| 접근·발견 | 검색 시스템이나 AI가 해당 URL을 찾고 읽는가? | 읽기 쉬운 본문을 만들어도 후보로 발견되는지 별도로 확인한다. |
| 상품 식별 | 브랜드·모델·옵션·용량이 명확한가? | 다른 상품의 사양이나 다른 옵션의 가격을 섞지 않는다. |
| 조건 판단 | 질문의 조건을 확인할 사실이 있는가? | 규격·소재·호환성·구성품·사용 조건 등 빠진 사실을 보완한다. |
| 추천·인용 | 상품을 추천했는가? 해당 URL을 인용했는가? | 추천과 URL 인용을 각각 기록한다. |
| 구매 | 방문한 사용자가 실제로 구매했는가? | AI 추천 효과와 구매전환 효과를 별도 측정한다. |

2026-11-16 대화에서는 **AI가 상품을 판단하는 정보와 우리가 고치는 정보의 연결**을 핵심으로 잡았다. 당시 OpenAI 공식 설명은 가격·제품 설명 등의 구조화된 상품 정보와 외부 콘텐츠를 상품 선택에 활용한다고 안내했다. Google 공식 지침은 상품 페이지의 구조화 데이터와 판매자 상품 데이터 경로를 설명했다.

따라서 조사에서 정한 방향은 **상품을 발견하고 비교할 수 있도록 실제 상품 정보를 정비하는 것**이다. 글의 길이나 홍보 표현만 늘리는 작업으로 정의하지 않았다.

## 3. 정보 수정 기준

### 3.1 무엇을 바꾸는가?

| 대상 | 수정 방법 | 사용할 근거 |
|---|---|---|
| 상품 식별 | 브랜드·상품명·모델번호·옵션을 구분한다. | 판매자 상품 DB, 같은 모델의 제조사 자료 |
| 구매 조건의 누락 | 크기·무게·소재·구성품·전원·호환 모델·사용 조건을 보완한다. | 설명서, 인증 자료, 확인된 사양 |
| 이미지에만 있는 정보 | 이미지의 핵심 사양을 확인한 뒤 읽을 수 있는 본문·목록·표·지원 속성 칸으로 옮긴다. | 해당 상품·옵션의 이미지 원본 |
| 모호한 수량·가격 단위 | 개당·세트·묶음과 포함 수량을 구분해 설명한다. 판매 조건 자체는 바꾸지 않는다. | 현재 상품·옵션·판매 조건 |
| 설명의 구성 | 주요 용도, 조건·규격, 구성품, 사용·관리 정보를 구분한다. | 확인된 사실 목록 |
| 요약 설명 | AI나 외부 채널이 읽는 짧은 설명에도 필요한 사실이 전달되는지 확인한다. | 플랫폼의 전송 필드와 상품 원본 |
| SEO 정보·상품 속성 | 제목·설명·브랜드·모델·색상·규격을 지원 필드에 맞춘다. | 플랫폼별 입력 규칙 |
| 구조화 데이터·피드 | 본문·옵션·가격·재고와 같은 사실을 전달하는지 대조한다. | 공개 페이지와 실제 판매자 데이터 |

가격·재고·배송·판매 상태는 사실 대조의 대상이다. 설명 개선을 이유로 임의 변경하는 대상은 아니다.

### 3.2 어떤 사실을 넣는가?

1. 상품의 원본과 공개 상세페이지를 읽는다.
2. 제조사·설명서 등에서 같은 모델과 옵션의 자료를 모은다.
3. 이미 있는 정보와 빠진 정보를 구분한다.
4. 자료로 확인된 누락 사실을 먼저 보완한다.
5. 수집으로 해결되지 않은 필수 정보만 판매자에게 묻는다.
6. 수정안과 기존 값을 비교해 승인받는다.
7. 저장 후 원본 재조회와 공개 화면을 확인한다.
8. 실제로 읽힌 페이지 버전과 AI 응답을 다시 측정한다.

다른 모델의 사양, 다른 옵션의 값, 확인되지 않은 성능·호환성·인증·효능·후기는 추가하지 않는다. 여러 자료의 표현이 다르다는 이유만으로 모든 충돌을 판매자 질문으로 보내지 않는다. 현재 질문 선정 규칙은 [AI 수집과 최소 질문](../01_기획/AI수집과최소질문.md)에서 관리한다.

### 3.3 기존 디자인은 어떻게 다루는가?

2026-11-17 대화에서 검토한 작업 방식은 다음과 같다.

- 기존 상세 이미지와 브랜드 문구를 확인한다.
- 필요한 사양·호환·구성품·사용 조건을 읽을 수 있는 정보로 보완한다.
- 기존 이미지·링크·편집기 구성을 보존한다.
- 권한과 플랫폼 지원 범위가 맞으면 별도 속성·구조화 데이터·피드도 대조한다.

페이지를 전부 다시 만드는 방식과 필요한 정보만 보완하는 방식을 구분했다. 저장 가능한 HTML의 범위도 플랫폼별로 확인하도록 했다.

## 4. 정보가 전달되는 경로

2026-11-16 대화에서 ‘화면에 보이지 않는 상품 데이터’를 질문했을 때 구분한 내용이다.

| 경로 | 역할 | 확인할 점 |
|---|---|---|
| **상세페이지 HTML 본문** | 사람이 읽는 설명과 기계가 처리할 텍스트를 제공한다. | 공개 페이지에서 실제로 읽히는지 확인한다. |
| **상품 속성·요약·SEO 필드** | 플랫폼의 상품 정보와 검색·전송용 설명을 관리한다. | 어느 칸이 실제 출력·전송에 쓰이는지 확인한다. |
| **Product·Offer 구조화 데이터** | 상품·모델·가격·재고 등의 의미를 표준 형식으로 표현한다. | 고객에게 안내하는 사실과 일치해야 한다. |
| **공식 상품 피드** | 지원되는 외부 채널에 상품 데이터를 별도 제출한다. | 국가·판매자 자격·연동 경로와 실제 수신 값을 확인한다. |
| **별도 공개 상품 문서** | 추가 설명을 공개 URL로 제공한다. | URL 생성 외에 검색·수집·연결 경로가 필요하다. |

공개 HTML이나 공개 문서는 사람이 소스나 주소로 확인할 수 있다. 이를 ‘AI만 접근하는 비밀 문서’로 설명하지 않는다.

**상세 본문을 바꿨다는 사실과 외부 AI에 전달되는 상품 데이터가 바뀌었다는 사실은 다르다.** 2026-11-17 조사에서는 카페24 Google 연동의 설명에 **상품 요약 설명이 우선 사용될 수 있다는 점**을 확인했다. 이 경우 상세 본문만 수정하면 전송 설명은 그대로 남을 수 있다. 원래 조사에서 연결한 근거는 [카페24 전송 항목 안내](https://shopnotice.cafe24.com/view?bbs_no=12&no=349182)다.

이 링크들은 당시 대화의 근거를 다시 찾기 위한 원문 주소다. 현재 정책 확인 결과를 새로 추가한 목록은 아니다.

### 5.2 상품 설명을 바꾸면 어떤 결과가 있었는가?

| 연구 | 전환 이후 조사에서 확인한 내용 | 실험 조건과 해석 |
|---|---|---|
| [LIVE-GEO](https://arxiv.org/html/2611.01126v1) | 실제 웹의 상품 설명 재작성이 후보 선택 순위에 영향을 준 사례 | 후보 URL을 먼저 제공했다. 이미 주어진 상품의 선택과 새로운 상품의 자연 발견을 구분한다. |
| [E-GEO v3](https://arxiv.org/html/2511.20867v3) | 후보 10개·질문 2,000개에서 설명 재작성 비교. GPT-5·Claude는 평균 약 0.56~0.57순위 상승, GPT-4o-mini는 약 0.36순위 하락 | 후보 상품의 재정렬 실험이다. 설명 길이와 순위 상승의 관계는 거의 없었다. |
| [C-SEO Bench](https://arxiv.org/html/2506.11097v3) | 문체 교정·쉬운 표현 등의 효과가 모델·상품군에 따라 제한적 | 문체 교정, 누락 사실 보완, 구조화 데이터 변경을 나눠 시험하는 근거로 사용했다. |
| [온라인 소매의 상품 설명 무작위 실험](https://arxiv.org/html/2510.12049v6) | 약 45,000개 상품·4,772,937명 대상. 소비자당 매출 상대 +2.05%, 구매전환 상대 +1.27% | 상세페이지 방문 이후의 구매 효과다. 외부 AI에서의 발견·추천 증가율은 측정값이 다르다. |

마지막 연구의 기존 설명 길이별 매출 변화는 짧은 설명군 +6.50%, 충분한 설명군 +0.03%였다. 이 세부 분석은 영어 실험 기준이다. 한국어의 글자 수나 목표 분량으로 그대로 옮기지 않았다. 상세 수치와 표 위치는 [기존 효과 검토 1절](쇼핑몰상세페이지_효과와플랫폼검토.md#1-효과는-얼마나-커질-수-있는가)에 있다.

이 조사에서 채택한 판단은 **길게 쓰기보다 질문의 구매 조건을 확인할 수 있는 사실을 보완하고, 실제 상품의 발견·추천 변화를 따로 측정한다**는 것이다.

## 6. 쇼핑몰 실험에서 확인한 것

### 6.1 읽을 수 있음과 발견됨을 나눴다

2026-11-24 ‘쇼핑몰 AI 노출 실험 수행’ 대화에서는 수박씨·사차인치 탈지 단백질 분말을 대상으로 다음 세 결과를 분리했다.

1. 상품 URL을 주었을 때 페이지를 읽는가?
2. 브랜드·스토어·URL을 주지 않아도 상품을 발견하고 추천하는가?
3. 발견한 상품의 원료·용량·가격 등을 정확히 설명하는가?

초기 진단에서 ChatGPT는 정확한 상품명 검색으로 두 상품을 찾지 못했다고 답했다. 반면 카페24 수박씨 URL을 직접 주었을 때는 본문을 읽었다. 이 관찰은 **URL 지정 열람 성공과 자연 발견 성공을 같은 점수로 계산하지 않은 이유**다. [초기 실행 기록](../03_실험/쇼핑몰_AI노출_전후비교_20261124/초기실행결과_20261124.md)

### 6.2 확인된 기준선 결과

[CLI·API 통합 결과](../03_실험/쇼핑몰_AI노출_전후비교_20261124/CLI_API_B0_통합결과_20261124.md)에는 Codex CLI 36회와 Gemini API 36회의 유효 응답이 기록돼 있다.

| 측정 경로 | 수박씨 자연 발견 | 사차인치 자연 발견 | 대상 상품 URL 인용 |
|---|---:|---:|---:|
| Codex CLI | 0/24 | 0/24 | 0건 |
| Gemini API | 0/24 | 0/24 | 0건 |

상품별 분모 24회는 일반 질문 12회와 해당 원료 질문 12회를 합한 값이다. 서로 다른 상품에 대한 평가 분모를 합쳐 실제 질문 실행 횟수로 세지 않는다. CLI·API 결과와 소비자 웹 결과도 합산하지 않았다.

이 연결 기록은 **수정 전 기준선**이다. 상세페이지 정비 후의 효과 측정 결과로 사용하지 않는다.

### 6.3 전후 비교에서 나누기로 한 변경

- 영양 수치·사양 등 새로운 사실을 추가하는 변경.
- 같은 사실의 문체·구성을 바꾸는 변경.
- 구조화 데이터·상품 피드 전달 경로를 바꾸는 변경.

예를 들어 ‘단백질 50g 이상’ 조건을 시험하려면 해당 완제품의 확인된 영양자료가 먼저 필요하다. 원료사의 수치를 완제품 수치로 바꾸어 넣지 않는다. 정보 추가 효과와 HTML 구성 변경 효과를 나누려면 두 상품의 사실 조건을 맞춘 뒤 기준선을 다시 측정하도록 계획했다. [실험계획](../03_실험/쇼핑몰_AI노출_전후비교_20261124/실험계획.md)

## 7. 조사 범위와 구현 규칙

위에서 검토한 방법이 모두 현재 자동화 기능에 들어 있다는 뜻은 아니다. **2026-11-25 상품정보 정비 기준**의 작성 범위는 다음과 같다.

| 구분 | 정본에 기록된 범위 |
|---|---|
| 상세 본문 | 확인된 사실을 `상품 정보` 목록 영역으로 만들어 기존 본문 끝에 추가한다. 같은 seelo 영역이 있으면 그 영역만 바꾼다. |
| 기존 구성 | 이미지·링크·편집기 HTML을 보존한다. |
| 요약·간략·SEO 설명 | 기본은 비어 있는 칸만 대상으로 한다. |
| FAQ·표·JSON-LD | 현재 정비안에서 자동 생성하지 않는다. |
| 외부 상품 피드 | 외부 채널 전송 필드·수신 값은 현재 서버 계약에 없다. |
| 판매 조건 | 가격·재고·옵션·배송·판매·진열·구매 제한은 정비 대상에서 제외한다. |

HTML 본문 저장 경로는 스마트스토어의 `originProduct.detailContent`, 카페24의 `description` 등으로 조사했다. 이 경로는 정비안을 저장하는 수단이다. 별도의 ‘GEO 켜기’ 기능을 호출하는 방식은 아니다. [수정 API와 GEO 적용 범위](쇼핑몰_수정API와_GEO적용범위_확인_20261124.md)
