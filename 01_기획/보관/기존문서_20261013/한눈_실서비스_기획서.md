## 1. 서비스 개요

### 1.1 한 줄 정의

한눈은 가게의 온라인 정보를 수집해 ChatGPT·Gemini 추천 노출을 측정하고, AI가 가게를 더 정확히 이해하고 추천할 수 있도록 영문 정보와 채널별 개선안을 만들어 주는 GEO 웹 서비스다.

### 1.2 핵심 가치

가게 정보를 단순히 번역하거나 지도에 등록하는 데서 끝나지 않는다. 실제 관광객형 질문에서 가게가 얼마나 등장하는지 측정하고, 누락된 정보와 근거를 보완할 실행 자료를 만든 뒤 같은 조건으로 다시 확인한다.

### 1.3 핵심 흐름

```text
회원가입·로그인
  → 가게 등록 및 지도 링크 입력
  → 온라인 정보 수집·사장님 확인
  → 무료 AI 노출 진단
  → 유료 AI 노출 최적화 보고서
  → 영문 정보·채널별 수정안 적용
  → 동일 조건 재측정·전후 비교
```

### 1.4 GEO 개선 원칙

- SEO는 검색 결과의 순위와 클릭을 개선하는 데 초점을 둔다.
- GEO는 생성형 AI가 답변을 만들 때 가게를 이해하고, 근거를 확인하며, 관광객의 조건과 연결할 수 있게 하는 데 초점을 둔다.
- 한눈은 질문 조건과 연결되는 정보, 여러 채널에서 일치하는 사실, 읽을 수 있는 텍스트, 확인 가능한 외부 근거를 함께 개선한다.
- 특정 순위나 추천 노출을 보장하지 않는다. 가짜 리뷰, 숨은 광고, 허위 정보를 사용하지 않는다.

## 2. 문제 정의와 근거

### 2.1 핵심 문제

외국인 관광객을 유치하려는 소규모 가게는 AI가 가게를 얼마나 추천하는지 확인하기 어렵고, 추천에 필요한 온라인 정보와 외부 근거도 부족해 관광객에게 발견될 기회를 놓칠 수 있다.

### 2.2 확인된 사실

- 미국 활동 여행자의 여행 계획 생성형 AI 이용률은 2025년 상반기 33%, 하반기 43%, 2026년 56%로 증가했다.
- Adobe 조사에서 AI 여행 이용자의 53%는 지역 명소·식당·숨은 장소를 찾는 데 AI를 사용했다.
- 발리 음식점·카페·바 4,776곳과 AI 답변 2,208개를 분석한 연구에서는 전체 매장의 85.6%가 한 번도 추천되지 않았다.

### 2.3 팀의 해석과 주의점

- 여행자가 가게를 발견하는 과정에서 AI 답변의 영향력이 커지고 있다.
- AI는 지역의 모든 가게를 고르게 추천하지 않는다.
- 영문 정보, 가격, 공식 웹페이지, 외부 언급 같은 온라인 근거가 적은 가게는 AI가 질문 조건과 연결하기 어려울 가능성이 있다.
- 위 연구만으로 프랜차이즈가 소규모 가게보다 더 많이 추천된다고 단정하지 않는다.
- 미국·발리 자료를 한국 방문 외국인 전체에 그대로 일반화하지 않는다. 국내 실제 가게 사용자 조사를 별도로 수행한다.

### 2.4 UX 인사이트

소규모 가게 사장님에게는 AI 노출을 숫자로 확인하는 진단뿐 아니라, 부족한 정보를 실제로 정비하고 개선 전후를 확인할 수 있는 지원이 필요하다.

### 2.5 근거 출처

- Phocuswright Research (2026), *The AI Surge*
- Adobe Digital Insights (2025), *Generative AI Boosts Travel Planning*
- Pitenin (2026), *Invisible to the Machine*, arXiv:2608.07069

## 3. 목표 사용자와 서비스 범위

### 3.1 1차 사용자

- 외국인 관광객이 방문하는 음식점·카페·바 사장님
- 소품샵·편집숍·공방·체험 매장 운영자
- 디지털 마케팅이나 영어 정보 관리에 익숙하지 않은 1인·소규모 사업자

### 3.2 최종 수혜자

- 지역, 예산, 언어, 식단, 결제 조건에 맞는 로컬 가게를 찾는 외국인 관광객

### 3.3 구매 단위

- 가게별 개별 구매를 기본으로 한다.
- 상인회·지자체 단체구매와 다점포 통합 관리는 초기 범위에서 제외한다.

### 3.4 초기 지원 범위

- 언어: 영어
- 매장: 계정당 우선 1개 가게
- AI: OpenAI와 Gemini의 공식 API
- 비교군: 같은 지역의 주변 가게
- 외부 채널: 정보를 수집하고 수정안을 제공하되 자동 수정하지 않는다.

## 4. 상품과 과금 경계

| 구분 | 사용자가 받는 결과 | 과금 |
|---|---|---|
| AI 노출 진단 | 모델별 추천 등장 여부, 추천 등장률, 평균 등장 순서, 주변 가게 비교, 측정 조건과 실패 내역 | 무료 |
| AI 노출 최적화 보고서 | 미노출 원인, 누락·불일치 정보, 우선순위, 영문 소개·메뉴·이용 정보, 채널별 수정 문안, 공개 영문 페이지 초안 | 유료 |
| 개선 후 재측정 | 같은 질문·모델·반복 조건으로 다시 측정한 전후 변화 | 유료 보고서 범위에 포함 |
| 월간 재측정 | 노출 변화와 잘못된 정보의 정기 확인 | 구현 예정, 세부 정책 보류 |

무료 진단은 현재 상태를 보여 주고, 유료 보고서는 사용자가 실제로 고칠 수 있는 상세 항목과 완성된 개선 자료를 제공한다. 가격, 무료 사용 제한, 결제 방식은 결정 로그에서 관리한다.

## 5. 대표 사용자 여정

1. 사장님이 회원가입 후 로그인한다.
2. 가게명과 지도 링크를 입력한다.
3. 서비스가 지도 링크의 제공자를 식별하고 상호·주소·영업시간·메뉴·가격·리뷰·이용 정보를 수집한다.
4. 수집하지 못한 항목과 서로 다른 정보는 사장님이 확인·수정한다.
5. 가게의 업종·지역·특징을 바탕으로 관광객형 질문 세트를 만든다.
6. 질문 세트를 OpenAI·Gemini에 반복 실행하고 원본 응답과 출처를 저장한다.
7. 무료 진단에서 가게의 등장률·평균 등장 순서·주변 가게 비교를 확인한다.
8. 사장님이 유료 최적화 보고서를 열면 구체적인 문제와 우선순위, 영문 개선 문안, 채널별 수정안을 확인한다.
9. 사장님이 사실관계를 확인하고 승인한 정보만 공개 영문 페이지나 외부 채널에 반영한다.
10. 같은 측정 조건으로 재측정하고 전후 결과를 비교한다.

## 6. 핵심 기능 요구사항

### 6.1 계정과 가게 관리

| ID | 요구사항 | 구현 완료 기준 |
|---|---|---|
| AUTH-01 | 회원가입·로그인·로그아웃 | 사용자가 계정을 만들고 로그인 상태에서 자신의 가게와 보고서만 조회할 수 있다. |
| AUTH-02 | 비밀번호·세션 보안 | 비밀번호를 단방향 해시로 저장하고, 세션 만료·CSRF 방어·로그인 시도 제한을 적용한다. |
| STORE-01 | 가게 등록·수정 | 사용자가 가게명, 업종, 지역, 지도 링크를 저장하고 수정할 수 있다. |

로그인 방식과 비밀번호 찾기 범위는 결정 로그에서 확정한다.

### 6.2 지도 링크 정보 수집

| ID | 요구사항 | 구현 완료 기준 |
|---|---|---|
| COLLECT-01 | 지도 링크 판별 | 입력 URL에서 지원 제공자와 매장 식별자를 판별하고, 지원하지 않는 링크에는 이유와 대체 입력 방법을 안내한다. |
| COLLECT-02 | 가게 정보 수집 | 허용된 API·공개 데이터 범위에서 상호, 주소, 영업시간, 연락처, 웹사이트, 메뉴·가격, 사진, 리뷰 관련 정보를 수집한다. |
| COLLECT-03 | 누락·불일치 확인 | 수집하지 못한 항목과 채널별 값이 다른 항목을 구분해 보여 주고, 사용자가 직접 수정할 수 있다. |
| COLLECT-04 | 원본 보존 | 수집 시각, 출처 URL, 원본 값, 사용자가 승인한 값을 별도로 저장한다. |

수집이 실패해도 서비스 전체가 중단되지 않으며, 직접 입력으로 다음 단계에 진입할 수 있어야 한다. 지도 서비스 약관에 위배되는 무단 수집은 사용하지 않는다.

### 6.3 AI 노출 진단

| ID | 요구사항 | 구현 완료 기준 |
|---|---|---|
| MEASURE-01 | 질문 세트 생성·버전 고정 | 가게의 지역·업종·가격·관광객 조건을 반영한 질문을 생성하고, 측정에 사용한 문장을 버전으로 저장한다. |
| MEASURE-02 | 반복 AI 실행 | 동일 질문을 OpenAI·Gemini에 정해진 횟수만큼 새 대화 조건으로 실행하고 모델명·설정·시각을 기록한다. |
| MEASURE-03 | 추천 결과 추출 | 가게명, 등장 여부, 등장 순서, 설명된 조건, 인용 URL을 구조화해 저장하고 원본 응답과 연결한다. |
| MEASURE-04 | 지표 계산 | 모델별 추천 등장률, 평균 등장 순서, Top-N 비율, 출처 제공률, 응답 변동성을 계산한다. |
| MEASURE-05 | 실패 분리 | API 오류·검색 실패·시간 초과를 미노출로 계산하지 않고 별도 실패율로 표시한다. |
| MEASURE-06 | 주변 가게 비교 | 같은 질문에서 등장한 주변 가게와 대상 가게의 노출 지표를 비교한다. |

질문은 가게마다 생성하되, 전후 비교가 끝날 때까지 같은 질문 세트 버전을 유지한다. 주변 가게의 정확한 반경·수·동종업종 기준은 결정 로그에서 확정한다.

## 7. 측정 설계

### 7.1 기본 원칙

- 한 번의 답변이 아니라 반복 측정 결과를 비율로 본다.
- 소비자 앱 결과와 API 결과를 같은 지표로 섞지 않는다.
- 모델별 결과를 분리해서 표시한다.
- 기술 실패는 추천 미노출과 별도로 기록한다.
- 질문·모델·검색 설정·시간·원본 응답을 재현 가능한 형태로 저장한다.

### 7.2 질문 세트

- 지역·업종 기본 질문
- 예산 질문
- 혼자 방문·단체 방문 질문
- 영어 메뉴·외국 카드 질문
- 채식·할랄·알레르기 질문
- 대표 메뉴·상품·체험 질문

질문은 가게별로 생성하되, 생성 후 담당자가 검수하고 하나의 버전으로 고정한다. 전후 비교에서는 동일 버전을 사용한다.

### 7.3 핵심 지표

| 지표 | 정의 |
|---|---|
| 추천 등장률 | 성공한 전체 응답 중 대상 가게가 한 번 이상 등장한 비율 |
| 평균 등장 순서 | 대상 가게가 등장한 응답에서의 평균 추천 순서 |
| Top-N 비율 | 대상 가게가 1위·3위·5위 안에 등장한 비율 |
| 조건 반영률 | 질문의 조건이 대상 가게 설명에 포함된 비율 |
| 정보 정확도 | AI가 말한 주소·시간·가격·메뉴 등이 승인된 사실과 일치한 비율 |
| 출처 제공률 | 대상 가게를 뒷받침하는 직접 출처 URL이 포함된 비율 |
| 실행 실패율 | API 오류·시간 초과·검색 실패가 발생한 비율 |
| 반복 변동성 | 같은 질문 반복 간 추천 가게 집합의 변화 정도 |

### 7.4 비교군

- 대상 가게 주변의 동종 또는 유사 업종 가게를 비교군으로 사용한다.
- 같은 질문 세트에서 함께 추천된 주변 가게를 우선 관찰한다.
- 비교군은 정보 정비 대상이 아니며, 같은 기간에 재측정한다.
- 정확한 반경, 가게 수, 프랜차이즈 포함 여부는 결정 로그에서 확정한다.

## 9. 기술 구조

### 9.1 권장 스택

| 영역 | 기술 | 역할 |
|---|---|---|
| 웹 | Flask + Jinja2 + HTML/CSS/JavaScript | 기존 MVP를 확장해 사용자 화면과 서버 렌더링 제공 |
| 인증 | Flask-Login, 비밀번호 해시, CSRF 방어 | 계정·세션·접근 권한 관리 |
| 애플리케이션 | Flask 서비스 계층 + SQLAlchemy + Alembic | 비즈니스 로직, RDB 접근, 스키마 변경 관리 |
| 데이터베이스 | PostgreSQL | 사용자·가게·수집값·AI 응답·보고서·버전·결제 권한 저장 |
| 비동기 작업 | Redis + RQ 또는 Celery | 반복 AI 호출, 지도 수집, 보고서 생성을 웹 요청과 분리 |
| AI 연동 | OpenAI API, Gemini API | 관광객형 질문 실행, 구조화 추출, 보고서 초안 생성 |
| 파일 저장 | S3 호환 오브젝트 스토리지 | 메뉴판 이미지, 보고서 PDF, 실행 증거 저장 |
| 배포 | Docker 기반 웹·워커·PostgreSQL 구성 | 개발·운영 환경 일치와 확장 |
| 관측 | 구조화 로그·오류 추적·작업 상태 | 실패 원인과 비용, 응답 시간을 확인 |

PostgreSQL을 중심 저장소로 사용한다. JSON 파일은 시연 데이터에만 적합하므로 실제 사용자·이력·동시 작업이 있는 서비스 데이터에는 사용하지 않는다.

       │

       ▼

                  ├─ 지도 링크 수집
                  ├─ 질문 세트 실행

                       │

## 10. API·데이터 처리 원칙

- 지도 정보는 공식 API, 가게가 제공한 정보, 약관상 허용된 공개 데이터만 사용한다.
- 외부 페이지의 문장은 명령으로 취급하지 않고 데이터로만 처리한다.
- AI 응답의 원문과 구조화 결과를 함께 저장해 재검수할 수 있게 한다.
- 가게명 매칭은 상호만으로 확정하지 않고 주소·지점·지도 식별자를 함께 확인한다.
- 가격·알레르기·할랄·채식·결제 정보는 사장님 승인 없이는 공개하지 않는다.
- API 키와 비밀값은 환경변수 또는 비밀 관리 도구에 저장한다.
- 사용자가 탈퇴하면 법적 보존이 필요한 기록을 제외한 계정·가게 데이터 삭제 절차를 제공한다.

| 상황 | 사용자에게 보이는 동작 | 내부 처리 |
|---|---|---|

| 보고서 생성 실패 | 진단 결과는 유지하고 보고서 재생성 제공 | 중복 결제·중복 작업 방지 키 사용 |

## 12. 운영·윤리·품질 기준

- 추천 노출과 순위를 보장하지 않는다.
- 가짜 리뷰, 리뷰 구매, 허위 정보, 숨은 광고를 제공하지 않는다.
- 진단 결과에는 측정일, 모델, 질문 수, 반복 횟수, 실패율을 표시한다.
- 생성한 문안은 `확인된 사실`, `AI가 생성한 초안`, `사장님 승인 완료` 상태를 구분한다.
- 기술 실패율이 높으면 결과를 확정하지 않고 재측정 필요 상태로 표시한다.
- 유료 보고서는 문제를 나열하는 데서 끝내지 않고 복사·게시 가능한 개선 문안을 포함해야 한다.

- 유료 권한이 있는 사용자는 상세 최적화 보고서와 개선 문안을 확인할 수 있다.
- 승인된 정보로 영문 소개 페이지 또는 게시 가능한 결과물을 만들 수 있다.
- 동일 조건 재측정과 전후 비교가 가능하다.
- 핵심 정상·실패 시나리오의 자동 테스트와 실제 사용자 평가 기록이 있다.

## 15. 검증 계획과 현재 상태

### 15.1 현재 확인된 것

- 기존 더미 MVP에 랜딩, 입력, 진단, 개선안, 영문 페이지, 전후 비교 화면이 있다.
- 반복 응답의 등장률·평균 순서·정보 정확도·조건 반영률 계산과 누락·불일치 탐지 테스트 14개가 통과했다.
- 소비자 웹 파일럿과 별도로 한국어 CLI 탐색 실험을 수행해 반복 측정 시 모델·반복별 추천 결과가 달라짐을 확인했다.

### 15.2 아직 구현·검증하지 않은 것

- 실제 서비스 로그인·권한·계정 복구
- 지도 링크의 실제 정보 수집과 약관별 지원 범위
- 제품 내부 OpenAI·Gemini API 연동
- PostgreSQL 영구 저장과 비동기 작업 큐
- 실제 가게의 유료 최적화 보고서 생성·승인·적용
- 실제 정보 정비 후 AI 노출 전후 비교
- 실제 결제와 월간 재측정

기존 14개 테스트 통과는 계산 로직과 더미 화면의 검증이며, 실제 AI 추천 개선 효과나 운영 준비 완료를 의미하지 않는다.

## 16. 핵심 리스크와 대응

| 리스크 | 대응 |
|---|---|
| API 결과와 소비자 앱 추천이 다름 | API 지표임을 표시하고, 파일럿에서 소비자 앱 결과를 별도 수동 대조 |
| AI 답변 변동과 모델 업데이트 | 반복 측정, 질문 버전 고정, 모델·날짜 기록, 주변 가게 대조 |
| API 오류를 미노출로 오인 | 기술 실패를 별도 상태와 분모로 관리 |
| 지도 서비스별 수집 가능 필드 차이 | 제공자별 지원표와 직접 입력 폴백 제공 |
| 무단 수집·약관 위반 | 공식 API와 허용된 데이터만 사용하고 제공자별 법적 검토 기록 |
| AI가 틀린 개선 문안을 생성 | 원본 근거 연결, 규칙 검증, 사장님 승인 후 확정 |
| 알레르기·할랄 정보 오류 | 사장님 확인 필수, 책임 범위와 안내 문구 표시 |
| 반복 호출 비용 증가 | 질문 수·반복 수 상한, 작업 예산, 캐시·재시도 정책 적용 |
| 소규모 가게의 낮은 디지털 이해도 | 전문 용어를 줄이고 `무엇을 왜 고칠지` 중심의 단계형 UX 제공 |
| 노출 개선이 없을 수 있음 | 순위 보장 금지, 정확도·정보 완성도·출처 개선도 함께 보고 |
