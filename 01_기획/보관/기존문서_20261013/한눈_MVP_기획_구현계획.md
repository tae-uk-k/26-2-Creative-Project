# 한눈 MVP 기획 및 구현 계획

## 1. 서비스 개요

### 서비스명

**한눈**

### 한 줄 설명

외국인 관광객이 ChatGPT·Gemini 같은 AI에게 장소를 물어볼 때, 소규모 가게가 추천 답변에 더 잘 발견되도록 현재 노출 상태를 진단하고 온라인 정보를 정비한 뒤 개선 전후를 비교해 주는 서비스다.

### 핵심 가치

가게 정보를 단순히 번역하거나 지도에 등록하는 데서 끝나지 않고, 관광객이 실제로 AI에게 질문하는 조건과 가게 정보를 연결한다. AI가 읽고 확인할 수 있는 영문 정보와 외부 근거를 보강하고, 같은 질문으로 다시 측정해 변화를 보여준다.

### 핵심 메시지

> AI 추천에서 우리 가게가 보이는지 한눈에 확인하세요.

보조 설명:

> 한눈은 AI가 우리 가게를 어떻게 소개하는지 진단하고, 추천에 필요한 정보를 정비한 뒤 개선 전후를 비교해 줍니다.

## 2. 문제 정의

### 문제 상황

외국인 관광객은 검색 결과를 하나씩 비교하는 대신 AI에게 지역, 취향, 예산, 식이 조건 등을 말하고 방문할 장소를 추천받기 시작했다. 하지만 소규모 가게는 온라인 정보가 부족하거나 여러 채널의 정보가 일치하지 않아 AI가 관광객의 조건과 가게를 연결하기 어렵다.

### 문제 정의 문장

**외국인 관광객을 유치하려는 소규모 가게는 온라인 정보가 부족하고 AI 노출 상태를 확인하기 어려워 관광객에게 발견될 기회를 놓칠 수 있다.**

### 확인된 배경 자료

- Phocuswright에 따르면 미국의 활동적인 여행자 가운데 여행 계획에 생성형 AI를 사용한 비율은 2025년 상반기 33%, 하반기 43%, 2026년 56%로 증가했다.
- Adobe가 미국 소비자 5,000명을 조사한 결과 29%가 여행 계획에 AI를 사용했으며, AI 사용자의 53%는 지역 명소·음식점·숨은 장소를 찾는 데 AI를 사용했다.
- 발리의 음식점·카페·바 4,776곳을 대상으로 4개 AI의 답변 2,208개를 분석한 연구에서는 전체 매장의 85.6%가 한 번도 추천되지 않았다. Google 평가가 50개 이상인 매장도 72.6%가 추천되지 않았다.

### 자료 해석 시 주의점

- 미국 조사 결과를 한국 방문 외국인 관광객 전체에 그대로 일반화하지 않는다.
- 발리 연구는 한국 시장을 직접 조사한 자료가 아니다.
- 발리 연구만으로 프랜차이즈나 대형 매장이 소규모 매장보다 더 자주 추천된다고 단정할 수 없다.
- 연구에서 확인할 수 있는 핵심은 많은 가게가 AI 추천에서 누락되며, 리뷰 수, 자체 웹사이트, 가격 정보, 제3자 언급과 같은 온라인 정보 기반이 추천 진입과 연관된다는 점이다.

## 3. SEO와 GEO의 차이

| 구분 | SEO | GEO |
|---|---|---|
| 목표 | 검색 결과에서 웹사이트나 지도 정보의 순위를 높임 | 생성형 AI 답변에 가게 정보가 선택·인용·추천될 가능성을 높임 |
| 사용자 행동 | 키워드로 검색하고 결과를 직접 비교함 | 상황과 조건을 문장으로 설명하고 추천을 요청함 |
| 주요 대응 | 검색어, 페이지 제목, 링크, 지도 등록 최적화 | 질문 조건과 연결되는 정보, 일관된 출처, 검증 가능한 근거, AI가 읽기 쉬운 구조 보강 |
| 측정 | 검색 순위, 클릭 수, 방문 수 | 추천 등장률, 평균 추천 순서, 인용 출처, 정보 정확도, 조건 반영률 |

한눈은 기존 SEO를 대체하는 서비스가 아니다. 검색과 지도에 존재하는 가게 정보를 기반으로, 생성형 AI가 관광객의 구체적인 질문에 답할 때 가게를 이해하고 추천할 수 있도록 정보를 보완하는 GEO 지원 서비스다.

## 4. 주요 고객과 사용 상황

### 1차 고객

- 외국인 관광객을 유치하려는 소규모 음식점·카페·바 사장님
- 소품샵·편집숍·공방·체험 매장 운영자

### 구매 단위

**가게별 개별 구매**를 기본으로 한다. 상인회·지자체 단체구매와 다점포 통합 관리는 초기 범위에서 제외한다.

### 대표 사용 상황

1. 사장님이 가게명과 온라인 채널 링크를 입력한다.
2. 한눈이 관광객이 사용할 만한 질문으로 현재 AI 노출 상태를 보여준다.
3. AI 답변에서 가게가 빠지는 원인을 정보 부족, 출처 부족, 채널 불일치로 구분한다.
4. 한눈이 영문 소개, 메뉴·가격·이용 정보와 공개 소개 페이지를 만들어 준다.
5. 사장님이 내용을 확인하고 승인한다.
6. 동일한 조건으로 다시 측정해 개선 전후를 비교한다.

### 사용자 스토리

- 사장님으로서, AI가 내 가게를 실제로 추천하는지 알고 싶다.
- 사장님으로서, 내 가게가 추천되지 않는 이유를 어려운 전문 용어 없이 확인하고 싶다.
- 사장님으로서, 부족한 영문 정보와 채널별 수정 문안을 한 번에 만들고 싶다.
- 사장님으로서, 정보 정비 전후에 AI 노출과 정보 정확도가 어떻게 달라졌는지 비교하고 싶다.
- 관광객으로서, 유명 매장뿐 아니라 내 조건에 맞는 다양한 로컬 가게를 발견하고 싶다.

## 5. 서비스 제공 형태

### AI 노출 건강검진

- 현재 AI 추천 등장 여부와 추천 순서 확인
- AI가 설명하는 가게 정보의 정확도 확인
- AI가 참고한 출처와 경쟁 가게 비교
- 누락 원인을 조건 정보 부족·출처 부족·채널 불일치로 분류

### AI 노출 개선 패키지

- 영문 가게명·소개·메뉴·상품·가격 작성
- 영업시간·주소·결제수단·예약 방법 정리
- 영어 응대·채식·할랄·알레르기 등 관광객 조건 정보 추가
- Google Maps, 공식 홈페이지, 네이버, TripAdvisor, SNS의 수정 문안 제공
- 홈페이지가 없는 가게를 위한 AI가 읽기 쉬운 공개 영문 소개 페이지 제작

### 월간 모니터링

- 동일 질문 세트의 추천 등장률 변화 확인
- 잘못된 영업시간·주소·메뉴 정보 탐지
- 새로운 정보 누락과 채널 불일치 알림
- 월별 비교 보고서 제공

MVP에서는 위 세 상품을 소개하되, 실제 결제·구독·자동 모니터링 기능은 구현하지 않는다.

## 6. MVP 목표와 검증 범위

### MVP 목표

더미데이터 기반의 클릭 가능한 웹 서비스로 다음 가설을 확인한다.

1. 사장님이 30초 안에 한눈의 역할을 이해할 수 있는가?
2. 진단 → 원인 확인 → 정보 개선 → 전후 비교 흐름이 자연스럽게 이해되는가?
3. 사장님이 결과 보고서와 영문 정보 정비 결과를 유료 서비스로 인식할 수 있는가?

### MVP에서 검증하는 것

- 서비스 설명과 가치 제안
- 입력 폼과 진단 흐름의 사용성
- 진단 결과의 이해도
- GEO 개선안의 실용성
- 개선 전후 지표의 설득력

### MVP에서 검증하지 못하는 것

- 실제 ChatGPT·Gemini 추천 노출 개선 효과
- 외부 채널 정보 수정의 자동화 가능성
- 장기간 모니터링 정확도
- 실제 고객의 결제 전환율
- 대규모 가게 분석 성능

즉, 이번 MVP는 **서비스 개념과 사용자 경험을 검증하는 시연용 프로토타입**이며 실제 AI 노출 효과를 입증하는 제품은 아니다.

## 8. 화면 구성

### 화면 1. 랜딩 페이지

#### 헤더

- 로고: 한눈
- 메뉴: 서비스 소개 / 이용 과정 / 예시 결과 / 요금 안내
- 주요 버튼: 무료 진단 체험

#### 히어로 영역

- 제목: **AI 추천에서 우리 가게가 보이는지 확인하세요**
- 설명: 한눈은 AI가 우리 가게를 어떻게 소개하는지 진단하고, 추천에 필요한 정보를 정비한 뒤 개선 전후를 비교해 줍니다.
- 버튼: 무료 진단 체험
- 보조 문구: 시연용 가상 데이터로 체험할 수 있습니다.

#### 문제 제시 영역

- 관광객은 AI에게 지역과 조건을 말하고 장소를 추천받는다.
- 온라인 정보가 부족한 가게는 실제로 좋은 가게여도 답변에서 빠질 수 있다.
- 사장님은 AI가 가게를 어떻게 설명하는지 직접 확인하기 어렵다.

#### 3단계 서비스 영역

1. **진단**: 실제 관광객형 질문으로 현재 추천 상태 확인
2. **정비**: 영문·가격·이용 정보와 AI가 읽을 수 있는 소개 페이지 제작
3. **측정**: 같은 질문으로 다시 확인하고 개선 전후 비교

#### 예시 결과 영역

- 추천 등장률 변화
- 평균 추천 순서 변화
- 정보 정확도 변화
- 조건 반영률 변화
- 모든 수치에 `시연용 가상 데이터` 배지 표시

#### 서비스 상품 영역

- AI 노출 건강검진
- AI 노출 개선 패키지
- 월간 모니터링
- MVP에서는 가격 대신 `상담 신청` 또는 `출시 알림 받기` 버튼 사용

#### 신뢰와 윤리 안내

- 특정 순위나 추천 노출을 보장하지 않는다.
- 가짜 리뷰와 숨은 광고를 사용하지 않는다.
- 사실에 기반한 정보 정비와 반복 측정으로 노출 가능성을 높인다.

### 화면 2. 가게 정보 입력

필수 입력:

- 가게명
- 업종
- 지역
- Google Maps 또는 공식 홈페이지 링크

선택 입력:

- 네이버 지도 링크
- Instagram 링크
- 메뉴판 이미지

MVP에서는 입력값을 서버에 영구 저장하지 않고, 시연 화면 전환에만 사용한다.

### 화면 3. 분석 진행

- `가게 기본 정보를 확인하고 있습니다.`
- `관광객형 질문에서 추천 여부를 확인하고 있습니다.`
- `채널별 정보 일치 여부를 점검하고 있습니다.`
- 2~3초 후 더미 결과 화면으로 이동
- 실제 외부 AI API를 호출하지 않았음을 화면 하단에 명시

### 화면 4. AI 노출 진단 보고서

요약 카드:

- 현재 추천 등장률
- 평균 추천 순서
- 정보 정확도
- 조건 반영률

발견된 문제:

- 영문 소개가 없음
- 메뉴와 가격이 이미지에만 있음
- 채널별 영업시간이 다름
- 해외 카드 결제 정보가 없음
- 혼밥·채식·알레르기 등 관광객 조건 정보가 없음

원인 분류:

| 분류 | 의미 | 예시 |
|---|---|---|
| 조건 정보 부족 | 관광객 질문과 연결할 정보가 없음 | 혼밥 가능, 영어 메뉴, 채식 메뉴 |
| 출처 부족 | AI가 사실을 확인할 공개 근거가 적음 | 공식 영문 페이지 없음 |
| 채널 불일치 | 채널마다 정보가 다름 | 영업시간·주소 불일치 |

동일한 측정 조건을 화면에 먼저 표시한다.

- 질문 수: 20개
- 반복 횟수: 질문당 5회
- 대상 AI: ChatGPT, Gemini
- 질문 언어: 영어
- 측정 응답 수: 전후 각각 200개

비교 지표:

| 지표 | 개선 전 | 개선 후 | 의미 |
|---|---:|---:|---|
| 추천 등장률 | 9% | 26% | 전체 응답 중 가게가 추천된 비율 |
| 평균 추천 순서 | 4.2위 | 2.8위 | 추천되었을 때의 평균 등장 순서 |
| 정보 정확도 | 68% | 93% | 주소·시간·가격 등 사실 정보 일치율 |
| 조건 반영률 | 12% | 58% | 혼밥·영어 메뉴 등 질문 조건이 설명에 반영된 비율 |

모든 수치는 **실제 측정값이 아닌 시연용 가상 데이터**라고 반복해서 표시한다.

## 10. 기능 요구사항과 완료 기준

### P0: 반드시 구현

#### 랜딩 페이지

- 서비스 문제, 해결 방식, 3단계 과정, 예시 결과, 상품 구성을 한 페이지에 표시한다.
- 데스크톱과 모바일에서 주요 문구와 버튼이 잘리지 않는다.
- 모든 주요 CTA가 진단 입력 화면으로 이동한다.

완료 기준:

- 처음 보는 사용자가 서비스의 대상, 문제, 제공 결과를 랜딩 페이지에서 확인할 수 있다.
- `무료 진단 체험` 버튼이 정상 작동한다.

#### 진단 입력과 분석 진행

- 필수 항목을 검증한다.
- 잘못된 URL이나 빈 필드에는 즉시 오류 문구를 표시한다.
- 제출하면 분석 진행 상태를 보여준 뒤 더미 보고서로 이동한다.

완료 기준:

- 필수 정보가 없으면 제출되지 않는다.
- 정상 입력 시 새로고침이나 오류 없이 보고서까지 이동한다.

#### AI 노출 진단 보고서

- 네 가지 핵심 지표와 문제 목록을 표시한다.
- 각 문제를 조건 정보 부족·출처 부족·채널 불일치 중 하나로 구분한다.
- 지표와 결과가 더미데이터임을 명시한다.

완료 기준:

- 사용자가 무엇이 부족한지와 왜 AI 추천에 불리할 수 있는지를 한 화면에서 이해할 수 있다.

#### GEO 기반 정보 개선

- 관광객형 질문과 AI 답변·인용 출처를 분석했다는 흐름을 보여준다.
- 미노출 원인을 조건 정보 부족·출처 부족·채널 불일치로 분류한다.
- 질문 조건과 연결되는 영문 설명, AI가 읽기 쉬운 공개 소개 페이지, 채널별 수정 문안을 제공한다.
- 사장님 승인 후 소개 페이지 미리보기로 이동한다.

완료 기준:

- 진단 결과의 각 문제에 대응하는 개선 문안이 존재한다.
- 개선 전·후 문안을 비교할 수 있다.
- 승인 버튼을 누르면 공개 영문 소개 페이지 미리보기가 표시된다.

#### 개선 전후 비교

- 동일한 질문, 언어, AI 모델, 반복 횟수를 사용한 것으로 표현한다.
- 추천 등장률, 평균 추천 순서, 조건 반영률, 정보 정확도를 비교한다.
- 실제 결과가 아닌 시연용 수치임을 명시한다.

완료 기준:

- 네 지표의 개선 전·후 값과 산정 의미가 함께 표시된다.
- 사용자가 정비 전후에 무엇이 달라졌는지 바로 확인할 수 있다.

### P1: 시간이 허용되면 구현

- 진단 항목 상세보기 아코디언
- 영문 문안 직접 수정
- 문안 복사 버튼
- 보고서 인쇄 기능
- 모바일 카드 레이아웃 개선
- 간단한 상담 신청 폼

### P2: 후속 버전

- 실제 ChatGPT·Gemini API 연동
- 예약된 반복 측정 작업
- 계정·가게·보고서 저장
- 이메일 결과 발송
- 실제 채널 정보 수집과 변경 감지
- 결제 및 월간 구독

## 12. MVP 기술 선택

### 권장 기술 스택

| 영역 | 기술 | 선택 이유 |
|---|---|---|
| 백엔드 | Python 3.11 + Flask | 현재 프로젝트의 Flask 구조를 재사용할 수 있고 시연용 API 구현이 단순함 |
| 화면 렌더링 | Jinja2 | 별도 프론트엔드 빌드 없이 Flask에서 화면과 더미데이터를 전달할 수 있음 |
| 프론트엔드 | HTML5 + Vanilla JavaScript | MVP 상호작용에 충분하며 의존성과 개발 복잡도가 낮음 |
| 스타일 | CSS3 | 브랜드 화면, 반응형 레이아웃, 막대형 비교 차트를 직접 구현 가능 |
| 데이터 | JSON 파일 | 가상 매장과 보고서 데이터가 한 건이므로 데이터베이스가 불필요함 |
| 임시 상태 | 브라우저 메모리 또는 localStorage | 입력 내용과 현재 단계를 간단히 유지할 수 있음 |
| 테스트 | pytest + Flask test client | 페이지와 API 응답을 빠르게 자동 검증할 수 있음 |

### 이번 MVP에서 사용하지 않는 기술

- React·Vue 등 프론트엔드 프레임워크
- PostgreSQL·MySQL 등 데이터베이스
- Redis·Celery 등 작업 큐
- OpenAI·Gemini 실제 API
- 외부 지도·SNS 크롤러
- 별도 차트 라이브러리

이 선택은 실제 서비스의 최종 기술 구조가 아니라, 최소 비용으로 사용자 흐름을 검증하기 위한 결정이다.

## 13. 시스템 구조

### MVP 구조

```text
사용자 브라우저
  ├─ 랜딩 페이지
  ├─ 진단 입력·진행 화면
  ├─ 진단 보고서
  ├─ GEO 개선안
  ├─ 영문 소개 페이지
  └─ 전후 비교 화면
            │
            │ HTTP 요청
            ▼
Flask 애플리케이션
  ├─ 페이지 라우터
  ├─ 시연용 분석 API
  ├─ 승인 처리 API
  ├─ 입력값 검증
  └─ Jinja 템플릿 렌더링
            │
            ▼
data/demo_store.json
  ├─ 가상 매장 정보
  ├─ 진단 문제 목록
  ├─ 개선 문안
  └─ 전후 비교 지표
```

### 구조 원칙

- 브라우저는 화면 표시와 간단한 상호작용만 담당한다.
- Flask는 입력값을 검증하고 정해진 더미 결과를 반환한다.
- 더미데이터는 HTML에 흩어 넣지 않고 하나의 JSON 파일에서 관리한다.
- 외부 서비스와 네트워크 통신하지 않는다.
- 시연 결과를 실제 분석 결과처럼 오해하지 않도록 모든 단계에서 표시한다.

## 14. 컴포넌트 역할

### 페이지 라우터

- 랜딩, 진단, 보고서, 공개 소개 페이지를 제공한다.
- 템플릿에 필요한 데이터만 전달한다.

### Demo Analysis Service

- 입력된 가게명과 링크 형식을 확인한다.
- `demo_store.json`에서 진단 결과를 불러온다.
- 2~3초의 분석 진행 연출 후 결과를 반환한다.
- 실제 AI 호출 결과가 아니라는 상태값을 함께 제공한다.

### Improvement Service

- 진단 문제와 대응하는 개선 문안을 묶어 반환한다.
- 사용자가 수정한 영문 문안을 브라우저 세션 안에서만 유지한다.
- 승인 요청 시 공개 소개 페이지 미리보기 데이터를 만든다.

### Comparison Service

- 개선 전후 더미 지표를 반환한다.
- 측정 조건과 지표 설명을 함께 제공한다.

### Demo Data Repository

- JSON 파일을 읽어 가상 매장, 진단, 개선안, 측정값을 제공한다.
- JSON이 없거나 형식이 잘못된 경우 사용자용 오류 메시지를 반환한다.

## 18. 데이터 흐름

### 진단 흐름

1. 사용자가 가게 정보를 입력한다.
2. JavaScript가 필수 항목과 URL 형식을 1차 확인한다.
3. Flask가 같은 항목을 다시 검증한다.
4. 서버가 더미 JSON에서 진단 보고서를 읽는다.
5. `isDemo: true`와 함께 결과를 반환한다.
6. 화면이 지표, 문제 원인, 개선 버튼을 표시한다.

### 개선과 승인 흐름

1. 사용자가 진단 문제별 개선 문안을 확인한다.
2. 필요하면 영문 문안을 수정한다.
3. 승인 버튼을 누르면 수정된 문안을 서버에 전달한다.
4. MVP에서는 서버가 데이터베이스에 저장하지 않고 미리보기 URL을 반환한다.
5. 공개 영문 소개 페이지가 가상 매장 정보와 함께 표시된다.

### 전후 비교 흐름

1. 더미 JSON에서 동일 측정 조건과 전후 값을 불러온다.
2. 화면은 수치와 간단한 막대 그래프를 함께 표시한다.
3. 각 지표의 의미와 가상 데이터 안내를 표시한다.

## 19. 오류 처리와 개인정보 원칙

### 오류 처리

- 필수값 누락: 해당 입력창 아래에 구체적인 안내 표시
- URL 형식 오류: 올바른 링크 예시 제공
- JSON 로드 실패: `시연 데이터를 불러오지 못했습니다. 다시 시도해 주세요.` 표시
- API 오류: 입력값을 유지한 채 재시도 버튼 제공
- JavaScript 비활성화: 최소한 랜딩 정보는 읽을 수 있도록 서버 렌더링 유지

### 개인정보와 보안

- MVP에서는 이름, 전화번호, 이메일을 필수로 받지 않는다.
- 입력된 가게 정보는 영구 저장하지 않는다.
- 메뉴 이미지가 있더라도 서버 저장 기능은 구현하지 않는다.
- 화면에 API 키나 내부 오류 내용을 노출하지 않는다.
- 실제 상담 폼을 추가할 경우 수집 항목, 목적, 보관 기간 동의를 별도로 받아야 한다.

## 20. 비기능 요구사항

### 반응형

- 360px 모바일 화면부터 데스크톱까지 사용 가능
- 모바일에서는 지표 카드를 한 열로 배치
- 표가 좁은 화면을 넘을 경우 가로 스크롤 또는 카드형 전환

### 접근성

- 텍스트와 배경의 명도 대비 확보
- 버튼과 입력창에 키보드 포커스 표시
- 색상만으로 개선 여부를 구분하지 않고 수치와 문구 병기
- 폼 입력창에 명확한 label 연결

### 성능

- 첫 화면의 불필요한 대형 이미지와 외부 라이브러리 사용 최소화
- 로컬 기준 주요 페이지를 2초 이내 표시
- 더미 분석 연출을 제외한 API 응답은 500ms 이내를 목표로 함

### 브라우저

- 최신 Chrome과 Edge에서 핵심 흐름 검증
- 모바일 화면은 Chrome 개발자 도구의 360px·390px 기준 검증

## 22. 테스트 계획

### 자동 테스트

- `/`, `/demo`, `/store/demo`이 200 응답을 반환한다.
- 정상 입력 시 `/api/demo/analyze`가 `ok: true`, `isDemo: true`를 반환한다.
- 필수값 누락과 잘못된 URL은 400 응답을 반환한다.
- `/api/demo/approve`가 미리보기 URL을 반환한다.
- 더미 JSON의 필수 키가 모두 존재한다.

### 수동 테스트

- 랜딩의 모든 CTA가 진단 화면으로 연결된다.
- 진단 입력부터 전후 비교까지 중단 없이 진행된다.
- 브라우저 새로고침과 뒤로가기로 화면이 깨지지 않는다.
- 모바일에서 버튼과 표가 화면 밖으로 잘리지 않는다.
- 모든 가상 매장과 가상 수치에 시연용 표시가 있다.
- 개발자 도구 콘솔에 오류가 없다.

### 사용자 검증

- 5명 중 4명 이상이 30초 안에 서비스 목적을 설명할 수 있다.
- 5명 중 4명 이상이 3분 안에 전체 시연 흐름을 완료한다.
- 5명 중 4명 이상이 진단과 정보 정비의 차이를 구분한다.
- 가상 데이터가 실제 측정값이라고 오해한 사용자가 없어야 한다.

## 23. MVP 구현 완료 기준

다음 조건을 모두 만족하면 MVP 구현이 완료된 것으로 본다.

- 랜딩에서 대상 고객, 문제, 해결 방식, 제공 결과가 명확히 보인다.
- 가게 정보를 입력하고 더미 분석을 실행할 수 있다.
- 진단 보고서에서 추천 누락 원인과 현재 지표를 확인할 수 있다.
- 단순 번역이 아니라 관광객 질문 조건, 외부 근거, 채널 일관성을 보완하는 GEO 개선안을 확인할 수 있다.
- 사장님 승인 후 공개 영문 소개 페이지 미리보기가 열린다.
- 동일한 측정 조건 아래 개선 전후 네 가지 지표를 비교할 수 있다.
- 모든 결과에 가상 매장·시연용 데이터 안내가 명확히 표시된다.
- 데스크톱과 모바일에서 핵심 흐름이 정상 작동한다.
- 페이지·API 핵심 자동 테스트가 통과하고 브라우저 콘솔 오류가 없다.

## 26. 실제 서비스로 확장할 때의 구조

실제 AI 연동과 반복 측정을 시작하면 다음 구조로 확장한다.

```text
웹 클라이언트
      │
      ▼
API 서버
  ├─ 인증·가게 관리
  ├─ 진단 요청 관리
  ├─ 개선 콘텐츠 관리
  └─ 보고서 조회
      │
      ├───────────────┐
      ▼               ▼
관계형 데이터베이스   작업 큐
                      │
                      ▼
                측정 워커
                  ├─ ChatGPT 어댑터
                  ├─ Gemini 어댑터
                  ├─ 답변·인용 분석
                  └─ 전후 지표 계산
                      │
                      ▼
                원본 응답 저장소
```

### 확장 시 추가 기술 후보

- 데이터베이스: PostgreSQL
- 비동기 작업: Celery + Redis 또는 클라우드 작업 큐
- 배포: Docker 기반 웹 서버
- 원본 결과 저장: 객체 저장소
- 모니터링: 오류 추적과 작업 성공률 대시보드
- AI 연동: 공급자별 어댑터 구조로 ChatGPT·Gemini 분리

### 실제 측정 설계 원칙

- 질문 세트, 언어, 모델, 날짜, 반복 횟수를 저장한다.
- 각 답변의 추천 가게, 추천 순서, 인용 URL, 사실 오류를 원본과 함께 보관한다.
- 모델별 결과를 섞지 않고 각각 표시한다.
- 전후 비교 시 가능한 한 같은 조건을 유지한다.
- 공급자 정책과 이용약관을 확인한 방식으로만 데이터를 수집한다.

## 27. 기술 선택의 장단점

### Flask + Jinja

- 장점: 현재 프로젝트 재사용, 빠른 구현, 단순한 배포
- 단점: 화면 상호작용이 복잡해지면 프론트엔드 코드 관리가 어려워짐

### JSON 파일

- 장점: 설치 없이 바로 시연 가능, 데이터 수정이 쉬움
- 단점: 여러 사용자 저장, 검색, 동시 수정에는 적합하지 않음

### Vanilla JavaScript

- 장점: 빌드 도구 없이 작동, MVP 규모에 충분함
- 단점: 기능이 늘어나면 상태 관리와 컴포넌트 재사용이 어려워짐

### 결론

현재 단계에서는 Flask·Jinja·Vanilla JavaScript·JSON 조합이 가장 빠르고 관리하기 쉽다. 실제 고객 데이터 저장, 외부 AI 호출, 반복 작업이 필요해지는 시점에 데이터베이스와 작업 큐를 도입하고 프론트엔드 분리를 재검토한다.
