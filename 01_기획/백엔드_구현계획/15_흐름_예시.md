# 15. 흐름도와 예시

- 여기 있는 예시 JSON은 통합 테스트의 기대값으로 그대로 쓴다(값은 예시, 형태가 정답).
- 흐름도의 "같은 트랜잭션" 표시는 06 3장 `jobs.defer` 규칙이다.

## 1. 흐름도

### 1.1 이메일 가입·인증(W-01-2)

```mermaid
sequenceDiagram
  participant B as 브라우저
  participant A as API
  participant D as PostgreSQL
  participant W as worker(email)
  participant M as SMTP
  B->>A: GET /api/auth/csrf
  A-->>B: 204 + seelo_csrf 쿠키
  B->>A: POST /api/auth/signup (X-CSRF-Token)
  A->>D: rate_limits +1, users(미인증)+auth_identities+auth_tokens(verify)
  A->>D: email_logs(secret_payload 암호문) + sendEmail 작업 (같은 트랜잭션, 커밋)
  A-->>B: 201 {email, mailTicket}
  D-->>W: NOTIFY → sendEmail
  W->>D: email_logs 읽고 토큰 복호화
  W->>M: 인증 메일
  W->>D: sent, secret_payload = NULL
  B->>A: GET /api/auth/signup/mail-status?ticket= (S03이 3초마다)
  B->>A: POST /api/auth/verify-email {token}
  A->>D: auth_tokens used_at(조건부) + users.email_verified_at + sessions
  A-->>B: 200 {user} + seelo_session·seelo_csrf 쿠키 → /home
```

### 1.2 가게 등록 → 무료 진단(W-02~W-06)

```mermaid
sequenceDiagram
  participant B as 브라우저
  participant A as API
  participant X as 지도 API(Google·카카오·네이버)
  participant D as PostgreSQL
  participant WC as worker(collect)
  participant WM as worker(measure)
  participant WO as worker(ai_openai/ai_gemini)
  B->>A: POST /api/stores/identify {name, link}
  A->>X: 짧은 링크 Location만 / 기준 지도 검색 / 다른 두 지도 검색 (10초 안)
  A->>D: stores + store_sources + measurement_runs(queued) + collectStore 작업 (커밋)
  A-->>B: 200 confirmed {storeId, runId} → /runs/{runId}
  loop 3초마다
    B->>A: GET /api/runs/{runId}/progress
  end
  WC->>X: Places 상세(ko·en), 웹사이트(robots→본문), AI 웹 검색 2회
  WC->>D: source_snapshots(google·website·instagram), web_evidence, 가게 measuring + generateQuestions
  WM->>D: question_sets+questions, runMeasurement 등록
  WM->>D: ai_executions 60행 + callAi 60개(공급자 큐)
  WO->>WO: 질문 문장만 보내고 웹 검색 켬(60초, 최대 3번)
  WO->>D: 측정 행 UPDATE(잠금) → ai_responses + extractRecommendations
  WM->>D: 추천 저장 → 측정 행 잠금 → maybe_finalize → finalizeRun

```

### 1.3 자동 정비(W-08·W-09, `AUTO_FIX_ENABLED=true`)

```mermaid
sequenceDiagram
  participant O as 사장님
  participant A as API
  participant AD as 관리자(A01)
  participant D as PostgreSQL
  participant WF as worker(fix)
  participant WP as worker(plan)
  participant G as Google·카카오 관리 화면
  O->>A: POST /api/fix/requests
  A->>D: fix_requests(requested) + 관리자 메일
  AD->>A: POST /api/admin/fix-requests/{id}/approve
  A->>D: approved→connecting, map_connections 2행, 메일 fix_decided
  O->>G: seelo 계정 초대(관리자·운영자)
  O->>A: POST /api/fix/connect/google/invited
  AD->>G: 초대 수락(사람)
  AD->>A: POST /api/admin/connections/{id}/verify
  A->>D: verifyConnection 작업
  WF->>G: 가게·편집 화면 확인
  WF->>D: connected + fix_plans(generating) + readCurrentValues + 메일
  WF->>G: 지금 값 읽기
  WF->>D: fix_plan_items(current_value) + generateFixPlan
  WP->>WP: 정비안 단계 판정 → 사실 목록 → LLM 글 → 사실 검사 → 글자 수
  WP->>D: awaiting_approval + 메일 fix_plan_ready
  O->>A: POST /api/fix/plans/{id}/approve
  A->>D: 칸 승인 값, 정비안 approved(조건부), connecting→fixing, fix_logs(queued), applyFix
  loop 칸마다
    WF->>G: 지금 값 읽기
    WF->>D: before_value 커밋
    WF->>G: 승인 값 쓰기 → 다시 읽기
    WF->>D: applied 또는 pending_reflection + finalizeFix
  end
  WF->>D: 모든 칸 끝 → remeasure_scheduled, 예약(+14일), 메일 fix_completed
```

```http
{"email": "owner@example.com", "password": "abc", "passwordConfirm": "abd", "agreeTerms": true, "agreePrivacy": false}
```

```json
422
{"error": {"code": "VALIDATION_ERROR", "message": "입력값을 확인해 주세요",
```

## 4. 실패 상황별 처리 한눈표

| 상황 | 어디서 | 상태 변화 | 사용자에게 | 관리자에게 |
|---|---|---|---|---|
| 짧은 링크 4번째 이동 | identify | 저장 없음 | 422 `LINK_UNRESOLVED` | — |
| 지도 API 5xx·10초 초과 | identify | 저장 없음 | 503 `TRY_LATER` | Sentry 경고 |
| Google 상세 2번 실패 | collectStore | 스냅샷 failed, 계속 | S10 표에서 Google 열 비움 | 로그 |
| 지역 못 얻음 | collectStore | 측정 failed(collect_insufficient), 가게 measure_failed | S07 측정 실패, 메일 | — |
| 비용 상한 | runMeasurement | waiting_reason, 30분 뒤 재등록 | S10 대기 문구 | 로그 |
| AI 400(설정 오류) | callAi | 실행 failed(bad_request) | — | Sentry |
| 실패율 31% | finalizeRun | 측정 failed, 가게 measure_failed | S07 측정 실패(차감 없음), 메일 | — |
| 워커 강제 종료 | — | 작업 doing으로 남음 | 진행률 멈춤 | `retryStalledJobs`가 다시 실행 |
| 작업이 사라짐 | — | 30분 뒤 측정 failed(stuck) | S07 측정 실패 | 로그 |
| 정비안 LLM 2번 실패 | generateFixPlan | generation_failed | S07 정비안 준비 중 | A01 실패 필터 |
| 로그인 화면 나옴 | applyFix | 남은 칸 manual_required | S13 "seelo 팀 처리 중" | 메일 + 다시 로그인 필요 |
| 저장 버튼 시간 초과 2번 | applyFix | 그 칸 manual_required, 다음 칸 계속 | 같음 | 메일 |
| 사장님이 권한 회수 | 아무 fix 작업 | 연결 revoked, 남은 칸 disconnected | S07 "연결이 끊겼어요" | — |
| 24시간 반영 안 됨 | recheckPendingFixes | manual_required(not_reflected_24h) | S13 "seelo 팀 처리 중" | 메일 |
| 재측정 실패율 31% | finalizeRun | 신청 remeasure_failed | S07 재측정 실패 | — |
| 보고서 2번 실패 | generateComparisonReport | 보고서 generation_failed | S07 재측정 중 유지 | A01 실패 필터 |
| 메일 4번 실패 | sendEmail | email_logs failed | (S03이면 다시 보내기 안내) | 로그 |
