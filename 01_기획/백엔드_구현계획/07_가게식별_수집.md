## 1. 정규화 함수(`domain/normalize.py`)

| 함수 | 규칙 |
|---|---|
| `normalize_name(s)` | ① 유니코드 NFKC ② 괄호와 그 안 내용 삭제(`\([^)]*\)`, `\[[^\]]*\]`) ③ 지점 표기 삭제: 공백으로 나눈 마지막 토큰이 `점`으로 끝나고 2자 이상이면 그 토큰 삭제(예: "명동교자 명동본점" → "명동교자"), 남은 문자열 끝의 `본점`·`직영점` 삭제, 영문 끝의 `main branch`·`branch`·`<단어> branch`·`<단어> store` 삭제(대소문자 무시) ④ `casefold()` ⑤ 한글·영문·숫자 말고 모두 삭제(공백·기호 포함). 결과가 빈 문자열이면 ⑤만 적용한 값을 쓴다 |
| `normalize_phone(s)` | 숫자만 남김. `+82`로 시작하면 `0`으로 바꿈(`+82 2-123-4567` → `021234567`) |
| `normalize_address(s)` | 도로명 주소에서 (도로명, 건물번호) 튜플을 뽑는다: 정규식 `([가-힣A-Za-z0-9]+(?:로|길))\s*(\d+(?:-\d+)?)`. 못 뽑으면 `None`(비교하지 않음) |
| `domain_of(url)` | 소문자 host, 앞의 `www.` 삭제 |
| `map_kind(domain, url)` | `google.com/maps`·`maps.google.com`·`goo.gl`·`maps.app.goo.gl` → `google_maps`, `map.kakao.com`·`place.map.kakao.com`·`kko.to` → `kakao_map`, `map.naver.com`·`m.place.naver.com`·`naver.me` → `naver_map`, 그 밖 `None` |
| `name_similarity(a, b)` | 정규화한 두 이름의 `rapidfuzz.fuzz.ratio`. 한쪽이 다른 쪽을 포함하고 짧은 쪽이 2자 이상이면 100 |
| `same_name(a, b)` | `name_similarity >= NAME_SIMILARITY_THRESHOLD`(D-11, 기본 85) |

단위 테스트(W-05-2·W-02-3): 대소문자, 공백, 기호, 지점명(한글·영문), 괄호, 한영 혼합 각 3개 이상.

### 2.3 짧은 링크 따라가기(`integrations/http.py`의 `resolve_short_link`)

- **리디렉션을 자동으로 따라가지 않는다.** `httpx.AsyncClient(follow_redirects=False, timeout=5)`.
- 최대 3번: `HEAD` 요청 → 3xx면 `Location`(상대 주소는 `urljoin`)으로 바꾼다. `HEAD`가 405·400이면 같은 주소에 `GET`을 `stream`으로 보내 상태·헤더만 보고 본문은 읽지 않고 닫는다.
- 바뀐 주소를 `classify()`해 긴 링크면 끝. 3번 넘거나, 3xx가 아닌 응답이거나, 5초 넘으면 `LINK_UNRESOLVED`.
- `Location`이 `consent.google.com`이면 쿼리 `continue` 값을 다음 주소로 쓴다 `[확인 필요]`.
- **지도·짧은 링크 호스트(`map_kind`가 아는 곳)와 `consent.google.com`이 아닌 `Location`은 따라가지 않는다**(내부 주소로 유도하는 요청 방지, 2026-10-27 구현 때 추가). 그런 경우 `LINK_UNRESOLVED`.
- 구현: `HttpShortLinkResolver.resolve(link) -> LinkInfo`를 `Clients.short_links`로 둔다(가짜 모드는 `FakeShortLinks`, 17 1장). 테스트는 `httpx.MockTransport`로 체인을 기록한다(`unit/test_links.py`).

## 3. 가게 찾기(`services/identify_service.py`, W-02-3·4)

`POST /api/stores/identify` 전체를 `asyncio.timeout(10)`으로 감싼다. 넘거나 외부 API가 5xx·429·연결 오류면 503 `TRY_LATER`이고 아무것도 저장하지 않는다. 이 단계의 외부 호출은 재시도하지 않는다.

### 3.1 순서

1. 입력 검증(이름 1~50자), 요청 제한(`identify:{userId}` 분당 10).
2. `mode`·기존 가게 확인: 보관 중이 아닌 가게가 있으면 `can_change_store` 아니면 409 `FIX_IN_PROGRESS`. 있는데 `confirmReplace=false`면 409 `CONFIRM_REPLACE_REQUIRED`(`usedFree`).
3. 링크 판별(2장). 짧은 링크면 따라간다.
4. 기준 지도에서 찾기(3.2) → 확정 1곳 / 후보 여러 곳 / 없음.
   - 없음 → 422 `STORE_NOT_FOUND`.
   - 후보 → `identify_sessions` 저장(3.4), 200 `candidates`.
5. 확정되면 업종 판정(5장). 대상이 아니면 422 `NOT_TARGET_CATEGORY`.
6. 다른 두 지도에서 같은 가게 찾기(3.3, 동시에).
7. 03 E1 처리(가게·출처·측정 저장, 기존 가게 보관, `collectStore` 등록). 200 `confirmed`.

### 3.2 기준 지도에서 찾기

| 지도 | 방법 | 확정 | 후보 | 없음 |
|---|---|---|---|---|
| Google, `place_id` 있음 | Place Details(최소 필드) | 응답이 있으면 | — | 404 |
| Google, 이름·좌표 | Text Search(`textQuery` = 링크의 이름, 없으면 사장님 입력 이름. 좌표가 있으면 `locationBias` 반경 200m) → 좌표가 있으면 200m 안의 결과만 → `same_name(결과 이름, 링크 이름 또는 입력 이름)`인 결과 | 1개 | 2개 이상(최대 5) | 0개 |
| 카카오 | 키워드 검색(`query` = 사장님 입력 이름, `size=15`, `page` 1~3, `meta.is_end`면 멈춤) | `id == external_id`인 결과 | 같은 id가 없으면 `same_name`인 결과(최대 5) | 둘 다 없음 |
| 네이버 | 지역 검색(`query` = 사장님 입력 이름, `display=5`) | `normalize_name(title) == normalize_name(입력 이름)`인 결과가 정확히 1개 | 그런 결과가 2개 이상이면 그것들, 0개면 `same_name`인 결과 | 둘 다 없음 |

- 네이버 API는 장소 번호를 주지 않으므로 링크의 번호와 대조하지 않는다. 링크의 번호는 `store_sources.external_id`에만 둔다.
- 구현 메모(2026-10-27): Google 이름 비교는 링크 이름과 입력 이름 **둘 다** 본다(하나라도 같으면 같은 이름). 카카오는 id 일치를 찾으면 그 쪽에서 멈춘다.
- `stores.input_url`과 `identify_sessions.input_url`에는 판별에 쓴 링크(짧은 링크면 따라간 긴 링크)를 둔다. 후보 선택 때 링크를 다시 따라가지 않으려고.

### 3.3 다른 지도에서 같은 가게 찾기

- 기준 좌표: 확정한 결과의 좌표(Google `location`, 카카오 `y`·`x`, 네이버 `mapy`·`mapx`를 07 4.3 규칙으로 바꾼 값).
- 검색 이름: 확정한 결과의 이름. 결과가 없으면 사장님 입력 이름으로 한 번 더.
- 지도별 호출(각 5초, 동시에)
  - Google: Text Search, `locationBias` 반경 200m.
  - 카카오: 키워드 검색, `x`, `y`, `radius=200`, `sort=distance`.
  - 네이버: 지역 검색 `display=5`.
- 판정: `haversine(기준, 결과) <= 100m` **그리고** `same_name`. 여러 개면 유사도가 높은 것, 같으면 가까운 것 하나.
- 구현 메모: "결과가 없으면"은 같은 가게를 **못 찾았으면**으로 구현했다(입력 이름이 확정 이름과 정규화해 다를 때만 한 번 더). 지도별 5초는 `asyncio.timeout`으로 따로 끊는다. 오류·시간 초과가 나면 다시 검색하지 않고 바로 not_found.
- 찾음 → `store_sources`(found, external_id, url). 못 찾음·오류 → `store_sources`(not_found). 오류는 로그만 남기고 계속한다.
- 저장할 수 있는 값: Google `id`·`googleMapsUri`, 카카오 `id`·`place_url`, 네이버는 링크(입력 링크가 네이버면 그 링크와 번호, 아니면 `url = NULL`).

### 3.4 후보(S09)

- `identify_sessions.candidates`에는 `[{candidateId, provider, externalId, fingerprint}]`만 저장한다(02의 DDL 주석은 `url`이라고 적었지만 이 형식이 맞다. `fingerprint`는 네이버만, 나머지는 null).
  - Google: `candidateId = "google:" + place id`, `externalId = place id`.
  - 카카오: `candidateId = "kakao:" + id`, `externalId = id`.
  - 네이버: `candidateId = "naver:" + 순번`, `externalId = NULL`, `fingerprint = sha256(normalize_name(title) + "|" + roadAddress)`.
- 응답의 `candidateToken`은 `new_token()` 원문, DB에는 `token_hash`.
- `POST /api/stores/identify/select`: 토큰으로 세션 조회(만료면 410 `CANDIDATE_EXPIRED`) → 고른 후보를 다시 불러온다(Google: Place Details / 카카오: 같은 검색에서 id 일치 / 네이버: 같은 검색에서 fingerprint 일치, 없으면 410) → 3.1의 5번부터 진행 → 세션 삭제.
- 응답의 후보 표시값(이름·주소·업종)은 그때 불러온 값으로 만들고 저장하지 않는다.

## 4. 외부 API 어댑터

모든 어댑터는 `integrations/`에 두고, 반환값은 아래 데이터클래스로 통일한다. 원본 JSON은 `raw`에 담아 Google·웹사이트만 저장에 쓴다.

```python
@dataclass
class Place:
    provider: str            # google|kakao|naver
    external_id: str | None
    name: str
    address: str | None      # 도로명 우선
    lat: float | None
    lng: float | None
    phone: str | None
    category_raw: list[str]  # google types, kakao [category_group_code, category_name], naver [category]
    url: str | None
    raw: dict
```

### 4.1 Google Places API(New)(2026-10-23 공식 문서로 확인)

공통
- 키 헤더 `X-Goog-Api-Key`, 필드 마스크 헤더 `X-Goog-FieldMask`. **필드 마스크는 필수**(없으면 오류)이고 **공백을 넣으면 안 된다**(쉼표로만 잇는다).
- `languageCode` 기본값은 `en`이므로 항상 명시한다. `regionCode`는 기본값이 없으므로 `KR`을 명시한다.

Text Search: `POST https://places.googleapis.com/v1/places:searchText`
- 필드 마스크(`GOOGLE_SEARCH_FIELDS`, 각 이름 앞에 `places.`): `places.id,places.displayName,places.formattedAddress,places.location,places.types,places.primaryType,places.googleMapsUri`
- 본문: `{"textQuery": q, "languageCode": "ko", "regionCode": "KR", "pageSize": 5, "locationBias": {"circle": {"center": {"latitude": lat, "longitude": lng}, "radius": 200.0}}}`
  - `pageSize`는 1~20(`maxResultCount`는 폐지 예정이라 쓰지 않음). 좌표가 없으면 `locationBias`를 뺀다.
  - `locationBias`의 원 반경은 0~50000m. `locationRestriction`은 사각형만 되고 `locationBias`와 함께 못 쓰므로 쓰지 않는다(거리 거르기는 코드에서 한다).
- 응답: `{"places": [Place...]}`.

Place Details: `GET https://places.googleapis.com/v1/places/{placeId}?languageCode=ko&regionCode=KR`
- 필드 이름은 공식 문서 기준이다. 요금 등급(SKU)은 요청한 필드 중 가장 비싼 등급으로 매겨진다.

| 등급 | 쓰는 필드 |
|---|---|
| Essentials | `addressComponents`, `formattedAddress`, `location`, `types`, `photos`(IDs Only) |
| Pro | `displayName`, `primaryType`, `primaryTypeDisplayName`, `googleMapsUri`, `businessStatus`, `accessibilityOptions` |
| Enterprise | `nationalPhoneNumber`, `internationalPhoneNumber`, `websiteUri`, `regularOpeningHours`, `priceLevel`, `priceRange`, `rating`, `userRatingCount` |
| Enterprise + Atmosphere | `editorialSummary`, `reviews`, `dineIn`, `takeout`, `delivery`, `reservable`, `paymentOptions`, `servesVegetarianFood`, `servesBreakfast`, `servesLunch`, `servesDinner`, `servesBeer`, `servesWine`, `servesCocktails`, `servesCoffee`, `servesDessert`, `goodForChildren`, `goodForGroups`, `outdoorSeating`, `allowsDogs`, `restroom`, `parkingOptions` |

- 수집용 한국어 호출(`GOOGLE_DETAIL_FIELDS`): 위 표의 필드 전부(최고 등급 Enterprise + Atmosphere로 과금).
- 영문 호출: 같은 주소에 `languageCode=en`, 필드 `displayName,addressComponents`만(Pro 등급). 영문 소개는 판정에 쓰지 않으므로 Atmosphere 필드를 넣지 않는다.
- 가게 식별·후보 확인용 호출(`GOOGLE_IDENTIFY_FIELDS`): `id,displayName,formattedAddress,location,types,primaryType,googleMapsUri`(Pro).
- 주변 가게 사실 조회(08 6.6): Enterprise·Atmosphere 필드가 필요하므로 주변 가게 5곳 × 1회가 측정 1건마다 더 든다. 비용이 크면 이 조회를 끄는 설정 `COMPETITOR_FACTS_ENABLED`(기본 true)를 둔다.
- 오류: 404 → 없음, 그 밖 4xx·5xx·시간 초과 → 오류.

### 4.2 카카오 로컬 API(2026-10-23 공식 문서로 확인)

- `GET https://dapi.kakao.com/v2/local/search/keyword.json`
- 헤더: `Authorization: KakaoAK {KAKAO_REST_API_KEY}`
- 파라미터: `query`(필수), `category_group_code`, `x`(경도), `y`(위도), `radius`(0~20000m), `rect`, `page`(1~45, 기본 1), `size`(1~15, 기본 15), `sort`(`accuracy` 기본, `distance`는 `x`·`y`가 있어야 함).
- 응답 `meta`: `total_count`, `pageable_count`(최대 45), `is_end`, `same_name`. `documents[]`: `id`, `place_name`, `category_name`("음식점 > 한식 > ..."), `category_group_code`(FD6 음식점, CE7 카페), `category_group_name`, `phone`, `address_name`, `road_address_name`, `x`(경도, 문자열), `y`(위도, 문자열), `place_url`, `distance`(x·y를 준 경우, 미터 문자열).
- 가게 찾기에서 `category_group_code`로 거르지 않는다(바는 FD6 아래에 있고, 대상 업종 판정은 5장에서 따로 한다).
- **저장 금지**: `id`·`place_url` 말고는 DB·작업 인자·스냅샷에 넣지 않는다. 화면 표시·비교 때마다 다시 부른다.
- 다시 부르기(`refetch_kakao(store)`): `query`를 사장님 입력 이름 → Google `displayName` 순으로 바꿔 가며 키워드 검색(가능하면 Google 좌표로 `x`·`y`·`radius=200`), `id == external_id`인 문서를 찾는다. 못 찾으면 `None`(화면에 "불러오지 못함").

### 4.3 NAVER API HUB 지역 검색(2026-10-23 네이버 클라우드 API 문서로 확인)

- `GET https://naverapihub.apigw.ntruss.com/search/v1/local`(기존 개발자센터 `openapi.naver.com/v1/search/local.json`은 쓰지 않는다. 신규 키 발급이 끝났고 HUB 키로 옛 주소를 부르면 401이 난다는 보고가 있다)

- 오류 코드: 400 `SE01`(잘못된 요청)·`SE02`(display)·`SE03`(start)·`SE04`(sort)·`SE06`(인코딩), 404 `SE05`(주소 오류), 500 `SE99`. 400·404는 설정·코드 오류로 Sentry에 보낸다.
- 호출 한도: 검색 API 하루 25,000건(문서 기준). 가게 1곳 등록에 1~3번, 화면 표시마다 1번 쓴다.
- **AI 입력 금지**: 네이버 응답 값은 OpenAI·Gemini 요청 본문에 넣지 않는다. 테스트로 확인한다(요청 본문에 네이버 fixture의 `title`·`telephone`·`roadAddress` 문자열이 없음).
- 저장: 입력 링크와 장소 번호만. 응답 내용은 저장하지 않고 필요할 때 다시 부른다. 예외: `link`로 찾은 공식 웹사이트 주소는 웹사이트 출처로 저장한다(6.3, 2026-10-27 확정).
- 다시 부르기(`refetch_naver(store)`): 사장님 입력 이름으로 검색 → Google·카카오 좌표 기준 100m 안이고 `same_name`인 결과.

### 6.3 공식 웹사이트(W-03-3)

1. 주소: Google `websiteUri`. 없으면 네이버 다시 부르기(4.3) 결과의 `link`. 둘 다 없으면 스냅샷 `skipped`.
2. 주소 host가 `instagram.com`이면 웹사이트가 아니라 인스타그램 출처 후보로 넘기고 `skipped`.
3. `robots.txt`: `GET {scheme}://{host}/robots.txt`(5초). RFC 9309 규칙: 2xx면 `urllib.robotparser`로 해석, 4xx면 모두 허용, 5xx·시간 초과·연결 오류면 모두 금지. `can_fetch("SeeloBot", url)`이 거짓이면 스냅샷 `robots_disallowed`, **본문 요청 0번**.
4. 첫 페이지 `GET`(10초, 리디렉션 최대 3번, 리디렉션된 주소도 robots 검사). `Content-Type`이 `text/html`이 아니면 실패. 본문을 조각으로 읽다가 1MB를 넘으면 중단하고 실패.
5. 메뉴 링크: 같은 host의 `<a>` 중 글자나 `href`가 `(?i)(menu|메뉴|food|price|가격|dining)`에 맞는 첫 링크. robots 허용이면 4번과 같은 규칙으로 1개만 읽는다.
6. 본문 텍스트: selectolax로 `script`·`style`·`noscript` 제거 후 텍스트, 공백 정리, 페이지당 20,000자까지.
7. 영문 페이지 여부: `<html lang="en...">`, `hreflang="en"`, `href`가 `/en/` 또는 `/en`으로 끝남, 링크 글자 `English` 중 하나라도 있으면 true.
8. 정리(LLM, `OPENAI_CHEAP_MODEL`, `structured`): 입력은 두 페이지 텍스트. 스키마:

```python
class MenuItemOut(BaseModel):
    name: str
    price: int | None            # 원. 숫자로 적혀 있을 때만
    description: str | None

class WebsiteExtractOut(BaseModel):
    hours_text: str | None       # 원문 그대로
    hours: WeeklyHoursOut | None # 08 0.4 → 저장 때 WeeklyHours로 변환
    menu: list[MenuItemOut]
    intro: str | None
    phone: str | None
    address: str | None
```

   지시문: "주어진 텍스트에 있는 내용만 옮긴다. 없는 값은 null 또는 빈 목록. 추측 금지."
9. 저장 `payload`: `{"url", "menuUrl", "hasEnglishPage", "extract": WebsiteExtract, "fetchedAt"}`. 원문 HTML은 저장하지 않는다.

구현 메모(2026-10-27, 5단계)
- `store_sources`에 `website` 행(found + url / not_found)을 만든다(스냅샷의 `source_id`가 필요하므로). 주소가 없거나 인스타그램이면 not_found.
- **공인 주소가 아니면 요청하지 않는다**(사설·루프백·링크 로컬 IP로 풀리는 이름): 스냅샷 `failed`·`blocked_host`. 가게 정보의 `websiteUri`로 내부망을 찌르는 요청을 막는다. DNS가 요청 직전에 바뀌는 경우까지는 못 막는다(추론: 베타 범위).
- robots.txt 리디렉션은 5번까지 따라가고(각각 공인 주소 확인), 넘으면 없는 것(허용)으로 본다(RFC 9309 2.3.1.2). 본문은 500KiB까지 읽는다.
- LLM에는 **두 페이지의 텍스트만** 넣는다(주소·HTML 없음). 네이버 `link`로 찾은 사이트라도 주소 문자열은 AI에 가지 않는다.
- 정리(LLM) 실패면 스냅샷은 `ok`로 두고 `extract: null`, `extractError: <사유>`(페이지 정보 `hasEnglishPage` 등은 남긴다).
- 정리 호출 비용은 측정 `cost_usd`에 더한다(06 6장).
- **네이버로 찾은 웹사이트 주소 저장(확정, 2026-10-27)**: 1번에서 네이버 `link`로 공식 웹사이트를 찾으면, 그 주소를 웹사이트 출처의 `url`과 스냅샷 `url`로 저장한다. 그 가게 공식 웹사이트의 주소로 보며, 4.3의 "네이버 응답 내용 저장 금지"의 예외다. AI 요청에는 넣지 않는다(본문 텍스트만).

### 6.4 AI 웹 검색(W-03-4)

- 입력: 가게 이름(사장님 입력)과 주소(Google `formattedAddress`, 없으면 카카오 다시 부르기의 도로명 주소). **네이버 값은 넣지 않는다.**
- 1단계(웹 검색 답변, 공급자별 1회, 각 60초):

```text
Find publicly available information about this place.
Name: {name}
Address: {address}
Search the web and list every website that has information about this exact place.
For each website, give the URL, the site name, and the place's name, address, phone number,
opening hours, and menu items with prices exactly as stated on that site.
```

  OpenAI는 `web_answer`(웹 검색 도구), Gemini는 `web_answer`(Google 검색 그라운딩).
- 2단계(정리, `OPENAI_CHEAP_MODEL`, `structured`): 1단계 답변과 출처 목록을 넣어 아래 스키마로.

```python
class EvidenceSiteOut(BaseModel):
    url: str
    site_name: str | None
    name: str | None
    address: str | None
    phone: str | None
    hours_text: str | None
    menu: list[MenuItemOut]
    instagram_url: str | None

class WebEvidenceExtractOut(BaseModel):
    sites: list[EvidenceSiteOut]
```

- 저장 형식(`web_evidence.fields`, 코드의 `EvidenceSite`)은 `EvidenceSiteOut`과 필드가 같다(`hours`는 없음, `hours_text`만). 웹사이트 저장 형식 `WebsiteExtract`는 `WebsiteExtractOut`에서 `hours`만 `WeeklyHours`로 바꾼 것이다.

- 거르기: `same_name(site.name, 우리 가게 이름 후보)` 또는 `normalize_address(site.address) == normalize_address(우리 주소)`인 사이트만 남긴다. 둘 다 판단할 수 없으면(이름·주소 모두 null) 버린다.
- 저장: 사이트마다 `web_evidence` 1행(`fields` = 사이트 정보, `expires_at`). 두 단계 호출 비용을 측정 `cost_usd`에 더한다.
- 한쪽 공급자 실패 → 다른 쪽만 저장. 둘 다 실패 → 행 없음, 외부 사이트가 필요한 판정은 건너뛴다(08 6장).

구현 메모(2026-10-28, 7단계)
- 1단계 모델은 측정 모델(`OPENAI_MEASURE_MODEL`·`GEMINI_MEASURE_MODEL`, 웹 검색을 쓰는 모델), 2단계는 `OPENAI_CHEAP_MODEL`. 각 단계 60초지만 수집 전체 45초가 먼저 끊을 수 있다.
- 주소를 끝내 못 얻으면(Google·카카오 모두 없음) 이 가게라고 특정할 수 없어 부르지 않는다.
- 거르기 이름 후보: 사장님 입력, Google ko·en 이름, (주소를 카카오에서 얻은 경우) 카카오 `place_name`. 카카오 이름은 코드 비교에만 쓰고 AI에 보내지 않는다. 함수 `domain/matching.evidence_matches`.
- 주소(`url`)가 빈 사이트도 버린다(`site_url`이 필수). 2단계 프롬프트는 `collect_service.EVIDENCE_PROMPT` + 1단계 답변(출처 번호 넣은 원문) + 출처 주소 목록.
- 남긴 사이트의 `instagram_url`·`url`은 6.5 후보(웹사이트 링크·Google `websiteUri` 다음 순서)로 넘긴다.

### 6.5 인스타그램(W-03-5)

1. 후보 주소 모으기: 웹사이트 첫 페이지의 링크, Google `websiteUri`, `web_evidence`의 `instagramUrl`·`site_url`.
2. 프로필 주소만: `^https?://(www\.)?instagram\.com/([A-Za-z0-9._]{1,30})/?(\?.*)?$`, 사용자 이름이 `p`·`reel`·`reels`·`explore`·`stories`·`accounts`·`tv`가 아닌 것. 처음 찾은 것.
3. `store_sources` instagram(found, `external_id` = 사용자 이름, `url`). 없으면 not_found.
4. `INSTAGRAM_BUSINESS_DISCOVERY_ENABLED=true`일 때만 Business Discovery 호출 `[확인 필요: Graph API 버전]`:
   `GET https://graph.facebook.com/{버전}/{INSTAGRAM_BUSINESS_ACCOUNT_ID}?fields=business_discovery.username({username}){username,biography,website,followers_count,media_count,media.limit(10){caption,timestamp,permalink}}&access_token={INSTAGRAM_GRAPH_TOKEN}`
   성공 → 스냅샷 instagram(ok). 실패·개인 계정 → 스냅샷 failed, 계속.
5. 플래그가 꺼져 있으면 Graph API 호출 0번(테스트로 확인).

구현 메모(2026-10-28, 7단계, `integrations/instagram.py`)
- 설정(`INSTAGRAM_GRAPH_TOKEN`·`INSTAGRAM_BUSINESS_ACCOUNT_ID`·`INSTAGRAM_GRAPH_VERSION`) 중 하나라도 비면 부르지 않고 스냅샷 `failed`·`not_configured`.
- 오류는 스냅샷 `error_code`로: Graph 오류 본문의 `code`가 있으면 `graph_<code>`, 연결 오류는 예외 이름, 시간 초과는 `timeout`. 개인 계정·없는 계정의 실제 오류 코드는 PoC(17 3장)에서 확인한다 `[PoC]`.
- 토큰이 요청 주소(`access_token`)에 실리므로 httpx·httpcore 표준 로그를 WARNING부터만 남긴다(`logging.setup_logging`). 요청 주소는 우리 로그에도 남기지 않는다.
- 성공 payload는 BD 응답의 `business_discovery` 그대로. 모은 정보 표 `intro`의 인스타그램 열 = `biography`.
