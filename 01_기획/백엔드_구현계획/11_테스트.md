# 11. 테스트(명세서 10장·13장)

## 1. 구조와 실행

```text
backend/tests/
├─ conftest.py           # DB·앱·클라이언트·가짜 외부 연동·시간 고정
├─ factories.py          # make_user(), make_store(), make_run(), make_fix_request() ...
├─ fakes.py              # FakePlaces, FakeKakao, FakeNaver, FakeLlm, FakeMailer, FakeMapAdmin
├─ fixtures/
│  ├─ links/links.csv                 # 테스트 가게 20곳 × 3사 × 긴·짧은 링크 + 거부 10개
│  ├─ google/*.json  kakao/*.json  naver/*.json   # 녹화 응답
│  ├─ openai/*.json  gemini/*.json    # 측정·추출 녹화 응답
│  ├─ website/*.html  robots/*.txt
│  ├─ browser/google/*.html  browser/kakao/*.html  # 관리 화면·로그인·보안 확인 화면
│  ├─ fact_check/wrong_20.json
│  ├─ metrics/case_{1,2,3}.json       # 손 계산 지표 예시
│  └─ report/case_{1,2,3}.json        # 손 계산 전후 예시
├─ unit/                 # domain/ 순수 함수
├─ integration/          # DB + API + 작업(가짜 외부 연동)
└─ live/                 # 실제 외부 API(-m live)
```

- 실행: `uv run pytest -q`(live 제외), `uv run pytest -m live`(실제 키 필요, 테스트 가게 세트만).
- `pyproject.toml`: `[tool.pytest.ini_options] asyncio_mode = "auto"`, `markers = ["live: real external APIs"]`, `addopts = "-m 'not live'"`.

## 2. 공통 장치(`conftest.py`)

| fixture | 내용 |
|---|---|

| `fake_mailer` | `set_clients(dataclasses.replace(build_fake_clients(), mailer=FakeMailer()))`. 보낸 메일을 모으고 `fail_times`만큼 먼저 실패한다 |
| `db`(function) | 테스트마다 모든 서비스 테이블 `TRUNCATE ... RESTART IDENTITY CASCADE`(procrastinate 테이블 포함) |
| `clients` | 외부 연동 묶음(`get_clients()`)을 가짜로 바꾼다(3장) |
| `queue` | 기본은 `InMemoryConnector`로 바꾼 Procrastinate 앱. 등록된 작업 목록(`queue.jobs`)을 확인한다. 동시성 테스트는 실제 PG 커넥터 사용 |
| `run_jobs` | 인메모리 큐에 쌓인 작업을 순서대로 실제 함수로 실행하는 도우미(흐름 테스트용). `until="finalizeRun"`처럼 멈출 지점 지정 |
| `api` | `httpx.AsyncClient(transport=ASGITransport(app), base_url="http://test")`(CSRF 없음, 읽기 전용 확인용) |
| `make_client()` / `client` | 브라우저 하나 = 클라이언트 하나. 처음에 `/api/auth/csrf`를 부르고, 상태를 바꾸는 요청에 `seelo_csrf` 쿠키 값을 `X-CSRF-Token`으로 자동으로 붙인다(`tests/support.py`의 `build_client`). 작업 큐 앱을 연다 |
| `login(c, email)` 등 | `tests/support.py`: `signup`, `signup_verified`, `make_user`(DB에 바로), `mail_secret`(메일 링크 토큰 복호화), `raw_request`(쿠키 저장소 없이 정한 쿠키만), `dump_db_text`, `capture_all_logs`(DEBUG까지 가림 전 원본) |
| `maps` | 빈 가짜 지도 세계(`FakePlaces`·`FakeKakao`·`FakeNaver`·`FakeShortLinks`). 테스트가 `world`·`mapping`을 채우고 `fail_next(n, "5xx"|"timeout"|"hang")`로 오류를 흉내 낸다. 응답 만들기는 `tests/map_world.py` |
| `map_admin` | (10단계) 가짜 지도 관리 화면 `FakeMapAdmins`를 `map_admin`으로. `map_admin["google"].not_visible()`처럼 상황을 만든다 |
| `ai` | 가짜 OpenAI·Gemini(`FakeLlm`)를 `openai`·`gemini`로. `results[스키마 이름]`, `answers(prompt, n)`, `fail_next(n, 사유, only=None)`(`"hang"`은 응답 없음, `only`는 스키마 이름이나 `"web_answer"`: 수집처럼 호출이 섞일 때 그 호출에서만 실패), `calls`(보낸 프롬프트) |
| `settings_env` | 테스트 동안 설정 바꾸기: `settings_env(AI_REPEAT_COUNT="2", PRICING_FILE=...)`. 설정·비용표 캐시를 비운다 |
| (도우미) | `tests/map_world.py`의 `seed_measuring`(가게 measuring·측정 running·질문 3개), `seed_google_snapshot`. `updated_at`은 DB 트리거가 UPDATE마다 덮으므로, 과거로 돌리는 테스트는 그 문장에서만 `SET LOCAL session_replication_role = replica`. (11단계) `seed_plan_world`(진단 끝난 가게·findings·웹사이트·신청·두 지도 연결), `new_plan`(generating 정비안). 칸 사전 검사는 `unit/test_fact_check.py`에 함께 있다 |
| `web` | `FakeWebServer`(url → 상태·헤더·본문, 지연, 받은 요청 기록)를 진짜 `HttpWebsiteFetcher`에 붙이고(`fake_website`), `FakeLlm`(스키마 이름별 결과·`fail_next`·`calls`)을 `openai`로. `maps` 위에 얹는다. 가게 만들기는 `tests/map_world.py`의 `seed_store`·`g_detail` |
| `fake_oauth` | `FakeOAuth`로 바꾼다. `profiles[code] = OAuthProfile(...)`로 제공자 사용자를 정한다 |
| `frozen_time` | 시계를 어느 분의 10초에 멈춘다(`tick=False`). 분 단위 요청 제한 테스트용. 다른 경계(24시간·14일·10분)는 테스트 안에서 `time_machine.travel(now + Δ, tick=True)` |

- 시간 이동 주의: httpx 쿠키 저장소도 `Max-Age`를 시계로 판단해 만료 쿠키를 보내지 않는다. 서버가 만료 세션을 거부하는지 보려면 `raw_request`로 쿠키를 직접 싣는다.

외부 연동 주입: 서비스는 외부 어댑터를 직접 만들지 않고 `seelo.integrations.get_clients()`(FastAPI 의존성이자 작업에서 부르는 함수)로 받는다. 테스트는 `app.dependency_overrides`와 `monkeypatch`로 가짜를 넣는다.

## 3. 가짜 외부 연동(`fakes.py`)

| 가짜 | 동작 |
|---|---|
| `FakePlaces` | `fixtures/google/`의 응답을 place id·검색어로 돌려준다. `fail_next(n, kind)`로 시간 초과·5xx를 흉내 |
| `FakeKakao`, `FakeNaver` | 같은 방식. 호출 기록 `calls` |
| `FakeLlm` | 프롬프트 패턴 → 미리 정한 결과. `web_answer` 호출의 `prompt` 원문을 `calls`에 남긴다(네이버 값이 들어갔는지 검사) |
| `FakeMailer` | 보낸 메일 목록. `fail_times(n)` |
| `FakeMapAdmin` | 칸 값을 메모리에 둔 가짜 관리 화면. `block_on(field)`, `transient_on(field, times)`, `not_visible()`, `delay_reflection(field)`로 상황을 만든다. 쓰기·읽기 순서를 `events`에 남긴다 |
| 로컬 HTML 서버 | `fixtures/browser/*.html`을 `http.server`로 띄우고 Playwright로 실제 셀렉터를 시험(9장 W-09-5). (13단계 구현) PoC 전이라 `tests/browser_site.py`의 흉내 낸 화면을 Playwright route로 그린다(포트·네트워크 없음). 브라우저는 따로 스레드의 이벤트 루프에서 돈다(Windows 테스트 루프는 subprocess 불가). Playwright가 없으면 건너뛴다(`uv sync --group browser` + `playwright install chromium`) |

## 5. 인수 테스트(명세서 10장 → `integration/test_acceptance.py`)

### 5.1 정상 흐름(가짜 외부 연동으로 처음부터 끝까지 한 테스트)

1. 이메일 가입 → 인증 → 로그인.
2. 가게 등록(Google 링크) → 카카오·네이버에서도 찾음.
3. `run_jobs`로 수집 → 질문 → 60번 호출 → 추출 → 마무리. 성공 응답 원문 60개 저장.
4. 진단 결과 API: 등장률·평균 순서·출처·주변 가게 5곳·고쳐야 할 점 개수.
5. 정비 신청 → 관리자 승인 → 메일 `fix_decided`.
6. 사장님 [초대했어요] → 관리자 [연결 확인](FakeMapAdmin) → connected → 정비안 awaiting_approval.
7. 승인 → 승인 칸만 FakeMapAdmin 값이 바뀜, `fix_logs` 고치기 전·바꾼 값·확인 시각.
8. 정비 완료 → 예약 14일 → [지금 재측정] → 같은 질문으로 재측정 → 보고서 completed → 메일.
9. 메일 10종이 모두 한 번 이상 나감(구글·카카오 가입 흐름은 별도 테스트에서).
10. 비밀번호 재설정으로 바꾼 비밀번호로 로그인.

### 5.2 실패·경계 흐름

명세서 10장 "실패·경계 흐름" 22개 항목을 각각 테스트 함수 하나로 만든다. 이름은 `test_acceptance_fail_{번호}_{요지}`. 대부분은 4장의 W-ID 테스트를 다시 부르는 얇은 테스트여도 된다.

## 6. 실제 외부 API 시험(`-m live`)

- 테스트 가게 세트(기획서 11.1)만 쓴다. 측정 시험은 그중 5곳.
- 실제 지도를 고치는 시험은 동의하고 seelo를 초대한 지인 가게에서만 수동으로 실행한다(자동 테스트에 넣지 않음).
- 결과(정확도·시간·비용)는 `03_실험/구현시험/<W-ID>.md`에 남긴다: 날짜, 가게 수, 성공·실패 수, 평균 시간, 비용(USD), 잘못 찾은 사례.
