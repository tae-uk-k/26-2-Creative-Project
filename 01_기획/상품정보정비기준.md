# 상품정보 정비 기준

기준일: 2026-11-25. 이 문서는 스마트스토어·카페24 상품의 어떤 칸을 어떻게 고치는지 정한다. 규칙 구현 위치는 `04_MVP/seelo/backend/seelo/domain/commerce.py`, 관리자 화면 입력 칸 설정은 `seelo/integrations/browser/selectors/{platform}.yaml`이다.

**원칙: 확인한 사실만 추가한다. 기존 본문·이미지·편집기 구성을 지우지 않는다. 판매 조건은 고치지 않는다.**

**AI용 정보는 화면에 보이는 사실을 기계용 형식(구조화 데이터·이미지 대체 문구·접힘 영역·메타데이터)으로 넣는다. 화면에 없는 다른 내용은 숨겨 넣지 않는다(D16 결정 전 기본값).** 확장 기법은 8절에 있다.

## 1. 플랫폼별 정비 칸

| 플랫폼 | 필드 | 이름 | 관리자 화면 자동화(기본) | API 모드 |
|---|---|---|---|---|
| 카페24 | `description` | 상세 설명 | 자동 | 자동 |
| 카페24 | `mobile_description` | 모바일 상세 설명 | 미지원(화면 입력 칸 미확인) | 자동 |
| 카페24 | `summary_description` | 요약 설명 | 자동 | 자동 |
| 카페24 | `simple_description` | 간략 설명 | 자동 | 자동 |
| 카페24 | `seo.meta_title`·`seo.meta_description`·`seo.meta_keywords` | 검색엔진 최적화 제목·설명·키워드 | 자동 | 자동 |
| 스마트스토어 | `description` | 상세설명 | 자동(기존 HTML 작성 방식 상품) | 편집기 전환 승인 시 자동, 아니면 수동 |
| 스마트스토어 | `attributes` | 상품 속성 | 수동 | 수동 |

서버는 현재 편집 모드와 화면 설정을 보고 필드를 자동·수동·미지원으로 나눠 알려 준다(`fieldSupport`). 미지원 필드는 정비안 생성·승인·저장 전에 `field_not_supported`로 거부한다. 원본을 읽지 못하는 필드는 수정 전 값을 알 수 없으므로 수동 경로로도 제공하지 않는다. 스마트스토어 상품 속성은 예외다. 관리자 화면 자동화는 속성의 수정 전 값을 읽지 않으므로 정비안의 현재 값이 비어 있을 수 있다. 운영자가 관리 화면에서 현재 값을 확인한 뒤 작업 지침대로 직접 고친다.

카페24 모바일 설명은 실제 화면 입력 칸을 확인한 뒤 설정에 추가한다(운영 현황 C-01). 스마트에디터 ONE 상품의 본문은 자동 저장하지 않는다(D9).

## 2. 기본 정비 범위

판매자가 필드를 고르지 않으면 서버가 현재 실행기의 자동 저장 필드 중에서 아래 범위를 고른다.

| 필드 | 기본 포함 조건 |
|---|---|
| 상세 설명 | 항상 |
| 요약 설명·간략 설명·SEO 설명 | 현재 값이 비어 있을 때만 |

판매자는 정비할 항목 선택에서 범위를 직접 바꿀 수 있다.

## 3. 값을 만드는 규칙

| 필드 | 만드는 값 |
|---|---|
| 상세 설명·모바일 상세 설명 | 확인한 사실을 `상품 정보` 목록 영역(`<section data-seelo="product-facts">`)으로 만든다. 기존 본문 끝에 붙이고, 같은 영역이 이미 있으면 그 영역만 바꾼다. 기존 이미지·링크·편집기 HTML은 그대로 둔다. |
| 요약 설명 | 확인한 사실을 ` · `로 이어 50자 안에서 만든다. 기존 값이 있으면 덮어쓰지 않는다. |
| 간략 설명·SEO 제목·설명·키워드 | 같은 방식으로 255자 안에서 만든다. 기존 값이 있으면 덮어쓰지 않는다. |
| 상품 속성 | 확인한 사실의 키와 값 목록을 만든다. 관리자가 화면에서 직접 고친다. |

기존 값이 있는 요약 설명·간략 설명·SEO 칸은 골라도 바뀌지 않는다. SEO 제목·키워드도 사실 목록을 이어 붙인 값이라 검색 제목·키워드 형식과 다를 수 있다. 그래서 기본 범위에 넣지 않으며, 고를 때는 승인 전에 값을 확인한다. 두 칸의 전용 작성 규칙은 아직 없다.

목록 줄은 `사실 이름: 값` 형식이다. 사실 순서는 AI가 정한 순서를 먼저 쓰고 나머지를 뒤에 붙인다. 만든 값이 현재 값과 같으면 변경으로 넣지 않는다. 바꿀 항목이 하나도 없으면 정비안은 `no_changes`다.

자료로 확인하지 않은 사양, 다른 옵션의 값, 효능·인증·후기는 넣지 않는다. 현재 구현은 FAQ·표·구조화 데이터(JSON-LD)를 만들지 않는다. 이를 넓히는 계획은 8절이다.

## 4. 고치지 않는 칸

가격·재고·옵션·배송·판매 상태·진열·구매 제한은 정비 대상이 아니다. 관리자 화면 자동화는 원본 수집 때 아래 보호 칸을 함께 읽는다. 승인 값을 입력한 뒤 저장 버튼을 누르기 직전에 보호 칸을 원본과 다시 대조하고, 하나라도 다르면 저장하지 않는다(`protected_field_changed`).

| 플랫폼 | 보호 칸 |
|---|---|
| 카페24 | 판매가, 진열 상태, 판매 상태, 재고 관리 사용, 재고 수량, 품절 표시, 구매 가능 대상·등급, 최소·최대 구매 수량 |
| 스마트스토어 | 판매가, 재고, 최소·최대 구매 수량, ID당 최대 구매 수량, 판매 기간, 판매 채널과 채널별 전시 상태, 옵션 |

## 5. 저장과 반영 판정

| 단계 | 기준 |
|---|---|
| 저장 전 | 관리 화면 주소·스토어 식별값·상품번호·상품명을 확인한다. 원본 해시가 승인 때와 다르면 `conflict`로 멈춘다. |
| 저장 | 승인한 필드만 입력한다. 전송 전에 쓰기 이력을 남기고 저장 완료 표시를 기다린다. |
| 재조회 | 관리 화면을 다시 읽어 승인 값과 같으면 `applied`, 다르면 `pending_reflection`이다. 결과를 알 수 없으면 `uncertain`이다. |
| 공개 반영 | 운영자가 공개 상세페이지의 PC·모바일 화면을 보고 기록한다. 재조회 성공을 공개 반영으로 표시하지 않는다. |

카페24 Froala 편집기는 본문 바깥·문단 사이 줄바꿈 차이만 정규화해 비교한다. 원본 해시·재조회·복구 판정에 같은 규칙을 쓴다.

카페24의 Google 연동은 요약 설명이나 SEO 값을 쓸 수 있다. 상세 설명만 고친 뒤 외부 전송 완료로 판단하지 않는다. 외부 채널의 전송 필드·수신 값은 현재 서버 계약에 없다.

## 6. 복구

복구는 고객이나 운영자가 별도 확인 뒤 실행한다. 운영자는 고객 승인 기록이 있는 정비안만 복구한다. 해당 변경에서 승인한 필드의 수정 전 값만 되돌린다. 이후 판매자나 다른 정비안이 같은 칸을 바꿨다면 충돌로 보고 중단한다. 편집기 형식 복구(스마트에디터 형식으로 되돌리기)는 이 복구와 구분한다.

## 8. GEO 확장 기법 (2026-11-28 계획)

현재 구현은 본문 끝 사실 목록 하나다. 아래 순서로 넓힌다. ID는 [GEO 기법 확장 조사](../02_조사/GEO_기법확장_HTML메타데이터_20261128.md) 3절의 기법 번호다.

### 8.1 상세 설명 영역의 새 구성

`<section data-seelo="product-facts">` 하나를 유지하고 안쪽 구성을 바꾼다. 같은 영역만 바꾸고 기존 본문은 그대로 두는 규칙은 같다.

| 순서 | 블록 | 화면 | 기법 | 상태 |
|---|---|---|---|---|
| 1 | 요약 문단: 무엇인지·용도·핵심 사양 1~2문장 | 보임 | D1 | 미구현 |
| 2 | 사양 목록 `dl`: `사실 이름`·`값`·자료 출처와 확인일 | 보임 | D2·D3 | 미구현(현재는 `ul`) |
| 3 | 사용·보관·주의 소제목 | 보임 | D4 | 미구현 |
| 4 | 자주 묻는 질문: 판매자 확인 답변만 | 보임 | D5 | 미구현 |
| 5 | 접힘 영역 `details`: 자료 원문 인용·세부 사양 | 접힘 | D6 | 저장 유지 시험 후 |
| 6 | 보조 JSON-LD: 위 사양과 같은 값의 `additionalProperty` | 안 보임 | B2 | 카페24만, 저장 유지 시험 후 |

이미지 대체 문구(E1)는 기존 이미지의 `alt`가 비었을 때만 제안한다. 이미지 속 글자를 판독한 값과 확인한 사실이 같을 때만 쓴다. 기존 `alt`는 덮어쓰지 않는다.

### 8.2 다른 칸

| 칸 | 새 규칙 | 기법 | 상태 |
|---|---|---|---|
| SEO 제목 | `상품명 + 핵심 사양 + 분류`, 60자 안 | C1 | 미구현 |
| SEO 설명 | 요약 문단과 같은 사실, 155자 안 | C1 | 미구현 |
| 간략 설명(카페24) | 요약 문단의 첫 문장. 자동 JSON-LD `description`과의 연결은 시험으로 확인 | B1·C2 | 미구현 |
| 판매자 태그(스마트스토어) | 확인 사실의 원료·형태·용도 단어 | C3 | 미구현 |

기존 값이 있는 칸을 덮어쓰지 않는 규칙은 유지한다.

### 8.3 상품 정비 밖의 작업

쇼핑몰 단위 작업은 상품 정비안에 넣지 않는다. 운영 현황 C-16에서 따로 추적한다.

| 작업 | 기법 | 플랫폼 |
|---|---|---|
| 쇼핑몰 분류·소개 정정(기본 스킨 분류 제거) | A4 | 카페24 |
| Search Console·사이트맵 | A3 | 카페24 |
| Google Merchant Center 연동 | F1 | 카페24 |
| 스킨 템플릿 JSON-LD 확장 | B3 | 카페24 |

### 8.4 쓰지 않는 기법

CSS 숨김 텍스트, AI 지시문 삽입, 검색봇 전용 내용, 화면에 없는 값의 구조화 데이터, 가짜 리뷰는 정비안에 넣지 않는다. 숨김 텍스트의 사용 여부는 사용자가 D16에서 정한다. 이유는 조사 문서 3절 H에 있다.
