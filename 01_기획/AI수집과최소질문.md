## 1. 우선 원칙

1. **있는 자료로 AI가 먼저 끝낸다.** 같은 지점의 여러 출처·기존 소개·메뉴·공식 안내·연결 후 현재 값을 찾고 읽고 대조한다.
2. **지도 칸이 비어 있는 것과 사실을 못 찾은 것을 구분한다.** 다른 자료에 값이 있으면 AI가 옮겨 정리하며 질문하지 않는다.
3. **누락 정보부터 묻는다.** 가격·단위·영업시간처럼 실제 정비에 쓸 사실 중, 끝까지 확보하지 못한 항목만 우선 후보로 둔다.
4. **값이 다르면 먼저 AI가 판단한다.** 지점·적용일·메뉴 크기·홀/배달·임시 공지 여부를 비교해 채택할 값을 정한다. 출처별 값이 다르다는 이유만으로 질문하지 않는다.
5. **필요한 정보가 많아도 질문은 늘리지 않는다.** 준비 가능한 정비부터 진행하고, 미해결 항목은 시스템이 이번 수정에서 보류한다.
6. **AI의 판단은 자료 선택·해석·구성까지다.** 근거 없는 가격·시간·판매 조건을 새로 만들지 않는다.
7. **사장님은 사실을 보완하고 마지막에 승인한다.** 문장 작성·번역·자료 비교·칸별 재입력을 사장님 업무로 넘기지 않는다.

## 2. 서비스에 필요한 정보와 질문 조건

아래는 AI가 관리할 정보 목록이다. 사장님에게 전부 입력받는 설문 목록이 아니다. ‘조건부 필수’는 그 정보를 수정·등록할 때만 필요하며, 가게 전체의 진행 조건으로 쓰지 않는다.

| 정보 | 필요한 최소 내용 | 필요 수준 | 사장님에게 묻는 조건 | 확보하지 못하면 |
|---|---|---|---|---|
| 가게 식별 | 가게명·지점, 지도 링크/장소 식별자, 위치, 업종 | 조사·정비 시작에 필수 | 링크와 주소 등을 대조해도 어느 지점인지 결정할 수 없는 경우 1회 후보 선택 | 지점이 불명확한 자료·해당 가게 정비는 보류. 다른 지점 자료로 채우지 않음 |
| 가게가 파는 것 | 음식 종류 또는 실제 메뉴명 | 새 소개 작성에 조건부 필수 | 업종만으로 음식 종류를 알 수 없고, 기존 소개·메뉴·공식 자료를 모두 찾아도 무엇을 파는지 불명확한 경우 | 정확한 기존 소개 유지. 구체적인 음식·특징을 새로 지어 쓰지 않음 |
| 메뉴·가격 | 수정할 메뉴의 이름·금액, 가격 해석에 필요한 판매 단위/크기/구성 | 해당 메뉴 등록·가격 수정에 조건부 필수 | 대상 메뉴의 가격·필요 단위를 어디에서도 확보하지 못했고, 그 메뉴를 완성하면 실제 수정이 가능할 때 | 해당 메뉴 등록·가격 수정만 보류. 다른 메뉴와 소개는 진행 |
| 영업시간 | 적용 요일과 영업 구간, 확인된 정기 휴무·휴게 구간 | 시간 수정에 조건부 필수 | 현재 적용할 영업시간 자체가 없고 관련 자료·연결 후 현재 값으로도 채울 수 없을 때 | 시간 칸 유지 또는 미입력 유지. 임의의 ‘매일 영업’·‘휴게 없음’ 생성 금지 |
| 주문·이용 필수 조건 | 최소 주문, 인원 기준, 필수 추가금, 판매 시간 등 해당 메뉴/서비스에 적용되는 조건 | 그 조건이 적용되는 수정에 조건부 필수 | 확보한 안내에 조건의 존재가 드러나지만 적용 값이 빠져, 메뉴/이용 안내를 정확히 만들 수 없을 때 | 관련 메뉴·안내만 보류. 모든 식당에 조건 유무를 일괄 질문하지 않음 |
| 연락·공식 링크 | 확인된 전화, 홈페이지·메뉴·예약·SNS의 공식 주소 | 해당 칸 수정에 조건부 필수 | 일반 질문 대상에서 제외. 여러 필수 누락값을 한 번에 해소할 공식 자료 링크 요청만 예외 | 기존 값 유지·빈칸 유지. URL·전화 추정 금지 |
| 음식 특징·조리 방식 | 원자료에 명시된 특징 중 소개에 필요한 것 | 선택 | 기본 질문에서 제외 | 확인한 음식·업종만으로 간결하게 소개 작성. 장점·스토리 입력 요구 없음 |
| 편의·방문 정보 | 주차, 포장, 예약, 외국어 메뉴, 결제 등 확보된 항목 | 선택 | 기본 질문에서 제외. 예약 필수·입장 제한 등 명시된 필수 이용 조건만 위 조건 규칙 적용 | 미확인 유지. 자료가 없다는 이유로 ‘불가’·‘없음’을 입력하지 않음 |
| 알레르기·할랄 등 | 명시된 근거와 기존 정책상 필요한 사장님 확인 | 선택적 공개 주장 | 공개할 필요와 근거가 모두 있고 사장님 확인을 선택한 경우에만 전체 질문 한도 안에서 처리 | 확인 전 해당 주장은 새 공개 값에서 제외. 필수 확인을 생략해 게시하지 않음 |
| 영문 소개·번역·태그 | 위에서 확보한 사실과 실제 지원 입력 칸 | AI 작성 | 질문하지 않음 | 확인된 사실 범위에서 작성하거나 불필요한 문구 생략 |

‘최소 메뉴 3개’, ‘편의 정보 5개’, ‘가게 장점 3개’ 같은 입력 할당량은 두지 않는다. AI는 확보한 메뉴를 가능한 만큼 정리하되, 메뉴 수를 맞추기 위해 사장님에게 추가 메뉴를 쓰게 하지 않는다. 정기 휴무와 주문 마감 시각이 자료에 없다는 이유만으로 모든 가게에 따로 묻지 않는다.

## 3. AI가 스스로 결정하는 기준

### 3.1 질문 없이 수행할 일

- 기존 자료에서 사실 추출, 명칭·금액·요일·시간 형식 통일, 같은 메뉴의 중복 병합.
- 소개에 흩어진 사실을 메뉴·시간·시설의 실제 입력 칸으로 분리하고, 원뜻을 유지한 요약·번역 작성.
- 지점·판매 채널·기간·인원·크기를 구분해 겉보기 불일치 해소.
- 동일 항목의 적용 시점이 명확한 공식 변경 공지를 반영하고, 만료된 임시 공지를 현재 값에서 제외.
- 공식 자료에 명시된 메뉴를 소개에 사용할 후보로 고르기. 선택한 메뉴를 근거 없이 ‘판매 1위’·‘가장 인기’라고 표현하지 않음.
- 충분하고 정확한 기존 값 유지, 불필요한 수정 생략, 근거 부족한 선택 항목 보류.
- 글자 수·문장·번역·형식 문제의 재작성. 스스로 해결하지 못한 편집 문제는 관리자 검토로 넘기며 사장님에게 문구를 대신 작성하게 하지 않음.

### 3.2 출처가 다를 때의 채택 순서

1. **같은 지점·같은 메뉴·같은 판매 조건인지** 확인한다. 다르면 별도 사실로 관리한다.
2. **자료의 실제 적용일과 종료일**을 확인한다. 조회한 시각·검색 순위만으로 최신성을 정하지 않는다. 미래 적용 가격을 현재 가격으로 바꾸지 않는다.
3. **그 사실을 직접 안내하는 근거**를 우선한다. 예: 해당 지점의 현재 메뉴 안내, 적용일이 명확한 공식 변경 공지, 이번에 저장한 사장님 답변.
4. 작성 주체·적용 시점·상세 조건을 함께 비교한다. 공식 홈페이지라는 이유만으로 최근의 명확한 공식 변경 공지보다 늘 우선하지 않는다.
5. 결론을 낼 수 있으면 채택값과 근거·짧은 판정 이유를 남겨 정비안에 반영한다. 사실별 재확인 질문이나 체크박스를 추가하지 않는다.
6. 결론을 낼 수 없으면 기존 공개 값을 새 추정값으로 덮어쓰지 않고 해당 변경만 보류한다. 불일치 전체를 사장님에게 고르게 하지 않는다.

별점·리뷰 빈도·인접 가게의 값·인터넷 다수결은 가격·시간·성분의 확정 근거가 아니다. 선택 정보에서 자료가 없으면 ‘미확인’이고 ‘제공하지 않음’이 아니다. 같은 글을 재전재한 여러 출처는 독립 근거 여러 개로 세지 않는다.

## 4. 누락 상태를 구분하는 법

| 내부 상태 | 뜻 | 다음 처리 |
|---|---|---|
| 대상 칸만 비어 있음 | 다른 허용 자료에 필요한 사실이 있음 | AI가 활용. 질문 0개 |
| 필수 사실 누락 | 관련 자료를 읽고 보완 탐색했으나 필요한 값 자체가 없음 | 질문 후보로 평가 |
| 자료 접근 실패 | 자료 존재는 알지만 읽지 못함 | 다른 출처·연결 후 값·재시도로 보완. 자료가 없다고 단정하지 않음 |
| 일부 판독 불가 | 메뉴판 일부 숫자·단위 등을 읽지 못함 | 읽힌 부분은 활용. 필요한 값만 후보 평가 |
| 해소한 불일치 | 적용 시점·조건으로 채택값을 결정함 | AI가 반영. 질문 0개 |
| 해소하지 못한 불일치 | 다른 값이 남고 채택 근거 부족 | 기본 보류. 아래 예외 조건을 모두 만족할 때만 최대 1문항 후보 |
| 선택 정보 누락 | 없어도 준비된 정비·방문 안내가 성립함 | 질문 없이 생략/유지 |
| 직접 관리 범위 밖 | 이번 지원 칸·계정 권한으로 수정할 수 없음 | 수정 대상에서 제외. 정보 입력을 사장님에게 요구하지 않음 |

불일치를 질문하기 위해 ‘필수 사실 누락’으로 이름만 바꾸지 않는다. 잘못된 가게 식별은 자료 수집 전 해결해야 할 예외이며 S09 후보 선택도 아래 3문항 한도에 포함한다.

## 5. 질문 후보 선정과 개수 제한

### 5.1 질문으로 올리는 공통 조건

다음 조건을 전부 만족해야 한다.

1. 이번에 실제 수정 가능한 칸이나 가게 식별에 필요한 사실이다.
2. 기존 소개·메뉴·공식 안내·연결 후 값에서 찾았고, 관련 출처 보완 탐색까지 했는데 해결되지 않았다.
3. 답변을 받으면 구체적인 수정 하나 이상이 완성되거나, 다른 지점을 잘못 고치는 것을 막을 수 있다.
4. AI의 요약·번역·기존 값 유지·선택 항목 생략만으로 처리하기 어렵다.
5. 짧은 선택·단일 값·자료 링크 하나로 답할 수 있고, 동일 사실을 이미 묻지 않았다.

### 5.2 우선순위

예외적인 지점 식별을 먼저 해결한다. 그다음에는 **필수 이용 조건 누락 → 영업시간 누락 → 수정 대상 메뉴의 가격·단위 누락 → 주력 음식 자체가 불명확한 경우** 순으로 고른다. 앞 항목이 실제로 필요하지 않으면 건너뛴다. 단순 칸 채우기보다 방문·결제의 오해를 줄이고 준비된 수정이 완성되는 질문을 앞에 둔다.

같은 우선순위에서는 답변 한 번으로 더 많은 실제 수정이 완성되고 입력 노력이 적은 것을 먼저 고른다. 최신 공식 메뉴 안내 링크 하나가 여러 메뉴의 가격·단위를 해결할 수 있으면 개별 가격 질문을 그 자료 요청 하나로 대체한다. 해당 자료가 없다고 답하면 전체 메뉴 재작성으로 전환하지 않는다.

해소하지 못한 불일치 질문은 기본 제외한다. **방문·필수 결제 조건에 직접 영향을 주고, 이번 핵심 수정을 위해 꼭 필요하며, 보완 탐색·기존 값 유지/해당 변경 보류로도 핵심 작업을 진행할 수 없는 경우**에만 전체 최대 3문항 중 1개까지 허용한다. 단순 가격 업데이트를 보류하고 다른 수정을 할 수 있으면 질문하지 않는다. 이 예외로 누락 질문을 밀어내거나 추가 문항을 만들지 않는다.

### 5.3 한도와 계산법

- 기본은 0~2문항이다. 준비 가능한 정비가 충분하면 질문 0개가 정상이다. 꼭 필요한 질문 후보가 있을 때만 세 번째 문항을 쓴다.
- **최대 3문항은 화면당 한도가 아니라 가게 한 곳·정비 신청 한 건의 누적 노출 한도다.** S09의 지점 확인, Google·카카오, 나중에 연결한 지도, 새로고침·재생성·재방문을 합산한다.
- 질문은 원칙적으로 조사와 연결 후 값 확인을 마친 뒤 한 번에 보여 준다. 사전 지점 확인을 썼으면 남은 한도는 최대 2개다.
- S09 시점에 정비 신청이 아직 없으면 같은 가게의 수집 문맥에 노출 이력을 기록하고 이후 신청으로 승계한다. 같은 가게의 신청 전 진단 재시도도 이 이력을 초기화하지 않는다.
- 1문항은 독립된 사실 하나 또는 자료 제출 한 번이다. 질문 하나에 ‘메뉴명·가격·구성·단위·영업시간’을 모두 입력하게 하지 않는다. 공통 영업 시간 구간은 한 항목으로 받되 휴무·휴게·주문 마감은 별도 결정이다.
- 여러 요일의 개별 시간표를 전부 입력하게 하거나 여러 메뉴를 행별로 채우게 하는 폼을 1문항으로 세지 않는다. 복잡한 전체 안내는 기존 자료 링크 한 번으로 받거나 보류한다.
- 5개씩 나누기, ‘추가 확인’ 팝업, 질문별 확인 체크, 답변 뒤 자동 꼬리질문으로 한도를 늘리지 않는다.
- 한 번 보여 준 질문은 나중에 자료로 해결돼 없어져도 노출 이력에 남는다. 이미 쓴 문항 수를 초기화하지 않는다.
- 필수값이 10개 비어 있어도 질문 10개를 만들지 않는다. 최대 3개를 고르고 나머지 수정은 시스템이 보류한다.
- 영문·번역문·가게 이야기·대표 메뉴 전체 목록·주차·외국어 응대 등을 기본 설문으로 추가하지 않는다.
- 권한 연결과 최종 변경 승인은 기존 필수 행위다. 이를 누락값을 우회해 추가 입력받는 설문으로 이용하지 않는다.

## 6. 사용할 질문 문구

고정 설문을 매장마다 똑같이 보여 주지 않는다. 아래는 필요한 누락이 있을 때만 선택하는 질문 후보이며, 실제 가격·메뉴를 뜻하지 않는 가상 예시다.

| 후보 | 문항 | 답변 | 사용 조건 |
|---|---|---|---|
| 자료 하나로 보완 | ‘최신 메뉴판을 볼 수 있는 링크를 하나 넣어 주세요.’ | 링크 1개 / 자료 없어요 | 여러 필요한 메뉴 사실을 해소할 가능성이 있고 직접 입력보다 부담이 작음 |
| 메뉴 가격 누락 | ‘들깨수제비 1인분 가격이 얼마인가요?’ | 금액 / 잘 모르겠어요 | 메뉴명과 1인분 단위는 이미 확인했고 금액만 없음 |
| 판매 단위 누락 | ‘온담 세트는 몇 인 기준인가요?’ | 1인 / 2인 / 기타 / 모름 | 메뉴와 금액은 확인됐고 인원 기준만 필요한 경우 |
| 공통 영업시간 누락 | ‘평일 영업시간을 알려 주세요.’ | 시작~종료 / 요일마다 달라요 / 모름 | 평일 공통 안내가 필요하고 자료에 시간 없음. 요일마다 다르면 자동 세부 질문 없이 자료 활용/보류 |
| 정기 휴무 누락 | ‘정기 휴무일이 있나요?’ | 요일 / 정기 휴무 없음 / 변동 / 모름 | 휴무가 실제 시간 안내 완성에 꼭 필요한 경우만. 모든 매장에 기본 질문하지 않음 |
| 필수 주문 조건 누락 | ‘이 메뉴는 최소 몇 인분부터 주문할 수 있나요?’ | 수량 / 모름 | 원자료에 최소 주문 조건이 있음을 확인했지만 수량만 없음 |
| 음식 정보 자체 누락 | ‘주로 판매하는 음식 하나를 알려 주세요.’ | 짧은 메뉴명 / 모름 | 소개·메뉴 자료로도 음식 종류를 특정할 수 없어 새 소개를 만들 수 없음 |

문항마다 필요한 이유는 한 줄로만 표시한다. 출처와 AI 판단 과정은 펼쳐 볼 수 있게 하고 기본 화면을 자료 비교 과제로 만들지 않는다. 보기에는 자료에 없는 ‘예상 정답’을 미리 선택해 놓지 않는다. ‘모름’과 ‘없음’을 구분한다.

메뉴판 사진 1장 제출은 자료 요청 부담을 줄이는 후속 기능으로 설계한다. 현재 베타의 업로드·보관·판독 기능이 마련되기 전에는 실제 제출 버튼이나 사진 요청 문항을 노출하지 않는다. 이미지 기능을 도입해도 재촬영·추가 페이지 요청을 자동으로 이어 붙이지 않고, 읽힌 사실만 활용한다.

## 7. 질문하지 않을 때와 미응답 처리

- 선택 정보는 비워 두고 확인된 사실만으로 정비안을 완성한다.
- 필수값이 없는 **새 변경만 자동으로 승인 대상에서 제외**한다. 기존 공개 값을 지우거나 기존 메뉴 전체를 삭제하지 않는다.
- S13은 준비된 수정과 ‘이번에 보류한 항목 N개’를 구분해 보여 준다. 사장님이 보류 항목마다 [빼기]를 누르게 하지 않는다. 상세 이유는 선택해서 볼 수 있다.
- 사장님은 질문에 답하지 않고 [준비된 내용만 확인]으로 이동할 수 있다. 보류될 수정 범위를 알린 뒤 준비된 변경만 최종 승인받는다. 무응답을 값 확인이나 승인으로 처리하지 않는다.
- 일부 답변만 저장해도 이어서 진행한다. 금액 형식 오류 등은 같은 입력 칸에서 바로 고치게 하되, 새 사실을 묻는 질문으로 확장하지 않는다. 사장님은 모름·건너뛰기로 해당 새 변경을 보류할 수 있다.
- 제출한 링크가 열리지 않거나 다른 지점 자료면 그 결과를 기록하고 다른 확보 자료로 처리한다. 자동으로 새 링크·재촬영·전체 메뉴 입력을 연달아 요구하지 않는다. 답변 뒤 새 누락이 생겨도 자동 후속 질문 없이 해당 새 변경을 보류한다.
- 자료가 부족한 메뉴를 제외해도 다른 메뉴·소개·시간 등은 진행한다. 관련 없는 부분까지 다시 작성하거나 기다리지 않는다.
- 작성 가능한 새 소개가 없으면 정상 기존 소개를 유지한다. 영어 문장을 만들기 위한 질문을 추가하지 않는다.
- 준비된 수정이 0개면 ‘이번에 적용할 수정이 없어요’와 유지·보류 이유를 보여 준다. 실제 수정이 없는데 정비 완료·반영 완료로 표시하거나 정비 후 14일 재측정을 새로 예약하지 않는다. 베타에서는 A01 검토로 넘긴다.
- 사장님이 나중에 자발적으로 수정·자료를 추가할 수는 있지만 자동 질문·필수 입력으로 유도하지 않는다. 기존 1회 정비 완료 후에는 자료 추가만으로 새 공개 수정이 실행되지 않는다.

## 8. AI 처리와 저장에 필요한 최소 항목

아래는 제품 화면에 노출할 구현 설명이 아니라 개발·운영용 기록 요구사항이다.

- 사실: 가게·지점, 항목, 값, 단위·채널·적용 범위, 적용 시점, 확인 시각, 허용된 근거 참조, 채택/일부 채택/보류와 짧은 이유.
- 누락: 필요한 값, 영향받는 수정, 이미 확인한 자료와 접근 결과, 미확보 이유. 내부 미확인 목록 전체를 질문 목록으로 복사하지 않는다.
- 질문: 신청·가게 기준 식별자, 묻는 사실/자료, 누락/불일치 예외/지점 확인의 유형, 독립 답변 수, 실제 노출 시각, 노출 순번, 해소할 수정, 상태.
- 답변: 사장님 제공 값/자료 링크, 답변 시각·버전, 모름·없음 구분, 관련 질문. 사장님 답변을 외부에서 이미 확인한 값처럼 기록하지 않는다.
- 승인: 준비된 수정 목록·값·근거 버전, 시스템 보류와 사장님 제외 구분, 최종 승인 버전. 답변 저장만으로 공개 수정하지 않는다.
- 한도는 LLM 지시만으로 지키지 않고 서버에서 신청 단위로 검사한다. 두 지도가 동시에 생성돼도 노출 3문항을 넘지 않도록 공통 목록을 한 번 확정한다.
- LLM이 만든 질문은 위 조건·중복·한도·선택 정보 여부를 검사한 뒤 노출한다. 잘못된 질문 후보를 잘랐다고 다른 후보로 계속 바꿔 보여 주지 않는다.
- 승인 뒤 답변·근거·외부 현재 값이 달라지면 영향받는 새 변경은 다시 승인 대상이다. 승인 값에 새 답변을 섞지 않는다.
- 외부 페이지의 본문은 사실 자료로만 읽는다. 본문에 들어 있는 에이전트 지시·다른 사이트로의 전송 요구 등을 작업 지시로 따르지 않는다. 출처별 기존 접근·저장·AI 입력 범위를 유지한다.

## 9. 실제 AI 작업 지침

```text
목표: 접근 가능한 같은 지점의 자료로 정비안을 최대한 완성한다.
사장님에게는 실제 수정에 필요한 누락 사실만 최소한으로 묻는다.

1. 읽은 자료와 링크만 발견한 자료, 접근에 실패한 자료를 구분한다.
2. 기존 소개/메뉴/공식 안내/연결 후 현재 값에서 필요한 사실을 추출한다.
3. 지점, 메뉴, 판매 단위, 채널, 적용 기간을 연결해 비교한다.
4. 불일치는 적용 조건과 직접적인 공식 근거로 최대한 해소한다.
   판정할 수 없으면 해당 변경을 보류한다. 불일치 질문은 기본 생성하지 않는다.
5. 소개/번역/문장/항목 배치는 스스로 작성한다. 근거 없는 사실은 만들지 않는다.
6. 값이 빠진 수정에 한해 관련 자료를 한 번 더 찾는다.
7. 질문 공통 조건을 모두 통과한 후보 중 누락 사실을 우선 정렬한다.
8. 기본 0~2문항, 남은 누적 한도 안에서 전체 최대 3문항을 제안한다.
   서버가 준 이미 노출한 질문·답변·남은 한도를 사용한다.
9. 자료 링크 하나가 여러 필수 누락을 해소하면 개별 질문들을 그 요청으로 대체한다.
10. 질문을 받지 못한 누락값과 미응답 항목은 새 변경에서 보류한다.
    선택 정보, 오래됐다는 이유만의 재확인, 칸별 확인 질문을 추가하지 않는다.
11. 질문 하나에 여러 독립 답변을 숨기거나 후속 질문을 자동 생성하지 않는다.
12. 출력: 준비된 수정, 유지할 값, 보류한 수정과 이유, 필요한 질문 0~3개,
    질문별 필요한 이유/해결할 수정/근거 참조를 구조화해 반환한다.
    출처의 값이 다른 과정을 사장님이 대신 해결해야 하는 과제로 내보내지 않는다.
```

|---|---|
| Google 메뉴 칸은 비었지만 공식 메뉴 안내에 가격·단위가 있음 | AI가 정비안 작성, 질문 0개 |
| 영문 소개가 없지만 한국어 사실 자료는 충분함 | AI가 번역·작성, 질문 0개 |
| 과거 9,000원 / 적용일이 명확한 현재 공식 가격 10,000원 | AI가 현재 값을 채택, 질문 0개 |
| 내일부터 적용할 가격만 새로 공지됨 | 오늘 값과 미래 값을 구분. 미래 값을 오늘 가격으로 반영하지 않음 |
| 홀·배달 또는 크기 차이로 가격이 다름 | 조건별 분리, 충돌 질문 0개 |
| 두 유효 출처가 다르고 다른 수정은 진행 가능 | 해당 변경 보류, 가격 비교 질문 0개 |
| 주차·외국어 응대 자료가 없음 | 기본 질문 0개. ‘주차 불가’·‘영어 불가’ 생성 없음 |
| 메뉴 가격 하나만 없고 메뉴명·단위는 확인됨 | 그 금액만 질문, 메뉴 전체 재작성 요구 없음 |
| 누락값이 많지만 최신 메뉴 안내 링크 하나로 해결 가능 | 자료 요청 1문항으로 대체, 같은 값 재질문 없음 |
| 필수 누락 후보가 10개임 | 최대 3문항, 남은 변경은 자동 보류. 페이지를 나눠 10개를 묻지 않음 |
| S09에서 이미 지점을 한 번 선택함 | 정비 단계의 추가 정보 질문은 최대 2개 |
| Google에서 2문항 노출 후 카카오 연결·정비안 재생성 | 신청 전체 남은 한도 최대 1개, 같은 사실 중복 없음 |
| 질문 하나에 메뉴명·가격·구성·단위를 함께 입력하게 함 | 다중 독립 질문으로 판정해 노출 차단. 자료 요청 또는 단일 사실 질문으로 축소 |
| 잘 모르겠어요 / 무응답 / 기간 경과 | 사실값·동의로 처리하지 않음. 준비된 수정은 따로 승인 가능 |
| 복잡한 요일별 영업시간에 ‘요일마다 달라요’ 답변 | 7일 상세 설문 자동 생성 없음. 자료 활용 또는 해당 변경 보류 |
| 새 메뉴 일부만 미확인 | 미확인 새 변경만 보류, 기존 메뉴 삭제·전체 중단 없음 |
| 알레르기·할랄 확인이 미완료임 | 해당 새 주장 제외, 다른 수정 승인 가능 |
| 자료를 다시 찾았더니 질문이 해결됨 | 질문 제거 가능, 이미 노출한 문항 이력과 사용 한도는 유지 |
| 답변 이후 다른 사실 누락이 새로 발견됨 | 자동 꼬리질문 없음, 추가 변경 보류 |
| 답변 저장 또는 자료 링크 제출 | 관련 초안만 갱신, 공개 수정은 최종 승인 뒤 실행 |
| 실제로 바꿀 값이 하나도 없음 | 허위 완료·새 재측정 예약 없음, 유지/보류 상태와 A01 검토 |

## 11. 운영 측정과 출시 기준

강제 기준은 **누적 질문 3개 초과 0건, 기본 선택 정보 질문 0건, 이미 해결된 사실 재질문 0건, 근거 없는 필수값 반영 0건, 미승인 수정 0건**이다. 운영자가 대신 연락해 같은 설문을 늘리는 방식도 허용하지 않는다.

초기 10개 가게에서 문항 수 중앙값 1개 이하·90%가 2개 이하·답변 활동 시간 중앙값 1분 이내를 목표 가설로 측정한다. 자료 링크 요청도 1문항이며, 포함된 필수 입력 칸 수·실제 조작 수를 함께 본다. 3문항 이하는 강제 한도이고 이 평균 목표들은 실측 후 조정한다.

질문 축소와 함께 준비된 수정 수·보류 수·기존 값 유지 수, 필수 누락 중 AI가 자료로 해소한 비율, 질문을 생략해 놓친 필수 조건을 확인한다. 분모는 실제 수정 후보에 필요한 누락 사실로 한정하고 수집 실패와 불일치를 따로 집계한다. 질문을 줄이기 위해 유용한 수정 전체를 보류하는 결과도 검수한다.

출시 전 위 검수 사례를 모두 만족해야 한다. 질문 유형·누적 한도·보류 구분이 없는 현재 화면/코드가 이미 이 규칙을 만족한다고 간주하지 않는다. 기존 추천 측정은 같은 질문 세트·조건을 유지하고, 사장님 보완 답변을 추천 질문의 정답으로 주입하지 않는다.


## 12. 조사 대상과 수집 범위

AI는 검색·접근 도구의 실제 응답을 근거로 정리한다. 다음 표에서 플랫폼별 조사 경로를 확인한다. 1차 수집은 기존 30초 목표를 유지하고, 필요한 누락의 보완 탐색은 별도 작업으로 둔다. 보완 탐색 3분 상한은 실측 전 초기 가설이다. 하나의 출처가 실패해도 나머지 확보 자료로 진행한다.

| 조사 대상 | 찾으려는 정보 | 베타에서 적용할 경로 |
|---|---|---|
| Google 지도 | 동일 가게, 공개 기본정보·시간·공식 링크, 연결 후 현재 입력값 | 기존 Places 조회·정비 연결 경로를 사용한다. API별 허용 용도와 저장 범위 안에서 조회·비교한다. |
| 카카오맵 | 동일 가게·기본정보, 연결 후 소개·메뉴·시간의 현재 값 | 기본정보 조회와 연결 뒤 관리 화면 읽기를 구분한다. 로컬 API가 메뉴·영업시간까지 모두 주는 것으로 가정하지 않는다. |
| 네이버 | 같은 지점과 공식 홈페이지를 찾는 단서·기본정보 비교 | 기존 F-04의 사용 제한을 유지한다. 상세 메뉴 수집이나 API 응답의 AI 입력을 자동으로 추가하지 않는다. |
| 가게 공식 홈페이지·메뉴·예약 안내 | 메뉴·가격·단위·시간·방문 조건·가게 특징 | 접근·사용 가능한 본문을 확인한다. 현재 베타의 첫 페이지·메뉴 링크 수집에서 시작하고 추가 페이지 탐색은 별도 확장한다. |
| 공식 Instagram 등 SNS | 최근 휴무·가격 변경·운영 공지, 공식 메뉴 안내 | 기존 검색 경로에서 확인 가능한 자료를 사용한다. 링크·검색 요약만으로 최신 사실을 확정하지 않는다. |
| Tripadvisor·그 밖의 채널 | 다른 출처와의 불일치, 추가 공식 안내의 위치 | 확장 후보로 둔다. 접근·사용 경로를 확인한 출처부터 활성화한다. |
| 리뷰·블로그·플랫폼 AI 요약 | 추가로 확인할 메뉴·조건·오래된 정보의 단서 | 원자료 탐색과 질문 후보에 사용한다. 가격·성분·현재 운영 조건의 확정 근거로 바로 쓰지 않는다. |

수집 채널과 수정 채널은 별개다. 베타의 실제 수정은 연결된 Google·카카오 기존 입력 칸으로 유지한다. 모든 출처의 본문을 영구 저장하거나 다른 플랫폼에 재게시하는 방식은 전제하지 않는다. 공통 사실 정리는 활용 가능한 공식 원자료·업주 제공 사실을 중심으로 하며, 제한된 출처는 허용된 식별자·링크와 필요 시 재조회로 다룬다.

## 13. 화면 연결과 실행 계획

| 단계 | 추가하는 동작 |
|---|---|
| S08·S09 가게 등록·식별 | 이름과 지도 링크로 시작하고, 같은 이름의 다른 지점이 섞이면 지점부터 확인한다. 홈페이지·SNS 링크 입력은 선택이다. |
| S10 수집·측정 | 여러 출처를 찾고 사실을 정리한다. 부족한 정보가 있어도 무료 진단은 가능한 자료로 진행한다. |
| S11 무료 결과 | 기존 결과 구성을 유지한다. 상세 보완 질문과 정비안은 정비 신청 승인·연결 후 S13에서 보여 준다. |
| S15 지도 연결 | 연결 후에야 볼 수 있는 현재 값을 추가 확인한다. 이미 확보한 값으로 질문을 해소할 수 있으면 사장님에게 묻지 않는다. |
| S13 정비안 확인 | 상단에 선정된 누락 질문만 0~3개 둔다. 답변하거나 [준비된 내용만 확인]으로 넘어가고, 시스템이 보류한 항목을 제외한 준비된 변경을 승인한다. |
| S07·S12 홈·진행 | ‘정보 확인 필요 N개’와 이어서 확인하기 버튼을 제공한다. 답변 중 나가도 저장한 지점부터 이어 간다. |

### 개발 순서

1. **필요 정보·판정 규칙 확정:** 이 문서 2절의 정보별 필수 조건을 지도별 실제 입력 칸에 연결한다. 같은 자료에 누락·불일치·접근 실패를 다르게 표시할 수 있어야 한다.
2. **AI 자료 판단 연결:** 기존 수집과 연결 후 읽은 값으로 사실을 통합하고 채택/유지/보류를 출력한다. 공식 변경 공지·미래 적용일·홀/배달·다른 지점 사례를 구분하고, 문장 작성만 필요한 경우 질문 0개를 만든다.
3. **공통 질문 선정·누적 기록:** 가게 식별 단계의 이력을 신청에 승계하고, 두 지도가 같은 질문 목록과 답변을 사용한다. 동시 생성·나중 연결·재생성에도 실제 노출 3개 초과를 서버에서 막는다.
4. **S13와 승인 처리 연결:** 0문항은 바로 정비안으로, 1~3문항은 한 번에 표시한다. 부분 답변·건너뛰기·자동 보류·준비된 수정만 승인·실행 0개 처리를 완성한다. 답변 저장과 공개 수정을 분리한다.
5. **검수 후 소규모 확인:** 운영 지침의 검수 사례를 모두 확인한 뒤 동의한 시험 가게에서 조사→보완→승인 흐름을 검증한다. 실제 쓰기는 기존 초대·승인 조건을 유지한다. 초기 10개 가게의 질문 부담과 준비된 수정/보류 비율로 기준을 조정한다.

앞 단계의 완료 조건을 충족한 뒤 다음 단계로 넘어간다. 메뉴판 업로드·신규 플랫폼 확대는 이 흐름이 먼저 검증된 뒤 붙인다. 이 순서는 개발 계획이며 이번 작업에서 코드를 구현·배포했다는 뜻이 아니다.
