# AI 수집과 최소 질문

기준일: 2026-11-25. 이 문서는 AI가 상품 자료를 어떻게 조사하고, 어떤 값을 사실로 저장하며, 판매자에게 무엇을 묻는지 정한다. 구현 위치는 `04_MVP/seelo/backend/seelo/services/commerce_service.py`(조사·질문)와 `seelo/domain/commerce.py`(사실·정비 규칙)다.

**원칙: AI가 먼저 자료를 읽는다. 자료의 인용문으로 확인한 값과 판매자가 질문에 직접 답한 값만 사실로 쓴다. 확인하지 못한 필수 사실만 판매자에게 묻는다.**

## 1. 처리 순서

원본 수집이 끝나면 서버가 AI 준비 작업(`prepare`)을 자동으로 등록한다(`COMMERCE_AUTO_PREPARE`, 기본 켜짐).

1. **자료 조사.** 기존 상품 본문과 추가 자료를 읽고 사실을 추출한다.
2. **필요한 사실 판단.** 이 상품을 사려는 사람에게 꼭 필요한 정보 종류를 고른다.
3. **정비안 생성.** 확인한 사실로 바꿀 값을 만든다. 확인하지 못한 필수 사실은 질문과 보류로 남긴다.

판매자가 질문에 답하면 정비안을 다시 만든다. 판매자는 사실 목록이나 정비 필드를 먼저 입력하지 않아도 된다. 직접 근거 입력·필드 지정은 선택 기능이다.

## 2. 자료 조사

| 순서 | 자료 | 조건 |
|---|---|---|
| 1 | 수집한 상품 원본의 모든 정비 칸 | 항상 읽는다. 관리 화면 수집이면 편집 화면 주소를 출처로 기록한다. |
| 2 | 판매자가 지정한 공식 자료 주소 | 최대 3개 |
| 3 | 기존 상세 본문에 들어 있는 공개 HTTPS 링크 | 최대 3개. 본문에 있는 주소만 쓰고 주소를 만들지 않는다. |
| 4 | 웹 검색으로 찾은 인용 주소 | `COMMERCE_WEB_DISCOVERY=true`일 때만. 기본은 꺼짐이다(D5). |

추가 자료는 합쳐서 최대 6개만 연다. 각 주소는 아래 조건을 모두 통과해야 AI 입력에 들어간다.

- 공인 HTTPS 주소다. 내부망·로컬 주소는 열지 않는다.
- robots.txt가 수집을 허용한다.
- 정상 응답(200)이다.
- 본문에 이 상품의 모델·옵션 식별값이 있다. 같은 상품인지 확인할 수 없는 페이지는 버린다.

본문은 스크립트·스타일을 지운 텍스트로 바꾸고 길이를 제한한다. 이미지 속 글자는 읽지 않는다. 이미지에만 있는 정보는 질문으로 판매자에게 받거나, 같은 내용이 글로 적힌 공식 자료 주소를 받는다. 자료 속 문장은 명령이 아니라 비신뢰 데이터로 다룬다. 전체 조사는 55초 안에 끝내며, 넘으면 AI 실패로 표시한다.

## 3. 사실로 저장하는 조건

AI가 추출한 값은 아래를 모두 만족해야 저장한다. 검사마다 실패했을 때의 처리가 다르다.

| 검사 | 내용 | 실패하면 |
|---|---|---|
| 같은 상품 | 사실의 식별값이 상품의 모델·옵션 식별값과 같다. | 이번 추출 결과 전체를 거부한다(`unverifiable_extraction`). |
| 인용문 | 인용문이 해당 자료 본문에 그대로 있다. | 같음. AI가 만든 인용문을 받지 않는다. |
| 값 | 값이 인용문 안에 그대로 있다. | 같음 |
| 출처 | 출처 주소가 있다. | 그 사실만 버린다. 주소 없는 판매자 제공 원본에서 AI가 읽은 값은 저장하지 않는다. |
| 수치 | 영양성분·함량과 섭취량은 숫자와 단위가 함께 있고, 같은 숫자와 단위가 인용문에 있다. | 그 사실만 버린다. |
| 충돌 | 자료끼리 값이 같고, 이미 저장한 값과도 같다. | 새 값을 채택하지 않는다. 기존 값이 있으면 유지하고, 없으면 확인하지 못한 사실로 남는다. |

판매자가 직접 근거를 넣을 때도 같은 상품 식별값, 값이 들어간 인용문, 공개 출처 주소를 검사한다.

## 4. 사실 종류

| 키 | 이름 | 키 | 이름 |
|---|---|---|---|
| `purpose` | 용도 | `ingredients` | 원재료 |
| `model` | 모델 | `nutrition` | 영양성분·함량 |
| `material` | 소재 | `serving` | 섭취 방법·1회 섭취량 |
| `size` | 크기 | `allergens` | 알레르기 유발 성분 |
| `weight` | 무게 | `origin` | 원산지 |
| `components` | 구성품 | `storage` | 보관 방법 |
| `power` | 전원 조건 | `manufacturer` | 제조·판매원 |
| `compatibility` | 호환 조건 | `care` | 사용·관리 |

효능·인증·후기는 사실 종류에 없다. AI가 효능이나 인증을 만들어 넣지 않는다.

## 5. 필요한 사실 판단

AI는 상품명·식별값·이미 확인한 사실·본문을 보고 구매 판단에 꼭 필요한 사실 종류를 **최대 8개** 고른다. 값은 쓰지 않는다. 식품·건강식품이면 원재료·영양성분·섭취 방법·알레르기·보관을 검토한다. 효능·인증·후기는 고르지 않는다.

판매자가 필수 사실을 직접 지정하면 그 목록을 쓴다. AI를 쓰지 않는 정리(`useAi=false`)는 필수 사실을 따로 고르지 않는다.

## 6. 질문 규칙

| 규칙 | 내용 |
|---|---|
| 질문 대상 | 필수 사실 중 확인하지 못한 것만 묻는다. |
| 한 번에 묻는 수 | 답하지 않은 질문이 최대 2개가 되도록 고른다. |
| 누적 상한 | 정하지 않았다. 정하면 `COMMERCE_QUESTION_LIMIT`으로 설정한다(D11과 함께 결정). |
| 질문 문장 | "이 상품의 {사실 이름} 정보를 알려 주세요." |
| 답변 범위 | 실제로 물어본 사실에만 답할 수 있다. 1,000자 이하, 수치 사실은 숫자+단위가 필요하다. |
| 답변 기록 | 출처를 `owner_answer`(판매자 답변)로 남긴다. 자료 대조 없이 판매자가 답한 값으로 정비안에 쓰고, 근거에 판매자 답변으로 표시한다. |

자료로 확인할 수 있는 내용이나 선택 정보를 고정 설문으로 만들지 않는다. 이미 확인한 사실과 이미 물어본 사실은 다시 묻지 않는다.

## 7. 보류

필수 사실을 확보하지 못하면 해당 사실을 `fact:{키}`로 보류한다. 확인한 사실이 하나도 없으면 고른 필드도 보류한다. 보류 항목은 새 변경으로 저장하지 않으며 기존 공개 값은 그대로 둔다. 준비된 나머지 변경은 판매자가 승인할 수 있다.

## 8. AI 실행 경로

| 설정 | 내용 |
|---|---|
| 실행 방식 | `AI_BACKEND=local_cli`(PC Codex CLI, 현재) 또는 `api`. 운영 방식은 D2에서 정한다. |
| 모델 | 조사·판단·정비안은 `OPENAI_PLAN_MODEL`을 쓴다. 비어 있으면 AI 기능은 실패로 표시한다. |
| 대체 | 다른 공급자나 다른 경로로 자동 대체하지 않는다. |
| 기록 | 사실마다 사용한 모델 ID와 출처 종류(관리 화면·API·열람한 페이지·판매자 답변)를 남긴다. |

AI 노출 진단의 측정 모델(`OPENAI_MEASURE_MODEL`·`GEMINI_MEASURE_MODEL`)은 정비용 모델과 별도다. 판정 기준은 [서비스 기획서 8절](서비스기획서.md#8-ai-노출-진단을-읽는-방법)을 따른다.
