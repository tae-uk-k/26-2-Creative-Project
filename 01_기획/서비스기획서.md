# seelo 서비스 기획서

기준일: 2026-11-09 · 대상: 기획자, 디자이너, 개발자, 프로젝트를 처음 보는 사람

**seelo는 여러 플랫폼에 흩어진 가게 정보를 정리해, AI가 가게를 정확히 이해하고 관광객의 조건에 맞춰 찾을 수 있도록 돕는 서비스다.** AI가 자료를 먼저 조사하고 정비안을 만들며, 사장님은 꼭 필요한 정보만 보완하고 바꿀 내용을 승인한다.

현재 베타에서는 Google 지도와 카카오맵을 정비한다. 정비 전후에는 ChatGPT·Gemini의 추천 결과를 같은 조건으로 측정해 비교한다. 이 문서는 만들 서비스의 기준이다. 구현·운영에서 실제로 확인한 상태는 [운영 현황](운영/운영현황.md)에서 별도로 확인한다.

## 2. 누구의 어떤 문제를 해결하는가

첫 사용자는 외국인 관광객을 받고 싶은 음식점·카페·바 사장님이다. 특히 여러 지도와 온라인 채널을 직접 관리하기 어려운 소규모 가게를 대상으로 한다.

사장님은 AI가 가게를 추천하는지 확인하기 어렵고, 소개·메뉴·가격·영업시간을 여러 곳에 맞춰 관리하는 데 시간을 써야 한다. 진단 결과나 고칠 문구만 받으면 실제 수정 작업은 여전히 사장님에게 남는다.

seelo는 자료 조사, 필요한 정보 보완, 지도 수정, 정비 전후 비교를 한 흐름으로 제공한다. 관광객에게는 음식·예산·위치·방문 조건을 판단할 수 있는 정보를 전달하고, 사장님에게는 반복적인 정보 관리 부담을 줄이는 것이 목표다.

## 3. 무엇을 제공하는가

| 제공 항목 | 사장님이 받는 내용 | 이용 조건 |
|---|---|---|
| 무료 진단 | AI별 추천 등장률과 평균 등장 순서, 주변 가게 비교, 참고 출처, 고쳐야 할 점의 개수를 보여 준다. | 계정당 한 번 제공한다. |
| 정보 정비 | AI가 조사한 사실로 정비안을 만들고, 승인받은 내용을 Google 지도·카카오맵에 반영한다. | 베타에서는 신청 후 seelo 관리자가 승인한다. 가격은 미정이며 결제를 받지 않는다. |
| 전후 비교 보고서 | 실제 정비 완료 14일 뒤 같은 질문으로 다시 측정하고 바뀐 정보와 결과를 나란히 보여 준다. | 정비 전후의 측정 조건이 같아야 한다. |

무료 진단에서는 문제의 개수까지 공개한다. 구체적으로 무엇을 어떻게 바꿀지는 정비 신청 승인과 지도 연결을 마친 뒤 정비안에서 보여 준다. 고칠 문구만 전달하는 별도 유료 보고서는 제공하지 않는다.

## 4. AI와 사장님의 역할

| 역할 | 담당하는 일 |
|---|---|
| AI | 같은 지점의 자료를 찾고 읽는다. 출처·적용일·판매 조건을 비교해 사용할 값을 결정한다. 소개·번역·정비안을 작성하고 필요한 누락 질문만 고른다. |
| 사장님 | 가게 이름과 지도 링크를 입력한다. 정비할 지도의 관리 권한을 연결하고, 필요한 누락 정보만 최소한으로 보완한 뒤 준비된 변경을 승인한다. |
| seelo 관리자 | 베타 신청과 연결을 확인한다. 자동 처리에 실패하거나 자료 판단이 어려운 항목을 검토하고 수동 처리한다. |

보완 질문은 기본 0~2개, 가게 한 곳의 정비 신청 전체에서 최대 3개로 설계한다. 여러 지도와 재생성, 사전 지점 확인을 모두 합산한다. AI가 자료로 해결할 수 있는 내용이나 주차·외국어 응대 같은 선택 정보를 고정 설문으로 만들지 않는다.

필수값을 확보하지 못한 새 변경은 시스템이 보류한다. 사장님이 보류 항목마다 제외 버튼을 누르지 않아도 준비된 다른 변경을 승인할 수 있다. 기존 공개 정보는 유지한다. 질문 선정과 예외의 정확한 기준은 [AI 수집·최소 질문](AI수집과최소질문.md)에서 관리한다.

## 5. 이용 순서

1. **가입한다.** 이메일·Google·카카오 중 하나로 가입하고 필요한 이메일 인증을 마친다.
2. **가게를 등록한다.** 이름과 Google·카카오·네이버 중 지도 링크 하나를 넣는다. AI가 다른 채널에서도 같은 지점을 찾는다.
3. **무료 진단을 본다.** 자료를 모으고 관광객의 질문에 대한 AI 추천 결과를 측정한다. 정보가 부족해도 가능한 자료로 진단을 진행한다.
4. **정비를 신청하고 지도를 연결한다.** seelo 관리자가 신청을 승인하면 사장님이 정비할 Google·카카오 계정에 seelo를 초대한다.
5. **정비안을 확인한다.** 연결 후 현재 값까지 대조해 정비안을 만든다. 꼭 필요한 누락만 짧게 묻고, 사장님이 준비된 변경을 승인한다.
6. **정보를 고치고 공개 반영을 확인한다.** 자동 처리가 막히면 seelo 관리자가 해당 항목을 처리한다.
7. **14일 뒤 결과를 비교한다.** 같은 질문과 측정 조건으로 다시 확인하고 전후 비교 보고서를 제공한다.

수정 가능한 항목이 하나도 없으면 유지·보류 이유를 보여 주고 관리자가 검토한다. 실제 수정이 없는데 정비 완료로 표시하거나 정비 후 재측정을 새로 예약하지 않는다.

## 6. 베타에서 만드는 범위

| 구분 | 이번 베타의 범위 |
|---|---|
| 계정·가게 | 이메일·소셜 가입, 로그인, 비밀번호 재설정, 탈퇴, 계정당 가게 한 곳 등록·변경을 제공한다. |
| 자료 수집 | 기존 지원 경로로 Google·카카오·네이버 기본정보와 공식 사이트·검색으로 확인 가능한 자료를 조사한다. 출처별로 실제 사용 가능한 범위를 구분한다. |
| AI 진단 | 관광객 질문을 만들고 ChatGPT·Gemini 결과를 반복 측정한다. 지표·주변 가게·출처를 보여 준다. |
| 정보 정비 | 신청 관리, 지도 연결, AI의 사실 판단, 누락 중심 최소 질문, 정비안 승인, 수정·반영 확인을 제공한다. |
| 보고서·알림 | 정비 후 재측정과 전후 비교 보고서를 제공하고 필요한 진행 상황을 화면·이메일로 알린다. |

메뉴판 사진 판독, 보고서 PDF 내려받기, 관리자 전체 조회는 후속 보완 항목이다. 사진 업로드·판독 기능이 준비되기 전에는 사진 제출을 요청하지 않는다. 실제 결제·구독, 여러 지점 관리, 월간 재측정, 영어 외 다국어는 후속 개발로 둔다.

리뷰 답변 대행·광고 집행·예약 및 주문 시스템 연동은 현재 상품에 포함하지 않는다. 리뷰는 정보 누락이나 혼동을 찾는 단서로만 사용한다. 정비는 연결된 계정의 실제 기존 입력 칸에서 진행하며, 지도 페이지의 배치나 새로운 입력 칸을 임의로 만들지 않는다.

| Tripadvisor | 후속 조사·정비 후보로 둔다. | 외국인 관광객의 식당 비교에 쓰이는 정보를 관리할 경로를 먼저 확인한다. |
| Facebook | 후속 후보로 둔다. | 매장 페이지의 실제 이용도와 권한·편집 가능 항목을 확인한다. |
| 당근·카카오톡 채널·샤오홍슈 | 가게의 실제 고객과 운영 채널에 맞춰 선택할 후속 후보로 둔다. | 국내 지역 고객·중화권 고객 등 이용 상황과 관리·등록 경로를 확인한다. |

추가 지원 상품은 Tripadvisor·Bing과 공식 경로가 확보된 네이버부터 검토한다. 병행해서 다이닝코드·식신·뽈레·테이블링의 정비 경로를 확인하고, 예약·SNS 채널은 가게의 이용 상황에 맞춰 붙인다. [플랫폼별 조사와 내부 출처 집계](../02_조사/플랫폼등록정비_대상조사.md)에서 근거·확인 상태·다음 확인 사항을 관리한다. 공통 흐름은 자료 확인 → 정비안 → 승인 → 등록·수정 → 공개 반영 확인 → 재측정으로 유지한다.

## 8. 진단 결과를 읽는 방법

추천 등장률은 정상적으로 받은 AI 답변 중 우리 가게가 추천된 답변의 비율이다. 평균 등장 순서는 우리 가게가 추천됐을 때 목록에서 몇 번째로 나왔는지의 평균이다. 오류가 난 답변은 추천되지 않은 답변으로 계산하지 않는다.

기준 측정은 관광객 질문 3개를 두 AI에 각각 10번씩 묻는 총 60회 구성이다. 질문은 영어 2개·한국어 1개이며 가게 이름을 넣지 않는다. AI별 결과를 따로 계산하고 같은 질문에서 자주 나온 주변 가게 5곳과 비교한다.

실제 전후 비교에는 같은 질문 버전·AI·반복 횟수·전송 방식을 사용한다. API와 로컬 CLI 같은 실행 경로도 기록하며 서로 다른 조건을 하나의 전후 비교로 섞지 않는다. 실제 실행 경로와 공급자 확인 상태는 [운영 현황](운영/운영현황.md), 계산과 오류 규칙은 [기능 정의](개발/기능정의.md)에서 확인한다.

## 9. 이용 중 지키는 규칙

- 무료 진단은 계정당 한 번이며 정상 완료 때만 사용 처리한다. 실패·취소는 사용 횟수에 넣지 않는다.
- 계정당 활성 가게는 한 곳이다. 가게를 바꾸면 이전 결과는 지난 기록으로 남겨 읽을 수 있다. 정비 신청부터 보고서 완료 전까지는 가게 변경을 막는다.
- 같은 가게의 정비 신청은 한 번 진행한다. 신청을 거절받은 경우에는 다시 신청할 수 있다.
- 한쪽 지도만 연결해도 그 지도부터 정비할 수 있다. 뒤늦게 연결한 지도도 같은 사실과 남은 질문 한도를 사용하되 바꿀 내용은 별도로 승인받는다.
- 사장님의 아이디·비밀번호를 받지 않는다. 승인한 값과 수정 전 값을 기록하고, 승인 뒤 새로운 값이 생겼다고 조용히 덮어쓰지 않는다.
- 측정과 재측정 실패 후 재시도는 가게당 하루 3회까지다. 실제 호출·오류 기준은 개발 문서에서 관리한다.

## 10. 개발과 검증의 순서

개발팀은 먼저 수집·출처 판정과 수정 가능한 칸을 확인한다. 그다음 AI의 사실 정리와 질문 한도를 연결하고, 정비안 화면·승인·자동 보류를 구현한다. 이후 실제 권한을 연결한 시험 가게에서 수정과 공개 반영을 확인하고 재측정으로 이어 간다.

| 확인할 목표 | 측정 방법 |
|---|---|
| 사장님이 적게 입력하는가? | 추가 질문 수와 입력 칸·조작 수를 함께 본다. 신청 전체 3문항 초과는 허용하지 않는다. |
| 정비안을 쉽게 이해하는가? | 무엇이 왜 바뀌는지 사장님이 설명할 수 있는지 확인한다. 초기 목표 80%는 가설이다. |
| 정보가 정확한가? | 반영한 값의 근거와 필수 주문 조건을 검수한다. 근거 없는 필수값은 반영하지 않는다. |
| 실제로 일이 끝나는가? | 진단 완료율, 정비 승인·완료율, 공개 반영 성공과 보류 이유를 구분해 본다. |
| 전후 결과를 비교할 수 있는가? | 측정 조건이 같은지 확인하고 AI별 지표·출처·주변 가게 변화를 함께 기록한다. |

단계별 작업과 완료 조건은 [개발 할 일](개발/개발할일.md), 최소 질문 검수는 [AI 수집·최소 질문](AI수집과최소질문.md), 실제 시험 결과는 [구현 시험 기록](../03_실험/구현시험/)에서 관리한다.

## 11. 아직 결정하거나 확인해야 할 것

가격·결제·구독과 환불 정책, 실제 모집 지역·가게 수, 외부 데이터의 저장·활용 범위는 확정이 필요하다. 플랫폼별 관리 권한과 쓰기 가능한 칸, 실제 공급자 인증·전체 진단, 매장 정비 성공 여부도 해당 환경에서 검증해야 한다.

이 항목들은 [운영 현황의 미완료 목록](운영/운영현황.md)과 개발 문서의 결정 항목에서 관리한다. 완료 근거가 생기면 해당 문서의 현재 상태를 고치며, 날짜를 붙인 별도 기획서나 이전 버전 사본을 만들지 않는다.

## 12. 주요 용어

| 용어 | 쉬운 뜻 |

| GEO | AI가 질문에 답할 때 가게 정보를 이해하고 찾을 수 있도록 돕는 정보 정비 활동이다. |

| 재측정 | 정비 전과 같은 조건으로 AI 추천 결과를 다시 확인하는 일이다. |
