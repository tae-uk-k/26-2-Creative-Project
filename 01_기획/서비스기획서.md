# seelo 서비스 기획서

기준일: 2026-11-28 · 대상: 기획자, 디자이너, 개발자, 프로젝트를 처음 보는 사람

**seelo는 스마트스토어·카페24 판매자의 상품 상세페이지를 AI가 정확히 이해할 수 있도록 정비하는 서비스다.** AI가 같은 상품·모델·옵션의 자료를 먼저 조사해 정비안을 만든다. 판매자는 자료로 확인되지 않은 필수 정보만 보완하고 바꿀 내용을 승인한다. seelo는 위임받은 관리자 화면에서 승인된 항목만 수정하고, 정비 전후의 AI 노출을 같은 조건으로 측정한다.

| 결정 | 날짜 | 내용 |
|---|---|---|
| 대상 플랫폼 | 2026-11-18 | 스마트스토어·카페24만 진행한다. 다른 쇼핑몰 플랫폼은 가입·정비·API 개발 대상에서 제외한다. |
| 기본 수정 방식 | 2026-11-24 | 관리자 위임 → 관리자 화면 브라우저 자동화. API 발급·앱 설치는 선행 조건이 아니다. |

이 문서는 만들 서비스의 기준이다. 실제 구현·검증 상태는 [운영 현황](운영/운영현황.md)에서 따로 관리한다. 2026-11-18 이전의 Google 지도·카카오맵 가게 정비 기획은 [이전 기획 보관](../98_이전기획/README.md)으로 옮겼다.

## 2. 누구의 어떤 문제를 해결하는가

첫 사용자는 스마트스토어·카페24에서 상품을 파는 판매자다. 특히 상세페이지에 원재료·규격·구성품처럼 구매 판단에 필요한 사실이 빠져 있거나 이미지에만 있는 판매자를 대상으로 한다. seelo는 아직 이미지 속 글자를 읽지 않는다. 이미지에만 있는 정보는 판매자 답변이나 공식 자료 주소로 보완한다.

판매자는 AI 쇼핑 질문에서 자기 상품이 나오는지 확인하기 어렵다. 상품마다 자료를 찾아 상세 설명·요약·SEO 항목을 직접 고치는 데 시간이 든다. 진단 결과나 고칠 문구만 받으면 실제 수정 작업은 여전히 판매자에게 남는다.

seelo는 자료 조사, 필요한 정보 보완, 관리자 화면 수정, 반영 확인, 전후 측정을 한 흐름으로 제공한다. 근거는 [쇼핑몰 상세페이지 효과 검토](../02_조사/쇼핑몰상세페이지_효과와플랫폼검토.md)에 있다. 이 검토가 인용한 무작위 실험의 영어 분석에서는 기존 설명이 없거나 짧은 상품의 매출 변화가 충분한 설명의 상품보다 컸다. 상품 후보를 고정한 E-GEO 실험에서는 설명을 고쳐 쓰면 AI의 추천 순위가 바뀌었다. 실제 ChatGPT·Gemini에서의 변화는 seelo가 직접 측정한다. 현재 B0 전후 비교 실험을 진행 중이며 계속 여부는 운영 현황 D8에서 정한다.

## 3. 무엇을 제공하는가

| 제공 항목 | 판매자가 받는 내용 | 현재 조건 |
|---|---|---|
| 상품 정비 | AI가 조사한 사실로 정비안을 만들고, 승인한 항목만 관리자 화면에 저장한다. 저장 뒤 재조회와 공개 화면 확인을 기록한다. | 관리자 위임이 확인된 스토어에서만 실행한다. |
| AI 노출 진단·보고서 | 운영자가 고정 질문 세트로 ChatGPT·Gemini에 같은 질문을 여러 번 묻고 자연 발견·추천·상품 링크 인용을 집계한다. 판매자는 같은 조건의 정비 전후를 비교한 보고서를 받는다. | 측정 모델·반복 횟수(D6)와 Gemini 사용(D3)을 정해야 한다. |
| 변경 이력·복구 | 수정 전 값·승인 값·저장 결과를 기록한다. 요청하면 승인 범위의 수정 전 값으로 복구한다. | 저장 뒤 판매자나 다른 정비안이 같은 칸을 바꿨으면 복구하지 않는다. |

가격·결제·구독·환불·무료 횟수·재측정 주기는 정하지 않았다(운영 현황 D11). 지도 베타의 무료 진단 1회·14일 재측정 정책은 쇼핑몰에 적용하지 않는다.

## 4. AI·판매자·운영자의 역할

| 역할 | 담당하는 일 |
|---|---|
| AI | 기존 상품 본문, 본문 속 공개 자료 링크, 판매자가 지정한 공식 자료를 읽는다. 이 상품의 구매 판단에 필요한 사실 종류를 고른다. 인용문으로 확인한 값만 사실로 저장하고 정비안을 만든다. 확인하지 못한 필수 사실만 질문으로 고른다. |
| 판매자(고객) | 스토어 주소를 등록한다. 플랫폼 관리 화면에서 seelo 담당자 계정에 상품 편집 권한을 준다. 정비할 상품을 가져온다. 필요한 누락 정보에 답하고 바꿀 항목을 승인한다. 전후 보고서를 본다. |
| seelo 운영자 | 초대를 수락하고 담당자 계정으로 로그인한다. 로그인 만료·보안 확인이 생기면 다시 로그인한다. 편집 권한과 스토어 고유값을 확인해 기록한다. 고객이 승인한 정비안을 확인하고 실행한다. 수동 항목과 공개 반영 결과를 기록하고, 필요하면 복구한다. 정비 전후 AI 노출을 측정한다. |

운영자는 고객의 승인을 대신할 수 없다. seelo는 판매자의 비밀번호·2단계 인증 정보·플랫폼 API 키를 받지 않는다. 판매자에게 개발자 가입·키 발급·HTML 복사·붙여넣기를 요구하지 않는다.

## 5. 이용 순서

1. **가입한다.** 이메일·Google·카카오 중 하나로 가입하고 이메일 인증을 마친다.
2. **스토어를 등록한다.** 스토어 주소를 넣으면 서버가 플랫폼·스토어 ID·카페24 쇼핑몰 번호를 판별한다. 연결 도메인처럼 판별할 수 없으면 몰 ID를 직접 입력한다.
3. **관리자 권한을 위임한다.** 스마트스토어는 seelo가 안내한 담당자 이름·휴대전화로 대행사 매니저를 초대한다. 카페24는 상품 수정 권한이 있는 seelo 전용 부운영자 계정을 만든다. 판매자가 초대 전달을 기록하면 운영자가 수락·로그인·권한을 확인한다. 플랫폼별 절차는 스토어 화면에서 메뉴 경로 순서로 안내한다(C-11). 카페24 부운영자 접속 정보는 화면 밖(전화·문자)에서 전달하고, seelo는 비밀번호를 입력받거나 저장하지 않는다(D14).
4. **상품을 가져온다.** 판매자나 운영자가 상품번호 또는 카페24 상품 주소를 넣는다. 운영자 설정이 있으면 관리 화면의 상품 목록에서 고를 수 있다. seelo가 관리 화면에서 현재 값을 읽어 원본으로 저장한다.
5. **AI가 정비를 준비한다.** 수집이 끝나면 자료 조사 → 필요한 사실 판단 → 정비안 생성이 자동으로 이어진다. 확인하지 못한 필수 사실만 한 번에 2개까지 묻는다. 판매자가 답하면 정비안을 다시 만든다.
6. **운영자가 정비 전 AI 노출을 측정한다.** 질문 세트를 만들고 저장 전에 기준 회차를 측정한다. 이 회차가 없으면 전후 비교를 할 수 없다. B0 실험은 정비 전 변동폭을 보려고 24~48시간 간격으로 기준 회차를 두 번 측정한다.
7. **판매자가 승인한다.** 정비안의 항목 중 바꿀 것만 골라 승인한다. 승인은 해당 정비안과 원본 해시에 묶인다.
8. **저장하고 확인한다.** 운영자가 승인 내용을 확인하고 저장을 실행한다. seelo가 관리자 화면에 자동으로 저장하고 다시 읽어 반영을 판정한다. 판매자 화면에는 저장 버튼이 없고 진행 단계만 보인다. 운영자가 공개 상세페이지의 PC·모바일 표시를 확인해 기록한다. 자동 저장 대상이 아닌 항목은 운영자가 작업 지침에 따라 수동으로 고치고 기록한다.
9. **전후를 비교한다.** 운영자가 같은 질문 세트와 같은 측정 조건으로 정비 후 회차를 측정한다. 판매자는 오늘 할 일에서 보고서 알림을 보고 전후 보고서를 연다. 정비 후 측정 시점은 정하지 않았다(D11). 진행 중인 B0 실험은 정비 3일·7일 뒤에 측정한다.

변경할 항목이 없으면 정비안을 `no_changes`로 남긴다. 실제 저장이 없는데 정비 완료로 표시하지 않는다.

## 6. 현재 범위

| 구분 | 범위 |
|---|---|
| 계정 | 이메일·Google·카카오 가입, 로그인, 이메일 인증, 비밀번호 재설정·변경, 탈퇴. |
| 스토어 | 스마트스토어·카페24 등록, 관리자 위임 상태·API 인증 상태를 따로 관리, 연결 해제. |
| 상품 원본 | 위임받은 관리 화면에서 수집한다. 판매자가 제공한 원본은 참고용이며 자동 저장 근거로 쓰지 않는다. |
| AI 정비 | 자료 조사·사실 확인·누락 질문·정비안 생성. 웹 검색 자료 발견은 서버 설정(`COMMERCE_WEB_DISCOVERY`)을 켠 경우에만 쓴다(D5). |
| 저장·확인 | 승인 항목 저장, 재조회, 공개 반영 기록, 복구, 쓰기 이력. 실행은 운영자 화면에서 한다. |
| AI 노출 진단 | 질문 세트, 회차 측정, 판정, 같은 조건 전후 비교(운영자). 판매자용 전후 보고서. 질문 자동 생성(C-13)과 재측정 예약(C-14)은 아직 없다. |
| 운영자 업무 | 고객 스토어 목록, 초대 확인 대기, 작업 대기, 스토어 고유값 기록. |
| 화면 | 랜딩 새 시안 `dark.html`과 토스 디자인 시스템 규칙으로 만들었다(D12, C-12). 이용약관·개인정보 처리방침은 검토 전 초안이다. |
| 진행 알림 | 메일 알림은 없다. 판매자는 오늘 할 일(`/home`)에서 질문·승인·보고서를 확인한다(D15). |

가격·재고·옵션·배송·판매·진열·구매 제한은 수정하지 않는다. 리뷰 답변 대행·광고 집행·주문 처리는 제공하지 않는다. 이미지 속 글자 판독은 하지 않는다. 스마트에디터 ONE 상품의 본문 자동 편집은 현재 수동 경로로 둔다(D9).

## 7. 플랫폼별 연결 방식

| 플랫폼 | 권한 위임 | 자동 편집 범위 | 선택 API 경로 |
|---|---|---|---|
| 카페24 | 대표운영자가 상품 수정 권한의 부운영자 계정을 만든다. | 상세 설명·요약 설명·간략 설명·SEO 제목·설명·키워드. 모바일 설명은 화면 설정 전까지 미지원이다. | 개발자 앱 설치 → 상품 OAuth 동의. 우리 몰의 Admin API 쓰기는 미검증이다. |
| 스마트스토어 | 통합매니저 또는 계정 주매니저가 대행사 매니저로 초대한다. | 상세설명(기존 HTML 작성 방식). 상품 속성은 수동 편집이다. | 커머스솔루션 또는 API 대행사 공식 경로. 외부 고객용 연결은 확보하지 않았다. |

가입, 관리자 권한 부여, API 자동 연동은 서로 다른 절차다. 초대 수락만으로 API 연결 완료로 표시하지 않는다. API 경로를 함께 운영할지는 운영 현황의 D10에서 결정한다. 절차와 공식 근거는 [쇼핑몰 진행 지침](../02_조사/쇼핑몰_타깃플랫폼과_수정수행방식_20261117.md)과 [관리 위임과 간편 API 연결](../02_조사/쇼핑몰_관리위임과_간편API연결_20261124.md)을 따른다.

## 8. AI 노출 진단을 읽는 방법

| 지표 | 판정 기준 |
|---|---|
| 자연 발견 | 정상 응답에서 정확한 상품명이나 대상 상품 주소로 대상 상품을 식별했다. 원료 일반 설명이나 브랜드만 언급한 경우는 제외한다. |
| 추천 | 상위 3개 소개 목록 안에 대상 상품이 있다. 목록 구조가 없으면 순위를 비우고 검토 대상으로 표시한다. |
| 상품 링크 인용 | 답변 본문이나 검색 출처에 대상 상품 주소가 있다. |
| 무효 | 호출 실패다. 노출 0으로 세지 않고 분모에서 뺀다. 1회만 다시 실행하고 최초 실패도 보관한다. |

자연 발견 질문에는 대상 상품명이나 상품 주소를 넣지 않는다. 전후 비교는 같은 질문 세트·공급자·모델·도구 옵션·반복 수끼리만 한다. 두 회차 사이에 상품 원본이 바뀌었으면 화면에 표시한다. 판정 기준은 [쇼핑몰 AI 노출 전후 비교 실험](../03_실험/쇼핑몰_AI노출_전후비교_20261124/실험계획.md)에서 가져왔다.

## 9. 이용 중 지키는 규칙

- 운영자가 위임을 확인(`verified`)하기 전에는 관리 화면에서 수집·저장하지 않는다.
- 운영자는 고객이 직접 승인한 정비안만 실행한다.
- 저장 전 원본 해시가 바뀌었으면 승인·저장을 멈추고 다시 수집한다.
- 저장 결과가 불명확하면 `uncertain`으로 남기고 같은 저장을 반복하지 않는다. 재조회로 판정한다.
- 로그인·캡차·보안 확인·예상과 다른 화면이 나오면 중단한다. 담당자가 해결한 뒤 다시 읽는다.
- 실제 쓰기는 서버 설정 `COMMERCE_WRITES_ENABLED`가 켜진 경우에만 실행한다. 기본값은 꺼짐이다. 파일럿에서는 `COMMERCE_WRITE_TARGETS`로 허용할 스토어·상품을 지정한다(D4).
- 복구는 해당 변경의 수정 전 값만 되돌린다. 이후 판매자가 바꾼 값을 덮어쓰지 않는다.

## 10. 검증 상태와 다음 순서

상품 정비의 기본 흐름과 플랫폼별 위임 안내를 로컬에서 확인했다. 두 플랫폼의 대표 계정에서 본문 수정·저장·공개 반영·원문 복구를 확인했다. 실제 고객의 위임 계정, 실제 AI 모델 실행, 쇼핑몰 기능의 운영 배포 상태는 운영 현황에서 관리한다.

남은 구현은 운영 현황의 C-01~C-14, 결정은 D1~D15, 사용자 조치는 U1~U11로 추적한다. 실행 순서도 같은 문서에 있다. 이 문서에는 상태를 복사하지 않는다.

## 11. 아직 결정할 것

서비스 범위에 관한 결정만 적는다. 배포·AI 실행·측정 조건 같은 운영 결정(D1~D6, D8)은 운영 현황에서 본다.

| 항목 | 운영 현황 ID |
|---|---|
| 가격·결제·구독·환불·무료 횟수·재측정 주기 | D11 |
| 출처별 접근·저장·AI 입력·공개 재사용 범위 | D13 |
| 스마트에디터 ONE 자동 편집 개발 여부 | D9 |
| API 연동 병행 여부 | D10 |
| 파일럿 판매자 | D7 |
| 카페24 부운영자 첫 로그인 뒤 비밀번호 변경 여부 | D14 |
| 진행 알림 범위 | D15 |
