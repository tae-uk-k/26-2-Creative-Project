# 지도정보 정비 기준

기준일: 2026-11-09 · 대상: 정비안을 만드는 AI, 운영 담당자, 기획자·개발자

이 문서는 **어떤 사실을 어느 입력 칸에 넣고, 무엇을 수정 완료로 볼지** 정합니다. AI가 자료를 선택하고 사장님에게 묻는 기준은 [AI 수집과 최소 질문](AI수집과최소질문.md)에서 관리합니다. 논문·공식 안내와 구체적인 현장 사례는 [근거와 판단 사례](../02_조사/지도정비_근거와판단사례.md)에 모았습니다.

## 1. 정비의 기본 원칙

기존 정보가 정확하고 충분하면 유지합니다. 글을 길게 쓰거나 영어 비율·키워드 수를 채우기 위해 수정하지 않습니다. 기존 소개는 말투와 핵심 내용을 보존하고 필요한 구절만 고치는 것이 기본입니다.

AI는 소개·기존 메뉴·공식 안내·활용 가능한 메뉴판에서 사실을 최대한 찾습니다. 다만 자료에서 찾은 사실 전체를 공개 소개에 복사하지는 않습니다. 방문이나 주문을 결정하는 데 필요한 사실만 해당 칸에 배치합니다.

다른 출처의 가격·시간이 다르면 지점·판매 단위·적용일·홀과 배달의 차이를 먼저 확인합니다. 현재 사실을 판단할 수 있으면 AI가 정비안에 반영하고, 근거가 부족한 새 변경은 보류합니다. 사장님 질문은 필요한 누락 중심으로 전체 상한 안에서만 선정합니다.

## 2. 수정할 수 있는 범위

| 구분 | 현재 정비 대상으로 다루는 내용 |
|---|---|
| Google 지도 | 지원되는 소개, 영업시간·특별 영업시간, 공식 링크·전화, 음식점 메뉴·가격, 편의 정보를 다룹니다. 실제 계정·업종의 지원 칸을 먼저 확인합니다. |
| 카카오맵 | 한 줄 소개, 영업시간·휴무·휴게, 가격 정보, 사이트·SNS 링크, 제공 서비스·태그를 다룹니다. 실제 관리 화면의 편집 범위에서 작업합니다. |
| 가게 이름·주소·업종 | seelo의 직접 수정 대상에서 제외합니다. 잘못된 경우에는 사장님이 해당 플랫폼에서 처리할 경로를 안내합니다. |
| 지도 밖의 채널 | 현재는 사실 확인에 사용합니다. 웹사이트·SNS 제작이나 정비를 기본 상품에 포함하지 않습니다. |

지도의 실제 기존 입력 칸만 사용합니다. AI용 숨김 값·HTML·JSON-LD를 지도에 삽입하거나 탭·글꼴·카드 배치·표시 위치를 바꿀 수 있다고 설명하지 않습니다. 이미 있는 공식 홈페이지·메뉴 링크를 수정하는 것과 외부 페이지를 새로 제작하는 것은 구분합니다.

## 3. 어떤 정보를 어디에 넣는가

| 입력 칸 | 넣을 정보 | 작성 기준 |
|---|---|---|
| 가게 소개 | 음식 종류·확인된 음식·가게의 핵심 특징을 담습니다. | 정확한 기존 소개를 보존합니다. 새로 쓰거나 전체 재작성할 때는 필요한 사실을 짧은 문장으로 연결합니다. |
| 메뉴 이름·가격 | 음식명·금액과 가격 해석에 필요한 단위·크기를 연결합니다. | 다른 크기·배달 가격·세트 가격을 섞지 않습니다. 필수값을 모르면 그 새 변경만 보류합니다. |
| 메뉴 설명 | 음식 구별에 필요한 구성과 최소 주문·필수 비용·판매 시간·선택 조건을 담습니다. | 소개나 시설 정보를 반복하지 않습니다. 불필요한 재료 나열을 줄입니다. |
| 영업시간 | 확인된 요일별 영업 구간·휴무·휴게·특별 영업을 담습니다. | 폐점 시각과 주문 마감 시각, 임시 휴무와 정기 휴무를 구분합니다. |
| 편의·서비스 | 자료로 확인한 포장·예약·결제 등 실제 제공 정보를 담습니다. | 자료가 없다는 이유로 ‘불가’·‘없음’을 만들지 않습니다. |
| 공식 링크·전화 | 해당 지점의 확인된 공식 주소·연락처를 넣습니다. | 소개문에 반복해서 넣지 않고 지원되는 전용 칸을 사용합니다. |
| 태그 | 확인된 사실을 나타내는 필요한 짧은 분류만 선택합니다. | 같은 뜻의 태그·과도한 키워드를 반복하지 않습니다. |

카카오 한 줄 소개는 공식 50자 한도를 지키고, 새 문장 편집 기준은 한 문장·40자 이내로 둡니다. Google 소개는 공식 750자 한도 안에서 새 작성·전체 재작성 시 기본 한 언어 1~2문장으로 씁니다. 이 분량은 과잉 입력을 줄이기 위한 자체 편집 기준이며 최소 작성량이 아닙니다. 영어·한국어 두 문단을 매번 함께 만들지 않습니다.

문장을 줄일 때는 중복과 선택적인 설명부터 덜어 냅니다. 최소 주문·필수 추가금·판매 시간을 지우거나 글자 중간을 잘라 의미를 바꾸지 않습니다. 길이 안에서 정확하게 표현할 수 없으면 관리자 검토 또는 해당 새 변경 보류로 처리합니다.

## 4. 사실을 추가하기 전 확인할 것

추가할 내용은 같은 지점의 현재 사실이어야 하고, 확인 가능한 근거가 있어야 합니다. 실제 지원 칸에 맞으며, 고객이 음식을 고르거나 방문·주문하는 데 필요한지도 확인합니다. 리뷰에서 자주 나왔다는 이유만으로 현재 가격이나 판매 단위를 확정하지 않습니다.

메뉴판을 읽을 때는 음식명과 가격이 대응하는 행·열, 공통 각주, 세트 인원, 판매 시간과 추가금을 함께 확인합니다. 사진에 보이는 외형으로 성분·중량·할랄·알레르기를 판단하지 않습니다. 흐린 숫자는 비슷한 가게 가격이나 평균값으로 채우지 않습니다.

읽지 못한 자료와 실제 빈칸을 구분합니다. 검색에서 링크만 찾은 상태는 본문을 읽은 상태가 아닙니다. 출처별 접근·저장·AI 입력의 기존 범위를 지키고, 읽을 수 있는 다른 공식 자료로 먼저 보완합니다.

## 5. 정비안을 만들고 승인받는 순서

1. 수정 권한과 해당 계정의 지원 입력 칸을 확인합니다.
2. 관련 자료와 현재 값을 대조해 채택할 사실을 정하고, 필요한 누락만 추가 탐색합니다.
3. 필요한 사실을 칸별로 배치해 짧고 구체적인 초안을 만듭니다. 문장마다 근거를 연결합니다.
4. [최소 질문 규칙](AI수집과최소질문.md)에 따라 질문을 선정합니다. 나머지 미확인 새 변경은 자동 보류합니다.
5. S13에서 현재 값·바꿀 값·이유와 보류 목록을 구분해 보여 주고, 준비된 변경만 승인받습니다.
6. 승인한 버전의 값만 수정합니다. 바꾸기 전 값을 먼저 기록하고 저장 후 다시 읽어 확인합니다.
7. 공개 반영 여부를 확인하고, 실패·지연·수동 처리를 항목별로 구분합니다.

한 메뉴가 보류됐다고 정상 메뉴 전체를 지우거나 다른 정비를 중단하지 않습니다. 민감한 새 주장은 필요한 근거와 사장님 확인 전 승인 대상에서 제외합니다. 사장님이 직접 수정한 승인 값도 형식·길이·필수 조건 보존 검사를 거칩니다.

## 6. 완료 판단과 오류 처리

수정 요청을 저장한 것과 공개 페이지에 값이 바뀐 것은 다릅니다. 요청 결과·관리 화면 재조회·공개 반영 확인을 구분하고, 확인 시각을 남깁니다. 반영 대기 항목은 기존 정해진 재확인 절차로 처리하며 같은 쓰기 요청을 반복하지 않습니다.

로그인·보안 확인 등으로 자동 처리가 막히면 해당 작업을 멈추고 관리자 수동 처리로 넘깁니다. 해결되지 않은 항목을 완료로 표시하지 않습니다. 실제 수정이 하나도 없으면 유지·보류 상태와 관리자 검토로 구분합니다.

정비가 완료되면 실제 완료일을 기준으로 14일 뒤 재측정을 예약합니다. 전후 질문과 AI·반복 횟수·전송 조건을 맞추고, 바뀐 정보와 추천 결과를 함께 확인합니다. 화면 시안·가상 숫자는 실제 공개 반영이나 서비스 실적의 증거로 사용하지 않습니다.

## 7. 승인 전 빠른 검수

- 같은 지점·같은 메뉴의 현재 사실인지 확인합니다.
- 가격과 단위·구성·적용 조건이 정확히 연결됐는지 확인합니다.
- 기존 정상 정보가 이유 없이 사라지지 않았는지 확인합니다.
- 소개·메뉴·시간·시설에 같은 사실을 과도하게 반복하지 않았는지 확인합니다.
- 근거 없는 사실과 미확인 민감 주장이 실행 대상에 섞이지 않았는지 확인합니다.
- 미확인 새 변경은 보류 목록으로 분리하고, 준비된 수정만 승인받는지 확인합니다.
- 수정 전 값·승인 버전·반영 확인 결과를 기록할 수 있는지 확인합니다.
