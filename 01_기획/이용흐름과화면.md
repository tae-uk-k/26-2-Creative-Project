# 이용 흐름과 화면

기준일: 2026-11-28. 이 문서는 판매자(고객)와 seelo 운영자가 각 화면에서 무엇을 보고 하는지 설명한다. 서비스의 목적과 범위는 [서비스 기획서](서비스기획서.md), AI 판단과 질문은 [AI 수집과 최소 질문](AI수집과최소질문.md), 고치는 칸의 규칙은 [상품정보 정비 기준](상품정보정비기준.md)에서 관리한다.

화면 디자인은 [랜딩 새 시안 dark.html](../05_발표자료/결과물/seelo_쇼핑몰_랜딩_새시안_20261125/dark.html)과 토스 디자인 시스템(TDS)의 색·글자 위계·간격·컴포넌트 모양을 따른다(운영 현황 D12). TDS 라이브러리는 설치하지 않았다. 화면은 `04_MVP/seelo/frontend/src/pages/`, 공통 컴포넌트는 `src/ui/`에 있다.

## 1. 화면 설계 원칙

글 설명 대신 화면 구조로 다음 행동을 이끈다.

1. 화면마다 주 행동은 하나다. 지금 할 수 있는 다음 단계만 강조 버튼으로 둔다. 할 수 없는 행동은 숨기고 단계 표시로 대신한다.
2. 진행 상태는 단계 표시·배지·진행 목록으로 보여 준다. 상태를 문단으로 설명하지 않는다.
3. 정비안은 현재 값과 바뀔 값을 나란히 놓고 추가된 부분을 색으로 표시한다. 근거는 출처 칩으로 붙인다.
4. 추천 항목은 미리 선택한다. 직접 보완·범위 지정 같은 고급 기능은 접어 둔다.
5. 기다리는 작업은 단계형 진행과 스켈레톤으로 보여 준다. 화면을 떠나도 `/home`에서 이어진다.
6. 빈 화면은 이모지와 행동 버튼 하나로 시작한다.
7. 되돌리기 어려운 행동(연결 해제, 탈퇴, 복구)은 결과를 먼저 보여 주는 확인 대화상자를 거친다.
8. 권한 위임은 실제 메뉴 경로를 칩 순서로 보여 주고 복사 버튼과 플랫폼 바로가기를 둔다.

## 2. 전체 흐름

```text
[판매자] 랜딩 → 가입·로그인 → 오늘 할 일 → 스토어 연결(주소 입력) → 관리자 권한 위임·전달 기록
→ [운영자] 위임 확인·스토어 고유값 기록
→ 상품 불러오기 → AI 조사(자동) → [판매자] 필요한 정보 답변
→ [운영자] 정비 전 AI 노출 측정
→ [판매자] 정비안 검토·승인 → [운영자] 확인하고 반영(자동 수정·재조회)
→ [운영자] 공개 페이지 확인 기록 → [운영자] 정비 후 측정
→ [판매자] 전후 보고서 → 필요 시 [운영자] 복구
```

| 역할 | 화면에서 하는 일 |
|---|---|
| 판매자 | 스토어 연결, 권한 위임과 전달 기록, 상품 불러오기, AI 정비 시작, 질문 답변, 정비안 승인, 보고서 확인, 연결 해제 |
| 운영자 | 위임 확인·고유값 기록, 승인한 정비안 반영, 수동 편집·공개 확인 기록, 재조회, 복구, AI 노출 측정 |

승인은 판매자만 한다. 판매자 화면에는 반영·복구 버튼이 없다. 운영자는 판매자 승인 기록이 있는 정비안만 반영한다. 서버 API는 소유자의 적용·복구 요청도 계속 받는다. 화면에서만 운영자 경로로 모았다.

- 로그인하지 않은 사용자가 P10~P08에 들어오면 로그인 화면으로 보낸다. 로그인 뒤 원래 경로로 돌아온다. 원래 경로가 없으면 `/home`으로 간다.
- 실제 API 모드에서 로그인한 사용자가 `/`에 오면 `/home`으로 보낸다.
- 이전 상품 목록 경로 `/stores/:storeId/products`는 검색어를 유지한 채 P02b로 보낸다.
- 시연 모드는 인증 화면 대신 `/home`을 연다.

## 4. 공통 화면 구조

| 요소 | 내용 |
|---|---|
| 머리글 | 로고, 홈·스토어·운영자(운영자만) 메뉴, 계정 이메일 |
| 하단 메뉴 | 좁은 화면에서 머리글 메뉴 대신 표시. 홈·스토어·운영자(운영자만)·계정 |
| 시연 띠 | 시연 모드에서만 표시. "조회 캐시 초기화" 버튼 |
| 화면 제목 | 브라우저 탭 제목은 `화면 제목 · seelo` |
| 반응형 | 판매자 화면은 1440·1024·768·390·320px에서 가로 넘침이 없게 맞춘다. 운영자 화면은 데스크톱 우선이며 390px에서 깨지지 않게 한다 |

플랫폼은 로고로 구분한다. 서버가 상품 이미지 주소를 주지 않으므로 상품은 플랫폼 로고·이모지·도형으로 표현한다.

## 5. P00 랜딩·P01 가입·로그인·P01b 약관

**랜딩.** dark.html의 구조·문구·스타일을 그대로 옮겼다. 바꾼 곳은 세 군데다.

| 바꾼 곳 | 내용 |
|---|---|
| 머리글 | 오른쪽에 `로그인` 버튼 추가. 로그인 상태면 `내 스토어` |
| FAQ "어떤 상품 자료를 준비하면 되나요?" | "쇼핑몰 주소만 등록하면 seelo가 현재 상세페이지와 공개 자료를 먼저 조사하고, 확인되지 않은 정보만 여쭤봅니다." |
| 바닥글 | 시안의 이미지 3종 링크 자리에 이용약관·개인정보 처리방침 링크 |

400px 이하에서는 머리글 메뉴의 `지원 쇼핑몰`을 숨긴다. 같은 내용은 본문 순서로 닿는다.

**가입·로그인.** 넓은 화면은 왼쪽에 시안의 어두운 첫 화면, 오른쪽에 입력 영역을 둔다. 좁은 화면은 입력 영역만 보인다.

| 동작 | 내용 |
|---|---|
| 이메일 가입 | 이메일·비밀번호·약관 동의(전체 동의, 항목별 보기 링크) → 메일 발송 화면 → 링크로 인증 → `/home` |
| 소셜 가입·로그인 | 카카오·Google 버튼. 시작 주소에 `intent=login` 또는 `signup`을 붙인다. 카카오에서 이메일을 받지 못하면 이메일을 입력한다 |
| 비밀번호 재설정 | 메일 요청 → 링크에서 새 비밀번호 입력 |

로그아웃·사용자 교체·세션 만료 때 조회 캐시를 비운다.

**약관.** 실제 수집·처리 항목으로 쓴 초안이다. 화면 위에 "검토 전 초안"을 표시하고, 정하지 않은 값은 `【】`로 남겼다. 공개 전에 사용자가 검토한다.

## 6. P10 오늘 할 일

스토어 목록과 상품 목록의 `summary`로 판매자가 할 일을 모은다. 카드 하나가 행동 하나다. 위에서부터 아래 순서로 놓는다.

| 순서 | 조건 | 카드 | 이동 |
|---|---|---|---|
| 1 | 권한 위임 전·연결 해제됨·API 미연결 | 권한 위임을 마쳐 주세요 / 연결이 끊겼어요 / API 연결을 마쳐 주세요 | 스토어 홈 |
| 2 | 답하지 않은 질문이 있음 | 질문 N개에 답해 주세요 | 상품 정비 |
| 3 | 질문 없는 정비안 승인 대기 | 정비안을 승인해 주세요 | 정비안 검토 |
| 4 | 정비 전·후 측정 회차가 모두 끝남 | 보고서가 준비됐어요 | 보고서 |
| 5 | 정비 전·조사 실패·원본 바뀜 | AI 정비를 시작하세요 / 다시 시작해 주세요 | 상품 정비 |

- 판매자 행동이 없는 상품(AI 조사 중, seelo 확인 중, 반영 중, 공개 확인 중)은 "진행 중" 목록에 상태 배지로 보여 준다.
- 위임 확인을 기다리는 스토어는 따로 보여 준다.
- 스토어가 없으면 "스토어를 연결하고 시작하세요"와 연결 버튼 하나만 둔다. 할 일이 없으면 빈 상태를 보여 준다.
- 운영자 계정에는 대기 작업 수와 `작업함 열기`를 함께 보여 준다.

## 7. P02 스토어

**목록(P02).** 스토어 카드에 플랫폼 로고, 이름, 연결 단계 표시를 둔다. 관리자 화면 방식은 `주소 등록 → 권한 위임 → seelo 확인 → 상품 정비`, API 방식은 `주소 등록 → API 연결 → 상품 정비` 단계를 쓴다.

**연결(P02a).** 판매자가 스토어 주소를 넣는다. 입력하는 동안 주소 모양으로 플랫폼을 미리 보여 준다. 등록하면 서버가 플랫폼·스토어 ID·카페24 쇼핑몰 번호를 판별한다. 연결 도메인처럼 판별할 수 없으면 플랫폼과 몰 ID를 직접 고른다. 등록 뒤 스토어 홈으로 간다.

**스토어 홈(P02b)·연결 전.** 권한 위임 안내를 진행 목록으로 보여 준다.

| 플랫폼 | 안내 |
|---|---|
| 스마트스토어 | 판매자센터 메뉴 경로 칩, 대행사 매니저로 초대할 seelo 담당자 이름·휴대전화와 복사 버튼, `판매자센터 열기` |
| 카페24 | 관리자 메뉴 경로 칩, seelo 전용 부운영자 생성과 상품 메뉴·상품 수정 권한 안내, `카페24 관리자 열기` |

- 담당자 이름·휴대전화는 빌드 설정 `VITE_SEELO_MANAGER_NAME`·`VITE_SEELO_MANAGER_PHONE`에서 받는다. 시연 모드는 예시 값을 쓴다.
- 카페24 부운영자 접속 정보는 화면 밖(전화·문자)에서 전달한다. seelo는 비밀번호를 입력받거나 저장하지 않는다(D14).
- 판매자가 `초대를 보냈어요`(스마트스토어) 또는 `부운영자를 만들었어요`(카페24)를 누르면 전달을 기록한다. 화면은 "seelo 확인" 단계로 넘어간다.
- 스마트스토어 담당자 이름·휴대전화가 설정되지 않았으면 복사 버튼 없이 권한 배지만 보여 준다.
- 운영자 계정에는 `운영자 · 권한 확인` 영역이 보인다. 위임 목록·관리 화면의 스토어 이름과 고유 ID를 기록하고 확인한다. 실행기는 이 값과 화면 값을 정확히 대조한다.
- API 방식 스토어는 API 연결 영역을 보여 준다. 카페24는 서버가 준 OAuth 주소로 연결한다.

**스토어 홈·연결 후.** 상품을 불러오고 목록을 본다.

| 영역 | 동작 |
|---|---|
| 상품 추가 | 상품번호(카페24는 상품 주소도 가능)를 넣고 불러온다. 작업 진행을 보여 주고 끝나면 상품 정비 화면으로 간다 |
| 불러온 상품 | 상품마다 상태 배지(답변 필요·승인 필요·반영 중·보고서 준비됨 등). 상품이 5개를 넘으면 검색을 보여 준다 |
| 쇼핑몰 상품 목록 | 운영자 설정(`catalog`)이 있으면 탭으로 보여 주고 골라 불러온다 |
| 판매자 제공 원본 | 접힌 영역. 상품번호·상품명·모델·옵션·현재 상세설명을 직접 등록한다. 참고용이며 자동 수정 근거로 쓰지 않는다 |

스마트스토어 공개 상품 주소의 번호는 원상품번호와 다르다. 판매자센터 상품 목록의 원상품번호를 넣는다. 수집 실패 사유(로그인 필요·권한 없음·다른 스토어 화면 등)를 그대로 보여 준다.

**연결 관리(P02c).** 아래 상태를 따로 보여 준다. 한 상태가 다른 상태의 완료를 뜻하지 않는다. 운영자가 확인한 스토어 이름·고유 ID도 함께 보여 준다.

| 표시 | 값 | 바꾸는 사람 |
|---|---|---|
| 관리자 권한 | 초대 전 → 초대 확인 중 → 권한 확인됨 → 권한 해제됨 | 판매자는 초대 전달만 기록한다. 확인·해제는 운영자가 기록한다 |
| 수정 방식 | 관리자 화면 자동화 또는 API | 서버 설정 |
| API 인증(API 방식만) | 미연결 → 인증됨 → API 조회 확인됨 → API 저장·재조회 확인됨 → 인증 해제됨 | 카페24 OAuth, 스마트스토어 공식 연결 |
| 자동 수정 | 켜짐·꺼짐 | 서버 설정(`COMMERCE_WRITES_ENABLED`) |

담당자 브라우저에 로그인·보안 확인이 필요하면 스토어 홈 위에 알림으로 보여 준다. 담당자가 로그인해 해결한다. 운영자는 연결 관리에서 권한 해제를 기록할 수 있다.

연결 해제는 확인 대화상자를 거친다. seelo의 수집·저장을 멈추고 보관한 API 토큰을 폐기한다. 대기 중인 작업을 취소하고 담당자 브라우저 세션을 지운다. 플랫폼 쪽 매니저·부운영자·앱 권한 삭제는 판매자가 관리 화면에서 직접 한다.

## 8. P04 상품 정비

화면 위에 단계 표시를 둔다: `상품 불러오기 → AI 조사 → 정보 보완 → 승인 → 쇼핑몰 반영 → 공개 확인`. 본문 카드에는 현재 단계의 내용과 행동만 펼친다. 옆 영역에는 확인한 정보, AI 노출, 정비 이력, 직접 보완·범위 지정(접힘), 원본 정보를 둔다.

| 단계 상태 | 판매자에게 보이는 것 | 운영자에게 보이는 것 |
|---|---|---|
| 정비 전 | `AI가 조사하고 정비안 만들기`. 공식 자료 주소(최대 3개)는 접힌 선택 입력 | 판매자 시작 대기 |
| AI 조사 중 | 진행 목록(상품 자료 조사 → 필요한 정보 판단 → 정비안 만들기) | 같음 |
| 조사 실패 | 실패 사유, `다시 조사하기` | 실패 사유 |
| 질문 있음 | "한/두/세 가지만 알려 주세요" 질문 카드. 답하면 정비안을 다시 만든다 | 보기만 |
| 정비안 준비 | 바뀌는 항목 칩, `정비안 확인하기` → P04b | `정비안 보기`, 판매자 승인 대기 |
| 바꿀 내용 없음 | 공식 자료 주소를 넣고 다시 조사 | 보기만 |
| 승인 후 | 진행 목록(승인 → seelo 확인 → 쇼핑몰 반영 → 공개 페이지 확인) | `승인한 변경 적용`·`수동 편집 요청`. 쓰기 차단 사유가 있으면 버튼 대신 사유 |
| 반영 중 | 진행 목록 | 같음 |
| 결과 확인 필요 | 확인 중 표시 | `반영 결과 다시 확인` |
| 원본 바뀜 | 다시 불러오고 정비안 재생성 | 같음 |
| 반영 완료·공개 확인 전 | 반영 완료 표시 | PC·모바일 공개 확인 기록, 수동 편집 결과 기록, `수정 전으로 되돌리기` |
| 공개 확인 완료 | 공개 확인일. 정비 전·후 측정이 끝났으면 `보고서 보기` | 같음, 되돌리기 |
| 되돌림 | `다시 정비하기` | 공개 확인 기록 |

- 직접 보완·범위 지정은 판매자만 연다. 근거 직접 입력과 변경할 필드·필수 사실 선택이 들어 있다.
- 필드 표시는 서버의 `fieldSupport`에 따라 자동 저장·관리자 수동 편집·미지원으로 나눈다. 미지원 필드는 고를 수 없다.
- `applying` 상태와 대기·실행 중 작업만 주기적으로 조회한다. 변경 요청은 자동으로 다시 보내지 않는다.

## 9. P04b 정비안 검토

| 영역 | 내용 |
|---|---|
| 변경 항목 | 항목마다 현재 값과 바뀔 값을 나란히 놓는다. HTML은 읽을 수 있는 글로 바꿔 보여 주고, 추가된 부분을 강조한다. `전체 보기`·`HTML 보기`를 둔다 |
| 근거 | 출처 칩 |
| 반영 선택 | 항목별 `반영` 체크. 기본은 전부 선택. 최신 정비안이고 승인 전일 때 판매자만 바꿀 수 있다 |
| 보류 항목 | 사실을 확보하지 못한 항목을 칩으로 따로 보여 준다 |
| 승인 | 화면 아래에 고정한 `승인하기` → 확인 대화상자 → 상품 정비로 돌아간다 |
| 쓰기 이력 | 이 정비안의 저장·재조회·복구 기록 |

스마트스토어 API 모드에서 상세설명을 바꾸면 HTML 형식으로 전환된다. 이 경우 승인 전에 별도 동의 체크를 받는다. 기본인 브라우저 모드에서는 요구하지 않는다. 이전 정비안도 같은 화면에서 보고, 운영자는 이전 정비안을 골라 복구할 수 있다.

## 10. 정비안 상태

| 상태 | 화면 이름 | 다음 행동 |
|---|---|---|
| `draft` | 답변 필요 또는 승인 필요 | 판매자 답변·승인 |
| `no_changes` | 바꿀 내용 없음 | 자료 보완 후 다시 조사 |
| `approved` | seelo 확인 중 | 운영자 적용 |
| `manual_required` | 반영 중 | 운영자가 작업 지침대로 편집 후 기록 |
| `applying` | 반영 중 | 자동으로 상태 조회 |
| `applied` | 공개 확인 중 → 반영 완료 | 운영자 공개 확인 기록 |
| `pending_reflection` | 반영 중 | 운영자 재조회 |
| `uncertain` | 반영 중 | 재조회만 가능. 다시 저장하지 않는다 |
| `conflict` | 상품이 바뀜 | 다시 불러오고 정비안 재생성 |
| `rejected` | 반영 실패 | 연결 상태 확인 |
| `manual_recorded` | 공개 확인 중 → 반영 완료 | 운영자 공개 확인 기록 |
| `rolled_back` | 되돌림 | 다시 정비 |

## 11. P07 AI 노출 전후 보고서

같은 질문 세트·공급자·모델·도구 옵션·반복 수의 끝난 회차 중에서 정비 전 회차(정비안 없음)와 정비 후 회차(정비안 있음)를 짝지어 만든다. 주소의 `before`·`after`로 회차를 직접 고를 수 있다.

| 영역 | 내용 |
|---|---|
| 공급자별 지표 | ChatGPT·Gemini마다 상품 발견·추천(상위 3)·상품 링크 인용의 전후 비율과 %p 변화, 막대 |
| 질문별 표 | 질문마다 정비 전·후 발견/정상 응답 수와 추천 수 |
| 측정 조건 | 모델, 반복 수, 정비 전·후 회차 이름과 날짜 |
| 바뀐 내용 | 그 정비안에서 승인한 변경 항목의 전후 비교, 공개 페이지 확인일과 PC·모바일 일치 여부 |
| 인쇄 | `인쇄·PDF` 버튼 |

무효 응답은 0%가 아니라 판정 불가로 표시한다. 짝을 만들 수 없으면 빈 상태를 보여 준다. 판정 기준은 [서비스 기획서 8절](서비스기획서.md#8-ai-노출-진단을-읽는-방법)을 따른다.

## 12. P06c 측정 관리(운영자)

판매자는 측정을 실행하지 않는다. 결과는 P04의 AI 노출 영역과 P07에서 본다.

| 동작 | 내용 |
|---|---|
| 새 질문 세트 | 세트 이름, 고정 질문(한 줄에 `ID \| 질문`), 대상 상품명·대상 상품 주소를 등록한다. 대상 상품명을 비우면 상품명을 쓴다. 질문 문장에는 대상 상품명·주소를 넣지 않는다 |
| 회차 실행 | 공급자·반복 수를 고른다. 회차 이름은 정비 전이면 `B0`·`B1`, 정비 후면 `P1`·`P2` 순서로 미리 채운다. 모델은 서버 설정 값을 기록한다 |
| 회차 목록 | 회차·AI·모델·상태·정상/계획·무효·발견·추천(상위 3)·상품 링크 인용. 대기·실행 중이면 5초마다 조회한다 |
| 비교 | 같은 세트·조건의 두 회차를 질문별로 비교한다. 두 회차 사이에 원본이 바뀌었으면 표시한다. `보고서로 보기`로 P07을 연다 |

## 13. P06 운영자 작업함

운영자(관리자 역할) 계정만 볼 수 있다. 고객 승인을 대신하지 않는다.

| 탭 | 내용 |
|---|---|
| 반영 대기 | 판매자가 승인한 정비안(`approved`) |
| 권한 확인 | 초대 전달을 기록한 스토어 |
| 직접 수정 | 수동 편집이 필요한 정비안(`manual_required`) |
| 결과 확인 | `applying`·`uncertain`·`pending_reflection` 정비안 |
| 고객 승인 대기 | 판매자 승인 전 정비안(`draft`) |
| 고객 스토어 | 스토어·고객·관리자 권한 상태·상품 수·단계별 대기 수. 권한 상태로 거르고 검색한다 |

탭은 주소의 `?tab=`으로 유지한다. 각 행은 해당 상품·스토어 화면으로 이동한다.

## 14. P08 계정

| 영역 | 내용 |
|---|---|
| 로그인 정보 | 이메일, 로그인 방법, 가입일 |
| 비밀번호 변경 | 지금 비밀번호와 새 비밀번호. 서버가 비밀번호 변경을 허용한 계정(`canChangePassword`)만 |
| 탈퇴 | 확인 대화상자에서 `탈퇴합니다`를 입력해야 실행한다 |

## 15. 예외 처리

| 상황 | 화면 동작 |
|---|---|
| 담당자 로그인 만료·캡차·보안 확인 | 작업을 멈추고 스토어 홈에 표시한다. 담당자가 해결한 뒤 다시 실행한다 |
| 열린 관리 화면의 스토어가 등록한 스토어와 다름 | 저장 전에 멈춘다 |
| 위임 목록에 같은 값의 스토어가 0곳 또는 2곳 이상 | 선택하지 않고 멈춘다 |
| 서버 자동 수정 꺼짐·파일럿 대상 아님 | 운영자 적용 버튼 대신 이유를 표시한다 |
| AI 모델 미설정·실패 | 실패 사유를 표시한다. 다른 공급자로 자동 대체하지 않는다 |
| 같은 상품 수집·같은 정비안 작업 중복 | 서버가 중복 등록을 막는다 |
| 조회 실패 | 오류 문구와 `다시 조회` |
| 없는 주소·없는 정비안 | 빈 상태와 돌아갈 버튼 |
