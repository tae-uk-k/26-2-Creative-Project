## 1. 서비스 정의

한눈은 외국인 관광객이 ChatGPT·Gemini에 맛집을 물을 때 우리 가게가 추천되는지 측정한다. 그다음 Google 지도·카카오맵의 가게 정보를 사장님 대신 고치고, 2주 뒤 같은 질문으로 다시 재서 무엇이 달라졌는지 보여 준다.

### 핵심 흐름

```text
1. 사장님이 가게 이름과 지도 링크를 넣는다
2. 한눈이 정보를 모으고 AI에 여러 번 물어 무료 진단 결과를 보여 준다
3. 사장님이 자동 정비를 신청하고, 한눈 관리자가 승인한다
4. 사장님이 Google·카카오 관리 화면에서 한눈 계정을 한 번씩 초대한다
5. 한눈이 정비안을 만들고, 사장님이 확인한 뒤 한 번 승인한다
6. 한눈이 Google 지도·카카오맵 정보를 고친다
7. 2주 뒤 같은 질문으로 다시 재고, 전후 비교 보고서를 보낸다
```

### 핵심 가치

- AI가 우리 가게를 실제로 추천하는지 숫자로 보여 준다.
- 추천되지 않는 이유와 고칠 항목을 사장님이 이해할 수 있게 보여 준다.
- 영문 소개·메뉴·가격·영업시간·편의 정보를 만들어 Google 지도·카카오맵에 직접 넣는다.
- 같은 질문으로 다시 재서 정비 전후의 변화를 보여 준다.

## 2. 문제 정의

소규모 가게는 AI가 자기 가게를 얼마나 추천하는지 알기 어렵다. 추천에 필요한 온라인 정보도 부족한 경우가 많다. 그래서 AI로 가게를 찾는 외국인 관광객에게 발견될 기회를 놓칠 수 있다.

### 확인된 배경

- 미국 여행자 중 여행 계획에 생성형 AI를 쓰는 비율: 2025년 상반기 33% → 하반기 43% → 2026년 56% (Phocuswright)
- AI로 여행을 계획하는 사람의 53%가 지역 명소·식당·숨은 장소를 찾는 데 AI를 썼다(Adobe).
- 발리의 음식점·카페·바 4,776곳과 AI 답변 2,208개를 분석한 연구에서, 85.6%의 가게가 한 번도 추천되지 않았다(Pitenin).

### 이 자료로 말할 수 있는 것과 없는 것

- 말할 수 있는 것: AI는 지역의 모든 가게를 고르게 추천하지 않는다.
- 추측: 영문 정보·가격·공식 페이지·외부 언급이 적은 가게는 관광객의 질문 조건과 연결되기 어려울 수 있다.
- 말할 수 없는 것: 해외 조사 결과가 한국을 찾는 외국인 전체에 그대로 맞는다고 할 수 없다. 프랜차이즈가 작은 가게보다 더 많이 추천된다고도 할 수 없다.

### 사장님에게 필요한 것

사장님에게는 노출을 숫자로 보여 주는 진단만으로는 부족하다. 고칠 문구만 건네면 여러 관리 화면을 직접 고치는 일이 다시 사장님 몫이 된다. 그래서 한눈은 진단, Google·카카오 정보 정비, 정비 전후 재측정을 한 흐름으로 제공한다.

## 3. SEO와 GEO의 차이

| 구분 | SEO | GEO |
|---|---|---|
| 사용자 행동 | 검색어를 넣고 결과 목록을 비교한다 | 조건을 문장으로 묻고 AI가 고른 추천을 본다 |
| 목표 | 검색 결과 위쪽에 나오고 클릭을 늘린다 | AI 답변에 추천·인용될 가능성을 높인다 |
| 고치는 것 | 키워드, 링크, 페이지 구조, 지도 등록 | 질문 조건과 맞는 정보, 출처끼리 일치하는 정보, AI가 읽을 수 있는 사실 |

한눈은 SEO를 대신하지 않는다. 이미 있는 지도·검색 정보를 바탕으로, AI가 관광객의 질문과 가게를 연결할 수 있게 보완한다.

## 5. 제공 상품

| 상품 | 사장님이 받는 것 | 비용 |
|---|---|---|
| 무료 진단 | ChatGPT·Gemini별 추천 등장률·평균 등장 순서·AI가 참고한 사이트, 주변 가게 5곳과 비교, 고쳐야 할 점 개수 | 무료(계정당 1회) |
| 자동 정비 + 전후 비교 보고서 | 고쳐야 할 점에 맞춰 한눈이 Google 지도·카카오맵 정보를 직접 고침, 2주 뒤 재측정, 전후 비교 보고서 | 베타: 신청 후 한눈 관리자 승인. 가격 미정 |

- 무료 진단에서는 고쳐야 할 점의 개수만 보여 준다. 무엇을 어떻게 바꿀지는 자동 정비를 신청하고 지도를 연결한 뒤 정비안 화면(S13)에서 보여 준다.
- 한눈이 고치는 곳은 Google 지도와 카카오맵뿐이다. 네이버 지도·공식 웹사이트·인스타그램·외부 사이트는 정보를 모으고 진단하는 데만 쓴다.
- 고칠 문구만 건네는 유료 보고서는 만들지 않는다(2026-10-17 결정).
- 가격과 결제 방식은 아직 정하지 않았다. 베타에서는 결제 없이 한눈 관리자가 신청을 승인한다.

## 6. 서비스 차별점

| 기존 방식 | 한계 | 한눈 |
|---|---|---|
| AI 노출 측정 도구 | 문제만 보여 주고 고치는 건 사용자 몫 | 측정한 뒤 Google·카카오 정보를 직접 고치고 다시 잰다 |
| 매장 정보 관리 도구 | 여러 채널의 기본정보를 맞추는 데 집중 | 관광객의 질문과 AI 답변을 기준으로 고칠 항목을 정하고, 전후 노출을 비교한다 |
| 메뉴 번역 | 번역이 AI 추천에 반영되는지 확인하지 않음 | 질문 조건에 필요한 정보를 지도에 넣고 재측정으로 확인한다 |
| 지도 등록 대행 | 한 채널 등록에 집중 | 여러 출처와 비교해 Google·카카오 정보를 맞추고, AI 답변 변화까지 확인한다 |

## 7. 대표 사용자 여정

**가입**

1. 사장님이 이메일·구글·카카오 중 하나로 가입하고 로그인한다.
   - 이메일 가입은 인증 메일의 링크를 눌러야 끝난다.
   - 같은 이메일이 이미 다른 방식으로 가입돼 있으면 "OO로 가입된 이메일"이라고 알리고 가입을 막는다.

**가게 등록과 무료 진단**

2. 사장님이 가게 이름과 지도 링크 1개(Google 지도·카카오맵·네이버 지도 중 하나)를 넣는다. 사장님이 넣는 가게 정보는 이 두 가지뿐이다.
3. 한눈이 링크로 가게를 찾고, 나머지 두 지도에서도 같은 가게를 찾는다. 공식 웹사이트·인스타그램·외부 사이트 정보도 모은다.
   - 후보가 여러 개면 사장님이 고른다.
   - 찾지 못하면 다른 링크를 달라고 한다.
4. 정보를 다 모으면 측정을 자동으로 시작한다. 무료 진단을 이미 쓴 계정은 자동 정비가 승인된 뒤에 측정한다.
5. 한눈이 관광객처럼 묻는 질문 3개(영어 2개, 한국어 1개)를 만든다. 이 질문을 ChatGPT·Gemini에 각각 10번씩, 모두 60번 묻는다. 끝나면 화면과 이메일로 알린다.
6. 사장님이 무료 진단 결과를 본다: AI별 추천 등장률, 평균 등장 순서, AI가 참고한 사이트, 주변 가게 5곳과 비교, 고쳐야 할 점 개수.

**자동 정비**

7. 사장님이 자동 정비를 신청한다(S12). 한눈 관리자가 승인하면 이메일로 알린다.
8. 사장님이 Google 관리 화면에서 한눈 계정을 "관리자"로, 카카오 파트너센터에서 "운영자"로 한 번씩 초대한다(S15).
   - 아이디·비밀번호는 받지 않는다.
   - 한쪽만 연결해도 그 지도부터 정비한다.
9. 한눈이 연결된 지도의 지금 값을 읽고 정비안을 만든다. 사장님이 정비안을 확인하고 [정비 시작]을 한 번 누른다(S13).
   - 근거가 없어 "확인 필요"로 표시된 칸은 사장님이 값을 넣거나 빼야 승인할 수 있다.
10. 한눈이 승인된 칸만 고치고, 제대로 바뀌었는지 다시 확인한다. 끝나면 화면과 이메일로 알린다.

**전후 비교**

11. 정비를 마치고 2주 뒤 같은 질문 3개로 다시 잰다. 전후 비교 보고서(S16)를 만들어 이메일로 알린다.

## 8. 범위

### P0: 베타에 반드시 넣는 것

**계정**

- 이메일·구글·카카오 가입과 로그인, 이메일 인증, 같은 이메일 중복 가입 차단
- 비밀번호 재설정(이메일 링크), 회원 탈퇴

**가게 등록과 정보 수집**

- 계정당 가게 1곳 등록. 언제든 바꿀 수 있다.
- 지도 링크(Google·카카오·네이버) 판별, 가게 찾기, 세 지도의 기본정보 수집
- 가게를 하나로 정하지 못하면 후보 선택 또는 다른 링크 입력
- 인터넷 정보 수집: 공식 웹사이트, AI 웹 검색으로 외부 사이트·인스타그램 확인. 인스타그램 공식 API(Business Discovery)는 사전 확인 결과를 보고 넣는다.

**측정과 무료 진단**

- 질문 3개(영어 2개, 한국어 1개) 자동 생성·검증
- ChatGPT·Gemini 반복 측정: 질문마다 AI별 10번, 모두 60번
- 추천 등장률·평균 등장 순서·출처 계산. 실패율은 내부에서만 계산하고 사장님 화면에는 보여 주지 않는다.
- 주변 가게 5곳과 비교
- 고쳐야 할 점 판정. 무료 진단에는 개수만 보여 준다.
- 무료 진단 결과(계정당 1회)

**자동 정비**

- 자동 정비 신청, 한눈 관리자의 신청 목록·승인·거절
- Google·카카오 연결: 초대 방법 안내, 초대 수락, 연결 상태 확인
- 정비안 생성: 지도별 바꿀 칸과 값, 이유, 사실 검사
- 정비안 확인과 한 번 승인. "확인 필요" 칸은 사장님이 넣거나 뺀다.
- 자동 정비 실행
  - Google: API 승인 전에는 관리 화면을 브라우저 자동화로 고치고, 승인 후에는 Business Profile API로 고친다.
  - 카카오: 파트너센터 매장정보 화면을 브라우저 자동화로 고친다.
  - 고친 뒤 다시 읽어 확인한다. 막히거나 실패한 칸은 한눈 관리자가 수동 처리한다.

**재측정과 보고서**

- 정비를 마치고 2주 뒤 재측정(정비 전과 같은 질문·같은 방식)
- 전후 비교 보고서

**공통**

- 이메일 알림 10종(F-12)
- 계정·가게·측정·정비 기록·보고서를 PostgreSQL에 저장한다. 정비 기록에는 칸마다 고치기 전 값과 바꾼 값을 남긴다. 외부에서 모은 데이터의 보관 기한은 미정이다(15장 미정 3).

### P1: 여유가 있으면 넣는 것

- 메뉴판 사진 읽기(OCR): Google 지도 사진 중 메뉴판이 있으면 메뉴·가격을 읽는다. 사진 파일은 저장하지 않는다.
- 전후 비교 보고서 PDF 내려받기
- 한눈 관리자용 사용자·가게·정비·보고서 전체 조회(정비 신청 관리는 P0)

### P2: 나중에 만드는 것

- 실제 결제(PG)와 구독
- 여러 지점 관리
- 영어 외 다국어
- 외부 채널 정보가 바뀌었는지 감지
- 월간 재측정과 알림
- 네이버 지도·공식 웹사이트·인스타그램 정비, 공개 영문 소개 페이지, LocalBusiness JSON-LD
- 소품샵·편집숍·공방·체험 매장으로 업종 확대

### 하지 않는 것

- 추천 순위나 노출 보장
- 가짜 리뷰, 리뷰 구매, 광고 집행
- 예약·주문 시스템 연동
- 상인회·지자체용 통합 대시보드
- 지도·SNS 페이지 크롤링, 로그인 세션을 이용한 정보 수집(정비용 관리 화면 자동화는 F-10에 정한 범위에서만 쓴다)
- 고칠 문구만 건네는 유료 보고서
- 초대 없이 지도의 "정보 수정 제안"을 대신 내는 정비
- 사장님 아이디·비밀번호 받기

## 9. 화면 구성

### 9.2 화면 이동

```text
S01 랜딩 → S02 회원가입 → (이메일 가입: S03 / 카카오 이메일 없음: S04) → S07 홈
S07 홈 → S08 가게 등록 → (후보가 여럿이면 S09) → S10 진행 → S11 무료 진단 결과
S11 → S12 자동 정비 신청 → (A01 승인) → S15 연결 → S13 정비안 승인 → 자동 정비
자동 정비 끝 → (2주 뒤) S10 재측정 → S16 전후 비교 보고서
```

- 로그인한 사장님이 랜딩이나 로그인 화면에 오면 S07로 보낸다.
- 로그인하지 않은 사람이 S07~S16에 오면 S05로 보내고, 로그인 후 원래 화면으로 돌려보낸다.

### 9.3 화면별 구성

#### S01 랜딩

- 첫 화면: "외국인 관광객이 ChatGPT에 맛집을 물을 때, 우리 가게가 나올까요?"와 [무료로 확인하기]
- 문제: AI는 지역의 일부 가게만 추천한다는 근거 수치 1개(2장)
- 이용 방법 4단계: 링크 넣기(무료 진단) → Google·카카오에 한눈 초대 → 바꿀 내용 승인 → 한눈이 고치고 2주 뒤 전후 비교
- 무료 진단과 자동 정비 비교표
  - 무료: 노출 정도, 주변 가게 비교, 고쳐야 할 점 개수
  - 자동 정비: 고쳐야 할 점 확인·승인, Google·카카오 정보 수정, 2주 뒤 재측정, 전후 비교 보고서
- 결과 화면 예시(무료 진단, 전후 비교 보고서). 예시 수치에는 "예시"를 붙여 실제 성과처럼 보이지 않게 한다.
- 측정 횟수(60번)는 보여 주지 않고 "여러 번"이라고만 쓴다(2026-10-16 결정).
- 안내 문구: "추천 순위나 노출을 보장하지 않습니다."
- 하단: 이용약관, 개인정보처리방침
- [무료로 확인하기]: 로그인 상태면 S07, 아니면 S02로 간다.

#### S02 회원가입

- 버튼: [구글로 시작하기], [카카오로 시작하기]
- 이메일 가입 입력: 이메일, 비밀번호, 비밀번호 확인
- 약관 동의: 이용약관(필수), 개인정보 수집·이용(필수), 전체 동의
- [가입하기], "이미 계정이 있나요? 로그인"
- 입력 규칙과 오류 문구

| 경우 | 문구·동작 |
|---|---|
| 이메일 형식이 아님 | "이메일 형식이 아니에요" |
| 비밀번호가 8자 미만이거나 영문·숫자가 섞이지 않음 | "8자 이상, 영문과 숫자를 함께 써 주세요" |
| 비밀번호 확인이 다름 | "비밀번호가 서로 달라요" |
| 필수 약관에 동의하지 않음 | [가입하기] 비활성 |
| 같은 이메일로 인증을 마친 계정이 있음 | "이 이메일은 [구글/카카오/이메일]로 가입되어 있어요"와 [그 방식으로 로그인]. 가입은 막는다. 소셜 가입도 같다 |

- 소셜 가입은 구글·카카오 동의 화면을 거쳐 돌아온다. 처음 가입이면 약관 동의를 받고 S07로 간다.

#### S03 이메일 인증 안내

- "OO@OO.com으로 인증 메일을 보냈어요. 메일의 링크를 누르면 가입이 끝나요."
- [인증 메일 다시 보내기]: 누른 뒤 60초 동안 누를 수 없다.
- [이메일 주소 바꾸기]: S02로 돌아가 다시 넣는다.
- 인증 링크는 24시간 동안 한 번만 쓸 수 있다. 만료된 링크는 "링크가 만료됐어요"와 [다시 보내기]를 보여 준다.
- 24시간 동안 인증하지 않은 계정은 지운다.
- 인증 전에 로그인하면 이 화면으로 보낸다.

#### S04 카카오 이메일 입력

- 카카오 로그인에서 이메일을 받지 못했을 때만 보인다.
- 이메일 입력 → 인증 메일 발송(S03과 같은 규칙) → 인증하면 가입 완료
- 같은 이메일 가입 차단 규칙은 S02와 같다.

#### S05 로그인

- [구글로 로그인], [카카오로 로그인], 이메일·비밀번호 입력, [로그인]
- [비밀번호를 잊으셨나요?] → S06, [회원가입] → S02
- 틀리면 "이메일 또는 비밀번호가 맞지 않아요". 어느 쪽이 틀렸는지는 알려 주지 않는다.
- 5번 연속 틀리면 10분 동안 로그인을 막는다.
- 소셜로 가입한 이메일로 비밀번호 로그인을 하면 "이 이메일은 [구글/카카오]로 가입되어 있어요"
- 로그인은 14일 동안 유지한다.

#### S06 비밀번호 재설정

- 1단계: 이메일을 넣으면 가입 여부와 관계없이 "가입된 이메일이면 재설정 메일을 보냈어요"를 보여 준다. 가입 여부를 드러내지 않기 위해서다.
- 2단계(메일 링크): 새 비밀번호와 확인을 넣으면 S05로 간다.
- 링크는 1시간 동안 한 번만 쓸 수 있다.
- 소셜 가입 계정이 요청하면 메일로 "[구글/카카오]로 로그인하세요"라고 알린다.

#### S07 홈(내 가게)

- 상단: 로고, 계정 메뉴(계정 설정, 로그아웃)
- 가게 정보 줄: 가게 이름, 주소, 찾은 출처(Google·카카오·네이버·공식 웹사이트·인스타그램 ✓/✕), [가게 변경]
- 상태 카드: 지금 상태에 맞는 카드 하나만 보여 준다.

| 상태 | 카드 내용 | 버튼 |
|---|---|---|
| 가게 없음 | "가게를 등록하고 AI 노출을 확인해 보세요" | 가게 등록 |
| 수집·측정 중 | 단계와 진행률 | 진행 상황 보기(S10) |
| 측정 실패 | "측정을 끝내지 못했어요. 무료 횟수는 차감되지 않았어요" | 다시 시도(하루 3번까지. 넘으면 "내일 다시 시도해 주세요") |
| 진단 완료 | ChatGPT·Gemini 등장률 요약, 고쳐야 할 점 N개 | 결과 보기(S11), 자동 정비 신청(S12) |
| 무료 사용 후 가게 변경 | "무료 진단은 계정당 1회예요" | 자동 정비 신청(측정 포함) |
| 정비 신청됨 | "신청이 접수됐어요. 승인되면 이메일로 알려 드려요" | 없음 |
| 신청 거절됨 | 거절 사유 | 다시 신청 |
| 연결 필요 | "Google·카카오에 한눈을 초대해 주세요"와 지도별 연결 상태 | 연결하기(S15) |
| 정비안 준비 중 | "연결된 지도의 정보를 읽고 바꿀 내용을 만들고 있어요" | 없음 |
| 정비안 확인 필요 | "바꿀 내용 N개를 확인해 주세요" | 정비안 확인(S13) |
| 정비 중 | 진행 표시. 수동 처리 칸이 있으면 "일부 칸은 한눈 팀이 직접 고치고 있어요" | 없음 |
| 재측정 대기 | "정비를 마쳤어요. M월 D일에 다시 측정해요"와 바꾼 항목 수 | 바꾼 내용 보기(S13, 읽기 전용) |
| 재측정 중 | 단계와 진행률 | 진행 상황 보기(S10) |
| 재측정 실패 | "다시 측정하지 못했어요" | 다시 시도(하루 3번까지) |
| 보고서 완료 | ChatGPT·Gemini 등장률 전후 요약 | 전후 비교 보고서(S16) |

- 정비 신청이 있으면 신청 상태 카드를 가게 상태보다 먼저 보여 준다.
- 정비 신청부터 보고서 완료 전까지는 [가게 변경]을 막고 "정비가 끝나기 전에는 가게를 바꿀 수 없어요"를 보여 준다.
- 사장님이 지도에서 한눈 권한을 지우면 "Google(또는 카카오) 연결이 끊겼어요"와 [다시 연결하기]를 보여 준다.
- 지난 기록: 가게를 바꾼 적이 있으면 이전 가게의 진단 결과와 전후 비교 보고서를 볼 수 있다(수정 불가).

#### S08 가게 등록·변경

- 입력: 가게 이름(필수, 1~50자), 지도 링크(필수)
- 링크 칸 안내: "Google 지도·카카오맵·네이버 지도에서 가게를 찾아 [공유 → 링크 복사]한 주소를 넣어 주세요." 지도별 복사 방법은 펼쳐서 본다.
- 공유 문구를 통째로 붙여 넣어도 링크만 골라낸다.
- [등록하기]를 누르면 가게를 찾는다(F-03).
  - 하나로 정해지면 S10으로 간다.
  - 후보가 여럿이면 S09로 간다.
  - 찾지 못하면 "가게를 찾지 못했어요. 다른 지도 링크를 넣어 주세요"
- 오류
  - 지원하지 않는 링크: "Google 지도·카카오맵·네이버 지도 링크만 넣을 수 있어요"
  - 음식점·카페·바가 아님: "지금은 음식점·카페·바만 진단할 수 있어요"(등록하지 않는다)
- 가게를 바꿀 때
  - "가게를 바꾸면 지금 가게의 결과는 지난 기록으로 옮겨져요"를 확인받는다.
  - 무료 진단을 이미 썼으면 "무료 진단은 다시 할 수 없어요"도 보여 준다.
  - 진행 중인 측정은 멈춘다.
  - 정비 신청이 진행 중이면 바꿀 수 없다.

#### S09 가게 후보 선택

- "어느 가게인가요?"와 후보 최대 5개(가게 이름, 주소, 업종, 찾은 지도)
- 후보를 고르면 S10으로 간다.
- [여기에 없어요]를 누르면 S08로 돌아가 "다른 지도 링크를 넣어 주세요"를 보여 준다.

#### S10 수집·측정 진행

#### S12 자동 정비 신청·진행

- 신청 전에 보여 줄 것

  - 고치지 않는 곳: 네이버 지도·공식 웹사이트·인스타그램·외부 사이트(진단에만 사용)

  - 사장님이 할 단계(연결, 확인)에는 해당 화면으로 가는 버튼을 둔다.

  - 이 문제를 고치는 칸(②)으로 가는 링크
- ② 지도별 바꿀 내용: Google 지도 / 카카오맵 탭(연결된 지도만)

  - "확인 필요" 칸: 모은 정보에 근거가 없는 값(영업시간·가격 등)이다. 사장님이 값을 넣거나 [이 칸은 빼기]를 눌러야 한다.
  - 알레르기·할랄 정보는 사장님이 확인 체크를 해야 승인할 수 있다.
  - 사장님은 바꿀 값을 직접 고칠 수 있다. 고친 값도 글자 수·형식 규칙(F-09)을 지켜야 한다.
  - 가게 이름·주소·업종은 한눈이 바꾸지 않는다. 다르면 사장님이 직접 고치는 방법을 알려 준다.
  - Google·카카오에서 가게를 찾지 못했으면 등록·인증 방법을 보여 준다. 등록하고 연결하면 정비안을 다시 만든다.
- ③ 진단 근거(펼치기): 질문별 AI 답변 원문. 우리 가게와 주변 가게 이름을 강조한다.
- 하단 안내와 버튼
  - "승인하면 위 내용으로 Google 지도·카카오맵을 고쳐요. 고치기 전 값은 한눈에 기록해 두고, 각 지도 관리 화면에서 언제든 직접 되돌릴 수 있어요."
  - [정비 시작]: 한 번 누르면 연결된 지도에서 승인한 칸을 모두 고친다.

- 승인 뒤에는 읽기 전용이 된다. 칸마다 결과(완료, 반영 대기, 한눈 팀 처리 중)를 보여 준다.

| 3 | 사장님 | 사이드메뉴에서 매장을 고르고, 대시보드 오른쪽 위 [⋮] → [운영자 관리]로 간다. |
| 4 | 사장님 | 한눈 화면에서 복사한 한눈 카카오계정(이메일 또는 전화번호)을 넣고 [운영자 초대]를 누른다. |
| 5 | 한눈 | 카카오톡 채널 메시지나 파트너센터 사이드메뉴 > 받은 요청에서 초대를 수락한다. |
| 6 | 한눈 | 파트너센터에 그 매장이 보이는지, 매장 > 매장정보 화면이 열리는지 확인한다. |
| 7 | 한눈 | 카드를 "연결됨"으로 바꾼다. 이후 처리는 Google과 같다. |

- 운영자가 할 수 있는 것: 매장 정보 수정, 후기 관리, 소식 작성
- 대표자만 할 수 있는 것: 대표자 변경, 매장 삭제, 매장주 인증, 운영자 초대·내보내기, 카카오톡 채널 연결
- 대표자는 [운영자 관리]에서 아직 수락하지 않은 초대를 취소하거나, 운영자를 [내보내기]로 뺄 수 있다.
- 한눈이 고칠 수 있는 칸: 영업시간(휴게·공휴일·임시 영업·날짜 지정 휴무), 가격 정보(상품·가격·사진·소개, 추천 2개), 매장 사진(최대 100장, 태그), 사이트·SNS 링크(가게가 직접 운영하는 곳만), 제공 서비스, 태그(5개), 한 줄 소개(50자)
- 주소·업종 변경은 사업자등록증이 필요해 사장님에게 맡긴다.
- 고치는 방법: 카카오는 매장 정보 수정 API가 없다. 그래서 한눈 카카오계정으로 파트너센터 매장 > 매장정보 화면을 브라우저 자동화로 고친다(2026-10-16 결정). 규칙은 Google과 같다(F-10).
- 매장관리에서 고친 내용은 30분~1시간 뒤 반영된다(주소·업종 제외).
- 외부 업체를 운영자로 둬도 되는지에 대한 카카오의 제한 문구는 찾지 못했다. 고객센터에 물어본다(13장 사전 확인).

#### 네이버 지도: 정비하지 않음

- 스마트플레이스의 운영자 권한은 네이버 도움말상 **사업자의 내부 직원에게만** 줄 수 있다. 운영자는 예약 고객 연락처 등을 볼 수 있어서, 외부인에게 주면 개인정보보호법상 동의 없는 제3자 제공이 될 수 있다.
- 한눈이 네이버 주인 권한을 대신 받지도 않는다. 네이버는 주인 변경 어뷰징을 감시하고, 대표자가 아닌 사람의 신청에는 재직증명서를 요구한다.
- 그래서 네이버는 정비하지 않는다(2026-10-17 결정). 네이버 기본정보는 가게 찾기와 진단 비교에만 쓴다.

### F-02 가게 등록·변경

- 계정당 가게 1곳이다. 언제든 바꿀 수 있다.
- 바꾸면 이전 가게의 진단·보고서는 지난 기록으로 옮기고(보기만 가능), 진행 중인 측정은 멈춘다.
- 정비 신청부터 전후 비교 보고서 완료 전까지는 바꿀 수 없다. 보고서가 끝났거나 신청이 거절되면 바꿀 수 있다.
- 대상 업종은 음식점·카페·바다. 지도에서 받은 업종이 아니면 등록하지 않는다.
- 무료 진단은 계정당 1회다. 진단이 정상으로 끝났을 때만 차감한다.

### F-03 링크 판별과 가게 찾기

| 지도 | 받는 링크 형식 |
|---|---|
| Google | `google.com/maps/place/…`, `maps.app.goo.gl/…`, `goo.gl/maps/…` |
| 카카오 | `place.map.kakao.com/{번호}`, `map.kakao.com/…`, `kko.to/…` |
| 네이버 | `map.naver.com/…/place/{번호}`, `m.place.naver.com/…/{번호}`, `naver.me/…` |

- 짧은 링크는 어디로 이동하는지만 확인하고, 지도 페이지 내용은 읽지 않는다.
- 찾는 순서
  1. 링크에서 지도 종류와 가게 번호를 얻는다. Google은 이름·좌표도 얻는다.
  2. 그 지도의 공식 API로 가게 이름을 검색해, 링크의 가게 번호와 같은 결과를 찾는다(Google·카카오). 네이버 API는 가게 번호를 주지 않으므로 이름이 맞는 결과로 판단한다.
  3. 나머지 두 지도에서 이름으로 검색한다. 좌표가 100m 안이고 이름이 비슷하면 같은 가게로 본다.
- 결과가 하나면 자동으로 정한다. 여러 개면 S09에서 고르게 한다. 없으면 다른 링크를 달라고 한다.
- 다른 지도에서 찾지 못하면 그 지도는 "찾지 못함"으로 두고 진행한다.
  - Google·카카오에서 찾지 못하면 고쳐야 할 점(지도 미등록)으로 세고, S13에서 등록·인증 방법을 알려 준다.
  - 네이버에서 찾지 못하면 그대로 진행한다.

공식 API, robots.txt가 허용한 공식 웹사이트, AI 웹 검색으로만 모은다. 크롤링은 하지 않는다.

| 카카오 로컬 API | 이름, 업종, 전화, 지번·도로명 주소, 좌표, 장소 링크 |
| 네이버 지역 검색 API | 이름, 업종, 지번·도로명 주소, 좌표, 홈페이지 링크 |
| 공식 웹사이트 | Google에 등록된 웹사이트(없으면 네이버 검색 결과의 홈페이지)가 robots.txt로 허용할 때만 읽는다. 첫 페이지와 메뉴 페이지 1개에서 메뉴·가격·영업시간·소개·영문 페이지 여부를 뽑는다 |

- 사진 파일은 저장하지 않는다. P0 분석에는 사진 수만 쓴다.
- (P1) Google 사진 중 메뉴판 사진이 있으면 그때 불러와, AI로 메뉴판인지 판별하고 메뉴·가격을 읽는다. 읽은 글자만 쓰고 사진은 저장하지 않는다.
- 수집은 30초 안에 끝내는 것이 목표다. 일부 출처가 실패해도 받은 값으로 진행한다.
- 로그인 세션으로 인스타그램을 자동 수집하는 도구(예: Agent-Reach의 인스타그램 기능)는 쓰지 않는다. 인스타그램 약관 위반이고 계정이 정지될 수 있다.
- 카카오·네이버의 영업시간·메뉴·리뷰·사진은 진단 단계에서 모으지 않는다. 공식 API로 주지 않고, 카카오는 크롤링 금지와 제휴 불가를 공식 답변했다(2026-09-21).
- 카카오의 지금 매장 정보는 사장님이 한눈을 운영자로 초대한 뒤(S15), 정비안을 만들 때 파트너센터 매장정보 화면에서만 읽는다(F-09).
- 카카오 API 데이터는 장소 ID와 장소 링크만 저장할 수 있다. 이름·주소 등은 필요할 때 다시 불러온다.
- 네이버 지역 검색 API 키는 2026-07-31부터 NAVER API HUB(네이버 클라우드)에서만 새로 받을 수 있다.

### F-05 질문 만들기

- 입력: 지역(동·구 또는 관광지 이름), 업종, 특징(가격대, 채식 가능 여부, 대표 메뉴 종류 등 모은 값)
- 질문 3개

| 질문 | 언어·형태 | 예 |
|---|---|---|
| 질문 1 | 영어, 기본형: 지역+업종 | "What are good Korean restaurants near Myeongdong?" |
| 질문 2 | 영어, 조건형: 지역+업종+특징 | "Where can I find affordable vegetarian-friendly Korean food in Myeongdong?" |
| 질문 3 | 한국어, 기본형: 지역+업종 | "명동 근처 맛있는 한식당 추천해줘" |

- 자동 검증: 가게 이름(한글·영문, 일부 포함)이 없을 것, 지역 이름과 업종이 들어 있을 것, 3개가 서로 다를 것
- 검증에 실패하면 3번까지 다시 만든다. 그래도 실패하면 업종별 고정 문장에 지역·업종만 넣는다.
- 질문은 측정 결과와 함께 저장한다.

### F-06 AI 측정

- ChatGPT는 OpenAI API, Gemini는 Gemini API로 묻는다. 둘 다 웹 검색을 켠다.
- 질문은 관광객이 묻듯 그대로 보낸다. 다른 지시는 붙이지 않는다.
- 질문 3개 × AI 2개 × 10번 = 60번
- 호출 하나의 제한 시간은 60초다. 실패하면 2번까지 다시 시도한다.
- 저장: 질문, AI, 모델 이름, 회차, 시각, 답변 원문, 출처 링크
- 실패한 호출은 "추천 안 됨"으로 세지 않는다.
- 실패율이 30%를 넘으면 결과를 확정하지 않고 "측정 실패"로 둔다. 무료 횟수는 차감하지 않는다.
- 측정 실패 후 다시 시도는 가게당 하루 3번까지다.

### F-07 추천 가게 뽑기와 지표

- 답변마다 추천한 가게 목록(이름, 순서, 함께 붙은 출처)을 뽑는다.
- 우리 가게 판정: 이름만 맞아도 등장으로 센다.
  - 비교할 이름: 세 지도의 한글·영문 이름
  - 대소문자·띄어쓰기·기호는 무시한다. "본점", "○○점" 같은 지점 이름은 떼고 비교한다.

| 지표 | 계산 | 사장님 화면 |
|---|---|---|
| 추천 등장률 | 우리 가게가 나온 답변 수 ÷ 성공한 답변 수(AI별 전체, AI별·질문별) | 보여 줌 |
| 평균 등장 순서 | 우리 가게가 나온 답변에서의 순서 평균 | 보여 줌 |
| 출처 | 사이트별 인용 횟수, 우리 가게 추천에 붙은 사이트 | 보여 줌 |
| 실패율 | 실패한 호출 ÷ 전체 호출 | 보여 주지 않음 |

- 추천 목록을 뽑지 못한 답변은 성공한 답변에서 빼고, 계산의 분모에도 넣지 않는다.
- 주변 가게 5곳: 우리 가게를 뺀 가게 중 60개 답변에서 가장 많이 나온 순서로 뽑는다. 같으면 평균 순서가 앞선 가게가 먼저다. 이름은 우리 가게와 같은 방식으로 묶는다.
- 주변 가게도 우리 가게와 같은 방식으로 등장률·평균 순서를 계산한다.

### F-08 고쳐야 할 점 판정

- 무료 진단 때 판정해 개수만 보여 준다. 내용은 정비안 화면(S13)에서 보여 준다.
- 한눈이 고치는 Google 지도·카카오맵에서 고칠 수 있는 것만 센다.

| 분류 | 판정 기준 | 예 |
|---|---|---|
| 지도에 정보 없음 | Google의 영업시간·가격대·웹사이트·전화·소개·메뉴·편의 정보 중 빈 칸. Google·카카오에서 가게를 찾지 못한 경우도 포함 | Google 지도에 영업시간이 없어요 |
| 출처끼리 정보 다름 | Google·카카오의 이름·주소·전화·영업시간이 공식 웹사이트·인스타그램·외부 사이트(AI 웹 검색)·네이버 기본정보와 다름 | 공식 웹사이트와 Google의 영업시간이 달라요 |
| 영문 정보 부족 | Google 소개·메뉴에 영어가 없음 | 영어 소개가 없어요 |
| 질문 조건 정보 부족 | 질문 조건(채식, 가격 등)에 맞는 정보가 Google 편의 정보·카카오 제공 서비스·태그에 없고, 주변 가게의 추천 이유에는 있음 | 채식 가능 여부가 표시돼 있지 않아요 |
| AI가 틀리게 말함 | AI가 말한 우리 가게 정보(영업시간·위치·가격)가 공식 웹사이트·Google·카카오 값과 다르고, 원인이 지도 값에 있음 | ChatGPT가 영업시간을 틀리게 말해요 |

- 인스타그램 검색 노출 부족, 외부 사이트 근거 부족처럼 Google·카카오 밖에서 고쳐야 하는 문제는 세지 않는다(2026-10-17 결정).
- 카카오의 영업시간·메뉴 등은 연결 전에는 알 수 없다. 그래서 무료 진단에서는 카카오 기본정보(이름·주소·전화·업종)만 판정한다. 나머지는 연결 뒤 정비안을 만들 때 판정해 더한다. 그래서 정비안의 항목 수가 무료 진단의 개수보다 많을 수 있다.
- 영향 순서: 주변 가게 5곳 중 그 정보를 갖춘 가게가 많을수록, 관련 질문이 많을수록 앞에 둔다. 근거가 부족한 항목은 맨 뒤에 둔다.
- 네이버 응답은 코드로만 비교하고 AI에 넣지 않는다.

### F-09 정비안 만들기

- 자동 정비가 승인되고 지도가 연결되면 그 지도의 정비안을 만든다. 진단 결과가 없는 가게는 측정(F-05~F-08)부터 한다.
- 입력: 모은 정보, 연결 뒤 읽은 Google·카카오의 지금 값, 진단 결과, 고쳐야 할 점
- 출력: 지도별 칸 이름, 지금 값, 바꿀 값, 이유(어떤 고쳐야 할 점 때문인지, 근거)
- 바꿀 수 있는 칸

| 지도 | 칸 |
|---|---|
| Google | 소개(영문 포함), 영업시간·특별 영업시간, 웹사이트, 전화, 메뉴·가격(지원되는 음식점만), 편의 정보(채식·결제·예약·포장 등) |
| 카카오 | 한 줄 소개(50자), 영업시간(휴게·공휴일·임시 영업·휴무), 가격 정보, 사이트·SNS 링크, 제공 서비스, 태그(5개) |

- 바꾸지 않는 칸: 가게 이름·주소·업종. Google은 재인증·검토 위험이 있고, 카카오는 사업자등록증이 필요하다. 다르면 S13에서 사장님이 직접 고치는 방법을 알려 준다.
- 쓰는 규칙
  - 모은 정보에 없는 사실은 지어내지 않는다. 모르는 값은 [ ]로 비우고 "확인 필요"를 붙인다. 사장님이 S13에서 넣거나 뺀다.
  - 알레르기·할랄 같은 민감 정보는 모은 정보에 있을 때만 쓰고 "사장님 확인 필요"를 붙인다.
  - 지도의 칸 이름과 글자 수 제한을 지킨다.
  - 바꿀 칸마다 근거(관련 AI 답변, 모은 정보, 주변 가게 비교)를 연결한다.
- 3분 안에 만드는 것이 목표다. 실패하면 1번 자동으로 다시 하고, 그래도 실패하면 A01에 "생성 실패"로 표시한다.
- 정비안은 만든 날, 기준 진단, 사장님이 승인한 최종 값과 함께 저장한다.

### F-10 연결과 자동 정비

**연결(S15)**

- Google은 한눈 공용 계정을 "관리자"로, 카카오는 한눈 공용 카카오계정을 "운영자"로 초대받는다.
- 초대 수락은 처음에는 한눈 관리자가 직접 한다. Google API 승인 뒤에는 API로 한다.
- 연결되면 그 지도의 지금 값을 읽는다.

**승인(S13)**

- 사장님이 [정비 시작]을 한 번 누르면 연결된 지도에서 승인한 칸만 고친다.

**고치는 방법**

| 지도 | 방법 |
|---|---|
| Google 지도 | API 승인 전: `business.google.com` 관리 화면을 브라우저 자동화로 고친다. 승인 후: Business Profile API로 고친다 |
| 카카오맵 | 파트너센터 매장 > 매장정보 화면을 브라우저 자동화로 고친다(수정 API 없음) |

**고칠 때 지키는 규칙**

- 고치기 전 값을 칸마다 저장한다. 전후 비교 보고서와 되돌리기 안내에 쓴다.
- 고친 뒤 다시 읽어 바뀌었는지 확인한다. 카카오는 30분~1시간 뒤 반영되고 Google은 검토가 붙을 수 있으므로, 반영을 기다리는 칸은 24시간 동안 다시 확인한다.
- 로그인 차단·보안 확인 같은 자동화 차단이 뜨거나 수정에 실패하면, 그 칸을 "수동 처리 필요"로 A01에 넘긴다. 한눈 관리자가 직접 고치고 [처리 완료]를 누른다. 차단은 우회하지 않는다.
- 승인한 칸이 모두 끝나면(자동 완료 또는 수동 처리 완료) 정비 완료로 바꾼다. 사장님에게 이메일을 보내고, 14일 뒤로 재측정을 예약한다(F-11).
- 사장님이 지도에서 한눈 권한을 지우면 그 지도의 정비를 멈추고, S07에 "연결이 끊겼어요"를 보여 준다.
- 정비는 신청 1건당 1번이다. 정비 뒤 사장님이 지도에서 직접 바꾼 값은 다시 덮어쓰지 않는다.

### F-11 재측정과 전후 비교 보고서

- 정비 완료 14일 뒤 자동으로 시작한다. 한눈 관리자는 테스트·시연용으로 A01에서 앞당길 수 있다.
- 정비 전 측정과 같은 질문 3개(질문 버전 고정), 같은 AI, 같은 반복 횟수로 잰다(F-06).
- 정보 수집(F-04)도 다시 해서, 고친 값이 지도에 반영됐는지 확인한다.
- 실패율이 30%를 넘으면 "재측정 실패"로 두고 보고서를 만들지 않는다. 다시 시도는 하루 3번까지다.
- 보고서에 넣는 전·후 지표: AI별 등장률, 평균 등장 순서, 질문별 등장 횟수, 우리 가게 추천에 쓰인 출처, 주변 가게 비교(정비 전 5곳의 전·후, 정비 후 새 5곳)
- 쓰는 규칙
  - 변화를 정비 효과라고 단정하지 않는다. 주변 가게의 변화와 측정일을 함께 보여 준다.
  - 순위·노출을 보장하는 표현을 쓰지 않는다. 변화가 없거나 줄어도 그대로 보여 준다.
- 3분 안에 만드는 것이 목표다. 실패하면 1번 자동으로 다시 하고, 그래도 실패하면 A01에 "생성 실패"로 표시한다.
- 보고서는 정비 전·후 측정, 정비 기록과 함께 저장하고 언제든 다시 볼 수 있다.

## 11. 할 일

베타에 넣을 기능(P0)을 할 일 단위로 나눈다. 할 일마다 정상 동작, 예외 처리, 완료 조건을 정한다. 자동 테스트·DB 제약·로그 같은 기술적 확인 방법은 명세서에 적는다.

### 11.1 공통 기준

- 담당: 개발 = 김태욱(개발·데이터), 기획 = 강가힐(기획·UI)
- 순서: 표의 "먼저 끝낼 일"이 끝나야 시작할 수 있다.
- **테스트 가게 세트**: 실제 음식점·카페·바 20곳(2개 이상 지역)
  - 가게마다 Google·카카오·네이버 링크(긴 링크·짧은 링크)와 정답(가게 이름, 주소, Google 장소)을 미리 적어 둔다.
  - 실제 가게 모집안과 함께 준비한다.
  - 비용이 큰 측정·재측정 시험은 이 중 5곳으로 한다.
- **정비 시험 가게**: 자동 정비는 실제 지도 정보를 바꾼다. 그래서 사장님이 동의하고 한눈을 초대한 가게(지인 가게 1~2곳)에서만 시험한다. 테스트 가게 세트의 다른 가게에는 정비를 하지 않는다.
- 모든 할 일의 완료 조건에는 "정상·예외 동작을 실제로 재현해 확인하고, 결과를 테스트 기록에 남겼다"가 들어 있다.

### 11.3 할 일별 정상·예외·완료 조건

#### W-01 계정

**W-01-1 가입·로그인 화면 설계**
- 정상: S02~S06의 입력 칸, 버튼, 안내 문구, 이동 경로를 9장대로 설계한다.
- 예외: 오류 문구(형식, 비밀번호 규칙, 중복 이메일, 잠금, 링크 만료)를 모두 화면에 배치한다.
- 완료: 설계가 9장의 문구·규칙과 같고, 개발 화면과 비교해 차이가 없다.

**W-01-2 이메일 가입·인증**
- 정상: 규칙에 맞는 이메일·비밀번호와 필수 약관 동의 → 미인증 계정 생성 → 인증 메일 발송 → S03. 링크를 누르면 인증되고 로그인된 상태로 S07에 간다.
- 예외
  - 같은 이메일로 인증을 마친 계정이 있으면 기존 가입 방식을 알리고 계정을 만들지 않는다.
  - 같은 이메일의 미인증 계정만 있으면 이전 계정을 지우고 새로 만든다.
  - 입력 규칙을 어기면 해당 오류 문구를 보여 준다.
  - 만료됐거나 이미 쓴 링크는 "링크가 만료됐어요"와 [다시 보내기]를 보여 준다.
  - 메일 발송이 3번 실패하면 S03에 "메일을 보내지 못했어요. 다시 보내기를 눌러 주세요"를 보여 준다.
  - 24시간 동안 인증하지 않은 계정은 지운다.
- 완료: Gmail·네이버 메일로 인증 메일을 받아 가입을 끝낼 수 있고, 위 예외가 모두 재현된다.

**W-01-3 구글·카카오 로그인**
- 정상: 구글·카카오 동의 후 돌아오면, 처음 가입이면 약관 동의 → S07, 기존 계정이면 바로 S07.
- 예외
  - 동의를 취소하면 S02로 돌아와 "로그인이 취소됐어요"를 보여 준다.
  - 구글 이메일이 인증되지 않았으면 가입하지 않는다.
  - 카카오가 이메일을 주지 않으면 S04로 보낸다.
  - 같은 이메일이 다른 방식으로 인증돼 있으면 알리고 막는다.
  - 구글·카카오 쪽 오류면 "잠시 후 다시 시도해 주세요"를 보여 준다.
- 완료: 실제 구글·카카오 계정으로 가입·로그아웃·재로그인이 되고, 중복 차단 3가지(이메일↔구글, 이메일↔카카오, 구글↔카카오)가 모두 막힌다.

**W-01-4 로그인·잠금·세션**
- 정상: 맞는 정보로 로그인하면 S07로 가고 14일 동안 유지된다. 로그아웃 후 보호 화면에 들어가면 S05로 간다.
- 예외: 틀리면 공통 문구를 보여 준다. 5번 연속 틀리면 10분 잠금을 알린다. 소셜 가입 이메일로 비밀번호 로그인을 하면 가입 방식을 알린다. 미인증 계정은 S03으로 보낸다.
- 완료: 잠금이 10분 뒤 풀리고, 로그아웃 후 뒤로 가기로 보호 화면이 보이지 않는다.

**W-01-5 비밀번호 재설정**
- 정상: 이메일 입력 → 같은 안내 문구 → 메일 링크 → 새 비밀번호 → S05 → 새 비밀번호로 로그인
- 예외: 가입되지 않은 이메일에도 같은 문구를 보여 주고 메일은 보내지 않는다. 소셜 가입 계정에는 가입 방식을 알리는 메일을 보낸다. 만료·재사용 링크, 비밀번호 규칙 위반, 요청 횟수 초과(IP당 분당 5번)를 처리한다.
- 완료: 재설정 후 이전 비밀번호로 로그인되지 않고, 같은 링크를 두 번 쓸 수 없다.

**W-01-6 계정 설정·탈퇴**
- 정상: 지금 비밀번호를 확인한 뒤 비밀번호를 바꾼다. 탈퇴는 확인 문구를 넣으면 바로 지우고 S01로 보낸다.
- 예외: 지금 비밀번호가 틀리면 바꾸지 않는다. 확인 문구가 다르면 탈퇴 버튼을 막는다. 측정·정비·보고서 생성 중이면 작업을 멈춘 뒤 지운다. 이미 고친 Google·카카오 정보는 지도에 남는다.
- 완료: 탈퇴 후 계정·가게·결과가 남지 않고, 같은 이메일로 다시 가입해도 무료 진단을 쓸 수 없다.

#### W-02 가게 등록·찾기

**W-02-1 가게 등록·후보 선택 화면 설계**
- 정상: S08(가게 이름, 링크, 지도별 링크 복사 방법), S09(후보 최대 5개)를 9장대로 설계한다.
- 예외: 오류 문구 4가지(지원하지 않는 링크, 가게를 찾지 못함, 대상 업종 아님, 신청 중 변경 불가)와 가게 변경 확인 문구를 배치한다.
- 완료: 설계와 개발 화면이 같다.

**W-02-2 링크 판별**
- 정상: 세 지도의 긴 링크·짧은 링크, 공유 문구를 통째로 붙여 넣은 경우에서 지도 종류와 가게 번호(Google은 이름·좌표)를 얻는다.
- 예외: 지원하지 않는 링크와 링크가 없는 입력에는 오류 문구를 보여 준다. 짧은 링크가 3번 넘게 이동하거나 5초 안에 확인되지 않으면 "링크를 확인하지 못했어요. 다른 링크를 넣어 주세요"를 보여 준다.
- 완료: 테스트 가게 20곳의 세 지도 링크(긴·짧은 형식)를 모두 판별하고, 지원하지 않는 링크 10개를 모두 거부한다.

**W-02-3 가게 찾기·다른 지도에서 같은 가게 찾기**
- 정상: 결과가 하나면 확정하고, 나머지 두 지도에서 같은 가게를 찾아 저장한 뒤 S10으로 간다.
- 예외: 결과가 여러 개면 S09, 없으면 다른 링크를 요청한다. 다른 지도에서 찾지 못하면 "찾지 못함"으로 두고 진행한다. 외부 API 오류나 10초 초과면 "잠시 후 다시 시도해 주세요"를 보여 주고 저장하지 않는다.
- 완료(테스트 가게 20곳 기준)
  - Google·카카오 링크: 20곳 모두 맞게 찾고, 잘못 찾은 곳 0곳
  - 네이버 링크: 18곳 이상 자동 확정되거나 후보 목록에 정답이 있고, 잘못 찾은 곳 0곳
  - 다른 지도에서 같은 가게 찾기: 지도별 18곳 이상 맞게 찾고, 다른 가게를 같은 가게로 잡은 경우 0곳

**W-02-4 업종 확인·가게 등록**
- 정상: 음식점·카페·바로 확인되면 등록한다.
- 예외: 대상 업종이 아니면 "지금은 음식점·카페·바만 진단할 수 있어요"를 보여 주고 등록하지 않는다.
- 완료: 테스트 가게 20곳이 모두 등록되고, 대상이 아닌 가게 5곳(예: 미용실, 편의점)은 모두 거부된다.

**W-02-5 가게 변경**
- 정상: 변경을 확인하면 이전 가게는 지난 기록으로 옮겨져 보기만 할 수 있다. 무료 진단을 아직 안 썼으면 새 가게도 수집 후 측정이 자동으로 시작된다. 이미 썼으면 수집까지만 하고 S07에 "무료 사용 후 가게 변경" 카드를 보여 준다.
- 예외: 정비 신청이 진행 중이면 변경을 막는다. 측정 중에 바꾸면 측정을 멈추고 무료 횟수는 차감하지 않는다.
- 완료: 무료 미사용·사용 완료·측정 중·신청 중 4가지 경우가 모두 맞게 동작한다.

#### W-03 정보 수집

**W-03-1 Google 상세정보 수집**
- 정상: F-04의 Google 항목을 받아 저장한다.
- 예외: 빈 항목은 빈 값으로 두고 화면에 보여 주지 않는다. API 오류는 1번 다시 시도하고, 그래도 실패하면 Google을 "수집 실패"로 두고 나머지 출처를 진행한다. Google에서 가게를 찾지 못했으면 고쳐야 할 점 판정(F-08)으로 넘긴다.
- 완료: 테스트 가게 20곳 모두 수집되고, 가게마다 받은 항목 목록이 기록되며, 30초 안에 끝난다.

**W-03-2 카카오·네이버 기본정보 수집**
- 정상: 카카오는 장소 ID·장소 링크만 저장하고, 이름·주소 등은 화면에 보여 줄 때 다시 불러온다. 네이버 결과는 가게 찾기, 홈페이지 주소 확인, 기본정보(이름·주소·전화·업종) 비교에만 쓴다.
- 예외: 호출에 실패하면 그 지도를 "찾지 못함"으로 표시하고 진행한다.
- 완료: 카카오 장소 ID·링크 외의 값이 저장되지 않고, AI에 보내는 내용에 네이버 결과가 들어가지 않는다.

**W-03-3 공식 웹사이트 수집**
- 정상: robots.txt가 허용하면 첫 페이지와 메뉴 페이지 1개를 읽어 메뉴·가격·영업시간·소개·영문 페이지 여부를 뽑는다.
- 예외: 웹사이트가 없으면 건너뛴다. robots.txt가 막으면 읽지 않고 "읽기 허용 안 됨"으로 기록한다. 10초나 1MB를 넘거나 오류가 나면 건너뛴다. 등록된 웹사이트가 인스타그램이면 인스타그램 출처로 분류한다.
- 완료: 웹사이트가 있는 테스트 가게 모두에서 robots.txt를 지키고(막힌 사이트를 읽은 경우 0건), 영업시간·대표 메뉴 추출 결과가 사람이 확인한 값과 80% 이상 같다.

**W-03-4 AI 웹 검색 수집**
- 정상: ChatGPT·Gemini에 각각 1번 물어 AI가 찾은 사이트와 사이트별 가게 정보를 저장한다.
- 예외: 한쪽이 실패하면 다른 쪽 결과만 쓴다. 둘 다 실패하면 외부 사이트 정보 없이 진행하고, 외부 사이트가 필요한 판정은 건너뛴다. 이름·주소가 맞지 않는 다른 가게 정보는 버린다.
- 완료: 테스트 가게 20곳 모두 결과가 저장되고, 사람이 확인했을 때 다른 가게 정보가 섞인 비율이 10% 이하다.

**W-03-5 인스타그램 확인(사전 확인 포함)**
- 정상: AI 웹 검색 결과의 인스타그램 주소로 가게 계정을 찾는다. 사전 확인을 통과하면 Business Discovery로 소개글·최근 게시물을 받는다.
- 예외: 계정을 찾지 못하거나 개인·비공개 계정이면 인스타그램 정보 없이 진행한다. 인스타그램은 정비 대상이 아니라 고쳐야 할 점으로 세지 않는다. Business Discovery가 실패하면 AI 웹 검색 결과만 쓴다.
- 완료: 사전 확인 결과(앱 심사·비즈니스 인증 없이 되는지)를 기록하고 쓸지 정한다. 인스타그램이 있는 테스트 가게에서 계정 찾기 성공률을 기록한다.

**W-03-6 모은 정보 표시**
- 정상: S10에 출처별로 값이 있는 항목만 보여 준다.
- 예외: 모든 출처가 실패해도 화면은 오류 없이 다음 단계로 넘어간다. 측정을 시작할지는 W-04-1이 정한다.
- 완료: 빈 칸이 화면에 나오지 않고, 카카오 값은 매번 새로 불러온 값이다.

#### W-04 질문 만들기·AI 측정

**W-04-1 질문 만들기·검증**
- 정상: 질문 3개(영어 2, 한국어 1)를 만들고 검증을 통과하면 확정한다.
- 예외: 검증에 실패하면 3번까지 다시 만들고, 그래도 실패하면 업종별 고정 문장을 쓴다. 수집에서 지역·업종을 얻지 못하면 측정을 시작하지 않고 "가게 정보를 가져오지 못했어요"와 [다시 시도]를 보여 준다(무료 횟수 차감 없음).
- 완료: 테스트 가게 20곳 모두 질문이 만들어지고, 가게 이름이 들어간 질문 0개, 지역·업종이 빠진 질문 0개다.

**W-04-2 AI 호출·원본 저장**
- 정상: 질문을 그대로 보내고 웹 검색을 켜서, 답변 원문·출처·모델 ID를 저장한다.
- 예외: 시간 초과·오류는 2번 다시 시도하고, 그래도 실패하면 실패로 기록한다("추천 안 됨"으로 세지 않음). 같은 호출이 두 번 실행되지 않게 막는다. 하루 비용 상한을 넘으면 새 측정을 기다리게 한다.
- 완료: 테스트 가게 5곳 × 60번 실행에서 성공한 답변 원문이 100% 저장되고, 중복 호출 0건, 호출마다 비용이 기록된다.

**W-04-3 백그라운드 측정·진행률**
- 정상: 측정을 시작하면 바로 S10이 열리고 3초마다 진행률이 바뀐다. 끝나면 S11로 가고 이메일을 보낸다.
- 예외: 창을 닫아도 측정은 계속되고, 끝나면 이메일이 온다. 작업 서버가 다시 시작되면 끝나지 않은 호출만 이어서 한다. 가게 변경·탈퇴 때는 측정을 멈춘다.
- 완료: 측정 중 작업 서버를 다시 시작해도 결과가 사라지거나 중복되지 않고, 테스트 가게 5곳의 측정이 15분 안에 끝난다.

**W-04-4 측정 실패·다시 시도**
- 정상: 실패율이 30% 이하면 결과를 확정한다.
- 예외
  - 30%를 넘으면 "측정 실패"로 두고 무료 횟수를 차감하지 않는다.
  - 다시 시도는 가게당 하루 3번까지다. 넘으면 "내일 다시 시도해 주세요"를 보여 준다.
  - 한 질문의 성공한 답변이 0개면 그 질문은 "측정하지 못함"으로 표시한다. 전체 실패율이 30% 이하면 나머지 결과는 확정한다.
- 완료: 실패율 29%·31%를 일부러 만들어 각각 확정·실패가 되고, 4번째 다시 시도가 거부된다.

**W-04-5 진행·오류 화면 설계**

- 완료: 예약 시각에 재측정이 시작되고, 질문 버전이 정비 전과 같으며, [지금 재측정]으로 앞당길 수 있다.

**W-12-2 전후 비교 계산·보고서 만들기**
- 정상: 정비 전·후 지표, 주변 가게 비교, 출처 변화, 바꾼 내용을 계산해 보고서를 저장하고 이메일을 보낸다.
- 예외: 한쪽 측정에서 "측정하지 못함"인 질문은 비교에서 빼고 표시한다. 생성에 실패하면 1번 다시 하고, 그래도 실패하면 A01에 표시한다.
- 완료: 손으로 계산한 전후 예시 3개와 결과가 같고, 보고서에 순위 보장 표현이 없다.

**W-12-3 전후 비교 보고서 화면 설계**
- 정상: S16의 요약, 주변 가게 전·후, 질문별 전·후, 출처 변화, 바꾼 내용, 측정 조건을 설계한다.
- 예외: 변화 없음·감소, "지금 지도 값이 달라요", 앞당겨 측정한 경우의 표시를 설계한다.
- 완료: 처음 보는 사람이 팀 내부 시연에서 설명 없이 무엇이 바뀌었는지 이해하고, 설계와 개발 화면이 같다.

**W-12-4 전후 비교 보고서 화면**
- 정상: 9장 S16 구성대로 보여 준다.
- 예외: 권한이 없으면 S07로 보낸다. 보고서가 아직 없으면 S12 진행 단계 화면으로 보낸다.
- 완료: 동의한 지인 가게의 보고서 숫자가 저장된 지표와 같고, 권한 없는 계정의 서버 응답에 보고서 내용이 없다.

| 우리 가게 판정 | 이름만 맞아도 등장으로 센다 |
| 주변 가게 | 같은 질문에서 AI가 가장 많이 추천한 다른 가게 5곳 |
| 모은 정보 화면 | 모은 값은 보여 주고, 빈 칸은 보여 주지 않는다 |
| 무료 진단 | 계정당 1회. 추천 등장률·평균 등장 순서·출처, 주변 가게 비교, 고쳐야 할 점 개수만 보여 준다 |
| 유료 보고서 | 없앰. 고칠 문구만 건네는 보고서는 만들지 않는다(2026-10-17) |
| 자동 정비 | 한눈이 Google 지도·카카오맵 정보를 직접 고친다. 베타는 신청 후 한눈 관리자 승인(가격 미정). 사장님은 정비안을 보고 한 번 승인한다(2026-10-17) |
| 전후 비교 | 정비를 마치고 2주 뒤, 정비 전과 같은 질문·같은 방식으로 다시 재서 전후 비교 보고서를 준다(2026-10-17) |
| 정비 대상 | Google 지도·카카오맵만. 네이버 지도·공식 웹사이트·인스타그램·외부 사이트는 수집·진단에만 쓴다(2026-10-17) |
| 사장님이 하는 일 | Google·카카오에 한눈 계정을 한 번씩 초대하고, 정비안을 한 번 승인한다. 고치는 일은 한눈이 한다. 초대하지 않은 지도는 고치지 않는다. 아이디·비밀번호는 받지 않는다 |
| 인터넷 정보 수집 | 공식 웹사이트(robots.txt 허용 시), AI 웹 검색으로 외부 사이트·인스타그램 확인. 인스타그램 Business Discovery는 사전 확인 뒤 넣을지 정한다. 로그인 세션으로 수집하는 도구(Agent-Reach 등)는 쓰지 않는다 |
| 베타 정비 권한 | 사장님 신청 → A01에서 한눈 관리자가 승인(결제 없음). 신청 목록·승인 기능은 P0 |
| 완료 알림 | 화면 + 이메일 |
| 가게를 못 찾았을 때 | 후보가 있으면 목록에서 고르고, 없으면 다른 링크를 받는다 |
| 베타 업종 | 음식점·카페·바 |
| 사장님 화면 표기 | ChatGPT·Gemini |
| 랜딩 측정 횟수 | 랜딩에서는 측정 횟수를 보여 주지 않고 "여러 번"이라고 쓴다(2026-10-16) |

### 지도별 정비 방법(결정)

| 지도 | 고치는 방법 | 사장님이 할 일 | 한눈이 고치지 않는 것 |
|---|---|---|---|
| Google 지도 | 관리자로 초대받는다. API 승인 전에는 `business.google.com` 관리 화면을 브라우저 자동화로, 승인 후에는 Business Profile API로 고친다. 막히거나 실패하면 사람이 고친다 | 비즈니스 프로필 소유권 인증(안 돼 있으면), 한눈 계정을 관리자로 초대 | 가게 이름·주소·업종(재인증·검토 위험) |
| 카카오맵 | 운영자로 초대받는다. 파트너센터 매장 > 매장정보 화면을 브라우저 자동화로 고친다(수정 API 없음). 막히거나 실패하면 사람이 고친다. 외부 운영자·자동화를 허용하는지는 고객센터에 확인 | 매장관리 대표 권한(없으면 사업자등록번호로 등록), 한눈 계정을 운영자로 초대 | 주소·업종(사업자등록증 필요), 가게 이름 |
| 네이버 지도 | 고치지 않는다. 운영자 권한은 사업자의 내부 직원에게만 줄 수 있고, 주인 권한을 대신 받지도 않는다 | 없음 | 전부 |

- 사장님이 초대한 지도만 고친다. 초대 없이 지도·검색의 "정보 수정 제안"을 대신 내는 방식은 쓰지 않는다(2026-10-17).
- 브라우저 자동화 원칙
  - 사장님이 초대한 가게, 사장님이 승인한 칸만 고친다.
  - 고친 뒤 다시 읽어 확인한다.
  - 로그인 차단·보안 확인 같은 자동화 차단이 뜨면 멈추고 사람이 고친다. 우회하지 않는다.
  - 위험은 14장 "Google 관리 화면 자동화", "카카오 매장관리 자동화"에 적었다.
- Google API 신청에 필요한 것: 한눈 도메인·웹사이트·도메인 이메일, Google Cloud 프로젝트, 조직 계정, 인증 후 60일이 지나고 웹사이트가 등록된 가게 1곳의 관리자 권한. 사업자등록 서류는 요구하지 않는다. 검토는 공식 14일 이내(사례 4일~6주).
- 카카오 대행사 권한 신청: 대행사 자격으로 사장님 대신 매장관리 권한을 신청하려면 대행사 사업자등록증과 위임장이 필요하다. 한눈 사업자가 생기면 사장님의 권한 등록 단계를 대신할 수 있다.
- 시연: 미리 동의하고 한눈을 초대한 지인 가게 1~2곳을 실제로 정비하고, 2주 뒤 전후 비교 보고서까지 보여 준다. 이전에 정한 "Google 정보 수정 제안 자동 채우기" 시연은 실제 자동 정비로 대신한다(2026-10-17).

### 미정 사항

1. (결정됨) 자동 정비 범위 → 위 "지도별 정비 방법"과 결정 사항의 자동 정비·전후 비교 행으로 옮겼다(2026-10-17).
2. 네이버 검색 API(NAVER API HUB) 약관
   - 검색 결과를 AI 학습·요약에 쓰지 못하게 했다는 보도가 있지만 원문을 확인하지 못했다.
   - 확인 전까지 네이버 결과는 가게 찾기, 홈페이지 주소 확인, 기본정보 비교(코드)에만 쓴다.
3. 모은 데이터 보관 정책
   - 사장님이 정비안에서 승인한 값과 고치기 전 값은 정비 기록으로 저장한다.
   - Google 원본 등 외부에서 모은 값의 보관 기한은 정하지 않았다.
   - 카카오는 장소 ID·장소 링크만 저장할 수 있다(나머지는 필요할 때 다시 불러온다). 연결 뒤 파트너센터에서 읽은 카카오 매장 정보를 어디까지 저장할지, Google·인스타그램·네이버의 저장 조건도 함께 확인해야 한다.
4. 실제 사용자 모집 지역과 가게 수(정비를 시험할 지인 가게 포함)
5. 자동 정비 가격
6. 구독·환불 정책
7. 다국어·여러 지점 지원 범위
