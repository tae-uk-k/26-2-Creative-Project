# 한눈 서비스 기획서

- 서비스명: 한눈(Hanoon)
- 문서 역할: 왜 만들고, 누구에게 어떤 가치를 제공하며, 어떤 기능을 어디까지 개발할지 정의하는 기준 문서
- 개발 완료 목표: 13주차 작동 베타
- 1차 고객: 외국인 관광객을 유치하려는 음식점·카페·바 사장님
- 기술 구현 기준: [한눈 명세서](./한눈_명세서.md) (이 문서는 기능, 명세서는 기술을 다룬다)

## 1. 서비스 정의

한눈은 가게의 온라인 정보를 수집해 ChatGPT·Gemini 추천 노출을 측정하고, AI가 가게를 더 정확히 이해하고 추천할 수 있도록 영문 정보와 채널별 개선안을 만들어 주는 GEO 웹 서비스다.

### 핵심 흐름

```text
가게 이름·지도 링크 입력, 정보 수집
→ 무료 AI 노출 진단
→ 유료 AI 노출 최적화 보고서
(미정) 자동 가게 정보 정비 → 일정 기간 뒤 재측정·전후 비교 안내
```

### 핵심 가치

- AI가 가게를 실제로 추천하는지 숫자로 확인한다.
- 추천되지 않는 원인을 사용자가 이해할 수 있게 설명한다.
- 영문 소개·메뉴·가격·이용 정보와 채널별 수정 문안을 직접 만들어 준다.
- (미정) 같은 질문으로 다시 측정해 정보 정비 전후의 변화를 보여 준다.

## 2. 문제 정의

외국인 관광객을 유치하려는 소규모 가게는 AI가 가게를 얼마나 추천하는지 확인하기 어렵고, 추천에 필요한 온라인 정보와 외부 근거도 부족해 관광객에게 발견될 기회를 놓칠 수 있다.

### 확인된 배경

- 미국 활동 여행자의 여행 계획 생성형 AI 이용률은 2025년 상반기 33%, 하반기 43%, 2026년 56%로 증가했다.
- Adobe 조사에서 AI 여행 이용자의 53%는 지역 명소·식당·숨은 장소를 찾는 데 AI를 사용했다.
- 발리 음식점·카페·바 4,776곳과 AI 답변 2,208개를 분석한 연구에서는 전체 매장의 85.6%가 한 번도 추천되지 않았다.

### 해석 범위

- AI는 지역의 모든 가게를 고르게 추천하지 않는다.
- 영문 정보, 가격, 공식 페이지, 외부 언급 등 확인 가능한 근거가 적은 가게는 질문 조건과 연결되기 어려울 가능성이 있다.
- 해외 조사 결과를 한국 방문 외국인 전체에 그대로 일반화하지 않는다.
- 위 연구만으로 프랜차이즈가 소규모 가게보다 더 많이 추천된다고 단정하지 않는다.

### UX 인사이트

소규모 가게 사장님에게는 AI 노출을 숫자로 확인하는 진단뿐 아니라, 부족한 정보를 실제로 정비하고 개선 전후를 확인할 수 있는 지원이 필요하다. 이 중 정보 정비와 개선 전후 확인은 15장 미정 1에 따라 13주차 베타 범위에 들어 있지 않다.

## 3. SEO와 GEO의 차이

| 구분 | SEO | GEO |
|---|---|---|
| 사용자 행동 | 검색어를 입력하고 결과 목록을 비교 | 조건을 문장으로 말하고 AI가 고른 추천을 확인 |
| 목표 | 검색 결과 상위 노출과 클릭 증가 | AI 답변에 선택·인용·추천될 가능성 향상 |
| 주요 개선 | 키워드, 링크, 페이지 구조, 지도 등록 | 질문 조건과 연결되는 정보, 출처 일치, 구조화된 사실, 읽을 수 있는 텍스트 |

한눈은 SEO를 대체하지 않는다. 기존 지도·검색 정보를 기반으로 생성형 AI가 관광객의 구체적인 질문과 가게를 연결할 수 있게 보완한다.

## 4. 목표 사용자

### 1차 사용자

- 외국인 관광객이 방문하는 음식점·카페·바 사장님
- 영어 정보와 여러 온라인 채널을 직접 관리하기 어려운 1인·소규모 사업자

### 후속 확장 대상

- 소품샵·편집숍·공방·체험 매장 운영자

### 최종 수혜자

- 지역, 예산, 언어, 식단, 결제 조건에 맞는 로컬 가게를 찾는 외국인 관광객

### 구매 단위

- 가게별 개별 구매
- 상인회·지자체 단체구매와 다점포 통합 관리는 초기 범위에서 제외

## 5. 제공 상품

| 상품 | 제공 가치 | 과금 |
|---|---|---|
| AI 노출 진단 | ChatGPT·Gemini별 추천 등장률·평균 등장 순서·출처, 주변 가게(AI 추천 상위 5곳) 대비 비교, 고쳐야 할 점 개수 | 무료(계정당 1회) |
| AI 노출 최적화 보고서 | 미노출 원인·개선 우선순위·영문 문안·채널별 수정안 | 유료 |

- 무료 진단은 얼마나 노출되는지, 주변 가게 대비 비교, 고쳐야 할 점의 개수만 보여 준다. 고쳐야 할 점의 내용은 유료 보고서에서만 제공한다.
- 가격과 실제 결제 방식은 아직 확정하지 않는다. 베타에서는 관리자가 유료 권한을 수동으로 부여한다.

## 6. 서비스 차별점

| 기존 방식 | 남은 한계 | 한눈의 개선 방향 |
|---|---|---|
| AI 노출 측정 도구 | 문제를 보여 주지만 수정은 사용자의 몫 | 측정 후 영문 정보·채널 수정안까지 제작 |
| 매장 정보 관리 도구 | 여러 채널의 기본정보 일치에 집중 | 관광객형 질문과 AI 추천 답변을 기준으로 개선 |
| 메뉴 번역 | 번역 결과가 AI 추천에 반영되는지 확인하지 않음 | 질문 조건에 필요한 정보를 보강하고 재측정(미정) |
| 지도 등록 대행 | 한 채널 등록에 집중 | 여러 출처의 일치, 읽기 쉬운 공개 정보, AI 답변을 함께 확인 |

## 7. 대표 사용자 여정

1. 사장님이 이메일·구글·카카오 중 하나로 회원가입 후 로그인한다. 이메일 가입은 인증 메일의 링크를 눌러야 완료된다. 같은 이메일로 다른 방식의 가입이 이미 끝나 있으면(인증 완료) "OO로 가입된 이메일"이라고 안내하고 가입을 막는다.
2. 사장님이 가게 이름과 Google 지도·카카오맵·네이버 지도 중 하나의 가게 링크를 입력한다. 사장님이 입력하는 가게 정보는 이 두 가지뿐이다.
3. 서비스가 링크로 가게를 식별하고, 나머지 두 지도에서 같은 가게를 찾아 세 곳의 기본정보를 수집한다. 공식 웹사이트·인스타그램·외부 사이트 정보도 함께 모은다. 가게가 하나로 정해지지 않으면 후보 목록에서 고르게 하고, 찾지 못하면 다른 링크를 요청한다.
4. 수집이 끝나면 측정이 자동으로 시작된다. 단, 무료 진단을 아직 쓰지 않은 계정만 해당하고, 이미 썼으면 유료 보고서가 승인된 뒤 측정한다. 가게의 지역·업종·특징을 바탕으로 관광객형 질문 3개(영어 2개, 한국어 1개)를 만들고 자동 검증을 통과하면 바로 확정한다.
5. 질문 3개를 ChatGPT·Gemini에 각각 10회씩, 모두 60회 물어본다. 끝나면 화면과 이메일로 알린다.
6. 무료 진단에서 ChatGPT·Gemini별 추천 등장률·평균 등장 순서·출처, 주변 가게(AI 추천 상위 5곳) 대비 비교, 고쳐야 할 점 개수를 확인한다.
7. 유료 보고서를 신청하면 관리자가 권한을 부여하고, 보고서가 자동으로 만들어진다. 완료되면 이메일로 알린다.
8. 유료 보고서에서 미노출 원인과 개선 우선순위, 영문 문안, 채널별 수정안을 확인한다. 고치는 대상은 Google 지도·카카오맵·네이버 지도와 인터넷 정보(공식 웹사이트·인스타그램·외부 사이트)이며, Google 지도에 비어 있는 정보도 고쳐야 할 점으로 포함된다. 네이버·카카오는 공식 API로 받은 기본정보만 비교하고, 칸별 수정 문구를 제공한다.

(미정) 사장님 승인 → 자동 가게 정보 정비 → 일정 기간 뒤 재측정·전후 비교 안내

## 8. 범위

### P0: 13주차까지 필수

- 회원가입·로그인(이메일·구글·카카오), 이메일 인증, 같은 이메일 중복 가입 차단
- 비밀번호 재설정(이메일 링크), 회원 탈퇴
- 계정당 가게 1곳 등록, 언제든 변경 가능
- 가게 이름 + 지도 링크(Google·카카오·네이버) 판별, 가게 식별, 세 지도의 기본정보 수집
- 인터넷 정보 수집: 공식 웹사이트, AI 웹 검색으로 외부 사이트·인스타그램 확인(인스타그램 Business Discovery는 8주차 PoC 결과에 따라 추가)
- 가게 식별 실패 시 후보 선택 또는 다른 링크 입력
- 질문 3개(영어 2개, 한국어 1개) 자동 생성·검증·확정
- ChatGPT·Gemini 반복 측정(질문마다 AI별 10회, 모두 60회)
- 추천 등장률·평균 등장 순서·출처 계산, 실패율은 내부 계산(사장님 화면 미표시)
- 주변 가게 비교(AI 추천 상위 5곳)
- 고쳐야 할 점 판정(무료 진단에는 개수만 표시)
- 무료 진단 결과(계정당 1회)
- 유료 보고서 신청, 관리자 신청 목록·권한 부여
- 유료 최적화 보고서: 미노출 원인·개선 우선순위, 영문 소개·메뉴·가격·이용 정보 문안, 채널별 수정안(Google 지도·카카오맵·네이버 지도·공식 웹사이트·인스타그램·외부 사이트), Google 지도에 비어 있는 정보
- 이메일 알림 6종(가입 인증, 비밀번호 재설정, 진단 완료·실패, 보고서 신청(관리자에게), 권한 부여·거절, 보고서 완료)
- 계정·가게·측정·보고서 데이터 PostgreSQL 저장(외부에서 수집한 데이터의 보관 기한은 15장 미정 3)

### P1: 일정이 허용되면

- 메뉴판 이미지 OCR: Google 지도 사진 중 메뉴판 사진이 있으면 받아서 메뉴·가격을 읽는다(사진 파일은 저장하지 않음)
- 보고서 PDF 내려받기
- 관리자용 사용자·가게·보고서 전체 조회(보고서 신청 관리는 P0)

### P2: 후속 개발

- 실제 PG 결제와 구독
- 다점포 관리
- 영어 외 다국어
- 외부 채널 변경 감지
- 소품샵·편집숍·공방·체험 매장 업종 확장

### 제외 범위

- 추천 순위·노출 보장
- 가짜 리뷰·리뷰 구매·광고 집행
- 예약·주문 시스템 연동
- 상인회·지자체용 통합 대시보드
- 지도·SNS 페이지 크롤링, 로그인 세션을 이용한 자동 수집

## 9. 화면 구성

### 9.1 화면 목록

| ID | 화면 | 누가 보나 | 목적 |
|---|---|---|---|
| S01 | 랜딩 | 누구나 | 서비스 소개, 무료 진단 시작 |
| S02 | 회원가입 | 비회원 | 이메일·구글·카카오 가입 |
| S03 | 이메일 인증 안내 | 가입 직후 | 인증 메일 확인 안내 |
| S04 | 카카오 이메일 입력 | 카카오가 이메일을 주지 않은 가입자 | 이메일 입력·인증 |
| S05 | 로그인 | 비회원 | 로그인 |
| S06 | 비밀번호 재설정 | 이메일 가입자 | 재설정 메일 요청, 새 비밀번호 입력 |
| S07 | 홈(내 가게) | 사장님 | 현재 상태와 다음 행동 안내 |
| S08 | 가게 등록·변경 | 사장님 | 가게 이름·지도 링크 입력 |
| S09 | 가게 후보 선택 | 가게 식별이 애매할 때 | 후보 중 내 가게 고르기 |
| S10 | 수집·측정 진행 | 사장님 | 진행 상황, 수집한 가게 정보 |
| S11 | 무료 진단 결과 | 사장님 | 노출 정도, 주변 가게 비교, 고쳐야 할 점 개수 |
| S12 | 유료 보고서 신청·대기 | 사장님 | 신청, 진행 상태 |
| S13 | 유료 보고서 | 권한을 받은 사장님 | 고쳐야 할 점, 영문 문안, 채널별 수정안 |
| S14 | 계정 설정 | 사장님 | 계정 정보, 비밀번호 변경, 로그아웃, 탈퇴 |
| A01 | 보고서 신청 관리 | 관리자 | 신청 목록, 권한 부여·거절 |
| S15 | 내 가게 연결하기(자동 정비, 범위 미정) | 유료 보고서를 받은 사장님 | Google·카카오에 한눈 계정 초대, 네이버는 붙여 넣을 문구 안내 |

### 9.2 화면 이동

```text
S01 랜딩 → S02 회원가입 → (이메일 가입: S03 이메일 인증 / 카카오 이메일 없음: S04) → S07 홈
S07 홈 → S08 가게 등록 → (애매하면 S09 후보 선택) → S10 수집·측정 진행 → S11 무료 진단 결과
S11 무료 진단 결과 → S12 보고서 신청 → (A01 관리자 권한 부여) → S13 유료 보고서
S13 유료 보고서 → (자동 정비 범위 확정 시) S15 내 가게 연결하기
```

로그인한 사장님이 랜딩이나 로그인 화면에 들어오면 S07 홈으로 보낸다. 로그인하지 않은 사람이 S07~S15에 들어오면 S05 로그인으로 보내고, 로그인 후 원래 화면으로 돌려보낸다.

### 9.3 화면별 구성

#### S01 랜딩

- 첫 화면: "외국인 관광객이 ChatGPT에 맛집을 물을 때, 우리 가게가 나올까요?" 문구와 [무료로 확인하기] 버튼
- 문제: AI는 지역의 일부 가게만 추천한다는 근거 수치 1개(2장 배경)
- 이용 방법 3단계: 가게 이름·지도 링크 넣기 → 무료 진단 → 유료 보고서
- 무료·유료 비교표: 무료(노출 정도, 주변 가게 비교, 고쳐야 할 점 개수) / 유료(고쳐야 할 점 내용과 우선순위, 영문 문안, 채널별 수정안)
- 결과 화면 예시 이미지
- 안내 문구: "추천 순위나 노출을 보장하지 않습니다."
- 하단: 이용약관, 개인정보처리방침
- [무료로 확인하기]: 로그인 상태면 S07, 아니면 S02로 이동

#### S02 회원가입

- [구글로 시작하기], [카카오로 시작하기] 버튼
- 이메일 가입 입력: 이메일, 비밀번호, 비밀번호 확인
- 약관 동의: 이용약관(필수), 개인정보 수집·이용(필수), 전체 동의
- [가입하기], "이미 계정이 있나요? 로그인"
- 입력 규칙
  - 이메일 형식이 아니면 "이메일 형식이 아니에요"
  - 비밀번호는 8자 이상, 영문과 숫자를 모두 포함. 아니면 "8자 이상, 영문과 숫자를 함께 써 주세요"
  - 비밀번호 확인이 다르면 "비밀번호가 서로 달라요"
  - 필수 약관에 동의하지 않으면 [가입하기] 비활성
- 같은 이메일로 인증을 마친 계정이 있으면 "이 이메일은 [구글/카카오/이메일]로 가입되어 있어요"와 [그 방식으로 로그인] 버튼을 보여 주고 가입을 막는다. 소셜 가입도 같은 규칙을 따른다.
- 소셜 가입은 제공자 동의 화면을 거쳐 돌아온 뒤, 처음 가입이면 약관 동의를 받고 S07로 이동

#### S03 이메일 인증 안내

- "OO@OO.com으로 인증 메일을 보냈어요. 메일의 링크를 누르면 가입이 끝나요."
- [인증 메일 다시 보내기]: 누른 뒤 60초 동안 비활성
- [이메일 주소 바꾸기]: S02로 돌아가 다시 입력
- 인증 링크는 24시간 동안 한 번만 쓸 수 있다. 만료된 링크는 "링크가 만료됐어요"와 [다시 보내기]
- 인증하지 않은 계정은 24시간 뒤 삭제
- 인증 전에 로그인하면 이 화면으로 보낸다.

#### S04 카카오 이메일 입력

- 카카오 로그인에서 이메일을 받지 못한 경우에만 보인다.
- 이메일 입력 → 인증 메일 발송(S03과 같은 규칙) → 인증하면 가입 완료
- 같은 이메일 가입 차단 규칙은 S02와 같다.

#### S05 로그인

- [구글로 로그인], [카카오로 로그인], 이메일·비밀번호 입력, [로그인]
- [비밀번호를 잊으셨나요?] → S06, [회원가입] → S02
- 틀리면 "이메일 또는 비밀번호가 맞지 않아요"(어느 쪽이 틀렸는지 알려 주지 않음)
- 5회 연속 틀리면 10분 동안 로그인 잠금
- 소셜로 가입한 이메일로 비밀번호 로그인을 시도하면 "이 이메일은 [구글/카카오]로 가입되어 있어요"
- 로그인 유지 기간 14일

#### S06 비밀번호 재설정

- 1단계: 이메일 입력 → 가입 여부와 관계없이 "가입된 이메일이면 재설정 메일을 보냈어요"(가입 여부 노출 방지)
- 2단계(메일 링크): 새 비밀번호, 확인 → 완료 후 S05로 이동
- 링크는 1시간 동안 한 번만 쓸 수 있다.
- 소셜 가입 계정이 요청하면 메일에 "[구글/카카오]로 로그인하세요"라고 안내한다.

#### S07 홈(내 가게)

- 상단: 로고, 계정 메뉴(계정 설정, 로그아웃)
- 가게 정보 줄: 가게 이름, 주소, 찾은 출처(Google·카카오·네이버·공식 웹사이트·인스타그램 ✓/✕), [가게 변경]
- 상태 카드: 상태별로 하나만 보인다.

| 상태 | 카드 내용 | 버튼 |
|---|---|---|
| 가게 없음 | "가게를 등록하고 AI 노출을 확인해 보세요" | 가게 등록 |
| 수집·측정 중 | 단계와 진행률 | 진행 상황 보기(S10) |
| 측정 실패 | "측정을 끝내지 못했어요. 무료 횟수는 차감되지 않았어요" | 다시 시도(하루 3회까지, 넘으면 "내일 다시 시도해 주세요") |
| 진단 완료 | ChatGPT·Gemini 등장률 요약, 고쳐야 할 점 N개 | 결과 보기(S11), 유료 보고서 신청(S12) |
| 무료 사용 후 가게 변경 | "무료 진단은 계정당 1회예요" | 유료 보고서 신청(측정 포함) |
| 보고서 신청됨(승인 포함) | "신청이 접수됐어요. 준비되면 이메일로 알려 드려요" | 없음 |
| 보고서 거절됨 | 거절 사유 | 다시 신청 |
| 보고서 생성 중 | 진행 표시 | 없음 |
| 보고서 완료 | 고쳐야 할 점 요약 | 보고서 보기(S13) |

- 현재 가게에 보고서 신청이 있으면 가게 상태보다 신청 상태 카드를 먼저 보여 준다.
- 보고서 신청이 진행 중(신청됨·승인·생성 중)이면 [가게 변경]을 비활성으로 두고 "보고서가 준비되는 중에는 가게를 바꿀 수 없어요"를 보여 준다.
- 지난 기록: 가게를 바꾼 적이 있으면 이전 가게의 진단 결과·보고서 목록(조회만 가능)
- (자동 정비 범위 확정 시) "보고서 완료" 카드에 [한눈이 대신 고쳐 드려요] 버튼을 두고 S15로 보낸다.

#### S08 가게 등록·변경

- 입력: 가게 이름(필수, 1~50자), 지도 링크(필수)
- 링크 칸 안내: "Google 지도·카카오맵·네이버 지도에서 가게를 찾아 [공유 → 링크 복사]한 주소를 넣어 주세요." 지도별 복사 방법은 펼치기로 보여 준다.
- 공유 문구를 통째로 붙여넣어도 링크만 골라낸다.
- [등록하기] → 가게 식별(10장 F-03)
  - 하나로 확정되면 S10
  - 후보가 여러 개면 S09
  - 찾지 못하면 "가게를 찾지 못했어요. 다른 지도 링크를 넣어 주세요"
- 오류
  - 지원하지 않는 링크: "Google 지도·카카오맵·네이버 지도 링크만 넣을 수 있어요"
  - 음식점·카페·바가 아닌 가게: "지금은 음식점·카페·바만 진단할 수 있어요"(등록하지 않음)
- 변경 모드(이미 가게가 있을 때): "가게를 바꾸면 지금 가게의 결과는 지난 기록으로 옮겨져요"를 확인받는다. 무료 진단을 이미 썼다면 "무료 진단은 다시 할 수 없어요"도 함께 보여 준다. 진행 중인 측정은 중단한다. 보고서 신청이 진행 중이면 변경할 수 없다.

#### S09 가게 후보 선택

- "어느 가게인가요?"와 후보 최대 5개(가게 이름, 주소, 업종, 찾은 지도)
- 후보를 고르면 S10으로 이동
- [여기에 없어요] → S08로 돌아가 "다른 지도 링크를 넣어 주세요"

#### S10 수집·측정 진행

- 단계 표시: ① 가게 정보 모으기(지도·공식 웹사이트·인스타그램·AI 웹 검색) ② 질문 만들기 ③ ChatGPT·Gemini에 물어보기(n/60) ④ 결과 정리
- 안내: "약 5~15분 걸려요. 창을 닫아도 끝나면 이메일로 알려 드려요."
- 수집한 가게 정보: 항목 | Google | 카카오 | 네이버 | 공식 웹사이트 | 인스타그램 표. 값이 있는 항목만 보여 주고 빈 칸은 표시하지 않는다.
- [내 가게가 아니에요] → S08 변경 모드. 측정을 중단하고 무료 횟수는 차감하지 않는다. 보고서 승인 뒤 진행되는 측정에서는 이 버튼을 보여 주지 않는다(신청 중 가게 변경 불가).
- 무료 진단을 이미 쓴 계정이 가게를 바꾼 경우에는 ① 가게 정보 모으기까지만 진행하고, 끝나면 S07로 이동한다.
- 화면은 진행률을 자동으로 새로고침하고, 끝나면 S11로 이동한다.

#### S11 무료 진단 결과

- 요약
  - "ChatGPT 답변 m개 중 n개에서 추천됐어요(x%)", Gemini도 같은 형식(m은 성공한 답변 수, 보통 30)
  - 평균 등장 순서: "추천될 때 평균 k번째"
  - 한 번도 나오지 않으면 "아직 한 번도 추천되지 않았어요"(오류가 아니라 정상 결과)
- 주변 가게 비교: 우리 가게와 AI 추천 상위 5곳의 가게 이름, ChatGPT 등장률, Gemini 등장률, 평균 등장 순서. 우리 가게는 강조 표시
- 질문별 결과: 질문 3개(원문, 한국어 질문이 아니면 번역 함께), 질문별 ChatGPT·Gemini 등장 횟수(n/성공한 답변 수, 보통 n/10). 성공한 답변이 없는 질문은 "측정하지 못함"
- 출처
  - AI가 답변에 많이 쓴 사이트 상위 5개(사이트 이름, 인용 횟수)
  - 우리 가게를 추천할 때 쓴 사이트(등장이 없으면 표시하지 않음)
- 유료 안내: "고쳐야 할 점 N개를 찾았어요"와 [유료 보고서 신청]. 내용은 보여 주지 않는다. 0개면 "눈에 띄는 문제를 찾지 못했어요"를 보여 주고 신청 버튼은 그대로 둔다.
- 측정 조건(작은 글씨): 측정일, 질문 3개 × 10회 × ChatGPT·Gemini
- 무료 결과는 언제든 다시 볼 수 있다.

#### S12 유료 보고서 신청·대기

- 신청 전: 보고서에 들어가는 내용(고쳐야 할 점과 우선순위, 영문 문안, 채널별 수정안), "베타 기간에는 신청 후 승인되면 제공돼요", [신청하기]
- 진단 결과가 없는 가게(무료 사용 후 가게 변경)는 "신청이 승인되면 측정부터 다시 진행해요"라고 안내한다.
- 신청 후: 신청 접수 → 승인 → 보고서 만드는 중 → 완료 단계 표시
- 같은 가게로는 보고서를 한 번만 받을 수 있다. 진행 중인 신청이 있거나 이미 보고서를 받았으면 다시 신청할 수 없고, 거절된 경우에만 다시 신청할 수 있다.

#### S13 유료 보고서

- (자동 정비 범위 확정 시) 맨 위에 [한눈이 대신 고쳐 드려요] 버튼 → S15
- 상단 요약: 진단 결과 3줄(① ChatGPT·Gemini 등장률 ② 평균 등장 순서 ③ 주변 가게 5곳과 비교한 위치), 고쳐야 할 점 N개(높음 a·보통 b·낮음 c), 보고서 생성일·기준 진단일
- ① 고쳐야 할 점: 우선순위 순 카드
  - 우선순위(높음·보통·낮음), 제목(예: "Google 지도에 영업시간이 없어요"), 분류(10장 F-08)
  - 왜 중요한가: 관련 AI 답변, 주변 가게와의 차이
  - 어떻게 고치나: 해당 채널의 수정안(③)으로 이동
  - 난이도(쉬움·보통·어려움, F-08 쉬움 점수 3·2·1)
- ② 영문 문안: 영문 가게명 표기, 한 줄 소개, 소개문, 메뉴·가격표, 이용 정보(영업시간·결제·예약·언어·식이 정보). 블록마다 [복사]
- ③ 채널별 수정안: Google 지도 / 카카오맵 / 네이버 지도 / 공식 웹사이트(있을 때) / 인스타그램(있을 때) / 외부 사이트(AI 웹 검색에서 찾았을 때) 탭
  - Google에서 가게를 찾지 못했으면 Google 탭에 Google 비즈니스 프로필 등록 방법을 보여 준다.
  - 고칠 칸 목록: 칸 이름, 현재 값(모르면 "확인 필요"), 바꿀 값, [복사]
  - 관리 페이지 바로가기(Google 비즈니스 프로필, 카카오비즈니스 파트너센터, 네이버 스마트플레이스, 인스타그램 프로필 편집)와 짧은 수정 방법
  - 인스타그램 탭: 프로페셔널(비즈니스·크리에이터) 계정 전환, 공개 계정 유지, "검색 엔진 결과에 표시" 설정 켜기, 소개글·캡션·대체 텍스트에 영어·지역·업종 키워드 넣기
  - 외부 사이트(다이닝코드·트립어드바이저 등)는 우리가 고칠 수 없으므로, 사이트별 "업주 정보 수정 요청" 방법과 보낼 문구를 제공
  - 카카오맵·네이버 지도 탭: 카카오 매장관리(매장 > 매장정보)와 스마트플레이스(내 업체 > 업체 정보)의 칸 이름에 맞춘 영업시간·가격·메뉴·소개·SNS 링크 문구. 현재 값은 공식 API로 받은 이름·주소·전화·업종만 보여 주고 나머지는 "확인 필요". 가게를 찾지 못했으면 등록 방법을 보여 준다.
- ④ 진단 근거: 질문별 AI 답변 원문(성공한 답변, 최대 60개), 우리 가게·주변 가게 이름 강조
- 보고서는 언제든 다시 볼 수 있다.

| 단계 | 누가 | 화면·행동 |

- 수정 방식(2026-10-16 결정): 카카오는 매장 정보 수정 API가 없으므로, 한눈 카카오계정으로 파트너센터 매장 > 매장정보 화면을 브라우저 자동화로 수정한다. 고친 뒤 화면에서 값이 바뀌었는지 다시 확인한다. 로그인 차단·보안 확인 같은 자동화 차단이 나타나거나 수정에 실패하면 멈추고 사람이 직접 수정하며, 차단을 우회하지 않는다. 위험은 14장 "카카오 매장관리 자동화"에 적는다.
- 매장관리에서 고친 내용은 30분~1시간 뒤 반영된다(주소·업종 제외).
- 외부 업체를 운영자로 초대하는 것에 대한 카카오의 제한 문구는 찾지 못했다. 13장 PoC에서 고객센터에 확인한다.

**네이버 지도 카드: 초대 없음**

- 스마트플레이스에는 "권한관리 → 운영자 추가" 기능이 있지만, 네이버 도움말에 따르면 **사업자의 내부 직원에게만** 줄 수 있다. 외부인에게 주면 개인정보보호법상 동의 없는 제3자 제공에 해당할 수 있다(운영자는 예약 고객 연락처 등을 볼 수 있음). 그래서 한눈은 운영자 권한을 받지 않는다.
- 한눈이 네이버 주인 권한을 대신 받는 것도 하지 않는다. 네이버는 주인 변경 어뷰징을 모니터링하고, 대표자가 아닌 사람의 신청에는 재직증명서를 요구한다.
- 한눈이 하는 일: 정보수정제안으로 틀린 사실 정보(영업시간·전화·업종·주소)를 제보한다. 네이버는 사람이 검수하고, 증빙 사진을 요구할 수 있다.
- 사장님이 하는 일(원할 때만): 스마트플레이스 > 내 업체 > 업체 정보에서 한눈이 준 소개·메뉴·가격·대표키워드 문구를 붙여 넣는다. 검토는 2시간~5일이고, 기본정보는 주 5회까지, 부가정보·가격·영업시간은 제한 없이 고칠 수 있다.
- 배달의민족과 연동된 음식점은 네이버에 배달의민족 메뉴가 먼저 노출되므로, 메뉴는 배달의민족에서 고치도록 안내한다.

### F-02 가게 등록·변경

- 계정당 가게 1곳. 언제든 변경할 수 있다.
- 변경하면 이전 가게의 진단·보고서는 지난 기록으로 옮기고(조회만), 진행 중인 측정은 중단한다.
- 보고서 신청이 진행 중(신청됨·승인·생성 중)이면 변경할 수 없다. 완료·거절 후에는 변경할 수 있다.
- 대상 업종은 음식점·카페·바다. 지도에서 받은 업종이 음식점·카페·바가 아니면 등록하지 않는다.
- 무료 진단은 계정당 1회다. 진단이 정상적으로 끝났을 때 차감한다.

### F-03 링크 판별과 가게 식별

| 지도 | 받는 링크 형식 |
|---|---|
| Google | `google.com/maps/place/…`, `maps.app.goo.gl/…`, `goo.gl/maps/…` |
| 카카오 | `place.map.kakao.com/{번호}`, `map.kakao.com/…`, `kko.to/…` |
| 네이버 | `map.naver.com/…/place/{번호}`, `m.place.naver.com/…/{번호}`, `naver.me/…` |

- 짧은 링크는 이동할 주소만 확인하고 지도 페이지 내용은 읽지 않는다.
- 식별 순서
  1. 링크에서 지도 종류와 가게 번호(Google은 이름·좌표도)를 얻는다.
  2. 그 지도의 공식 API로 가게 이름을 검색해 링크의 가게 번호와 같은 결과를 찾는다(Google·카카오). 네이버는 API가 가게 번호를 주지 않으므로 이름이 맞는 결과만으로 판단한다.
  3. 나머지 두 지도에서 이름으로 검색해, 좌표가 100m 안에 있고 이름이 비슷한 가게를 같은 가게로 본다.
- 확정 기준: 결과가 하나면 자동 확정, 여러 개면 S09 후보 선택, 없으면 다른 링크 요청
- 다른 지도에서 찾지 못하면 그 지도는 "찾지 못함"으로 두고 진행한다. Google에서 찾지 못하면 유료 보고서에서 고쳐야 할 점(Google 지도 미등록)으로 다루고, 네이버·카카오에서 찾지 못하면 유료 보고서에서 등록 방법을 안내한다.

- 카카오·네이버의 영업시간·메뉴·리뷰·사진은 수집하지 않는다. 공식 API로 제공되지 않고, 카카오는 크롤링 금지와 제휴로도 제공하지 않음을 공식 답변했다(2026-09-21). 두 지도의 정비 방법은 15장 미정 1의 지도별 정비 방법을 따른다.
- 카카오 API 데이터는 장소 ID와 장소 링크만 저장할 수 있다. 이름·주소 등 나머지는 필요할 때 다시 불러온다.
- 네이버 지역 검색 API는 2026-07-31부터 NAVER API HUB(네이버 클라우드)에서만 새로 발급받을 수 있다.

### F-05 질문 생성

- 입력: 지역(동·구 또는 관광지 이름), 업종, 특징(가격대, 채식 가능 여부, 대표 메뉴 종류 등 수집한 값)
- 질문 3개
  - 질문 1(영어, 기본형): 지역+업종. 예) "What are good Korean restaurants near Myeongdong?"
  - 질문 2(영어, 조건형): 지역+업종+특징. 예) "Where can I find affordable vegetarian-friendly Korean food in Myeongdong?"
  - 질문 3(한국어, 기본형): 지역+업종. 예) "명동 근처 맛있는 한식당 추천해줘"
- 자동 검증: 가게 이름(한글·영문, 일부 포함)이 없을 것, 지역 이름과 업종이 들어 있을 것, 3개가 서로 다를 것
- 검증에 실패하면 3번까지 다시 만든다. 그래도 실패하면 업종별 고정 문장에 지역·업종만 넣어 쓴다.
- 질문은 측정 결과와 함께 저장한다.

### F-06 AI 측정

- ChatGPT는 OpenAI API, Gemini는 Gemini API로 실행하고, 둘 다 웹 검색을 켠다.
- 질문은 관광객이 묻듯 그대로 보내고 다른 지시는 붙이지 않는다.
- 3개 질문 × 2개 AI × 10회 = 60회
- 호출 하나의 제한 시간은 60초. 실패하면 2번까지 다시 시도한다.
- 저장: 질문, AI, 모델 이름, 회차, 시각, 답변 원문, 출처 링크
- 실패한 호출은 미노출로 세지 않는다. 실패율이 30%를 넘으면 결과를 확정하지 않고 "측정 실패"로 처리하며 무료 횟수를 차감하지 않는다.
- 측정 실패 후 다시 시도는 가게당 하루 3회까지다.

### F-07 추천 추출과 지표

- 답변마다 추천한 가게 목록(이름, 순서, 함께 붙은 출처)을 뽑는다.
- 우리 가게 판정: 이름만 맞아도 등장으로 센다.
  - 비교할 이름: 세 지도의 한글·영문 이름
  - 대소문자·띄어쓰기·기호는 무시하고, "본점", "○○점" 같은 지점 이름은 떼고 비교한다.

| 지표 | 계산 | 사장님 화면 |
|---|---|---|
| 추천 등장률 | 우리 가게가 나온 답변 수 ÷ 성공한 답변 수(AI별 전체, AI별·질문별) | 표시 |
| 평균 등장 순서 | 우리 가게가 나온 답변에서의 순서 평균 | 표시 |
| 출처 | 사이트별 인용 횟수, 우리 가게 추천에 붙은 사이트 | 표시 |
| 실패율 | 실패한 호출 ÷ 전체 호출 | 표시 안 함 |

- 성공한 답변은 오류 없이 받았고 추천 목록 추출에도 성공한 답변이다. 추출에 실패한 답변은 분모에서 뺀다.
- 주변 가게 상위 5곳: 우리 가게를 뺀 나머지 중 60개 답변에서 가장 많이 나온 순서로 뽑는다. 같으면 평균 순서가 앞선 가게가 먼저다. 이름은 우리 가게와 같은 방식으로 묶는다.
- 주변 가게도 우리 가게와 같은 방식으로 등장률·평균 순서를 계산한다.

### F-08 고쳐야 할 점 판정

무료 진단 때 판정해 개수만 보여 주고, 내용은 유료 보고서에서 보여 준다.

| 분류 | 판정 규칙 | 예시 |
|---|---|---|
| Google 지도에 정보 없음 | Google의 영업시간·가격대·웹사이트·전화·편의 정보 중 비어 있는 항목, Google에서 가게를 찾지 못함 | Google 지도에 영업시간이 없어요 |
| 출처끼리 정보 다름 | Google 지도·공식 웹사이트·인스타그램·외부 사이트(AI 웹 검색 결과)의 이름·주소·전화·영업시간, 카카오·네이버의 이름·주소·전화·업종이 서로 다름 | 공식 웹사이트와 Google의 영업시간이 달라요 |
| 영문 정보 부족 | Google 영문 이름·소개 없음, 공식 웹사이트에 영문 페이지 없음, 인스타그램 소개글에 영어 없음 | 영어 소개가 없어요 |
| 인스타그램 검색 노출 부족 | AI 웹 검색에서 가게 인스타그램 계정·게시물이 잡히지 않음(개인·비공개 계정이거나 검색 노출 설정이 꺼진 경우), 소개글·캡션에 지역·업종 키워드 없음 | 인스타그램이 검색에 나오지 않아요 |
| 질문 조건 정보 부족 | 질문 조건(채식, 가격 등)에 맞는 정보가 우리 가게에는 없고, 주변 가게 추천 이유에는 있음 | 채식 가능 여부가 표시돼 있지 않아요 |
| 외부 근거 부족 | AI가 주변 가게를 추천할 때 쓴 사이트에 우리 가게 추천 근거가 없음 | AI가 많이 참고한 사이트에 우리 가게가 없어요 |
| AI가 틀리게 말함 | AI 답변 속 우리 가게 설명(영업시간·위치·가격)이 Google 지도·공식 웹사이트 값과 다름 | ChatGPT가 영업시간을 틀리게 말해요 |

- 우선순위 = 영향 점수(1~3) + 쉬움 점수(1~3)
  - 영향: 주변 가게 5곳 중 그 정보를 갖춘 가게 수, 관련 질문 수
  - 쉬움: Google 비즈니스 프로필·카카오 매장관리·스마트플레이스·공식 웹사이트·인스타그램에서 바로 고칠 수 있으면 높음, 외부 사이트에 수정 요청을 해야 하면 낮음
  - 합계 5~6은 높음, 4는 보통, 2~3은 낮음
  - 보고서의 난이도 표시는 쉬움 점수를 그대로 쓴다(3 쉬움, 2 보통, 1 어려움).
- 네이버·카카오는 공식 API로 받는 이름·주소·전화·업종만 판정에 쓴다. 네이버 응답은 코드로만 비교하고 AI에 넣지 않는다.

### F-09 유료 보고서 생성

- 관리자가 권한을 부여하면 자동으로 만든다. 진단 결과가 없는 가게는 측정(F-05~F-08)부터 실행한다.
- 입력: 수집한 값, 진단 결과, 고쳐야 할 점 목록
- 작성 원칙
  - 수집한 값에 없는 사실은 만들지 않는다. 모르는 값은 [ ]로 비워 두고 "확인 필요"로 표시한다.
  - 알레르기·할랄 같은 민감 정보는 수집한 값에 있을 때만 쓰고 "사장님 확인 필요"를 붙인다.
  - 채널별 수정안은 각 채널의 칸 이름과 글자 수 제한에 맞춘다.
  - 고쳐야 할 점마다 근거(관련 AI 답변, 수집한 값, 주변 가게 비교)를 연결한다.
- 생성 목표 시간은 3분 이내다. 실패하면 1번 자동으로 다시 시도하고, 그래도 실패하면 A01에 "생성 실패"로 표시한다.
- 보고서는 생성일과 기준 진단을 함께 저장하고 언제든 다시 볼 수 있다.

### 11.3 작업별 정상·예외·완료 조건

#### W-01 계정

**W-01-1 가입·로그인 화면 설계**
- 정상: S02~S06의 입력 칸, 버튼, 안내 문구, 이동 경로를 9장대로 설계한다.
- 예외: 오류 문구(형식, 비밀번호 규칙, 중복 이메일, 잠금, 링크 만료)를 모두 화면에 배치한다.
- 완료: 설계 파일이 9장의 문구·규칙과 일치하고, 개발 화면과 대조해 차이가 없다.

**W-01-2 이메일 가입·인증**
- 정상: 규칙에 맞는 이메일·비밀번호와 필수 약관 동의 → 미인증 계정 생성 → 인증 메일 발송 → S03. 링크를 누르면 인증 완료 후 로그인 상태로 S07.
- 예외
  - 인증을 마친 같은 이메일이 있으면 기존 가입 방식을 안내하고 계정을 만들지 않는다.
  - 같은 이메일의 미인증 계정만 있으면 이전 계정을 지우고 새로 만든다.
  - 입력 규칙을 어기면 해당 오류 문구를 보여 준다.
  - 만료되거나 이미 쓴 링크는 "링크가 만료됐어요"와 [다시 보내기]를 보여 준다.
  - 메일 발송이 3번 실패하면 S03에 "메일을 보내지 못했어요. 다시 보내기를 눌러 주세요"를 보여 준다.
  - 24시간 동안 인증하지 않은 계정은 삭제한다.
- 완료: Gmail·네이버 메일에서 인증 메일을 받아 가입을 끝낼 수 있고, 위 예외가 모두 재현된다.

**W-01-3 구글·카카오 로그인**
- 정상: 제공자 동의 후 돌아오면 처음 가입이면 약관 동의 → S07, 기존 계정이면 바로 S07.
- 예외
  - 동의를 취소하면 S02로 돌아와 "로그인이 취소됐어요"를 보여 준다.
  - 구글 이메일이 미인증이면 가입하지 않는다.
  - 카카오가 이메일을 주지 않으면 S04로 보낸다.
  - 같은 이메일이 다른 방식으로 인증돼 있으면 안내하고 막는다.
  - 제공자 오류면 "잠시 후 다시 시도해 주세요"를 보여 준다.
- 완료: 실제 구글·카카오 계정으로 가입·로그아웃·재로그인이 되고, 중복 차단 3가지 조합(이메일↔구글, 이메일↔카카오, 구글↔카카오)이 모두 막힌다.

**W-01-4 로그인·잠금·세션**
- 정상: 맞는 정보로 로그인하면 S07로 가고 14일 동안 유지된다. 로그아웃 후 보호 화면에 들어가면 S05로 간다.
- 예외: 틀리면 공통 문구, 5회 연속 틀리면 10분 잠금 안내, 소셜 가입 이메일로 비밀번호 로그인을 시도하면 가입 방식 안내, 미인증 계정은 S03으로 보낸다.
- 완료: 잠금이 10분 뒤 풀리고, 로그아웃 후 뒤로 가기로 보호 화면이 보이지 않는다.

**W-01-5 비밀번호 재설정**
- 정상: 이메일 입력 → 같은 안내 문구 → 메일 링크 → 새 비밀번호 → S05 → 새 비밀번호로 로그인.
- 예외: 가입되지 않은 이메일도 같은 문구를 보여 주고 메일은 보내지 않는다. 소셜 가입 계정에는 가입 방식 안내 메일을 보낸다. 만료·재사용 링크, 비밀번호 규칙 위반, 요청 횟수 초과(IP당 분당 5회)를 처리한다.
- 완료: 재설정 후 이전 비밀번호로 로그인되지 않고, 같은 링크를 두 번 쓸 수 없다.

**W-01-6 계정 설정·탈퇴**
- 정상: 현재 비밀번호를 확인한 뒤 비밀번호를 바꾼다. 탈퇴는 확인 문구를 입력하면 즉시 삭제하고 S01로 보낸다.
- 예외: 현재 비밀번호가 틀리면 바꾸지 않는다. 확인 문구가 다르면 탈퇴 버튼을 비활성으로 둔다. 측정·보고서 생성 중이면 작업을 멈춘 뒤 삭제한다.
- 완료: 탈퇴 후 계정·가게·결과가 남지 않고, 같은 이메일로 다시 가입해도 무료 진단을 쓸 수 없다.

#### W-02 가게 등록·식별

**W-02-1 가게 등록·후보 선택 화면 설계**
- 정상: S08(가게 이름, 링크, 지도별 링크 복사 방법), S09(후보 최대 5개)를 9장대로 설계한다.
- 예외: 오류 문구 4종(지원하지 않는 링크, 가게를 찾지 못함, 대상 업종 아님, 신청 중 변경 불가)과 변경 모드 확인 문구를 배치한다.
- 완료: 설계와 개발 화면이 일치한다.

**W-02-2 링크 판별**
- 정상: 세 지도의 긴 링크·짧은 링크, 공유 문구 통째 붙여넣기에서 지도 종류와 가게 번호(Google은 이름·좌표)를 얻는다.
- 예외: 지원하지 않는 링크와 링크가 없는 입력은 오류 문구를 보여 준다. 짧은 링크가 3번 넘게 이동하거나 5초 안에 확인되지 않으면 "링크를 확인하지 못했어요. 다른 링크를 넣어 주세요"를 보여 준다.
- 완료: 테스트 가게 20곳의 3사 링크(긴·짧은 형식)를 모두 판별하고, 지원하지 않는 링크 10개를 모두 거부한다.

**W-02-3 가게 식별·다른 지도 매칭**
- 정상: 결과가 하나면 확정하고, 나머지 두 지도에서 같은 가게를 찾아 저장한 뒤 S10으로 간다.
- 예외: 결과가 여러 개면 S09, 없으면 다른 링크를 요청한다. 다른 지도에서 찾지 못하면 "찾지 못함"으로 두고 진행한다. 외부 API 오류나 10초 초과 시 "잠시 후 다시 시도해 주세요"를 보여 주고 저장하지 않는다.
- 완료: 테스트 가게 20곳 기준
  - Google·카카오 링크: 20곳 모두 맞게 식별, 잘못 식별 0곳
  - 네이버 링크: 18곳 이상 자동 확정 또는 후보 목록에 정답 포함, 잘못 식별 0곳
  - 다른 지도 매칭: 지도별 18곳 이상 맞게 찾고, 다른 가게를 같은 가게로 잡은 경우 0곳

**W-02-4 업종 확인·가게 등록**
- 정상: 음식점·카페·바로 확인되면 가게를 등록한다.
- 예외: 대상 업종이 아니면 "지금은 음식점·카페·바만 진단할 수 있어요"를 보여 주고 등록하지 않는다.
- 완료: 테스트 가게 20곳이 모두 등록되고, 대상이 아닌 가게 5곳(예: 미용실, 편의점)은 모두 거부된다.

**W-02-5 가게 변경**
- 정상: 변경을 확인하면 이전 가게는 지난 기록으로 옮겨져 조회만 할 수 있다. 무료 진단을 아직 쓰지 않았으면 새 가게도 수집 후 측정이 자동으로 시작된다. 이미 썼으면 수집까지만 하고 S07에 "무료 사용 후 가게 변경" 카드를 보여 준다.
- 예외: 보고서 신청이 진행 중이면 변경을 막는다. 측정 중에 바꾸면 측정을 멈추고 무료 횟수는 차감하지 않는다.
- 완료: 무료 미사용·사용 완료·측정 중·신청 중 4가지 경우를 모두 재현해 맞게 동작한다.

#### W-03 정보 수집

**W-03-1 Google 상세정보 수집**
- 정상: 10장 F-04의 Google 항목을 받아 저장한다.
- 예외: 비어 있는 항목은 빈 값으로 두고 화면에 보여 주지 않는다. API 오류는 1번 다시 시도하고, 그래도 실패하면 Google을 "수집 실패"로 두고 나머지 출처를 진행한다. Google에서 가게를 찾지 못했으면 F-08 판정 대상으로 넘긴다.
- 완료: 테스트 가게 20곳 모두 수집되고, 가게마다 받은 항목 목록이 기록되며, 30초 안에 끝난다.

**W-03-2 카카오·네이버 기본정보 수집**
- 정상: 카카오는 장소 ID·장소 링크만 저장하고 이름·주소 등은 화면에 보여 줄 때 다시 불러온다. 네이버 결과는 가게 식별, 홈페이지 주소 확인, 기본정보(이름·주소·전화·업종) 비교에만 쓴다.
- 예외: 호출에 실패하면 해당 지도를 "찾지 못함"으로 표시하고 진행한다.
- 완료: 카카오 장소 ID·링크 외의 값이 저장되지 않고, AI에 보내는 내용에 네이버 결과가 들어가지 않는다.

**W-03-3 공식 웹사이트 수집**
- 정상: robots.txt가 허용하면 첫 페이지와 메뉴 페이지 1개를 읽어 메뉴·가격·영업시간·소개·영문 페이지 여부를 뽑는다.
- 예외: 웹사이트가 없으면 건너뛴다. robots.txt가 막으면 읽지 않고 "읽기 허용 안 됨"으로 기록한다. 10초나 1MB를 넘거나 오류가 나면 건너뛴다. 등록된 웹사이트가 인스타그램이면 인스타그램 출처로 분류한다.
- 완료: 테스트 가게 중 웹사이트가 있는 가게 모두에서 robots.txt를 지키고(막힌 사이트를 읽은 경우 0건), 영업시간·대표 메뉴 추출 결과가 사람이 확인한 값과 80% 이상 일치한다.

**W-03-4 AI 웹 검색 수집**
- 정상: ChatGPT·Gemini에 각각 1번 물어 AI가 찾은 사이트와 사이트별 가게 정보를 저장한다.
- 예외: 한쪽이 실패하면 다른 쪽 결과만 쓴다. 둘 다 실패하면 외부 사이트 정보 없이 진행하고, 외부 사이트가 필요한 판정 분류는 건너뛴다. 이름·주소가 맞지 않는 다른 가게 정보는 버린다.
- 완료: 테스트 가게 20곳 모두 결과가 저장되고, 사람이 확인했을 때 다른 가게 정보가 섞인 비율이 10% 이하다.

**W-03-5 인스타그램 확인(PoC 포함)**
- 정상: AI 웹 검색 결과의 인스타그램 주소로 가게 계정을 찾는다. PoC를 통과하면 Business Discovery로 소개글·최근 게시물을 받는다.
- 예외: 계정을 찾지 못하거나 개인·비공개 계정이면 "인스타그램 검색 노출 부족" 판정 대상으로 넘긴다. Business Discovery가 실패하면 AI 웹 검색 결과만 쓴다.
- 완료: PoC 결과(앱 심사·비즈니스 인증 없이 되는지)를 기록하고 사용 여부를 정한다. 인스타그램이 있는 테스트 가게에서 계정 찾기 성공률을 기록한다.

**W-03-6 수집 결과 표시**
- 정상: S10에 출처별로 값이 있는 항목만 보여 준다.
- 예외: 모든 출처가 실패해도 화면은 오류 없이 다음 단계로 넘어간다(측정 시작 여부는 W-04-1이 정한다).
- 완료: 빈 칸이 화면에 나오지 않고, 카카오 값은 매번 새로 불러온 값이다.

#### W-04 질문 생성·AI 측정

**W-04-1 질문 생성·검증**
- 정상: 질문 3개(영어 2, 한국어 1)를 만들어 검증을 통과하면 확정한다.
- 예외: 검증에 실패하면 3번까지 다시 만들고, 그래도 실패하면 업종별 고정 문장을 쓴다. 수집에서 지역·업종을 얻지 못하면 측정을 시작하지 않고 "가게 정보를 가져오지 못했어요"와 [다시 시도]를 보여 준다(무료 횟수 차감 없음).
- 완료: 테스트 가게 20곳 모두 질문이 만들어지고, 가게 이름이 들어간 질문 0개, 지역·업종이 빠진 질문 0개다.

**W-04-2 AI 호출·원본 저장**
- 정상: 질문을 그대로 보내고 웹 검색을 켜서 답변 원문·출처·모델 ID를 저장한다.
- 예외: 시간 초과·오류는 2번 다시 시도하고, 그래도 실패하면 실패로 기록한다(미노출로 세지 않음). 같은 호출이 두 번 실행되지 않게 막는다. 하루 비용 상한을 넘으면 새 측정을 대기시킨다.
- 완료: 테스트 가게 5곳 × 60회 실행에서 성공한 답변 원문이 100% 저장되고, 중복 호출 0건, 호출마다 비용이 기록된다.

**W-04-3 비동기 측정·진행률**
- 정상: 측정을 시작하면 바로 S10이 열리고 3초마다 진행률이 바뀐다. 끝나면 S11로 가고 이메일을 보낸다.
- 예외: 창을 닫아도 측정은 계속되고 끝나면 이메일이 온다. 작업 서버가 다시 시작되면 끝나지 않은 호출만 이어서 실행한다. 가게 변경·탈퇴 시 측정을 멈춘다.
- 완료: 측정 중 작업 서버 재시작 시험에서 결과 손실·중복이 없고, 테스트 가게 5곳의 측정이 15분 안에 끝난다.

**W-04-4 측정 실패·다시 시도**
- 정상: 실패율이 30% 이하면 결과를 확정한다.
- 예외
  - 30%를 넘으면 "측정 실패"로 두고 무료 횟수를 차감하지 않는다.
  - 다시 시도는 가게당 하루 3회까지이고, 넘으면 "내일 다시 시도해 주세요"를 보여 준다.
  - 한 질문의 성공 답변이 0개면 그 질문 결과는 "측정하지 못함"으로 표시하고, 전체 실패율이 30% 이하면 나머지 결과는 확정한다.
- 완료: 실패율 29%·31%를 강제로 만들어 각각 확정·실패가 되고, 4번째 다시 시도가 거부된다.

**W-04-5 진행·오류 화면 설계**
- 정상: S10의 단계 표시·예상 시간·수집 정보·[내 가게가 아니에요], S07 측정 실패 카드를 설계한다.
- 예외: 측정 실패, 다시 시도 횟수 초과, 가게 정보 수집 실패, 비용 상한 대기 문구를 배치한다.
- 완료: 설계와 개발 화면이 일치한다.

#### W-05 추천 추출·지표·주변 가게

**W-05-1 추천 추출**
- 정상: 답변마다 추천 가게 이름, 순서, 함께 붙은 출처를 뽑는다.
- 예외: 추천이 없는 답변은 빈 목록으로 두고 정상 집계한다(우리 가게 미등장). 목록이 아닌 문장형 답변은 언급 순서를 순위로 쓴다. 추출에 실패하면 원문을 남기고 지표 분모에서 빼며 건수를 기록한다.
- 완료: 실제 답변 100개를 사람이 정리한 정답과 비교해 가게 이름 90% 이상, 순서 90% 이상 일치한다.

**W-05-2 우리 가게 판정**
- 정상: 정규화한 이름이 세 지도의 한글·영문 이름 중 하나와 같으면 등장으로 센다.
- 예외: 지점명만 다르면 등장으로 센다. 이름만 맞아도 등장으로 세므로, 흔한 이름의 다른 가게가 섞일 수 있다는 점을 테스트 기록에 남긴다.
- 완료: 실제 답변 100개에서 사람의 판정과 95% 이상 일치한다.

**W-05-3 지표 계산**
- 정상: AI별·질문별·전체 등장률, 평균 등장 순서, 출처 집계, 실패율(내부)을 계산한다.
- 예외: 등장이 0이면 등장률 0%, 평균 순서 "없음". 성공 답변이 0개인 칸은 "측정하지 못함".
- 완료: 손으로 계산한 예시 3개와 결과가 같다.

**W-05-4 주변 가게 비교**
- 정상: 우리 가게를 뺀 상위 5곳을 뽑고 같은 방식으로 지표를 계산한다. 같으면 평균 순서가 앞선 가게가 먼저다.
- 예외: 다른 가게가 5곳보다 적으면 있는 만큼만 보여 준다. 지점명이 다른 같은 가게는 하나로 묶는다.
- 완료: 동률, 5곳 미만, 지점명 묶기 경우를 재현해 맞게 동작한다.

#### W-06 무료 진단 결과

**W-06-1 무료 진단 정보 구조·화면 설계**
- 정상: S11의 요약, 주변 가게 비교, 질문별 결과, 출처, 고쳐야 할 점 개수, 측정 조건을 설계한다.
- 예외: 등장 0%, 고쳐야 할 점 0개, "측정하지 못함" 질문 표시를 설계한다.
- 완료: 팀 내부 시연에서 처음 보는 사람이 숫자의 뜻을 설명 없이 이해하고, 설계와 개발 화면이 일치한다.

**W-06-2 무료 진단 화면**
- 정상: 9장 S11 구성대로 보여 준다.
- 예외
  - 등장이 0이면 "아직 한 번도 추천되지 않았어요"를 정상 결과로 보여 준다.
  - 성공 답변이 30개보다 적으면 실제 개수(m)를 보여 준다.
  - 고쳐야 할 점이 0개면 개수 대신 "눈에 띄는 문제를 찾지 못했어요"를 보여 주고, 유료 보고서 신청 버튼은 그대로 둔다.
  - 고쳐야 할 점의 내용은 화면과 응답 어디에도 넣지 않는다.
- 완료: 테스트 가게 5곳의 화면 숫자가 저장된 지표와 같고, 응답에 고쳐야 할 점 내용이 없다.

**W-06-3 홈 상태 카드**
- 정상: 9장 S07의 상태 9가지를 맞게 보여 준다.
- 예외: 보고서 신청이 진행 중이면 [가게 변경]을 비활성으로 둔다. 다시 시도 횟수를 넘으면 버튼을 비활성으로 두고 문구를 보여 준다.
- 완료: 9가지 상태를 모두 재현해 맞는 카드와 버튼이 나온다.

#### W-07 고쳐야 할 점 판정

**W-07-1 고쳐야 할 점 판정**
- 정상: 10장 F-08의 7가지 분류를 판정하고 근거와 함께 저장한다.
- 예외: 판정에 필요한 출처 정보가 없으면 그 분류는 판정하지 않는다(정보가 없어서 생기는 잘못된 판정 방지). 네이버·카카오는 공식 API로 받는 기본정보(이름·주소·전화·업종)만 판정에 쓴다.
- 완료: 테스트 가게 20곳의 판정 결과를 사람이 검토해 틀린 판정이 10% 이하다.

**W-07-2 우선순위 계산**
- 정상: 영향 점수와 쉬움 점수를 더해 높음·보통·낮음을 정한다.
- 예외: 점수를 정할 근거가 부족하면 해당 점수를 1점으로 둔다.
- 완료: 합계 경계값(3·4·5)에서 맞는 등급이 나온다.

#### W-08 유료 보고서 신청·관리자

**W-08-1 유료 보고서 신청**
- 정상: [신청하기] → 신청 접수 → 관리자에게 이메일 → S12에 단계 표시.
- 예외: 같은 가게로는 보고서를 한 번만 받을 수 있다(진행 중이거나 완료된 신청이 있으면 다시 신청 불가). 진단 결과가 없는 가게는 승인 후 측정부터 한다. 거절된 뒤에는 다시 신청할 수 있다. 신청이 진행 중이면 가게를 바꿀 수 없다.
- 완료: 신청 접수 → 승인 → 생성 중 → 완료, 신청 접수 → 거절 → 다시 신청 흐름을 모두 재현하고, 완료 후 같은 가게 재신청이 막힌다.

**W-08-2 관리자 신청 관리**
- 정상: A01에서 신청 목록을 상태별로 보고, [권한 부여]하면 보고서 생성이 시작되고 사장님에게 이메일이 간다. [거절]은 사유를 입력해야 하고 사장님에게 이메일이 간다. 생성 실패 건은 [다시 생성]할 수 있다.
- 예외: 관리자가 아닌 계정은 A01에 들어갈 수 없다. 이미 처리된 신청은 다시 처리할 수 없다.
- 완료: 사장님 계정으로 A01 접근이 거부되고, 부여·거절 기록이 남는다.

**W-08-3 신청·관리자 화면 설계**
- 정상: S12(신청 전·후), A01(목록, 필터, 부여·거절·다시 생성)을 설계한다.
- 예외: 중복 신청, 거절 사유 표시, 생성 실패 표시를 설계한다.
- 완료: 설계와 개발 화면이 일치한다.

#### W-09 유료 보고서 생성·화면

**W-09-1 유료 보고서 생성**
- 정상: 고쳐야 할 점 설명, 영문 문안, 채널별 수정안을 만들어 저장하고 사장님에게 이메일을 보낸다.
- 예외: 실패하면 1번 다시 시도하고, 그래도 실패하면 "생성 실패"로 A01에 표시한다. 3분을 넘겨도 생성은 계속하고 S12는 "보고서 만드는 중"을 유지한다.
- 완료: 테스트 가게 5곳의 보고서가 3분 안에 만들어지고, 고쳐야 할 점마다 근거가 연결된다.

**W-09-2 보고서 사실 검사**
- 정상: 수집한 값에 없는 영업시간·가격·전화·주소는 [ ]로 바꾸고 "확인 필요"를 붙인다. 알레르기·할랄 정보에는 "사장님 확인 필요"를 붙인다.
- 예외: 바꿀 값이 많아 문장이 어색해지면 해당 블록 전체를 "확인 필요"로 표시한다.
- 완료: 일부러 틀린 값을 넣은 시험 문장 20개를 모두 걸러 낸다.

**W-09-3 유료 보고서 화면 설계**
- 정상: S13의 요약, 고쳐야 할 점 카드, 영문 문안, 채널별 수정안(Google·카카오·네이버·공식 웹사이트·인스타그램·외부 사이트), 진단 근거를 설계한다.
- 예외: 출처가 없는 탭 숨김, "확인 필요" 표시, 권한 없음 화면을 설계한다.
- 완료: 12주차 사장님 평가 전에 설계와 개발 화면이 일치한다.

**W-09-4 유료 보고서 화면**
- 정상: 9장 S13 구성대로 보여 주고 블록마다 [복사]가 된다.
- 예외: 권한이 없으면 S12로 보낸다. 공식 웹사이트·인스타그램이 없으면 해당 탭을 숨긴다. 카카오·네이버 탭은 항상 보여 주고, 가게를 찾지 못했으면 등록 방법을 보여 준다.
- 완료: 테스트 가게 5곳 보고서를 화면에서 검수하고, 권한 없는 계정의 응답에 보고서 내용이 없다.

#### W-10 이메일 알림

- 정상: 발신 도메인을 설정하고 인증 메일을 보낼 수 있다.

**W-11-1 권한·보안 점검**

- 완료: 명세서 10장 인수 테스트의 정상 흐름이 배포 환경에서 모두 통과하고, 시연 시나리오를 2번 연속 문제없이 진행한다.

     | Google 지도 | 관리자 초대 → Business Profile API로 수정(승인 전에는 관리 화면을 브라우저 자동화로 수정, 막히면 사람이 수정) | 지도·검색의 "수정 제안"으로 이름·영업시간·전화·웹사이트·편의 정보 제안. Google 검토 10분~30일, 인증된 가게는 사장님에게 알림이 가고 4일 안에 응답이 없으면 공개 정보와 맞을 때 반영될 수 있음 | 불필요 |
     | 카카오맵 | 운영자 초대 → 한눈이 파트너센터 매장정보 화면을 브라우저 자동화로 매장 정보(영업시간·가격·사진·SNS·제공 서비스·태그·한 줄 소개) 수정(막히면 사람이 수정). 주소·업종 변경만 사업자등록증 필요. 외부 운영자 허용 여부는 8주차 확인 | 장소 상세 "정보 수정 제안"(간판·명함 등 증빙 이미지 첨부, 운영 담당자 확인 후 처리). 음식점 영업시간·메뉴는 "제보포인트"로 사진 제보 | 불필요. 대행사 자격으로 사장님 대신 매장관리 권한을 신청하려면 대행사 사업자등록증 + 위임장이 필요하므로, 한눈 사업자가 생기면 사장님의 권한 등록 단계를 대신할 수 있다 |
     | 네이버 지도 | 초대하지 않음. 운영자 권한은 사업자의 내부 직원에게만 줄 수 있고, 주인 권한을 대신 받는 것도 하지 않는다. 소개·사진·메뉴·대표키워드는 사장님이 스마트플레이스에 붙여 넣는다(선택) | 정보수정제안(사람 검수, 증빙 사진 요구될 수 있음, 영업시간 변경은 반려 사례 있음) | 사업자가 있어도 대행 불가 |

     - 수정 제안으로는 사실 정보만 고칠 수 있고, 소개글·사진·SNS 링크·태그 같은 홍보 문구는 고칠 수 없다.
     - 사장님이 관리하는 가게는 사장님이 넣은 정보와 제휴사 정보(예: 배달의민족 메뉴)가 우선한다. 그래서 초대 방식을 우선 권한다.
     - 정보 수정 제안은 사실과 맞는 정보만, 사람이 직접, 가게당 소수만 낸다. 자동 제출은 Google 시연 규칙 외에는 하지 않는다.
     - 카카오는 사장님이 매장관리 대표 권한을 갖고 있어야 초대할 수 있다. 권한이 없으면 초대 전에 사업자등록번호로 권한 등록(비즈니스 심사)을 한 번 더 해야 한다.
     - 함께 정할 것: S15 연결 완료·초대 미도착 알림을 이메일(F-10)로도 보낼지, S15와 연결 후 수정 작업의 작업 분해(11장 W 항목)
   - 참고: 한눈 영문 소개 페이지는 자동 생성 가능, Google 지도는 비즈니스 프로필 API로 수정 가능하지만 Google 승인이 필요, 외부 사이트(다이닝코드·블로그 등)는 우리가 직접 고칠 수 없음
   - Google 지도 수정 방식(결정)
     - 실제 서비스 방식: 사장님이 한눈 공용 Google 계정을 가게 비즈니스 프로필의 관리자로 초대하고, 한눈이 Business Profile API로 수정한다.
     - API 승인 전 방식(2026-10-16 결정): 같은 관리자 권한으로 비즈니스 프로필 관리 화면(`business.google.com`)을 브라우저 자동화로 수정한다. 고친 뒤 화면에서 값이 바뀌었는지 다시 확인한다. 로그인 차단·보안 확인 같은 자동화 차단이 나타나거나 수정에 실패하면 멈추고 사람이 직접 수정하며, 차단을 우회하지 않는다. API 승인을 받으면 API로 바꾼다. 위험은 14장 "Google 관리 화면 자동화"에 적는다.
     - API 신청 준비: 한눈 도메인·웹사이트·도메인 이메일, Google Cloud 프로젝트, 조직 계정, 인증 후 60일이 지나고 웹사이트가 등록된 가게 한 곳의 관리자 권한. 사업자등록 서류는 요구되지 않는다. 검토는 공식 14일 이내(사례 4일~6주).
     - 13주 시연 방식: 브라우저 자동화로 Google 지도 "정보 수정 제안" 화면에 보고서 수정안을 자동으로 채우는 장면을 보여 준다. 코드는 입력까지만 하고 제출은 사람이 누른다. 실제 제출은 미리 동의한 지인 가게에 1~2회만 하고, 지인(소유자)이 4일 안에 거절한다. 보안 문자 등 자동화 차단이 나타나면 멈추고 우회하지 않는다.
   - 함께 미정: 사장님 승인, 재측정·전후 비교(정비 후 일정 기간 뒤 변화 안내, 수정 직후 재측정이면 "아직 반영되지 않았을 수 있음" 안내), 월간 재측정과 알림, 공개 영문 소개 페이지, LocalBusiness JSON-LD, 알레르기·할랄 정보 공개 전 확인, Google·SNS 계정 자동 수정 여부, 전후 비교 시 동일 질문 버전 사용
   - 함께 미정인 성공 지표: 정보 정비 완료율, 정보 정확도(90% 가설), 정비 전후 노출 변화
