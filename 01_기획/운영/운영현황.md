# 운영 현황과 미완료 항목

문서 정리일: 2026-11-09. 아래의 확인 결과는 연결한 시험 기록의 날짜를 기준으로 합니다. 이번 문서 정리 작업에서 운영 서버·로그인·실제 매장 흐름을 다시 시험한 것은 아닙니다.

## 1. 구현 계획과 확인 결과를 읽는 방법

기획 문서는 만들 동작을 정의합니다. 시험 기록은 특정 날짜와 환경에서 확인한 결과를 남깁니다. 과거 문서의 ‘미구현’ 목록이나 테스트 개수 하나를 현재 서비스 전체의 완료 상태로 사용하지 않습니다.

## 2. 근거가 있는 확인 결과

| 항목 | 기록에서 확인한 내용 | 근거 |
|---|---|---|
| 서버·운영 구성 | GCP의 seelo 운영 VM에 Docker·PostgreSQL·API·nginx·워커·HTTPS를 구성한 기록이 있습니다. | [GCP 구축 기록](../../03_실험/구현시험/seelo_GCP_구축기록_20261030.md) |
| 로컬 AI 경로 | 운영 서버와 PC의 공식 Codex CLI를 연결하고 실제 웹 검색·출처 반환을 확인했습니다. PC가 실행 중이어야 하는 경로입니다. | [로컬 CLI 연동 기록](../../03_실험/구현시험/로컬CLI_AI_연동진행_20261031.md) |
| GitHub 자동 배포 | 2026-11-03 실행에서 검증과 배포가 성공했고 사이트의 Figma 링크와 health 응답을 확인했습니다. 당시 전체 CI 결과는 911 passed, 2 skipped, 5 deselected입니다. | [자동 배포 기록](../../03_실험/구현시험/자동배포_구축_20261103.md) |
| 자동 배포 범위 | `backend-0-13` 브랜치의 서비스 코드 또는 배포 워크플로 변경에 대해 검증 후 배포하도록 구성했습니다. | [배포 운영 절차](../../04_MVP/seelo/infra/CONTINUOUS_DEPLOYMENT.md) |

자동 배포 성공과 실제 두 AI 공급자의 전체 진단·지도 수정 성공은 별도로 확인해야 합니다. 테스트 결과가 현재 실제 매장 정보 정비나 새 기획의 구현 완료를 뜻하지 않습니다.

## 3. 남은 확인과 개발

| 항목 | 완료를 판단할 근거 |
|---|---|
| Gemini 인증과 두 공급자 전체 진단 | 실제 공급자별 인증, 검색·출처 응답, 같은 측정 조건의 전체 실행이 확인돼야 합니다. |
| 최종 가입·로그인 화면과 세션 | 최종 UI에서 약관·이메일·OAuth·세션을 잇는 흐름을 확인해야 합니다. |
| 카카오 웹훅 | 제공자 측 등록과 실제 이벤트 수신을 확인해야 합니다. |
| 실제 가게의 정비 흐름 | 동의받은 가게에서 초대·권한·현재 값 읽기·승인·수정·공개 반영을 확인해야 합니다. |
| AI 최소 질문 | 질문 선정·누적 3문항 한도·두 지도 공유·자동 보류·승인 처리를 구현하고 해당 검수 사례를 통과해야 합니다. |
| 이메일·독립 감시 | 실제 받은편지함 수신과 PC에 종속되지 않는 장애 감시·알림을 확인해야 합니다. |
| 외부 데이터 정책 | 출처별 접근·저장·AI 입력·공개 재사용 범위를 정하고 구현에 반영해야 합니다. |
| 상품 정책 | 가격·결제·구독·환불, 모집 지역과 가게 수, 추가 정비 허용 범위를 확정해야 합니다. |

## 4. 실제 운영 문서와 자료

- [서비스 운영 절차](../../04_MVP/seelo/infra/OPERATIONS.md)는 실행·점검·복구에 사용합니다.
- [자동 배포 절차](../../04_MVP/seelo/infra/CONTINUOUS_DEPLOYMENT.md)는 배포 조건과 복구 동작을 확인할 때 사용합니다.
- [구현 시험 폴더](../../03_실험/구현시험/)에는 날짜별 검증 근거가 있습니다. 새 결과가 생기면 근거를 추가하고 이 문서의 현재 목록을 고칩니다.
- 운영 비밀값·개인키·인증 파일·DB 덤프는 기획 문서와 GitHub 업로드 대상에 포함하지 않습니다.
