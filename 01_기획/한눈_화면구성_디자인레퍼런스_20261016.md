# 한눈 화면 구성과 디자인 참고 사이트

- 작성·사이트 확인: 2026-10-16
- 개정: 2026-10-17(유료 보고서를 없애고 자동 정비·전후 비교 보고서 구조로 바꿈)
- 기준: [한눈 기획서](./한눈_기획서.md) 5·7·8·9·15장, [한눈 명세서](./한눈_명세서.md) 7·8장
- 문서 역할: 현재 기능 범위를 화면에 어떻게 배치할지 제안한다. 기능 확정 기준은 기획서·명세서다.
- 사이트 선정 기준: 업종이나 AI/GEO 기능의 유사성보다 글의 읽는 순서, 입력과 버튼의 관계, 지표와 상세 설명의 배치가 한눈에 맞는지를 봤다.
- 확인 범위: 국내외 6개 사이트의 공개 페이지를 실제 브라우저로 확인했다. Plausible은 공개 대시보드, PageSpeed Insights는 example.com 분석의 진행·결과 화면까지 확인했다. 로그인 뒤 유료 관리 화면은 확인하지 않았다.

## 1. 먼저 맞춰야 할 최신 범위

| 항목 | 현재 기준 |
|---|---|
| 입력 | 가게 이름 + Google·카카오·네이버 중 지도 링크 1개. 별도 추가 정보 입력 화면 없음 |
| 가게 식별 실패 | 후보 선택 또는 다른 지도 링크 요청. 예전 발표 자료의 직접 입력 대체 흐름을 쓰지 않음 |
| 측정 | 질문 3개(영어 2·한국어 1) × ChatGPT·Gemini × 10회 = 60회. 랜딩에서는 횟수 대신 "여러 번" |
| 무료 진단 | 계정당 1회. AI별 등장률·평균 등장 순서·출처, 주변 가게 5곳 비교, 고쳐야 할 점의 **개수** |
| 자동 정비 | 무료 진단 뒤 신청. 사장님은 Google·카카오에 한눈 계정을 한 번씩 초대하고 정비안을 한 번 승인. 한눈이 Google 지도·카카오맵 정보를 직접 고침 |
| 전후 비교 | 정비 완료 2주 뒤 같은 질문으로 재측정, 전후 비교 보고서 |
| 정비 대상 | Google 지도·카카오맵만. 네이버·공식 웹사이트·인스타그램은 진단에만 사용 |
| 베타 신청 | 가격·PG 결제 미정. 신청 후 관리자가 승인 |
| 실패 | 기술 실패와 미노출을 분리. 측정 실패 시 무료 횟수 차감 없음. 저장된 과거 답변으로 정상 진단을 꾸미지 않음. 자동 정비가 막힌 칸은 한눈 팀이 직접 처리 |
| 없앰 | 채널별 수정 문안을 건네는 유료 최적화 보고서(2026-10-17) |
| 보류(P1·P2) | 보고서 PDF(P1), 월간 재측정·알림, 공개 영문 페이지, 네이버·웹사이트·인스타그램 정비 |

기존 발표 화면의 200회 측정이나 무료 결과의 상세 오류 공개를 현재 웹 화면에 그대로 가져오면 안 된다.

## 2. 사이트 전체 구조

```text
랜딩 S01
  └ 회원가입·로그인 S02~S06
       └ 내 가게 S07
            ├ 가게 등록·변경 S08
            │    └ 후보 선택 S09 (필요할 때만)
            │         └ 수집·측정 진행 S10
            ├ 무료 진단 결과 S11
            └ 자동 정비 신청·진행 S12
                 └ (관리자 승인 A01)
                      └ Google·카카오 연결 S15
                           └ 정비안 확인·승인 S13
                                └ (자동 정비 → 2주 뒤 재측정 S10)
                                     └ 전후 비교 보고서 S16

계정 메뉴 → 계정 설정 S14
```

### 공통 배치 제안

- 비로그인 헤더: 로고 / 이용 방법 / 무료 진단·자동 정비 안내 / 로그인 / **무료로 확인하기**.
- 로그인 뒤 헤더: 로고 / 내 가게 / 무료 진단 / 자동 정비 / 계정 메뉴. 등록 전·승인 전 메뉴는 해당 안내 화면으로 연결한다.
- 홈·결과·정비안·보고서에는 가게 이름과 주소를 먼저 보여 줘 어떤 가게의 결과인지 알 수 있게 한다.
- 주 버튼은 화면의 다음 행동 하나를 강조한다. 보조 버튼은 테두리나 텍스트 링크로 구분한다.
- 입력 화면은 좁은 중앙 폼, 결과 화면은 넓은 본문을 쓴다. 모든 화면에 큰 사이드바를 붙이지 않는다.
- 흰 배경, 짙은 제목, 회색 설명, 강조색 하나로 구성한다. 카드·그림자·장식을 늘리기보다 구분선과 여백으로 묶는다.

## 3. 화면별 내용과 버튼

| 화면 | 위에서 아래로 들어갈 내용 | 주요 버튼과 위치 |
|---|---|---|
| S01 랜딩 | 질문형 제목 → 두 줄 설명 → 실제 결과를 닮은 예시(무료 진단, 전후 비교) → 이용 방법 4단계 → 무료 진단·자동 정비 비교 → 근거 수치 1개·FAQ → 하단 재안내 | 첫 화면 설명 아래 **무료로 확인하기**, 옆에 결과 예시 보기. 하단에도 같은 주 버튼 |
| S02 회원가입 | 제목 → 구글·카카오 버튼 → 이메일 가입 구분 → 이메일·비밀번호·확인 → 약관 → 가입 | 폼 아래 가입하기. 로그인은 아래 텍스트 링크 |
| S03 이메일 인증 | 보낸 이메일 주소 → 인증 링크 확인 안내 → 만료·재전송 상태 | 다시 보내기와 이메일 바꾸기. 재전송 대기 시간을 버튼 주변에 표시 |
| S04 카카오 이메일 입력 | 이메일이 필요한 이유 한 줄 → 이메일 입력 → 인증 안내 | 폼 아래 인증 메일 보내기. S03의 안내 틀 재사용 |
| S05 로그인 | 구글·카카오 → 이메일·비밀번호 → 로그인 → 가입·재설정 링크 | 폼 아래 로그인. 오류는 입력 영역 가까이 표시 |
| S06 비밀번호 재설정 | 이메일 요청 화면 / 메일 링크에서 새 비밀번호 입력 화면 | 각 폼 아래 메일 보내기 / 변경하기 |
| S07 내 가게 | 가게 정보 줄 → 현재 상태 카드 1개 → 지금 할 일 → 이전 가게 기록(있을 때) | 상태 카드 오른쪽 또는 아래에 가게 등록·진행 보기·결과 보기·정비 신청·연결하기·정비안 확인·보고서 보기 중 해당 행동 하나 |
| S08 가게 등록·변경 | 제목·짧은 안내 → 가게 이름 → 지도 링크 → 지도별 링크 복사 도움말 → 변경 시 확인 안내 | 두 입력 아래 **등록하기**. 지도 복사 방법은 링크 칸 아래 펼치기 |
| S09 후보 선택 | 어느 가게인지 질문 → 이름·주소·업종·지도 출처가 있는 후보 최대 5개 | 후보 선택 후 아래 확인. 여기에 없어요는 보조 버튼 |
| S10 진행 | 현재 단계·n/60 → 완료되면 이메일로 알린다는 안내 → 수집한 가게 정보와 출처 → 필요 시 가게 오류 신고. 재측정도 같은 화면 | **내 가게가 아니에요**는 보조 행동(재측정에서는 숨김). 완료 시 결과·보고서로 자동 이동 |
| S11 무료 결과 | 가게·측정일 → AI별 추천 요약 → 주변 가게 비교 → 질문별 결과 → 출처 → 고쳐야 할 점 N개 | N개 안내 바로 옆에 **자동 정비 신청** |
| S12 자동 정비 신청·진행 | 신청 전: 한눈이 하는 일 → 사장님이 할 일(초대 한 번, 승인 한 번) → 정비하지 않는 곳 → 베타 승인 안내. 신청 후: 신청 접수 → 승인 → 지도 연결 → 바꿀 내용 확인 → 정비 중 → 재측정 대기(날짜) → 전후 비교 보고서 단계 | 신청 전 **신청하기**. 신청 후에는 사장님이 할 단계(연결, 확인)에만 해당 화면 버튼, 나머지는 상태 표시 |
| S13 정비안 확인·승인 | 진단 3줄 요약·바꿀 항목 N개(Google a·카카오 b)·연결 상태 → 고쳐야 할 점 카드 → 지도별 바꿀 내용 탭(칸·현재 값·바꿀 값·이유) → 진단 근거 → 승인 안내 | 하단 **정비 시작** 하나. "확인 필요" 칸 옆에 값 입력·이 칸은 빼기, 민감 정보 확인 체크. 승인 뒤 읽기 전용 |
| S14 계정 설정 | 이메일·가입 방식·가입일 → 비밀번호 변경(이메일 가입) → 로그아웃 → 탈퇴 | 각 행동을 구분. 탈퇴는 확인 단계를 거쳐 처리 |
| S15 Google·카카오 연결 | Google 지도·카카오맵 카드 2개: 연결 상태 → 초대 방법(그림 단계) → 한눈 계정 → 권한 회수 안내 | 카드마다 한눈 계정 **복사**, 초대 방법 보기, **초대했어요**. 가게가 지도에 없으면 카드 대신 등록 안내 |
| S16 전후 비교 보고서 | 등장률·평균 순서·주변 가게 위치 전→후 요약, 측정일·정비 완료일, 보장 아님 안내 → 주변 가게 전·후 → 질문별 전·후 → 출처 변화 → 바꾼 내용 → 답변 원문(펼치기) → 측정 조건 | 주 버튼 없음. 읽는 화면. PDF 내려받기는 P1 |
| A01 관리자 | 상태 필터 → 신청 목록 → 신청 상세(가게·연결 상태·정비안·수동 처리 칸) → 처리 | 승인 / 거절, 연결 확인, 수동 처리 칸의 처리 완료, 실패 건 다시 생성, 지금 재측정(테스트·시연용) |

기획서의 사장님 화면 16개(S01~S16)와 관리자 화면 1개(A01)를 따른다. 인증 안내는 동일한 폼·상태 화면 틀을 재사용하고, 핵심 사용자 흐름부터 와이어프레임을 만든다.

## 4. 특히 중요한 화면의 배치

### 랜딩 S01 — 먼저 결과와 행동을 보여 주기

```text
[로고]   이용 방법   자동 정비 안내       로그인 [무료로 확인하기]

AI가 맛집을 추천할 때,                [무료 결과 예시]
우리 가게도 나올까요?                 ChatGPT / Gemini
                                     등장률·주변 가게 비교
가게 이름과 지도 링크로
지금 노출 상태를 확인해 보세요.
[무료로 확인하기]  [결과 예시 보기]

무료 진단 → 정비 신청·한눈 초대 → 바꿀 내용 한 번 승인 → 한눈이 고치고 2주 뒤 전후 비교
무료 진단 / 자동 정비 비교
근거 수치 1개 + 출처
FAQ → 마지막 시작 버튼
```

- 긴 GEO 설명이나 연구 배경을 첫 화면에 넣지 않는다.
- 예시 수치는 ‘예시’로 표시하고, 실제 측정·개선 성과처럼 보이지 않게 한다. 전후 비교 예시도 같다.
- 무료는 계정당 1회이며, 추천·순위 보장 상품이 아니라는 안내를 관련 구역에 짧게 둔다.
- 측정 횟수(60회)는 쓰지 않고 "여러 번"으로 표현한다.
- 참고: 토스페이먼츠의 좌측 문장·버튼 / 우측 제품 미리보기, Tally의 짧은 소개·한 개의 주 행동.

### 내 가게 S07 — 메뉴보다 다음 할 일 먼저

```text
망원밥상 · 주소                         [가게 변경]
Google / 카카오 / 네이버 / 웹사이트 / Instagram 출처 표시

[현재 상태 카드 1개]
진단이 끝났어요
ChatGPT 등장률 … / Gemini 등장률 … / 고쳐야 할 점 N개
[결과 보기]  [자동 정비 신청]

지난 가게의 결과·보고서 (기록이 있을 때만)
```

- 가게·진단·신청·연결·정비·재측정 상태를 한 화면에 모두 쌓지 않고 카드 하나만 보여 준다(기획서 S07 표).
- 정비 신청이 있으면 가게 상태보다 신청 상태를 먼저 보여 준다.
- 신청 진행 중에는 가게 변경을 막고 이유를 해당 버튼 옆에 둔다.
- 측정 실패는 다시 시도, 거절은 사유와 다시 신청을 보여 준다. 무료 횟수·재시도 제한은 실제 상태에 맞춰 안내한다.
- 지도 연결이 끊기면 지금 카드에 "연결이 끊겼어요"와 다시 연결하기를 함께 보여 준다.

### 무료 결과 S11 — 요약 → 비교 → 근거 → 신청

```text
가게 이름 · 측정일

[ChatGPT: 성공 m개 중 n개 추천]    [Gemini: 성공 m개 중 n개 추천]
등장률 x% / 추천될 때 평균 k번째  등장률 y% / 추천될 때 평균 l번째

[우리 가게 + AI 추천 상위 5곳 비교 표]
가게 | ChatGPT 등장률 | Gemini 등장률 | 평균 등장 순서

[질문 3개별 결과]          [AI가 참고한 출처]
영문 질문 + 한국어 번역    많이 인용한 사이트·인용 횟수

고쳐야 할 점 N개를 찾았어요.
한눈이 Google 지도·카카오맵에서 직접 고쳐 드려요.   [자동 정비 신청]
```

- 성공한 답변 수를 분모로 표시한다. 실패를 미추천으로 세지 않는다.
- 0%는 정상 결과, 측정하지 못함은 별도 상태다. 평균 순서가 없으면 임의 숫자를 쓰지 않는다.
- 개선점 제목·상세 원인·바꿀 값은 무료 화면에 넣지 않는다(정비안 S13에서 보여 줌). N=0도 정상적으로 안내하고 신청 버튼은 그대로 둔다.
- 현재 기획에 없는 종합 점수·건강 점수는 만들지 않는다.
- 단일 진단에는 시간 추이 선그래프를 넣지 않는다. AI 두 개의 비교와 가게별 가로 막대·표가 알맞다.
- 참고: Plausible 공개 데모의 상단 핵심 수치·하단 비교 목록. 차트 모양보다 요약과 상세의 순서를 참고한다.

### 신청·연결 S12·S15 — 사장님 할 일 두 가지만 크게

- S12 신청 전에는 "한눈이 하는 일 / 사장님이 할 일 / 정비하지 않는 곳" 세 묶음만 보여 주고 바로 아래 **신청하기**를 둔다. 아이디·비밀번호를 받지 않는다는 문장을 사장님이 할 일 옆에 둔다.
- S12 신청 후에는 7단계 진행 표시를 가로(모바일은 세로)로 두고, 사장님 차례인 단계(지도 연결, 바꿀 내용 확인)만 버튼으로 강조한다.
- S15는 Google·카카오 카드 두 개를 같은 틀로 나란히 둔다. 카드 안 순서: 연결 상태 배지(연결 안 됨·초대 대기·연결됨·권한 확인 필요) → 한눈 계정과 **복사** → 초대 방법 보기(그림 단계 펼치기) → **초대했어요**.
- 한쪽만 연결해도 그 지도부터 정비한다는 안내를 카드 위에 한 줄로 둔다. 3일 안에 초대가 오지 않으면 카드에 "초대가 아직 오지 않았어요"와 단계 안내를 다시 펼친다.
- 참고: 채널톡 가격 안내의 같은 틀 비교(S12 신청 전), Tally의 필요한 도움말만 펼치기(S15 초대 방법).

### 정비안 확인·승인 S13 — 바꿀 내용을 보고 한 번 승인

상단에는 진단 3줄 요약, 바꿀 항목 수(Google a·카카오 b), 지도별 연결 상태만 둔다. 본문은 다음 네 영역으로 나눈다. PC에서는 짧은 고정 목차, 모바일에서는 가로 탭이나 목차 펼치기를 제안한다.

| 영역 | 내용 배치 | 행동 |
|---|---|---|
| 고쳐야 할 점 | 영향 순서 카드: 제목·분류 → 왜 중요한가(관련 AI 답변, 주변 가게와의 차이) | 해당 지도의 바꿀 칸으로 이동 |
| 지도별 바꿀 내용 | Google 지도 / 카카오맵 탭(연결된 지도만) → 칸 이름·현재 값·바꿀 값·이유. 영문 소개·메뉴·가격표처럼 긴 값은 펼치기 | 바꿀 값 직접 고치기, "확인 필요" 칸 값 입력·이 칸은 빼기, 알레르기·할랄 확인 체크 |
| 진단 근거 | 질문별 답변 원문 펼치기, 우리 가게·주변 가게 이름 강조 | 질문·답변 탐색 |
| 승인 | "승인하면 위 내용으로 고쳐요. 고치기 전 값은 기록해 두고, 각 지도 관리 화면에서 언제든 되돌릴 수 있어요" | **정비 시작** 하나. "확인 필요" 칸이 남거나 민감 정보 확인이 없으면 비활성 |

- 현재 값과 바꿀 값은 같은 줄 두 열로 두어 차이가 바로 보이게 한다. 사장님이 고친 칸은 표시를 남긴다.
- 가게 이름·주소·업종은 바꿀 칸에 넣지 않는다. 다르면 사장님이 직접 고치는 방법을 안내 문구로 보여 준다.
- 가게가 Google·카카오에 없으면 그 탭에 등록·인증 방법만 보여 준다.
- 승인 뒤에는 읽기 전용으로 바꾸고 칸마다 상태 배지(완료·반영 대기·한눈 팀 처리 중)를 붙인다.
- 문구 복사 버튼·채널별 관리 페이지 바로가기는 두지 않는다. 고치는 일은 한눈이 한다.
- 참고: PageSpeed Insights의 요약 지표 다음 상세 진단 항목으로 내려가는 구조. 기술 용어·성능 점수·무료 공개 범위까지 따라 하지는 않는다.

### 전후 비교 보고서 S16 — 전과 후를 같은 자리에

```text
가게 이름 · 정비 전 측정일 → 정비 후 측정일 · 정비 완료일

[ChatGPT 등장률  x% → y%]   [Gemini 등장률  x% → y%]
평균 등장 순서 k → l        주변 가게 5곳 중 위치 a → b
"추천 순위나 노출을 보장하지 않습니다 …"

[주변 가게 비교 전·후 표]   정비 후 새로 상위 5곳에 든 가게 표시
[질문 3개별 전 → 후]        [출처 변화: 우리 가게 추천에 쓴 사이트, Google·카카오 인용 여부]
[바꾼 내용: 지도·칸·정비 전 값 → 바꾼 값·반영 확인 시각]
답변 원문 전·후(펼치기) · 측정 조건(작은 글씨)
```

- 같은 지표는 전·후를 같은 줄에 두고 화살표로 잇는다. 시계열 선그래프는 쓰지 않는다(두 시점 비교).
- 변화가 없거나 줄어도 그대로 보여 준다. "이번 측정에서는 큰 변화가 없었어요"를 정상 결과 문구로 쓴다. 증가를 정비 효과로 단정하는 문장을 쓰지 않는다.
- 재측정 때 지도 값이 바꾼 값과 다르면 바꾼 내용 줄에 "지금 지도 값이 달라요"를 표시한다.
- [지금 재측정]으로 앞당긴 보고서는 상단에 "정비 후 N일 만에 측정"을 표시한다.
- 참고: Plausible의 상단 핵심 수치·하단 비교 목록, 데이터라이즈의 수치 아래 해석 한 문장.

## 7. 어떤 화면에서 어느 사이트를 볼지

| 한눈 화면 | 우선 참고 | 집중해서 볼 요소 |
|---|---|---|
| 랜딩 S01 | 토스페이먼츠 + Tally | 첫 문장 길이, 설명과 버튼 간격, 주/보조 행동 구분, 예시 화면 위치 |

전체 분위기는 토스페이먼츠처럼 절제하고, 사용 화면의 정보 밀도는 Plausible에 가깝게 가져가는 조합을 권한다. 메뉴·기능 수가 다른 사이트 한 곳을 통째로 따라 하기보다 화면별로 필요한 배치만 참고한다.

## 8. 와이어프레임 제작 순서

1. S11 무료 결과: 사용자가 얻을 결과와 무료 범위를 먼저 확정한다.
2. S13 정비안 확인·승인: 사장님이 보고 승인할 내용과 행동을 확정한다.
3. S15 연결: 사장님이 할 초대 단계를 실제 화면 기준으로 확정한다.
4. S16 전후 비교 보고서: 정비 전후에 무엇을 보여 줄지 확정한다.
5. S07 홈: 계정·가게·정비 신청 상태에 맞는 다음 행동을 정한다.
6. S08·S09·S10: 입력·식별·진행·실패를 연결한다.
7. S12: 신청·승인·연결·정비·재측정 단계를 붙인다.
