# 한눈 화면 구성과 디자인 참고 사이트

- 작성·사이트 확인: 2026-10-16
- 기준: [한눈 기획서](./한눈_기획서.md) 5·7·8·9·15장, [한눈 명세서](./한눈_명세서.md) 7·8장
- 문서 역할: 현재 기능 범위를 화면에 어떻게 배치할지 제안한다. 기능 확정 기준은 기획서·명세서다.
- 사이트 선정 기준: 업종이나 AI/GEO 기능의 유사성보다 글의 읽는 순서, 입력과 버튼의 관계, 지표와 상세 설명의 배치가 한눈에 맞는지를 봤다.
- 확인 범위: 국내외 6개 사이트의 공개 페이지를 실제 브라우저로 확인했다. Plausible은 공개 대시보드, PageSpeed Insights는 example.com 분석의 진행·결과 화면까지 확인했다. 로그인 뒤 유료 관리 화면은 확인하지 않았다.

## 1. 먼저 맞춰야 할 최신 범위

| 항목 | 현재 기준 |
|---|---|
| 입력 | 가게 이름 + Google·카카오·네이버 중 지도 링크 1개. 별도 추가 정보 입력 화면 없음 |
| 가게 식별 실패 | 후보 선택 또는 다른 지도 링크 요청. 예전 발표 자료의 직접 입력 대체 흐름을 쓰지 않음 |
| 측정 | 질문 3개(영어 2·한국어 1) × ChatGPT·Gemini × 10회 = 60회 |
| 무료 진단 | 계정당 1회. AI별 등장률·평균 등장 순서·출처, 주변 가게 5곳 비교, 고쳐야 할 점의 **개수** |
| 유료 보고서 | 미노출 원인·개선 우선순위·영문 문안·채널별 수정안·AI 답변 원문 |
| 베타 신청 | 가격·PG 결제 미정. 신청 후 관리자가 권한 부여 |
| 실패 | 기술 실패와 미노출을 분리. 측정 실패 시 무료 횟수 차감 없음. 저장된 과거 답변으로 정상 진단을 꾸미지 않음 |
| 보류 | 자동 정비, 사장님 승인, 재측정·전후 비교, 월간 알림, 공개 영문 페이지, S15 연결 화면 |

기존 발표 화면의 200회 측정이나 무료 결과의 상세 오류 공개를 현재 웹 화면에 그대로 가져오면 안 된다.

## 2. 사이트 전체 구조

```text
랜딩 S01
  └ 회원가입·로그인 S02~S06
       └ 내 가게 S07
            ├ 가게 등록·변경 S08
            │    └ 후보 선택 S09 (필요할 때만)
            │         └ 수집·측정 진행 S10
            ├ 무료 진단 결과 S11
            └ 보고서 신청·대기 S12
                 └ 관리자 권한 부여 A01
                      └ 유료 보고서 S13

계정 메뉴 → 계정 설정 S14
자동 정비 범위 확정 후 검토 → 내 가게 연결하기 S15
```

### 공통 배치 제안

- 비로그인 헤더: 로고 / 이용 방법 / 무료·유료 안내 / 로그인 / **무료로 확인하기**.
- 로그인 뒤 헤더: 로고 / 내 가게 / 무료 진단 / 최적화 보고서 / 계정 메뉴. 등록 전·권한 전 메뉴는 해당 안내 화면으로 연결한다.
- 홈·결과·보고서에는 가게 이름과 주소를 먼저 보여 줘 어떤 가게의 결과인지 알 수 있게 한다.
- 주 버튼은 화면의 다음 행동 하나를 강조한다. 보조 버튼은 테두리나 텍스트 링크로 구분한다.
- 입력 화면은 좁은 중앙 폼, 결과 화면은 넓은 본문을 쓴다. 모든 화면에 큰 사이드바를 붙이지 않는다.
- 흰 배경, 짙은 제목, 회색 설명, 강조색 하나로 구성한다. 카드·그림자·장식을 늘리기보다 구분선과 여백으로 묶는다.

## 3. 화면별 내용과 버튼

| 화면 | 위에서 아래로 들어갈 내용 | 주요 버튼과 위치 |
|---|---|---|
| S01 랜딩 | 질문형 제목 → 두 줄 설명 → 실제 결과를 닮은 예시 → 이용 방법 3단계 → 무료·유료 비교 → 근거 수치 1개·FAQ → 하단 재안내 | 첫 화면 설명 아래 **무료로 확인하기**, 옆에 결과 예시 보기. 하단에도 같은 주 버튼 |
| S02 회원가입 | 제목 → 구글·카카오 버튼 → 이메일 가입 구분 → 이메일·비밀번호·확인 → 약관 → 가입 | 폼 아래 가입하기. 로그인은 아래 텍스트 링크 |
| S03 이메일 인증 | 보낸 이메일 주소 → 인증 링크 확인 안내 → 만료·재전송 상태 | 다시 보내기와 이메일 바꾸기. 재전송 대기 시간을 버튼 주변에 표시 |
| S04 카카오 이메일 입력 | 이메일이 필요한 이유 한 줄 → 이메일 입력 → 인증 안내 | 폼 아래 인증 메일 보내기. S03의 안내 틀 재사용 |
| S05 로그인 | 구글·카카오 → 이메일·비밀번호 → 로그인 → 가입·재설정 링크 | 폼 아래 로그인. 오류는 입력 영역 가까이 표시 |
| S06 비밀번호 재설정 | 이메일 요청 화면 / 메일 링크에서 새 비밀번호 입력 화면 | 각 폼 아래 메일 보내기 / 변경하기 |
| S07 내 가게 | 가게 정보 줄 → 현재 상태 카드 1개 → 지금 할 일 → 이전 가게 기록(있을 때) | 상태 카드 오른쪽 또는 아래에 가게 등록·진행 보기·결과 보기·보고서 보기 중 해당 행동 |
| S08 가게 등록·변경 | 제목·짧은 안내 → 가게 이름 → 지도 링크 → 지도별 링크 복사 도움말 → 변경 시 확인 안내 | 두 입력 아래 **등록하기**. 지도 복사 방법은 링크 칸 아래 펼치기 |
| S09 후보 선택 | 어느 가게인지 질문 → 이름·주소·업종·지도 출처가 있는 후보 최대 5개 | 후보 선택 후 아래 확인. 여기에 없어요는 보조 버튼 |
| S10 진행 | 현재 단계·n/60 → 완료되면 이메일로 알린다는 안내 → 수집한 가게 정보와 출처 → 필요 시 가게 오류 신고 | **내 가게가 아니에요**는 보조 행동. 완료 시 결과로 자동 이동 |
| S11 무료 결과 | 가게·측정일 → AI별 추천 요약 → 주변 가게 비교 → 질문별 결과 → 출처 → 고쳐야 할 점 N개 | N개 안내 바로 옆에 **유료 보고서 신청** |
| S12 보고서 신청·대기 | 무료로 확인한 내용 / 보고서에서 추가로 얻는 내용 → 베타 승인 안내 → 신청 → 상태 단계 | 신청 전 **신청하기**. 신청 후에는 중복 신청 버튼 대신 상태 표시 |
| S13 유료 보고서 | 요약 → 고쳐야 할 점 → 영문 문안 → 채널별 수정안 → 진단 근거 | 개선 카드의 수정안 보기, 문안 블록 오른쪽 위 복사, 채널별 관리 페이지 바로가기 |
| S14 계정 설정 | 이메일·가입 방식·가입일 → 비밀번호 변경(이메일 가입) → 로그아웃 → 탈퇴 | 각 행동을 구분. 탈퇴는 확인 단계를 거쳐 처리 |
| A01 관리자 | 상태 필터 → 신청 목록 → 신청 상세·가게 정보 → 처리 | 목록·상세에 권한 부여 / 거절. 생성 실패 건은 다시 생성 |

기획서의 화면 ID 14개와 관리자 화면 1개를 유지한다. 인증 안내는 동일한 폼·상태 화면 틀을 재사용하고, 핵심 사용자 흐름부터 와이어프레임을 만든다.

## 4. 특히 중요한 화면의 배치

### 랜딩 S01 — 먼저 결과와 행동을 보여 주기

```text
[로고]   이용 방법   무료·유료 안내       로그인 [무료로 확인하기]

AI가 맛집을 추천할 때,                [무료 결과 예시]
우리 가게도 나올까요?                 ChatGPT / Gemini
                                     등장률·주변 가게 비교
가게 이름과 지도 링크로
지금 노출 상태를 확인해 보세요.
[무료로 확인하기]  [결과 예시 보기]

가게 등록 → 무료 진단 → 최적화 보고서
무료로 알 수 있는 것 / 보고서에서 더 알 수 있는 것
근거 수치 1개 + 출처
FAQ → 마지막 시작 버튼
```

- 긴 GEO 설명이나 연구 배경을 첫 화면에 넣지 않는다.
- 예시 수치는 ‘예시’로 표시하고, 실제 측정·개선 성과처럼 보이지 않게 한다.
- 무료는 계정당 1회이며, 추천·순위 보장 상품이 아니라는 안내를 관련 구역에 짧게 둔다.
- 참고: 토스페이먼츠의 좌측 문장·버튼 / 우측 제품 미리보기, Tally의 짧은 소개·한 개의 주 행동.

### 내 가게 S07 — 메뉴보다 다음 할 일 먼저

```text
망원밥상 · 주소                         [가게 변경]
Google / 카카오 / 네이버 / 웹사이트 / Instagram 출처 표시

[현재 상태 카드 1개]
진단이 끝났어요
ChatGPT 등장률 … / Gemini 등장률 … / 고쳐야 할 점 N개
[결과 보기]  [유료 보고서 신청]

지난 가게의 결과·보고서 (기록이 있을 때만)
```

- 가게 없음·진행 중·실패·완료·신청 중을 한 화면에 모두 쌓지 않는다.
- 신청이 있으면 가게 상태보다 보고서 신청 상태를 먼저 보여 준다.
- 신청 진행 중에는 가게 변경을 막고 이유를 해당 버튼 옆에 둔다.
- 측정 실패는 다시 시도, 거절은 사유와 다시 신청을 보여 준다. 무료 횟수·재시도 제한은 실제 상태에 맞춰 안내한다.

### 무료 결과 S11 — 요약 → 비교 → 근거 → 신청

```text
가게 이름 · 측정일

[ChatGPT: 성공 m개 중 n개 추천]    [Gemini: 성공 m개 중 n개 추천]
등장률 x% / 추천될 때 평균 k번째  등장률 y% / 추천될 때 평균 l번째

[우리 가게 + AI 추천 상위 5곳 비교 표]
가게 | ChatGPT 등장률 | Gemini 등장률 | 평균 등장 순서

[질문 3개별 결과]          [AI가 참고한 출처]
영문 질문 + 한국어 번역    많이 인용한 사이트·인용 횟수

고쳐야 할 점 N개를 찾았어요.            [유료 보고서 신청]
```

- 성공한 답변 수를 분모로 표시한다. 실패를 미추천으로 세지 않는다.
- 0%는 정상 결과, 측정하지 못함은 별도 상태다. 평균 순서가 없으면 임의 숫자를 쓰지 않는다.
- 개선점 제목·상세 원인·영문 수정 문구는 무료 화면에 넣지 않는다. N=0도 정상적으로 안내한다.
- 현재 기획에 없는 종합 점수·건강 점수는 만들지 않는다.
- 단일 진단에는 시간 추이 선그래프를 넣지 않는다. AI 두 개의 비교와 가게별 가로 막대·표가 알맞다.
- 참고: Plausible 공개 데모의 상단 핵심 수치·하단 비교 목록. 차트 모양보다 요약과 상세의 순서를 참고한다.

### 유료 보고서 S13 — 읽는 보고서와 바로 쓸 문구를 구분

상단에는 핵심 진단 요약과 우선순위별 개선점 개수만 둔다. 본문은 다음 네 영역으로 나눈다. PC에서는 짧은 고정 목차, 모바일에서는 가로 탭이나 목차 펼치기를 제안한다.

| 영역 | 내용 배치 | 행동 |
|---|---|---|
| 고쳐야 할 점 | 우선순위 → 한 문장 문제 → 왜 중요한가 → 근거 → 난이도 | 해당 채널 수정안 보기 |
| 영문 문안 | 영문 가게명·한 줄 소개·소개문·메뉴·가격·이용 정보를 짧은 블록으로 | 블록마다 복사 |
| 채널별 수정안 | Google / 카카오 / 네이버 / 해당 인터넷 채널 탭 → 칸 이름 → 현재 값 / 바꿀 값 | 복사 + 관리 페이지 바로가기 |
| 진단 근거 | 질문별 답변 원문 펼치기, 우리 가게·주변 가게 이름 강조 | 질문·답변 탐색 |

고쳐야 할 점의 세부 근거는 펼쳐 보고, 문구를 복사하는 버튼은 항상 해당 문구 가까이에 둔다. 전체 복사 버튼 하나만 제공하지 않는다. 확인하지 못한 채널 값은 ‘확인 필요’로 구분하고, 없는 공식 웹사이트·인스타그램 탭은 억지로 만들지 않는다.

자동 정비·영문 페이지 게시·전후 비교 버튼은 범위 확정 전에는 넣지 않는다. PDF 내려받기는 P1이며, 베타 필수 버튼으로 고정하지 않는다.

참고: PageSpeed Insights의 요약 지표 다음 상세 진단 항목으로 내려가는 구조. 기술 용어·성능 점수·무료 공개 범위까지 따라 하지는 않는다.

## 5. 국내 참고 사이트

### ① 토스페이먼츠 — 랜딩과 간단한 등록 폼

- [메인](https://www.tosspayments.com/)
- [전자결제 신청 첫 화면](https://onboarding.tosspayments.com/registration/business-registration-number?from=inbound)
- 확인: 메인의 좌측 큰 제목·설명·주/보조 버튼과 우측 제품 화면. 신청 첫 화면의 좁은 중앙 폼, 제목 아래 입력란, 입력란 너비에 맞춘 다음 버튼.
- 한눈 적용: S01 첫 화면, S08 가게 이름·지도 링크 입력. 신청 페이지에는 실제 정보를 입력하거나 제출하지 않았다.
- 적용 제안: 한눈은 입력이 두 개뿐이므로 두 항목을 한 화면에 배치한다. 토스처럼 항목마다 페이지를 나눌 필요는 없다.
- 가져오지 않을 것: 많은 서비스 메뉴, 상단 프로모션 배너, 결제 사업자의 가입 절차.

### ② 채널톡 — 무료·유료 차이를 같은 틀에서 비교

- [메인](https://channel.io/kr)
- [가격 안내](https://channel.io/kr/pricing)
- 확인: 헤더의 시작 버튼, 상품별 같은 위치의 이름·설명·주 버튼·기능 목록, 하단 FAQ.
- 한눈 적용: S01 무료·유료 비교, S12 신청 전 제공 내용 안내.
- 적용 제안: ‘무료 진단 / 최적화 보고서’ 두 열만 두고, 같은 항목 행으로 차이를 비교한다. 신청 버튼은 제공 내용을 읽은 직후에 둔다.
- 가져오지 않을 것: 4개 요금제·복잡한 사용량 계산·상담 팝업. 한눈의 가격이 정해진 것처럼 임의 금액을 넣지 않는다.

### ③ 데이터라이즈 — 결과를 설명하는 문장과 시각 자료의 연결

- [지표 소개](https://www.datarize.ai/metrics)
- 확인: 짧은 결과 중심 제목과 보충 설명, 옆의 데이터 시각 자료, 목적별로 나뉜 세로 설명 구역.
- 한눈 적용: S01 결과 예시 설명, S11 지표마다 붙는 짧은 해석 문장.
- 적용 제안: 수치 아래 ‘그래서 무엇을 뜻하는지’를 한 문장으로 붙인다. 예: ‘ChatGPT 답변에서 우리 가게가 추천된 비율이에요.’
- 가져오지 않을 것: 분홍 그라데이션·여러 장식 그래픽·쇼핑몰용 매출 지표. 공개 제품 소개 화면의 배치를 참고했으며, 로그인 뒤 관리 화면을 검증한 것은 아니다.

## 6. 해외 참고 사이트

### ④ Google PageSpeed Insights — 링크 입력 → 진행 → 결과

- [사이트](https://pagespeed.web.dev/)
- 확인: 상단 URL 입력과 바로 옆 분석 버튼, 간단한 진행 화면, 결과에서 요약 지표 다음 상세 진단으로 이어지는 순서. example.com을 분석해 실제 결과 표시까지 확인했다.
- 한눈 적용: S08 지도 링크 입력, S10 진행, S11 요약, S13 세부 진단의 펼침 구조.
- 적용 제안: 입력·분석이라는 한 가지 일을 선명하게 보여 준다. 한눈의 진행 화면은 5~15분이 걸릴 수 있으므로 현재 단계·n/60·이메일 안내를 추가한다.
- 가져오지 않을 것: 긴 웹 성능 전문 용어, 점수의 원형 게이지, 모든 문제를 무료로 공개하는 범위.

### ⑤ Plausible — 복잡한 메뉴 없이 읽히는 대시보드

- [메인](https://plausible.io/)
- [로그인 없이 보는 실제 데모](https://plausible.io/plausible.io)
- 확인: 데모의 상단 핵심 수치, 그 아래 차트, 하단 두 열의 출처·페이지 목록과 상세 보기. 제품 화면이 소개 이미지에만 머물지 않고 실제 탐색 가능한 공개 데모다.
- 한눈 적용: S11 결과 페이지. AI별 요약을 위에 두고 비교표·질문·출처를 아래에 배치한다.
- 적용 제안: 탭·필터를 많이 만들기보다 기본 화면만 읽어도 결론을 알 수 있게 한다. PC의 질문별 결과·출처는 두 열, 모바일은 한 열로 배치한다.
- 가져오지 않을 것: 현재 진단에 없는 시계열·방문자 수·전환율 지표. 재측정 미정 상태에서 기간 비교 기능을 넣지 않는다.

### ⑥ Tally — 적은 입력과 짧은 설명의 위계

- [메인](https://tally.so/)
- [공식 메인에서 연결한 공개 폼 예시](https://tally.so/r/3qDpEY)
- 확인: 메인의 큰 제목·짧은 설명·대표 버튼, 공개 폼의 한 구역 안에 모인 제목·선택지·아래쪽 다음 행동.
- 한눈 적용: S02·S05 인증 폼의 여백, S08 가게 등록, S09 가게 후보 선택.
- 적용 제안: 설명을 길게 쓰지 말고 필요한 도움말만 펼친다. 후보 카드는 가게 이름·주소·업종·출처만 비교하게 한다.
- 가져오지 않을 것: 낙서 일러스트, 설문 작성 도구의 블록 편집기, 한 항목씩 불필요하게 나누는 흐름. 공개 예시를 열어 보기만 했고 폼을 제출하지 않았다.

## 7. 어떤 화면에서 어느 사이트를 볼지

| 한눈 화면 | 우선 참고 | 집중해서 볼 요소 |
|---|---|---|
| 랜딩 S01 | 토스페이먼츠 + Tally | 첫 문장 길이, 설명과 버튼 간격, 주/보조 행동 구분, 예시 화면 위치 |
| 회원가입·로그인 S02~S06 | 토스 신청 폼 + Tally | 폼의 폭, 라벨·오류 문구 위치, 버튼과 입력의 정렬 |
| 내 가게 S07 | Plausible의 간결한 화면 틀 | 정보를 적게 둔 상단, 읽는 순서. 상태 카드 자체는 한눈 기준으로 설계 |
| 등록·후보 S08~S09 | 토스 신청 폼 + PageSpeed + Tally | 적은 입력, 바로 이어지는 주 버튼, 후보 비교 단위 |
| 진행 S10 | PageSpeed | 진행 상태 강조. 한눈에는 단계·60회 진행·이메일 안내 추가 |
| 무료 결과 S11 | Plausible + 데이터라이즈 | 핵심 수치 우선, 비교표·출처 후순위, 쉬운 해석 한 문장 |
| 신청 S12 | 채널톡 가격 안내 | 제공 내용 비교 후 신청. 월 구독·결제 구조는 제외 |
| 유료 보고서 S13 | PageSpeed 상세 진단 | 요약→문제→근거의 순서. 복사·채널별 수정안은 한눈 전용 구성 |

전체 분위기는 토스페이먼츠처럼 절제하고, 사용 화면의 정보 밀도는 Plausible에 가깝게 가져가는 조합을 권한다. 메뉴·기능 수가 다른 사이트 한 곳을 통째로 따라 하기보다 화면별로 필요한 배치만 참고한다.

## 8. 와이어프레임 제작 순서

1. S11 무료 결과: 사용자가 얻을 결과와 무료 범위를 먼저 확정한다.
2. S13 유료 보고서: 무료와 달라지는 정보·행동을 확정한다.
3. S07 홈: 계정·가게·보고서 상태에 맞는 다음 행동을 정한다.
4. S08·S09·S10: 입력·식별·진행·실패를 연결한다.
5. S12: 신청·승인·생성·거절 상태를 붙인다.
6. S01: 실제 결과 화면을 예시로 써서 서비스 가치를 설명한다.
7. 인증·설정·관리자 화면을 공통 컴포넌트로 정리한다.

이 단계의 산출물은 페이지별 콘텐츠와 배치 제안이다. 기존 Figma 발표용 페이지를 수정하거나 웹사이트를 구현한 것은 아니다.
