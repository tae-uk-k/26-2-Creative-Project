## 읽는 순서

기획을 처음 접하는 사람은 서비스 기획서만 먼저 읽는다. 화면을 만드는 사람은 이용 흐름과 화면을 이어서 읽는다. AI·정비 기능을 만드는 사람은 AI 수집과 최소 질문, 상품정보 정비 기준, 개발 문서 순서로 읽는다. 실제로 작동하는지 확인할 때는 운영 현황과 날짜가 있는 시험 기록을 본다.

## 문서 관리 원칙

- 주제마다 기준 문서 하나를 정하고 같은 파일을 고친다. 파일명에 날짜·수정2·최종본을 붙여 사본을 늘리지 않는다.
- 서비스 설명은 서비스 기획서, 화면 동작은 이용 흐름과 화면, AI 판단은 AI 수집과 최소 질문, 칸별 입력 규칙은 상품정보 정비 기준에서 관리한다. 다른 문서는 내용을 복사하지 않고 연결한다.
- 진행 상태는 운영 현황 한곳에서만 관리한다. 문서에 적었다는 이유로 구현 완료로 표시하지 않는다.
- 기능을 바꾸면 관련 화면·기능 정의·명세·검수 조건을 함께 맞춘다.
- 대상이 바뀌어 쓰지 않는 기획·조사·실험은 [98_이전기획](../98_이전기획/README.md)에 원래 경로 그대로 옮긴다. 현재 문서의 기준으로 쓰지 않는다.

화면은 `P00~P10`, 기능은 `F-01~F-13`, 남은 구현은 `C-01~C-16`, 결정은 `D1~D16`, 사용자 조치는 `U1~U11`로 찾는다. 지도 베타 문서의 `S01~S16`·`F-01~F-12`·`W-01~W-12`는 다른 체계다.
