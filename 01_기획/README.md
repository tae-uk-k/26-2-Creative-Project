## 읽는 순서

기획을 처음 접하는 사람은 서비스 기획서만 먼저 읽으면 됩니다. 화면을 만드는 사람은 이용 흐름과 화면을 이어서 읽고, AI·정비 기능을 만드는 사람은 AI 수집과 최소 질문, 지도정보 정비 기준, 개발 문서 순서로 읽습니다. 실제로 작동하는지를 확인할 때는 운영 현황과 날짜가 있는 시험 기록을 봅니다.

## 문서 관리 원칙

- 주제마다 기준 문서 하나를 정하고 같은 파일을 수정합니다. 파일명에 날짜·수정2·최종본을 붙여 사본을 늘리지 않습니다.
- 서비스 설명은 서비스 기획서, 화면 동작은 이용 흐름과 화면, AI 판단은 AI 수집과 최소 질문, 실제 입력 규칙은 지도정보 정비 기준에서 관리합니다. 다른 문서는 내용을 복사하지 않고 해당 문서를 연결합니다.
- 기능을 바꾸면 관련 화면·기능 정의·명세·검수 조건을 함께 맞춥니다. 문서에 적었다는 이유로 구현 완료로 표시하지 않습니다.
- 과거 시험 기록은 언제 무엇을 확인했는지 보여 주는 증거입니다. 현재 서비스 규칙이나 실시간 운영 상태와 구분해서 읽습니다.
- 주제가 끝난 아이디어와 고유한 참고 자료는 한 곳에 모읍니다. 중복 기획서·변경 전 사본·오래된 내보내기 파일을 참고 자료에 다시 보관하지 않습니다.
- 최신 내용은 GitHub의 이 문서 목록에서 찾습니다. 이전 기획서 파일이나 갱신되지 않은 PDF·HTML을 별도 기준으로 사용하지 않습니다.
