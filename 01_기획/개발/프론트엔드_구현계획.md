# 쇼핑몰 프론트엔드 구현계획

기준일: 2026-11-19. 범위: 디자인을 제외한 프론트엔드 로직.

2026-11-24 추가: 기본 수정은 [관리자 화면 자동화](쇼핑몰_관리자화면자동화.md)로 진행한다. `editingMode=browser`에서는 관리자 위임 확인으로 수집을 허용한다. `snapshotSource`와 변경 `method`에 `browser`를 추가했다. 아래 API 절차는 API 모드를 선택했을 때 적용한다.

## 1. 기준과 구현 범위

- 대상은 스마트스토어·카페24다. [쇼핑몰 진행 지침](../../02_조사/쇼핑몰_타깃플랫폼과_수정수행방식_20261117.md)을 따른다.
- 기존 지도 베타 화면·정비 로직과 분리한다. 현재 백엔드의 `api/commerce.py`·`schemas/commerce.py`를 쇼핑몰 계약으로 사용한다.
- 인증은 기존 백엔드의 이메일·Google·카카오 서버 세션을 사용한다. 실제 CSRF 쿠키 이름은 `seelo_csrf`다.
- React·TypeScript·Vite, React Router, TanStack Query, Zod를 사용한다. 디자인용 CSS·컴포넌트·랜딩·차트는 추가하지 않는다.
- 기본 HTML 폼은 기능 확인에만 사용한다. 기능과 검증 로직은 화면과 분리한다.
- 실제 HTTP 어댑터를 기본으로 사용한다. 명시적인 시연 모드에서만 메모리 어댑터를 사용한다. 오류 때 시연 데이터로 바꾸지 않는다.

## 2. 구현 순서와 결과

| 순서 | 구현할 로직 | 완료 조건 | 현재 결과 |
|---|---|---|---|
| 1 | 실행 환경·경로·공통 오류 | 개발 실행·타입 검사·빌드가 가능하다. | 구현 |
| 2 | 세션·CSRF·가입·로그인·인증·재설정·소셜 가입 | 미로그인 경로를 보존한다. 세션 종료·교체 때 사용자 조회 캐시를 비운다. | 구현. 실계정 미확인 |
| 3 | 스토어·플랫폼·연결 상태 | 가입·관리 권한·API 인증을 구분한다. | 구현 |
| 4 | 상품 원본 수집·검색·자료 조사 | API 원본과 판매자 제공 원본을 구분한다. 실제 서버 자료를 조회한다. | 구현 |
| 5 | 근거·누락 답변·정비안 | 근거와 모델·옵션을 검사한다. 누락은 보류한다. | 구현 |
| 6 | 항목별 승인·적용 | 선택한 필드와 원본 해시를 승인한다. HTML 전환을 별도 확인한다. | 구현 |
| 7 | 재조회·공개 확인·복구·이력 | 저장 성공, API 재조회, PC·모바일 확인을 구분한다. | 구현. 실상품 미확인 |
| 8 | 시연·회귀·서버 계약 | 업무 규칙·통신·기본 폼 통합·실제 Pydantic 요청 검증을 통과한다. | 검증 결과는 프론트엔드 안내에서 관리 |

## 3. 업무 규칙

1. 플랫폼 가입은 외부 절차다. 스토어 등록만으로 쇼핑몰 개설·관리 권한·API 인증을 완료 처리하지 않는다.
2. 소유자는 관리자 초대 전달만 기록한다. 관리 권한 확인은 관리자 역할에서 처리한다. API 인증 상태와 독립적으로 표시한다.
3. 카페24는 서버에서 받은 OAuth 인증 주소를 사용한다. 스마트스토어는 공식 판매자 연결 후 관리자가 API 인증을 처리한다. 개인용 키·판매자 비밀번호를 입력받지 않는다.
4. 원본은 `API 수집`과 `판매자 제공`을 구분한다. 판매자 제공 원본만으로 자동 API 쓰기를 실행하지 않는다.
5. 자료 조사는 기존 상품 원본과 선택적으로 제공한 공식 자료 주소를 서버에 전달한다. 조사 결과·실패를 그대로 표시한다. 브라우저에서 AI 키를 사용하지 않는다.
6. 근거를 직접 보완할 때도 같은 상품·모델·옵션과 실제 인용문을 검사한다. 근거 없는 사양을 생성하지 않는다.
7. 상품별 필요한 누락 답변만 받는다. 현재 서버의 누적 질문 한도는 상품당 3개다. 질문 선택·누적 기록은 서버가 관리한다.
8. 플랫폼의 허용 필드만 정비안 생성 대상으로 받는다. 보류 항목은 새 변경으로 포함하지 않는다.
9. 승인에는 정비안 ID·원본 해시·선택한 필드·HTML 전환 확인을 넣는다. 적용·복구는 서버에 저장된 승인 범위로 실행한다.
10. 스마트스토어 상세설명을 API로 바꿀 때는 생성 시 전환 허용과 승인 시 별도 확인을 받는다. 허용하지 않은 변경은 수동 편집 경로를 사용한다.
11. 서버의 자동 쓰기 설정·API 인증·API 원본 조건을 확인한다. 수동 편집은 관리자가 실제 작업 후 별도로 기록한다.
12. 저장 성공과 API 재조회 성공은 PC·모바일 공개 반영 확인과 다르다. 공개 반영은 관리자의 실제 관찰 기록으로 받는다.
13. 외부 채널의 전송 필드·수신 값은 현재 API에 없다. PC·모바일 확인을 외부 전송 완료로 표시하지 않는다.
14. 복구에는 별도 확인이 필요하다. 승인한 필드의 수정 전 값만 복구한다. 스마트에디터 형식 복구와 구분한다.
15. 변경 요청은 자동 재시도하지 않는다. 핵심 정비 명령의 동시 제출을 막는다. 서버의 상태 잠금과 충돌 검사를 함께 사용한다. 조회에는 취소 신호를 전달한다.
16. `applying` 상태만 주기적으로 조회한다. `uncertain`·`pending_reflection`은 재적용 대신 API 결과 재조회를 제공한다.
17. 상품 HTML·조사 자료를 실행하지 않는다. 기본 폼에서는 문자열로 표시한다.

가격·결제·무료 진단 횟수·14일 재측정은 쇼핑몰 범위에서 구현하지 않는다. 기존 지도 정책을 자동 적용하지 않는다.

## 4. 구조

| 위치 (`04_MVP/seelo/frontend/` 기준) | 역할 |
|---|---|
| `src/api/` | CSRF·쿠키·오류·응답 검증, 기존 인증 API |
| `src/commerce/schemas.ts` | 현재 쇼핑몰 요청·응답 타입과 런타임 검증 |
| `src/commerce/rules.ts` | 승인·근거·충돌·쓰기·복구의 화면 독립 규칙 |
| `src/commerce/http-gateway.ts` | 실제 서버 통신과 작업 화면 데이터 조합 |
| `src/commerce/demo-gateway.ts` | 외부 호출 없는 명시적 메모리 시연 |
| `src/app/` | 세션·경로·Query 캐시·작업 명령과 조회 훅 |
| `src/pages/` | 디자인 없는 기능 확인용 기본 폼 |
| `tests/` | 업무·통신·기본 폼 통합·백엔드 계약 검증 |

## 5. 연결한 서버 계약

접두 경로는 `/api/commerce`다. 현재 백엔드 소스를 기준으로 연결했다. 실제 외부 계정·상품 API 성공과는 구분한다.

| 요청 | 목적 |
|---|---|
| `GET /shops`, `POST /shops`, `GET /shops/{id}` | 스토어 등록·조회, 권한·API 상태 |
| `POST /shops/{id}/manager` | 초대 전달·관리자 권한 확인 기록 |
| `POST /shops/{id}/cafe24/authorize` | 카페24 OAuth 시작 |
| `POST /shops/{id}/products/import` | 플랫폼 상품번호로 API 원본 수집 |
| `POST /shops/{id}/products/manual-snapshot` | 판매자 제공 원본 등록 |
| `GET /shops/{id}/products`, `GET /products/{id}` | 원본·목록 조회 |
| `POST /products/{id}/research` | 기존 원본·공식 자료에서 AI 사실 추출 |
| `POST /products/{id}/facts`, `POST /products/{id}/answers` | 근거·필요한 누락 답변 저장 |
| `POST /products/{id}/plans`, `GET /products/{id}/plans` | 정비안 생성·조회 |
| `POST /plans/{id}/approve` | 원본 해시·필드·전환 확인을 포함한 승인 |
| `POST /plans/{id}/apply`, `POST /plans/{id}/verify` | 승인한 변경 적용·API 결과 재조회 |
| `POST /plans/{id}/rollback` | 승인 범위의 원본 값 복구 |
| `POST /plans/{id}/manual-result`, `POST /plans/{id}/publication` | 관리자 수동 편집·공개 반영 기록 |
| `GET /plans/{id}/writes` | 실제 쓰기 이력 조회 |
| `POST /shops/{id}/disconnect` | seelo 연결 해제·토큰 폐기·대기 작업 취소 |
| `GET /jobs/{id}`, `GET /shops/{id}/jobs` | 브라우저·AI 작업 상태(수집·저장·복구·재조회·목록·AI 준비·측정) |
| `POST/GET /shops/{id}/catalog` | 위임 관리 화면의 플랫폼 상품 목록 |
| `POST /products/{id}/prepare` | AI 조사 → 필요한 정보 판단 → 정비안 생성 |
| `GET /operator/shops`, `GET /operator/tasks` | 관리자 전용 고객 스토어·작업 대기 |
| `POST/GET /products/{id}/measure-sets`, `POST /measure-sets/{id}/runs`, `GET /products/{id}/measure-runs`, `GET /measure-runs/{id}`, `GET /measure-compare` | AI 노출 진단·전후 비교 |

가져온 상품 목록은 서버가 `query`·`page`·`pageSize`로 검색·페이지를 나눈다. 플랫폼 전체 상품 목록(`catalog`)과 구분해 표시한다. 진행 상태는 [운영현황](../운영/운영현황.md)의 C-01~C-10을 따른다.

조회·변경마다 서버가 소유권·역할·상태를 다시 확인해야 한다. 프론트엔드 검증이 서버 권한 검사를 대신하지 않는다. `openapi.json`은 같은 백엔드가 내보내는 계약 자료이며, 쇼핑몰 응답은 별도 Zod 스키마로 검사한다.

## 6. 남은 실환경 검증

- 필수: 실계정 이메일·소셜 가입, 인증 메일 수신, 세션·CSRF, OAuth 복귀 경로.
- 필수: 실제 스토어의 전용 권한·공식 API 인증·상품 원본 조회.
- 필수: 승인한 시험 상품의 쓰기·재조회·충돌·PC·모바일 확인·복구.
- 필수: 카페24에서 실제 외부 전송을 사용하면 전송 필드·수신 값을 별도로 대조.
- 미확인: 실제 AI 자료 추출·두 플랫폼의 실제 상품 쓰기. 메모리 시연이나 계약 검사로 완료 처리하지 않는다.

실행 방법과 최신 검증 결과는 [프론트엔드 안내](../../04_MVP/seelo/frontend/README.md)에서 관리한다.
