# 개발 문서 안내

먼저 [서비스 기획서](../서비스기획서.md)에서 대상과 범위를 확인합니다. 실제 동작 규칙은 아래 문서를 나누어 관리하며, 각 주제에는 현재 기준 파일 하나만 둡니다.

| 문서 | 찾을 수 있는 내용 |
|---|---|
| [기능 정의](기능정의.md) | F-01~F-12의 입력·처리·결과·예외 규칙을 설명합니다. |
| [서비스 명세서](서비스명세서.md) | 기술 스택, 권한, API·작업, 데이터와 상태, 외부 연동·검수 조건을 정의합니다. |
| [개발 할 일](개발할일.md) | W-01~W-12의 작업 목록과 정상·예외·완료 조건을 정리합니다. |
| [백엔드 구현계획](백엔드_구현계획/00_읽는순서.md) | DB·API·작업 큐·인증·수집·정비·보고서를 코드 수준으로 구체화합니다. |

기능을 수정할 때는 [이용 흐름과 화면](../이용흐름과화면.md), [AI 수집과 최소 질문](../AI수집과최소질문.md), [지도정보 정비 기준](../지도정보정비기준.md)을 함께 확인합니다. 같은 규칙을 여러 문서에 다시 정의하기보다 해당 주제 문서를 연결합니다.

백엔드 문서의 날짜가 붙은 구현 메모는 당시 확인한 동작을 설명합니다. 이후 추가된 요구사항은 구현 완료와 구분합니다. 특히 최소 질문의 신청 전체 한도·공통 질문 기록·시스템 보류는 별도 구현과 검수가 필요한 요구사항입니다.

현재 운영과 검증 결과는 [운영 현황](../운영/운영현황.md)과 [구현 시험 기록](../../03_실험/구현시험/)에서 확인합니다. 이 폴더에 완료 표시가 없는 작업을 추측으로 완료 처리하지 않습니다.
