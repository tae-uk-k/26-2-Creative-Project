# 쇼핑몰 관리자 화면 자동화

기준일: 2026-11-24. 사용자 결정에 따라 스마트스토어·카페24의 기본 수정 경로를 **관리자 위임 → 브라우저 자동화**로 정한다. API 발급·앱 설치는 이 경로의 선행 조건이 아니다.

## 고객과 seelo의 작업

| 단계 | 판매자 | seelo |
|---|---|---|
| 최초 연결 | 스마트스토어 대행사 매니저 초대 또는 카페24 상품 수정 부운영자 제공 | 초대 수락, 담당자 계정 로그인, 실제 상품 편집 권한 확인 |
| 원본 수집 | 상품 선택 | 관리 화면 접속, 스토어·상품번호 대조, 현재 본문·보호할 설정 읽기 |
| 정비 | 확인되지 않은 필수 사실 보완, 변경 범위 승인 | 자료 확인·정비안 생성, 승인 범위 입력·저장 |
| 검증 | 결과 확인 | 관리 화면 재조회, 공개 PC·모바일 확인, 변경 이력 기록 |

판매자에게 개발자 가입, 플랫폼 API 키 발급, IP 등록, HTML 복사·붙여넣기를 요구하지 않는다. 로그인·2단계 인증·보안 확인은 담당자가 직접 처리한다.

## 처리 규칙

1. 서버의 `COMMERCE_EDIT_MODE=browser`를 기본으로 사용한다. 기존 API 경로는 `api`로 선택할 수 있다.
2. 관리자가 확인한 `managerStatus=verified`가 있어야 브라우저 수집·저장을 실행한다. 고객이 ‘초대했어요’를 누른 것만으로 확인 완료가 되지 않는다.
3. 브라우저 원본은 `snapshotSource=browser`, 변경 방법은 `method=browser`로 저장한다. API 인증·조회 성공으로 기록하지 않는다.
4. HTTPS 관리자 주소, 스토어, 상품번호를 확인한다. 스마트스토어는 공통 관리자 도메인을 쓰므로 현재 스토어 식별값을 별도로 대조한다.
5. 원본 해시와 승인한 필드를 검사한다. 화면을 다시 연 후에도 같은 값인지 확인하고 입력한다.
6. 가격·재고·판매·진열·구매 제한은 수정 대상에서 제외한다. 화면별 설정에 보호할 입력 칸을 지정하고 저장 전 값을 대조한다.
7. 전송 전 변경 이력을 저장한다. 저장 클릭 후 완료 표시를 기다리고 새로 읽은 값으로 반영을 판정한다.
8. 결과가 불명확하면 `uncertain`으로 남긴다. 같은 저장을 반복하지 않고 재조회한다.
9. 복구는 해당 변경의 수정 전 값만 대상으로 한다. 이후 판매자가 바꾼 값과 충돌하면 중단한다.
10. 로그인·캡차·보안 확인·예상과 다른 화면에서는 중단한다. 해결 후 다시 읽어 작업 상태를 확인한다.

## 구현 위치

| 파일 | 역할 |
|---|---|
| `04_MVP/seelo/backend/seelo/integrations/browser/commerce.py` | 두 플랫폼의 관리자 화면 읽기·입력·저장, 식별값·원본·보호 설정 검사 |
| `04_MVP/seelo/backend/seelo/services/commerce_service.py` | 기존 원본 수집·승인·저장·재조회·복구 흐름에서 브라우저 경로 선택 |
| `04_MVP/seelo/backend/scripts/commerce_browser_login.py` | 담당자가 몰별 전용 브라우저 프로필에 로그인 |
| `04_MVP/seelo/backend/seelo/integrations/browser/selectors/{platform}.yaml` | 실제 화면에서 확인할 주소와 입력 요소 설정 |

기존 `BrowserSession`과 보안 화면 감지를 재사용한다. 몰별 브라우저 프로필을 분리한다. 직접 로그인한 전용 프로필의 세션 쿠키는 기존 Fernet 키로 암호화해 재사용한다. 일반 Chrome 프로필이나 플랫폼 API 토큰을 가져오지 않는다. Windows 브라우저 작업은 Proactor 루프에서 실행한다.

## 실행 준비

1. 백엔드에서 `uv sync --group browser`, `uv run --group browser playwright install chromium`을 실행한다.
2. 운영자가 실제 편집 화면에서 주소, 스토어 식별값, 상품번호, 상품명, 본문 입력 칸, 저장 버튼, 완료 표시와 보호할 설정을 확인한다.
3. 실제 화면에서 검증한 기본 YAML을 사용한다. 몰별 차이가 있으면 전용 YAML 폴더를 `COMMERCE_BROWSER_CONFIG_DIR`로 지정한다. 스마트스토어는 기존 HTML 작성 방식만 지원한다. 스토어명이 URL 아이디와 다르면 `shop_identity.expected`를 실제 화면 이름으로 지정한다.
4. `COMMERCE_BROWSER_PROFILE_ROOT`에 전용 프로필 경로를 설정한다.
5. 예를 들어 `uv run --group browser python scripts/commerce_browser_login.py --platform cafe24 --external-id 몰아이디`로 담당자가 로그인한다.
6. 관리자 권한 확인 후 상품 원본을 수집한다. 기존 API 연결 버튼을 누르지 않아도 된다.
7. 별도 검증 상품에서 수정·재조회·복구를 확인한 뒤 쓰기를 활성화한다. `COMMERCE_WRITES_ENABLED`의 기본값은 false다.

HTML 편집기는 화면의 HTML 입력 칸만 다룬다. 카페24 Froala의 코드 보기처럼 화면에 있는 전환 버튼은 설정으로 지정할 수 있다. 스마트에디터 ONE을 API로 HTML 방식으로 전환하지 않는다. 해당 편집기에 입력할 동작을 확인하지 못했다면 자동 저장하지 않는다.

## 2026-11-25 추가 동작

| 항목 | 동작 | 실제 화면 확인 |
|---|---|---|
| 실행 위치 | 서버에서는 worker-fix가 `commerce_browser` 큐로 실행한다. 같은 몰 프로필은 한 번에 하나만 연다. 자동 재시도하지 않는다. | 컨테이너 실행 미검증 |
| 서버 로그인 | PC에서 담당자가 로그인한 세션을 `scripts/commerce_browser_session.py export/import`로 서버 프로필에 옮긴다. 플랫폼 도메인 쿠키만 옮기고 값은 출력하지 않는다. | 미검증 |
| 스토어 식별 | 운영자가 기록한 스토어 이름·고유 ID를 화면 값과 정확히 대조한다. 비슷한 이름은 다른 스토어로 본다. 카페24는 최종 주소의 쇼핑몰 번호도 대조한다. | 카페24 쇼핑몰 번호 규칙은 기존 실계정 편집 주소 형식과 일치. 스마트스토어 고유 ID 요소는 미확인 |
| 위임 스토어 전환 | `store_switch` 설정이 있을 때만 목록에서 정확히 같은 1곳을 고른다. 0곳(권한 회수·다른 계정)·2곳 이상이면 저장 전에 멈춘다. | 실제 목록 요소 미확인. 기본 설정에 넣지 않음 |
| 플랫폼 상품 목록 | `catalog` 설정이 있을 때만 스토어를 대조한 뒤 상품번호·이름을 읽는다. | 실제 목록 요소 미확인. 기본 설정에 넣지 않음 |

로컬 HTML 시험(실제 Chromium)에서 목록 순서 변경·비슷한 이름·다른 스토어 선택·권한 회수·중복 이름·상품 목록 페이지 이동을 검사했다. 실제 화면 요소를 확인한 뒤 몰별 설정 폴더(`COMMERCE_BROWSER_CONFIG_DIR`)에 `store_switch`·`catalog`를 추가한다.

## 검증 범위

- 로컬 HTML 시험은 실제 Chromium에서 입력·저장·재조회·복구를 실행한다. 두 플랫폼 이름으로 실행하지만 실제 플랫폼 화면을 복제한 시험은 아니다.
- 서비스 시험은 API 토큰 없이 위임 확인·브라우저 원본으로 저장하고, 불명확한 결과를 재조회하며, 원본을 복구하는 경로를 검사한다.
- **실제 양 플랫폼에서 새 Python 실행기로 본문 입력·저장·재조회·공개 반영·원문 복구를 확인했다.** 카페24 샘플상품 9번과 스마트스토어 벌꿀 상품을 사용했다. 기존 API 수정 결과와 구분한다.
- 스마트스토어 벌꿀은 검증 문구를 제거하고 원문 문자열 그대로 복구했다. 수박씨·사차인치 상품은 수정하지 않았다. 가격·재고·판매·구매 제한은 유지했다.
- 카페24는 실제 Froala에서 확인한 본문 바깥·문단 사이 줄바꿈 차이만 정규화한다. 원본 해시와 재조회·복구 판정에 같은 규칙을 사용한다.
- 두 플랫폼 모두 대표 계정으로 검증했다. 실제 고객의 대행사 매니저·부운영자 계정에서의 권한 검증은 별도다. 스마트에디터 ONE과 상품 속성 편집도 미검증이다.
