# 서비스 명세서

기준일: 2026-11-25. 스마트스토어·카페24 상품 정비 서비스의 기술 구성·권한·데이터·상태·작업·외부 연동·설정·검수 조건을 정한다. 기능별 규칙은 [기능 정의](기능정의.md), 경로별 요청과 실행 방법은 [쇼핑몰 백엔드](../../04_MVP/seelo/backend/COMMERCE.md), 진행 상태는 [운영 현황](../운영/운영현황.md)을 따른다.

## 1. 기술 구성

| 영역 | 사용 기술 | 비고 |
|---|---|---|
| 프런트엔드 | React·TypeScript·Vite, React Router, TanStack Query, Zod | 화면은 dark.html·TDS 규칙으로 구현(D12, C-12). TDS 라이브러리는 설치하지 않음 |
| 백엔드 | FastAPI, SQLAlchemy(async), Alembic | 쇼핑몰 경로는 `/api/commerce` |
| DB | PostgreSQL 16 | 쇼핑몰 전용 테이블 8개 |
| 작업 큐 | Procrastinate(PostgreSQL 기반) | 브라우저·AI·측정 작업 분리 |
| 브라우저 실행 | Playwright Chromium | worker-fix 이미지에서만 실행. API 이미지에는 없다. |
| AI | PC Codex CLI(`local_cli`) 또는 API | 운영 방식은 D2 |
| 운영 | Docker Compose, nginx, GCP VM, GitHub Actions 자동 배포 | 자동 배포는 `backend-0-13` 푸시에서 실행(D1) |

계정·세션·CSRF·작업 큐·배포는 지도 베타 때 만든 공통 기반을 그대로 쓴다. 지도 베타 기능의 코드(`stores`·`diagnosis`·`fix_*` 등)는 코드에 남아 있으나 쇼핑몰 기능과 테이블·경로가 분리돼 있다.

## 2. 역할과 권한

| 역할 | 판별 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|---|
| 고객 | 스토어 소유자(`owner_id`) | 스토어 등록, 초대 전달 기록, 상품 수집 요청, 자료 보완, 정비안 생성·승인, 승인한 정비안의 저장·재조회·복구, 연결 해제, AI 노출 진단 | 위임 확인·회수, 스토어 고유값 기록, 수동 편집·공개 반영 기록 |
| 운영자 | 관리자 역할 계정 | 위임 확인·회수, 스토어 고유값 기록, 상품 수집 요청, 고객이 승인한 정비안의 저장·재조회·복구, 수동 편집·공개 반영 기록, AI 노출 진단, 고객 스토어·작업 조회 | 자료 보완·정비안 생성·승인, 고객 승인 없는 실행, 연결 해제 |

위 표는 서버가 받는 요청 기준이다. 화면에서는 저장·재조회·복구·AI 노출 진단 실행을 운영자 화면에만 두고, 고객 화면에는 해당 버튼이 없다([이용 흐름과 화면](../이용흐름과화면.md) 2절·12절). 서버가 고객의 이 요청을 계속 받을지는 실검증 뒤 정한다.

운영자가 수집을 시작해도 AI 정비안은 고객 소유로 만든다. 서버는 조회·변경마다 소유권·역할·상태를 다시 확인한다. 프런트엔드 검사가 서버 권한 검사를 대신하지 않는다. 운영자의 실행은 정비안의 `approvedBy`가 스토어 소유자인지 확인한다. 다른 고객의 스토어에 일반 소유자 명령을 보내면 `FORBIDDEN`이다.

## 3. 데이터

| 테이블 | 내용 | 마이그레이션 |
|---|---|---|
| `commerce_shops` | 플랫폼·스토어 ID·쇼핑몰 번호, 관리자 권한 상태, API 인증 상태, 암호화한 토큰, 위임 확인 고유값·담당자 브라우저 상태(`delegation`) | `0002_commerce`, `0003_commerce_jobs` |
| `commerce_products` | 상품번호·상품명·모델·옵션 식별값, 원본(필드·보호 칸)·해시·출처·수집 시각, 사실 목록, 물어본 사실 | `0002_commerce` |
| `commerce_plans` | 항목별 변경·근거·실행 방법, 질문·보류, 원본 해시, 승인 내용, 상태, 공개 반영 기록 | `0002_commerce` |
| `commerce_writes` | 저장·복구 시도별 변경 값·상태·오류 코드·시각 | `0002_commerce` |
| `commerce_jobs` | 브라우저·AI 작업의 종류·상태·오류 코드·결과 | `0003_commerce_jobs` |
| `commerce_measure_sets` | 고정 질문 세트와 대상 식별값 | `0004_commerce_measure` |
| `commerce_measure_runs` | 회차별 공급자·모델·도구 옵션·반복 수·상태, 측정 당시 원본 해시·마지막 반영 정비안 | `0004_commerce_measure` |
| `commerce_measure_answers` | AI 원문 답변·출처·판정·실패 기록 | `0004_commerce_measure` |

지도 베타 때 만든 기존 테이블은 변경하지 않는다. `0003`·`0004`는 시험 DB와 격리 Docker DB에만 적용했다. 운영 DB에는 백업 뒤 별도로 적용한다(U3). 탈퇴하면 쇼핑몰·상품·토큰·정비안이 FK 연쇄로 함께 정리된다.

## 4. 상태값

| 대상 | 값 |
|---|---|
| 관리자 권한(`manager_status`) | `not_requested`, `invited`, `verified`, `revoked` |
| API 인증(`api_status`) | `not_connected`, `authorized`, `read_verified`, `write_verified`, `revoked` |
| 정비안(`status`) | `draft`, `no_changes`, `approved`, `manual_required`, `applying`, `applied`, `pending_reflection`, `uncertain`, `conflict`, `rejected`, `manual_recorded`, `rolled_back`, `superseded`(DB 허용값, 현재 미사용) |
| 작업(`commerce_jobs.status`) | `queued`, `running`, `succeeded`, `failed`. 오래 멈춘 작업은 `failed`·오류 코드 `stalled` |
| 측정 회차 | `queued`, `running`, `completed`, `partial`, `failed` |
| 측정 답변 | `ok`, `failed` |

한 상품에는 진행 중 정비안(`approved`·`applying`·`pending_reflection`·`uncertain`)이 하나만 있을 수 있다. DB의 부분 고유 인덱스로 막는다. 정비안 상태의 화면 의미는 [이용 흐름과 화면 10절](../이용흐름과화면.md#10-정비안-상태)에 있다.

## 5. 작업 처리

| 작업 | 종류 | 큐 | 실행 위치 |
|---|---|---|---|
| 브라우저 작업 | `collect`, `apply`, `rollback`, `verify`, `catalog`, `forget_session` | `commerce_browser` | worker-fix |
| AI 준비 | `prepare` | `plan` | 일반 워커 |
| AI 노출 측정 | `measure` | `ai_openai`, `ai_gemini` | 공급자별 워커 |

- `COMMERCE_BROWSER_RUNNER=worker`(기본)면 API는 작업만 등록하고 202를 돌려준다. `inline`은 브라우저가 있는 로컬 PC 검증 전용이다.
- 같은 몰 프로필은 lock으로 한 번에 하나만 연다. 같은 상품 수집·같은 정비안 작업은 중복 등록을 막는다.
- 브라우저 작업은 자동으로 다시 시도하지 않는다. `COMMERCE_JOB_STALE_MINUTES`(기본 20분)를 넘긴 실행 중 작업은 `stalled`로 정리하고 새 작업을 받는다.
- `login_required`·`captcha`·`security_check`는 스토어의 담당자 브라우저 상태에 남긴다.
- 연결 해제 때 대기 작업을 취소하고 담당자 세션을 지운다.

## 6. API 묶음

모든 경로는 `/api/commerce` 아래에 있다. 변경 요청에는 CSRF 쿠키·헤더가 필요하다. 경로별 상세는 [쇼핑몰 백엔드의 API 절](../../04_MVP/seelo/backend/COMMERCE.md#api)을 따른다.

| 묶음 | 대표 경로 |
|---|---|
| 기능 정보 | `GET /capabilities` |
| 스토어·위임 | `GET/POST /shops`, `GET /shops/{id}`, `POST /shops/{id}/manager`, `POST /shops/{id}/disconnect` |
| 상품 | `POST /shops/{id}/products/import`, `POST /shops/{id}/products/manual-snapshot`, `GET /shops/{id}/products`, `POST/GET /shops/{id}/catalog`, `GET /products/{id}` |
| AI·사실 | `POST /products/{id}/prepare`, `POST /products/{id}/research`, `POST /products/{id}/facts`, `POST /products/{id}/answers` |
| 정비안 | `GET/POST /products/{id}/plans`, `GET /plans/{id}`, `POST /plans/{id}/approve` |
| 실행·확인 | `POST /plans/{id}/apply`, `POST /plans/{id}/verify`, `POST /plans/{id}/rollback`, `GET /plans/{id}/instructions`, `POST /plans/{id}/manual-result`, `POST /plans/{id}/publication`, `GET /plans/{id}/writes` |
| 작업 | `GET /jobs/{id}`, `GET /shops/{id}/jobs` |
| AI 노출 진단 | `POST/GET /products/{id}/measure-sets`, `POST /measure-sets/{id}/runs`, `GET /products/{id}/measure-runs`, `GET /measure-runs/{id}`, `GET /measure-compare` |
| 운영자 | `GET /operator/shops`, `GET /operator/tasks` |
| 선택 API 연결 | `POST /shops/{id}/cafe24/authorize`, `GET /cafe24/callback`, `POST /shops/{id}/smartstore/seller` |

API 계약은 `04_MVP/seelo/frontend/openapi.json`으로 내보낸다. 프런트엔드는 쇼핑몰 응답을 별도 Zod 스키마로 검사한다.

## 7. 외부 연동

| 대상 | 방식 | 상태 |
|---|---|---|
| 카페24 관리자 화면 | 부운영자 담당자 세션으로 상품 편집 화면 조작 | 대표 계정으로 본문 수정·복구 확인. 부운영자 역할 미검증 |
| 스마트스토어 판매자센터 | 대행사 매니저 담당자 세션으로 상품 수정 화면 조작 | 대표 계정으로 본문 수정·복구 확인. 대행사 매니저 역할 미검증 |
| 카페24 Admin API(선택) | 개발자 앱 → OAuth(`mall.read_product`, `mall.write_product`) → 상품 PUT | 우리 몰의 발급·쓰기 미수행 |
| 스마트스토어 커머스 API(선택) | 커머스솔루션 SELLER 인증 → 원상품 PUT | 외부 고객용 연결 미확보. 본인 스토어 SELF 시험만 수행 |
| AI 공급자 | 정비: `OPENAI_PLAN_MODEL`. 측정: `OPENAI_MEASURE_MODEL`·`GEMINI_MEASURE_MODEL` | 실제 모델 실행 미검증(C-08·C-09). Gemini 운영 값 비어 있음(D3) |
| 공개 웹 자료 | 공인 HTTPS·robots 허용·크기·시간 제한 | 웹 검색 발견은 기본 꺼짐(D5) |

관리자 화면 입력 칸은 `seelo/integrations/browser/selectors/{platform}.yaml`에 둔다. 몰별 차이는 `COMMERCE_BROWSER_CONFIG_DIR`의 전용 설정으로 덮어쓴다. 자세한 처리 규칙은 [쇼핑몰 관리자 화면 자동화](쇼핑몰_관리자화면자동화.md)를 따른다.

## 8. 설정값

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `COMMERCE_EDIT_MODE` | `browser` | 수정 경로. `api`는 선택 경로 |
| `COMMERCE_WRITES_ENABLED` | `false` | 실제 저장 허용 여부 |
| `COMMERCE_WRITE_TARGETS` | 빈 값 | 저장을 허용할 스토어별 상품 목록. 예: `{"12":["12345"]}`는 seelo 스토어 12의 원상품번호 12345만 허용한다. 비우면 쓰기 허용 시 모든 상품에 적용된다. |
| `COMMERCE_BROWSER_RUNNER` | `worker` | 브라우저 작업 실행 위치 |
| `COMMERCE_BROWSER_PROFILE_ROOT` | `/data/browser/commerce` | 몰별 담당자 브라우저 프로필 위치 |
| `COMMERCE_BROWSER_CONFIG_DIR` | 빈 값 | 몰별 화면 설정 폴더 |
| `COMMERCE_JOB_STALE_MINUTES` | `20` | 멈춘 작업 판정 시간 |
| `COMMERCE_AUTO_PREPARE` | `true` | 수집 뒤 AI 준비 자동 등록 |
| `COMMERCE_WEB_DISCOVERY` | `false` | 웹 검색 자료 발견 사용 |
| `COMMERCE_QUESTION_LIMIT` | 없음 | 상품별 누적 질문 상한 |
| `SEELO_BROWSER_WORKER` | 운영 env에서 지정 | `true`면 배포가 worker-fix를 빌드·기동 |

운영 값의 예시는 `04_MVP/seelo/infra/production.env.example`에 있다. 비밀값은 운영 env에만 둔다(U4).

## 9. 보안과 개인정보

- 판매자의 비밀번호·2단계 인증 정보·개인용 API 키를 받지 않는다. 담당자가 전용 브라우저 프로필에 직접 로그인한다.
- API 토큰과 담당자 세션 쿠키는 Fernet 키로 암호화해 저장한다. 응답·감사 기록에 토큰을 넣지 않는다.
- 세션 이전 도구는 플랫폼 도메인 쿠키만 옮기고 값을 출력하지 않는다. 평문 파일은 가져온 뒤 지운다.
- 상품 HTML·조사 자료는 비신뢰 데이터로 다룬다. 화면에서는 문자열로만 표시하고 실행하지 않는다.
- 외부 자료는 공인 HTTPS 주소와 robots 허용을 확인한 뒤 읽는다.
- 운영 비밀값·개인키·인증 파일·DB 덤프는 Git에 올리지 않는다.

## 10. 검수 조건

| 단계 | 완료 근거 |
|---|---|
| 로컬 구현 | 백엔드 단위·통합 시험, 프런트 업무·계약 시험, 빌드·정적 검사 통과. 외부 응답은 시험 대역이다. |
| 실계정 기능 | 위임받은 담당자 계정으로 정확한 스토어에 로그인해 상품을 수집했다. 승인 항목을 저장·재조회했다. 공개 PC·모바일 표시를 확인했다. 원본을 복구했다. |
| 실제 AI | 실제 모델로 실상품 1개를 조사·판단·정비안까지 실행했다. 같은 질문 세트로 측정 회차를 저장했다. |
| 전체 흐름 | 고객·운영자 분리 계정으로 등록부터 복구까지 진행했다(C-10). |

시험 대역이나 메모리 시연 결과를 실계정 완료로 표시하지 않는다. 항목별 현재 상태는 [운영 현황](../운영/운영현황.md)의 추적 표에서만 관리한다.
