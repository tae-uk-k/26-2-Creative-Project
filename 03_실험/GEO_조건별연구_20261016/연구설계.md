# 조건별 GEO 추천 연구

2026-10-16. 실험 실행 전 질문·실행표·분석 원칙을 고정한다. 기존 240회 및 정보 제공 96회와 합산하지 않는다.

## 연구 질문

가게의 어떤 사실이 **어떤 사용자 조건에서 추천 포함·순위·근거로 사용되는가**? 웹 검색 결과 순위·키워드 밀도 대신 생성 답변에 실제 들어가는 가게와 증거를 측정한다.

## 새 자연 검색 관찰

- 명동·성수·망원 × 8조건 × 2CLI × 새 세션 2회 = 96셀.
- 조건: 일반, 혼밥, 1만원 이하, 성인 6인 한 테이블, 만 5세 아이 동반, 전용/제휴 주차, 좌석 사전 예약, 비건.
- 조건 외 문장은 동일. 후보 이름·실험 데이터 미제공. 실행 순서를 고정 난수로 섞음.
- 3개 지도 우선, 접근 실패 시 다른 공개 출처 허용. **초기 지도만 지정한 18셀과 다른 출처 정책**이다. 상세 본문·스니펫·외부 자료를 구분한다.
- 검색 3개·페이지 열람 6개 상한을 지시한다. 지시 준수는 도구 기록으로 확인한다. 모델 자기보고만으로 원문 열람을 확정하지 않는다.
- 5곳 강제 충원이 아님. 모르는 조건은 unknown. 가격 단품과 최소 주문 포함 식사 총액, 주차장 근처와 제휴 주차, 일부 채식과 비건을 구분한다.

## 분석 단위

- 추천: 식당 지점 × 지역 × 조건 × 모델 × 반복. 성공 응답만 분모. 한 응답 안 동일 식당 중복 제거.
- 같은 지역 일반 질문 대비 조건별 등장률 변화. 모델별 결과 우선, 두 모델 단순 합계는 보조.
- 원문 상호 비교는 이름 수준이며 지점 동일성 확정과 구분. 다른 주소·동명이점·브랜드는 검수 대기.
- 조건에서 새로 발견된 식당의 등장률은 사후 발견 표본의 기술통계이며 대표성이나 인과성 없음.
- 추천 문장의 이유·조건 확인 여부는 **모델의 주장**. 독립 수집한 지도 특징과 혼용하거나 같은 답변을 원인과 결과 양쪽에 쓰지 않는다.

| 생성 결과 | 추천 포함·순위·이유·조건 확신·유보·인용 | 최종 답변에서 추출, 원인 특징 아님 |

## 분석 방법

1. 기존 240회를 질문별로 재집계한다. 기존 예산/음식 질문은 지역마다 문구가 달라 서로 같은 처치로 합치지 않는다.
2. 새 96셀은 지역/모델별 추천 명단과 일반 대비 변화를 기술한다. 2회 반복의 0/2·1/2·2/2는 탐색이며 유의성 검정으로 포장하지 않는다.
3. 독립된 지도 특징 60곳의 정보 가용성을 확인하고 조건 정보가 없는 것은 결측으로 둔다. 60곳의 메뉴/가격만으로 아이·주차·비건 효과를 학습하지 않는다.
4. 후속으로 조건별 특징을 결과와 독립적으로 수집하고, 식당 단위 분리·지역/모델 고정효과·조건×특징 상호작용을 둔 규제 로지스틱/혼합모형을 우선한다.
5. XGBoost는 비교 모델이다. 식당 그룹 교차검증과 지역 외 검증에서 기준 모형을 넘을 때만 해석한다. SHAP는 원인 증명이 아니다.
6. 지도 소개를 실제 바꾸는 검증은 추후 동의한 가게의 대조군 포함 전후 실험으로 한다. 이번 관찰만으로 어떤 문장을 쓰면 노출이 오른다고 결론내리지 않는다.

- [What Drives AI Citations?, 2026 preprint](https://arxiv.org/abs/2610.15033): 인용되는 페이지와 이름이 언급되는 브랜드, 검색 단계와 생성 단계를 나누는 설계 참고. 식당·국내 지도에 그대로 적용된다는 주장은 하지 않는다.
