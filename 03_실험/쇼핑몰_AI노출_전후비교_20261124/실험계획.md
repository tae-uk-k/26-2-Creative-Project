# 스마트스토어·카페24 AI 노출 전후 비교 실험

계획일: 2026-11-24. 상태: 계획 수립. 이번 작업에서 노출 측정이나 상품 변경은 실행하지 않았다.

## 1. 이번에 확인할 것

현재 페이지를 먼저 측정한 뒤 seelo가 상세페이지를 정비하고 같은 질문으로 재측정한다. 비교 대상은 **SEO와 일반 상세페이지가 적용된 현재 상태 → GEO 정비 후 상태**다. SEO 적용 전 상태와의 비교가 아니다.

다음 세 결과를 분리한다.

1. URL을 알려 줬을 때 페이지를 읽는가.
2. 브랜드·스토어·URL을 알려 주지 않아도 상품을 발견하고 추천하는가.
3. 발견한 상품의 원재료·용량·가격·영양정보를 정확히 설명하는가.

URL 지정 질문이나 본문 제공 질문은 자연 발견률에 합산하지 않는다. 상품 추천을 받기 위해 이 대화의 내용을 새 측정 대화로 옮기지 않는다.

- 네이버는 재고 1개·최소 2개·1회 및 1인 최대 2개다. 화면에 최소 2개 합계가 표시될 수 있으므로 개당 가격과 구분한다.

- 기존 벌꿀·귀리·서리태는 변경하지 않는다. 이들은 단백질 질문의 동등한 대조 상품으로 세지 않는다.

## 3. 영양소 조건 실험의 필수 자료

현재 정보로는 ‘식물성 단백질 분말’, ‘씨앗 원료’, ‘300g’, ‘요거트·스무디 활용’ 질문을 측정할 수 있다.

‘100g당 단백질 50g 이상’ 같은 수치 조건에는 원료 형태와 탈지 여부가 맞는 영양성분 자료가 먼저 필요하다. 상품별 단백질 g/100g, 1회 사용량, 자료 출처·날짜·대상 원료를 판정표에 고정한다. 자료가 없으면 수치형 4문항은 보류하고 기본 12문항으로 진행한다.

자료가 확보되면 수치와 출처를 **두 상품 모두에 먼저 반영하고 기준선을 다시 측정**한다. 그 뒤 GEO 구조를 바꾼다. 이렇게 해야 영양정보를 새로 추가한 효과와 HTML 구성 변경 효과를 섞지 않는다.

누락 정보 보완까지 포함한 seelo의 전체 효과를 별도로 볼 때는 그 실험을 ‘정보 추가 + 구성 정비’로 기록한다. 이를 HTML 구조만의 효과로 해석하지 않는다. 검증되지 않은 함량은 공개 상품에 넣지 않는다.

## 4. 비교 방식

| 단계 | 수박씨 | 사차인치 |
|---|---|---|
| 기준선 B0·B1 | 현재 상태 유지 | 현재 상태 유지 |
| 1차 정비 T | 양 플랫폼 상세를 seelo로 정비 | 양 플랫폼 모두 유지 |
| 사후 P1·P2 | 정비 상태 측정 | 유지 상태를 같은 시점에 측정 |
| 1차 결과 확정 후 | 상태 유지 | 같은 정비 절차를 늦게 적용해 후속 확인 |

수박씨를 먼저 적용할 상품으로 사전 지정한다. 사차인치는 시간이 지나며 검색에 수집되는 변화와 AI 응답 변동을 확인하는 대조 상품이다.

같은 상품의 네이버·카페24 페이지를 서로 다른 실험군으로 나누지 않는다. AI가 다른 플랫폼의 같은 상품을 찾을 수 있기 때문이다. **실험 단위는 상품 2개이며, URL 4개를 독립 상품 4개로 세지 않는다.**

두 상품은 원료가 다르다. 이 파일럿에서는 차이의 방향과 반복 양상을 확인한다. 질문 반복 횟수를 늘린 것을 독립 상품 표본 수 증가로 해석하지 않는다. 상품 간 일반화가 필요하면 후속 실험에서 원료·가격·검색 수요가 비슷한 상품 쌍을 늘린다.

## 5. 실행 순서와 시점

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1. 준비 | 4개 URL 공개 접근, 사차인치 네이버 검증 마무리, SEO·본문·사진·구매 제한 저장 | API 원본, 공개 화면, 본문 해시, 상품별 사실표 확보 |
| 2. 수집 진단 | 별도 대화에서 정확한 상품명 검색과 URL 지정 열람 | 검색에 잡힌 출처와 URL 직접 열람 결과를 따로 기록 |
| 3. 기준선 B0 | 기본 12문항을 AI별 3회 실행 | 원문·출처·설정·오류 기록 완료 |
| 4. 기준선 B1 | 24~48시간 뒤 같은 측정, 상품은 그대로 유지 | 수정 전 변동폭 확보 |
| 5. 정비 T | 수박씨만 양 플랫폼에 같은 정비 적용 | 변경안·적용 로그·API 재조회·공개 화면 일치 |
| 6. 즉시 확인 P0 | URL 지정 열람으로 새 본문 확인 | 저장·열람 성공 확인. 자연 노출 사후 점수에 합산하지 않음 |
| 7. 사후 P1 | T+3일에 같은 12문항 측정 | 수집 상태와 함께 기록 |
| 8. 사후 P2 | T+7일에 같은 측정 | 두 시점에서 변화 비교 |
| 9. 후속 | 검색 수집이 계속 미확인일 때 T+14일 관찰 1회 | 미수집·구버전 노출·추천 미등장을 구분해 정리 |

공개 직후의 기준선도 기록한다. 다만 정확한 상품명 진단에서도 두 상품이 검색 출처로 확인되지 않으면 ‘초기 수집 단계’로 표시한다. 이 상태의 상승을 바로 GEO 효과로 판정하지 않는다. 정비 시점을 늦춰 비교 가능한 기준선을 확보하거나, 자연 발견 실험과 별도로 본문 제공 이해 실험을 진행한다.

판정은 AI·플랫폼별로 한다. 카페24가 검색에 나타났다고 네이버도 수집된 것으로 처리하지 않는다. URL 직접 열람 성공을 검색 색인 갱신 완료로 처리하지 않는다. 검색 결과·인용문에서 새 본문이 관찰되면 증거를 보관하고, 확인할 수 없으면 버전은 ‘미확인’으로 남긴다.

시점은 실험 운영안이다. Google은 크롤링에 며칠에서 몇 주가 걸릴 수 있다고 안내한다. 따라서 수정 직후 검사와 검색을 통한 사후 측정은 분리한다. [Google 재크롤링 안내](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)

정비 전 기술적 접근 문제를 고칠 경우 양 상품에 동일하게 적용한 뒤 B0부터 새로 시작한다. 기준선 이후 robots·색인 설정을 바꿨다면 상세 정비만의 효과와 구분한다. ChatGPT 검색용 OAI-SearchBot 접근은 학습용 GPTBot 접근과 별개다. 네이버 도메인 설정은 판매자가 직접 수정할 수 있는 설정으로 가정하지 않는다. [OpenAI 크롤러 문서](https://developers.openai.com/api/docs/bots)

2026-11-28 확인: `smartstore.naver.com/robots.txt`는 OAI-SearchBot·Google-Extended·ClaudeBot·PerplexityBot 등을 차단하고 Googlebot만 허용한다. 따라서 ChatGPT 측정에서 네이버 URL 인용률은 구조적으로 낮을 수 있다. 네이버 인용 0을 상세 정비 실패로 해석하지 않는다. ChatGPT 측정의 상품 효과는 카페24 URL 인용과 상품 발견으로 판정한다. [GEO 기법 확장 조사 1절](../../02_조사/GEO_기법확장_HTML메타데이터_20261128.md)

## 6. 질문과 실행 횟수

기본 질문은 일반 조건 4개, 수박씨 조건 4개, 사차인치 조건 4개다. 브랜드·판매처 이름·URL은 넣지 않는다. 정확한 문장은 [고정질문.json](고정질문.json)에 저장했다.

예시:

- ‘300g 안팎의 식물성 단백질 분말을 찾아줘.’
- ‘콩이나 곡물 대신 씨앗을 원료로 한 단백질 분말을 찾아줘.’
- ‘수박씨를 원료로 한 300g 단백질 분말을 찾아줘.’
- ‘사차인치 탈지 단백질 분말을 찾아서 원재료와 중량을 비교해줘.’

각 질문 뒤에는 다음 문장을 동일하게 붙인다.

> 웹에서 제품을 찾아 3개까지 소개해줘. 제품명, 판매처, 근거 링크와 선택 이유를 알려줘. 확인되지 않은 정보는 추정하지 마.

기본 실험은 **12문항 × ChatGPT·Gemini 2종 × 3회 × B0·B1·P1·P2 4시점 = 288회**다. URL·색인 진단, 즉시 확인 P0, 오류 재실행은 별도 장부로 기록한다. 보류한 영양소 4문항을 기준선 전에 활성화하면 96회가 추가된다.

일반 조건 4문항은 두 상품을 함께 평가한다. 원료 지정 4문항은 해당 상품만 평가한다. 일반 질문에서 두 상품이 동시에 등장하면 상품별 적중은 각각 기록하되, 응답 1건을 실행 2회로 늘리지 않는다.

## 7. 조건 고정

- 소비자용 ChatGPT 검색과 소비자용 Gemini를 본 실험으로 사용한다. 모델·모드·계정·지역·언어·검색 설정을 기록하고 전후 동일하게 유지한다.
- 질문마다 새 대화를 쓴다. 이 프로젝트를 설명한 대화, 사용자 설정·프로젝트 파일·기억에 seelo 정보가 들어간 환경은 쓰지 않는다. ChatGPT가 기억을 검색 질의 구성에 사용할 수 있기 때문이다. 기존 사용자 전역 설정은 임의로 바꾸지 않고 측정 환경을 분리한다. [ChatGPT 검색 안내](https://help.openai.com/en/articles/9237897-searching-the-web-with-chatgpt)
- 브랜드·URL이 들어가는 진단 대화와 자연 추천 대화는 분리한다. 질문에 대한 후속 힌트나 ‘우리 상품을 찾아봐’ 재질문은 하지 않는다.
- 질문 순서는 시점별로 섞고, 반복은 서로 다른 세션에서 나눠 실행한다. 같은 AI에서 두 상품 질문을 같은 시간대에 교차 배치한다.
- 가격, 상품명, 사진, 원료·영양 사실, SEO Title·Description, 카테고리, 재고·구매 제한은 고정한다. 변경 대상은 승인된 상세 정비안이다.
- 네이버 최소 수량 2개의 합계와 개당 가격을 따로 기록한다. ‘지금 주문 가능한 상품만’은 본 실험 질문에 넣지 않는다. AI가 구매 제한을 찾아 제외했다면 그 이유를 별도 기록한다.
- 실행 중 모델·검색 모드가 바뀌면 별도 구간으로 분리한다. 바뀐 모델의 결과를 기존 모델 결과에 이어 붙이지 않는다.
- API 검색 연동으로 확장할 경우 별도 실험군으로 기록한다. API 결과를 소비자 앱 결과와 섞지 않는다. Gemini API의 Google Search 도구는 모델이 검색 필요 여부와 검색 질의를 결정하므로 검색 수행과 출처를 실제 응답에서 확인한다. [Gemini 검색 연동 문서](https://aistudio.google.com/docs/google-search)

## 8. seelo 적용 범위

실제 seelo가 동일한 원자료를 읽고 진단 → 정비안 → 승인된 범위 반영 → 재조회까지 수행하도록 한다. 실행 ID, 모델·프롬프트 버전, 입력 자료, 변경 필드, 수작업 수정 내역을 남긴다. 이전에 사람이 만든 현재 상세를 seelo의 개선 성과로 집계하지 않는다.

이번 공통 개선안은 확인된 사실의 요약·원료/용량/활용/주의 항목 정리와 읽을 수 있는 일반 HTML 구성에 한정한다. 사진·본문의 사실 범위를 늘리지 않는다. 기존 디자인과 상품 정체성은 보존한다.

네이버·카페24 공통 비교에서는 스크립트·커스텀 JSON-LD 추가를 제외한다. 플랫폼 기본 Product 데이터는 그대로 둔다. 네이버에서 모바일 이미지 미리보기로 바뀐 이력이 있는 HTML table도 사용하지 않고 일반 블록을 쓴다. 카페24만의 추가 스키마 효과는 후속 별도 실험으로 둔다.

최적화 입력에 평가 질문 원문이나 기준선 답변을 넣지 않는다. 고정 질문에 맞춘 문장 삽입을 방지한다. 정비 이후 질문을 유리하게 교체하지 않는다.

| 지표 | 정의 |
|---|---|
| 자연 발견률 | 정상 응답 중 seelo의 해당 상품이 명확히 식별된 비율. 제외 대상으로 언급된 경우도 발견은 1로 기록 |
| 추천률 | 정상 응답 중 상위 3개 소개·추천 목록에 해당 상품이 긍정적으로 포함된 비율 |
| 상품 링크 인용률 | 정상 응답 중 해당 상품 URL을 근거로 연결한 비율. 네이버·카페24·기타 출처를 구분 |
| 정보 정확도 | 근거가 있는 원재료·용량·가격·보관·주의를 올바르게 설명한 항목 수 / 판정 가능한 항목 수 |
| 근거 없는 추가 | 자료에 없는 단백질 수치·원산지·인증·제조원·효능을 확정한 건수 |
| 접근 성공률 | URL 지정 진단에서 해당 본문을 읽은 횟수 / 진단 시도 수 |
| 구매 제한 인지 | 제한을 발견했는지, 구매 가능 여부를 잘못 설명했는지. 추천 제외 사유와 함께 기록 |

‘수박씨 단백질’ 같은 원료 일반 설명이나 seelo 브랜드만의 언급은 상품 적중이 아니다. 정확한 상품 정체성이나 대상 URL이 필요하다. 동일 상품이 양 플랫폼 링크로 등장해도 상품 발견은 1건이며 플랫폼별 링크 인용은 각각 기록한다.

상품이 안 나오거나, 페이지를 찾지 못했다는 정상 답변은 자연 발견·추천 0점이다. 이를 분모에서 빼지 않는다. 측정 도구 오류·타임아웃·사용량 제한처럼 답변 자체가 완성되지 않은 실행만 무효로 구분한다. 무효는 같은 질문을 1회만 다시 실행하며 최초 실패와 재실행을 모두 보관한다. 최종 보고서에는 계획 횟수·유효 횟수·무효 횟수를 함께 표시한다.

질문군·AI별로 적중 수/분모와 비율을 함께 보고한다. 일반 조건과 원료 지정 조건은 따로 집계한다. 상품별 비교에는 일반 조건 4개와 해당 원료 지정 4개만 사용한다. 네이버·카페24의 인용률도 따로 낸다.

대조 보정 변화량은 다음처럼 계산한다.

`(수박씨 사후율 - 수박씨 기준율) - (사차인치 사후율 - 사차인치 기준율)`

B0·B1 평균과 P1·P2 평균을 비교하고, 각 시점의 원래 수치도 공개한다. 전체 평균 하나만 제시하지 않는다. 반복 응답이 동일 질문·상품에 묶여 있으므로 이를 독립 표본으로 가정한 유의확률을 제시하지 않는다.

파일럿의 긍정 신호는 정비 후 적중한 서로 다른 질문 ID가 2개 이상 늘고, 원료 지정 질문군의 대조 보정 변화가 P1·P2에서 모두 양수이며, 새로 만들어 낸 영양 수치가 없는 경우로 사전 정의한다. 발견·추천·인용 지표 중 어디에서 신호가 났는지 각각 표시한다. 접근이나 구버전 수집 문제가 남으면 원인 판정을 보류하고 그 상태를 결과로 기록한다.
