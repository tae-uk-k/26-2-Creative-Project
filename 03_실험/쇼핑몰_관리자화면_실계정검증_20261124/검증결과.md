카페24는 Froala가 추가하는 본문 바깥 줄바꿈과 연속 문단 사이 줄바꿈 수를 정규화한 값으로 비교한다. 본문·태그·속성은 그대로 비교한다. `pre`, `code`, `textarea`, `script`, `style` 또는 공백 보존 스타일이 있으면 문단 사이 정규화를 적용하지 않는다. 스마트스토어는 원문 문자열 그대로 일치했다.

스마트스토어의 재고 1개·최소 구매 2개·최대 구매 2개 조건은 유지했다. 저장 전후의 보호 항목도 일치했다. 수박씨·사차인치 상품은 수정하지 않았다.

각 폴더의 `before.json`, `after.json`, `restored.json`에 수집한 본문과 보호 항목이 있다. `intent.json`에는 전송 전 변경 의도가 있다. 기존 Chrome을 조작한 카페24 선행 시험은 `cafe24_ui_result.json`에 별도로 기록했다. 위 성공 판정은 그 선행 시험이 아니라 새 Python 실행기의 결과다.

`cafe24_python` 첫 실행은 편집기의 줄바꿈 변동으로 원본 충돌을 감지해 저장 전에 중단했다. `cafe24_python_v2`는 실제 반영·복구에는 성공했지만 문단 사이 줄바꿈으로 문자열 비교가 달랐다. 확인한 편집기 동작을 보완한 최종 기록은 `cafe24_python_v3`다. 이전 기록은 그대로 보존했다.

## 확인한 문제와 수정

1. Windows 백엔드의 Selector 이벤트 루프에서 Playwright 하위 프로세스를 실행할 수 없었다. 브라우저 작업은 전용 Proactor 루프에서 실행한다.
2. 브라우저를 닫으면 로그인 세션 쿠키가 사라졌다. 직접 로그인한 전용 프로필의 쿠키를 기존 Fernet 암호화로 보관하고 같은 몰에서 재사용한다. 일반 Chrome 쿠키나 비밀번호는 수집하지 않는다.
3. 카페24 코드 편집기 입력 버퍼는 전체 문서를 바로 노출하지 않았다. 코드 보기 후 전체 선택으로 원문을 읽는다. 첫 클릭이 포커스만 주면 닫힌 상태를 확인한 뒤 한 번만 코드 보기를 다시 연다.
4. 카페24 Froala의 줄바꿈 차이를 원본 충돌과 구분했다. 관찰한 범위만 정규화한다.
5. 스마트스토어의 구매 제한은 접힌 영역에 있었다. 영역을 연 후 최소·최대 구매 수량을 수집하고 저장 직전에 대조한다.
6. 카페24의 저장 완료 알림과 스마트스토어의 실제 완료 모달을 설정했다. 저장 결과가 불명확하면 같은 쓰기를 자동 재전송하지 않는다.

## 검증 경계

- 두 플랫폼의 로그인은 사용자의 대표 계정으로 수행했다. 별도 대행사 매니저·부운영자 계정의 초대 수락과 권한 범위는 이번 실험에서 확인하지 않았다.
- 실제 검증은 로컬 Python의 `BrowserProduct` 계층이다. 서비스의 승인·변경 이력·복구 흐름은 별도 PostgreSQL 통합 시험으로 확인한다. 운영 서버 배포와 운영 DB 변경은 하지 않았다.
- 스마트스토어는 **기존 HTML 작성 방식 상품**을 검증했다. 스마트에디터 ONE을 임의 전환하지 않는다. ONE 상품과 속성 편집은 추가 구현·검증 대상이다.
- 카페24는 상세 본문 쓰기를 검증했다. SEO 입력 칸은 실제 화면에서 확인했지만 이번에 별도로 수정 저장하지 않았다.
- 스마트스토어 기본 스토어 대조는 화면의 스토어명과 설정값을 비교한다. 스토어명이 URL 아이디와 다르면 몰별 설정에서 `shop_identity.expected`를 실제 이름으로 지정해야 한다.

최종 회귀: 쇼핑몰 규칙·API·브라우저·테스트 PostgreSQL·기존 지도 브라우저를 포함한 **86개 통과**. 변경한 Python의 ruff와 OpenAPI 일치 검사도 통과했다. 프런트엔드는 이번 후속 검증에서 수정하지 않았다.
