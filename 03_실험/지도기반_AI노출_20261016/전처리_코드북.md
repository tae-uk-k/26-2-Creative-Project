# 지도 필드 전처리 규칙

2026-10-16 고정. CLI 추천과 브라우저에서 수집한 지도 필드는 서로 다른 관측이다.

## 행 단위와 결합

- 응답: `run_id` × 요청 지도 × 지역 × CLI × 시각. 정상 완료, 권한 거절, 기타 실패를 보존한다.
- 추천: 응답 안의 순위별 한 행. 식당 신원을 검수하기 전에는 모델이 적은 이름·지점을 그대로 둔다. `pilot_name_appearances.csv`도 **같은 상호 문자열**의 등장 횟수이며 지점별 검증 노출률이 아니다.
- 지도 필드: 검증한 식당 ID × 지도 × 수집 시각 × 필드. 같은 브랜드의 다른 지점을 주소 없이 합치지 않는다.
- 지도 표본 `candidate_frame.csv`를 먼저 확정한 후, 그 명단의 모든 식당에 대한 후속 응답의 등장/미등장 표를 만든다. 이번 예시 3곳이나 파일럿 추천 64건에서 임의로 미노출 대조군을 만들지 않는다.

## 결측과 작성자

| 필드 | 허용값/규칙 |
|---|---|
| `field_status` | `observed`, `observed_empty`, `not_observed`, `not_observed_limited_view`, `unsupported`, `blocked`, `login_required`, `not_listed`, `identity_unresolved` |
| `author_type` | `owner`, `user_review`, `user_blog`, `platform_ai`, `platform`, `unknown`, `research_audit` |
| 실제 공란 | 해당 필드가 열렸고 빈 것이 확인된 경우만 `observed_empty`; 본문 접근 실패는 빈 글 0자가 아님 |
| 짧은 집계 표시 | `1.9만`, `999+` 원문 보존. 정확 수치 칸은 결측. 가짜 정밀도로 19000·999를 대입하지 않음 |
| 작성 주체 | 인증 매장 표시만으로 모든 텍스트를 업주 작성으로 분류하지 않음. AI 요약·후기 답변·업주 게시물·업주 소개를 각각 분리 |
| 실제 사실과 표시 | 주차 가능이라는 표시를 수집할 수는 있으나, 서로 충돌하면 실제 주차 가능 여부는 미확정으로 유지 |

## 작성 방식 변수

| 변수 | 계산과 해석 |
|---|---|
| `owner_description_chars` | 업주 소개가 관측됐을 때만 Unicode 글자 수. HTML 태그 제외, 원래 줄바꿈/공백과 정규화 규칙 버전 보존 |
| 목록·문단 구조 | 제목/줄바꿈/불릿 수를 원문에서 별도 계산. DOM이 줄바꿈을 없앤 경우 문단 수를 추정하지 않음 |
| 검색어 반복 | 사전에 고정한 지역·음식·이용 상황 사전의 정확 일치 횟수와 1000자당 빈도. 이번 예시에서 발견한 문구는 탐색 변수이며 검증 변수로 재사용할 때 따로 고정 |
| 구체적 가격 | 숫자와 통화·단위가 함께 있는 표현. 소개, 메뉴, 소유자 게시물의 가격을 별도 변수로 유지 |
| 사실 명시 | 메뉴/재료/조리법, 인원 한도, 역 출구·도보 시간, 주차 조건, 예약 경로 등. '가성비'와 실제 가격을 같은 값으로 세지 않음 |
| 정비 완성도 | 플랫폼이 지원하고 실제 열어 본 필드가 분모. 접근 성공률도 별도로 보고하여 보이는 식당만 골라 생기는 편향을 확인 |
| 정성 코딩 | 구체적 사실/추상적 표현 비율은 고정 지침으로 독립 검수. 모델이 코딩하면 추천 라벨을 숨기고 사용 모델·프롬프트·검수 결과 저장 |

소개와 게시물 길이는 서로 대체하지 않는다. 영문 게시물이 관측돼도 질문은 한국어로 유지한다. 언어는 지도에 실제 쓰인 내용의 특징으로만 기록한다.

## 현재 수행한 처리

1. 18개 실행 원문을 보존하고 `audit_map_pilot.py`로 정상 응답·권한 실패를 분리했다. 처음 두 건의 기록상 `format_error`는 원문 `denied_actions`를 대조해 파생표에서 권한 실패로 정정했다. 원본 기록은 변경하지 않았다.
2. 추천 64건과 출처 URL, 도구 결과 메타데이터를 분리했다. URL이 있다는 이유로 지도 본문 열람을 인증하지 않았다. Antigravity의 `DONE`은 도구 완료 이벤트이며 본문 전달 증거가 아니다.
3. 다른 사이트에 근거했다고 쓰면서 `map_fields_read`를 채운 5건은 귀속 충돌로 표시했다. 해당 칸을 실제 지도 수집값으로 사용하지 않았다.
4. 세 지도 상세 페이지에서 예시 3곳을 직접 확인했다. 업주 소개·업주 게시물·플랫폼 요약·출처 불명 필드와 결측을 보존해 정규화했다. 3곳은 표본 고정·노출 효과 분석에 사용하지 않는다.
5. 소비자용 기존 결과와 과거 240회 자료에는 새 라벨을 붙이거나 행을 합산하지 않았다.

## 본 분석 진입 조건

2026-10-16 후속: 카카오 목록에서 후보 60곳을 고정하고 상세 상호·주소를 모두 대조했다. 가격 있는 텍스트 메뉴 221개(57곳), 가격 미확보 3곳, 작성자 불명의 짧은 매장 정보 문단 6곳을 보존했다. 네이버 업주 소개를 동일 지점 2곳에서 확인했으며 전수 대응은 미완료다. 사진 수는 모두 + 표시라 정확 숫자로 변환하지 않는다. [최신 검수](./수집_검수_후속결과.md).

지도 본문을 CLI가 실제로 읽는 경로와 자연 검색 노출 라벨을 확보한 후 노출 관계를 분석한다. 반복 90회가 식당 90곳을 뜻하지 않는다. 주요 설명변수 수는 독립 식당 수와 노출 분포에 맞춰 줄인다.

주 분석은 지역·지도·모델·검색 순위·리뷰 규모를 고려한 규제/혼합효과 로지스틱 회귀다. 브랜드 단위 교차검증과 날짜 외부 검증을 사용하고 결측 대체·표준화는 학습 분할 내부에서만 한다. XGBoost는 같은 분할의 예측 비교에 둔다. 검색 순위·리뷰를 보정한 계수도 소개문 정비의 인과 효과는 아니다.

직접 지도 열람을 확보하지 못하면 자연 검색 연구는 접근 제한 결과로 남긴다. 별도 대안인 **브라우저 수집 정보를 후보별로 CLI에 제공하는 통제 실험**은 12곳에서 1차 48회와 동일 정보 표현 비교 48회, 총 96회 완료했다. 발견·검색 가능성은 측정할 수 없고, 제공된 후보 중 선택 변화를 비교한다. 자연 검색 결과에 합산하지 않는다.

메뉴 선택 규칙도 고정한다. ‘처음 2개 메뉴’와 ‘식사 목적에 맞는 메뉴’를 혼용하지 않으며, 가격 범위나 최솟값은 수집한 항목에만 해당한다. 57곳 중 23곳에 처음 2개보다 뒤의 3~4번째 항목에 낮은 가격이 있었으므로, 앞선 정보 제공 실험을 식당 전체의 대표 식사비 효과로 해석하지 않는다. 다른 식당 상호가 업주 소개에 언급되더라도 추천 라벨로 추출하지 않는다.
