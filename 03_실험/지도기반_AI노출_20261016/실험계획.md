# 지도에 작성한 정보와 CLI 추천 노출 연구

고정일: 2026-10-16. 이번 사용자 요청에 따라 네이버 지도/플레이스를 새 연구 범위에 포함한다. 기존 240회 CLI 자료·다이닝코드 분석·소비자 웹 자료는 변경하거나 합산하지 않는다.

## 연구 질문

CLI에 네이버 지도, 카카오맵, 구글 지도를 각각 기준으로 식당을 찾게 했을 때, 어떤 식당이 반복 추천되는가? 해당 식당의 지도에 적힌 정보 중 **가게가 정비할 수 있는 내용과 작성 방식**이 노출과 어떤 연관을 보이는가?

지도 서비스 자체의 검색 순위, CLI가 추천한 순위, 지정 지도를 실제 열람했는지는 서로 다른 관측이다. 지도 순위 효과를 AI 효과로 바꾸어 해석하지 않는다.

## 진행 순서와 실행 규모

1. **출처 접근 파일럿**: 지도 3종 × 지역 3곳(명동·성수·망원) × CLI 2종(Codex·Antigravity) × 1회 = 18개 셀. 새 세션, 한국어, 매회 최대 5곳, 가게 이름·기존 표본 목록·로컬 실험 파일은 모델에게 제공하지 않는다. 실패는 별도로 남긴다.
2. **출처 검수**: 검색 로그·열람 로그·인용 URL을 대조한다. 실제 지도 상세 본문, 해당 지도 도메인의 검색 스니펫, 다른 사이트로의 대체, 근거 없는 지도 링크를 구분한다. 모델의 '확인했다'는 자기 보고나 지도 검색 URL 자체만으로 열람을 인증하지 않는다.
3. **본 측정 준비**: 파일럿에서 상세 본문을 수집할 수 있으면, AI 추천과 독립적으로 지도 검색에서 지역별 20곳, 총 60곳의 후보를 먼저 고정한다. 지도별 검색어·정렬·지도 중심·시각·표시 순위를 보존하고 중복 브랜드와 지점은 대조한다. 특정 지도 미등재/접근 불가는 미노출과 구분한다. 파일럿 추천 식당은 표본 선정 근거로 쓰지 않는다.
4. **본 측정**: 공통 일반 식사 질문을 3지도 × 3지역 × 2CLI × 5반복 = 90회. 일반 질문이 주 분석이며, 혼밥·예산 등 조건형 질문은 별도 층으로 확장한다. 18회 파일럿은 접근 검사용이므로 본 측정에 합산하지 않는다. 상세 본문 접근이 불가능한 플랫폼에는 동일 요청을 무작정 늘리지 않고 접근 문제를 기록한다.
5. **정보 작성 방식 분석**: 미리 고정한 후보 모두에서 같은 지도 필드를 수집하고, 원문과 인용 위치를 보존한 뒤 특징을 추출한다. 노출 식당만 수집하거나 수집 실패를 '내용 없음'으로 바꾸지 않는다.

## 질문과 출력

공통 질문 예: “네이버 지도 기준으로 서울 성수동에서 한 끼 식사할 식당 5곳을 추천해줘. 디저트만 판매하는 카페는 제외해줘.” 지도 이름과 지역만 바꾼다.

공통 부가 지시: 실제 검색하고 지점을 구분한다. 각 식당의 주소·선정 근거·실제 사용한 출처 URL·지도의 확인 수준을 JSON으로 남긴다. 상세 페이지를 못 읽었으면 그 사실을 밝히고 다른 출처로 판단한 경우 해당 URL을 기재한다. URL·소개문·식당 정보를 지어내지 않는다. 부족한 결과를 억지로 5곳으로 채우지 않는다.

가게의 소개문 길이·키워드·항목 완성도 등을 질문에 미리 제시하지 않는다. 특정 작성 방식을 유도한 뒤 그 방식이 많이 나온다고 결론 내리지 않는다.

## 지도 정보 특징과 코드북

식당 × 지도 × 수집 시각이 한 행이다. **가게 작성 / 이용자 리뷰 / 플랫폼 요약 / 작성자 불명**을 분리한다. 구글의 자동 장소 요약을 가게가 작성한 소개로 분류하지 않는다.

| 구분 | 수집/추출 항목 |
|---|---|
| 소개문 | 원문, 작성자 유형, 글자 수, 문장/목록 구분, 추상적 칭찬 대비 구체적 사실 문장 비율 |
| 메뉴 표현 | 대표 음식 명시, 재료·조리법 설명, 메뉴 종류, 가격과 단위, 텍스트/사진 표시 구분 |
| 이용 상황 | 혼밥·단체·가족·예약·주차·포장·채식 등 사실을 구체적으로 명시했는지 |
| 방문 정보 | 도로명 주소, 층/호수, 출구·도보·랜드마크 안내, 운영/휴무/브레이크/마지막 주문 구분 |
| 명칭과 연결 | 본점/지점 명확성, 상호·주소·전화 일치, 자체 홈페이지·예약 연결 |
| 키워드 표현 | 지역명·음식명·이용 상황 단어, 같은 표현 반복, 지역/업종과 무관한 문구 |
| 정비 완성도 | 플랫폼에서 관측 가능한 필드 가운데 확인된 필드 비율; 플랫폼 미지원 필드는 분모 제외 |
| 통제 변수 | 지역·메뉴군·가격대·지도 표시 순위·리뷰 수/별점·사진 수·거리·수집 시각 |

작성자와 지도 소유자 인증을 같은 것으로 취급하지 않는다. 미지원 필드, 실제 빈 필드, 로그인 필요, 차단/미열람을 서로 다른 값으로 보존한다. 리뷰 수는 플랫폼끼리 합산하지 않는다. 지도 내부의 대표 키워드가 공개되지 않으면 소개문에서 추정해 채우지 않는다.

## 측정·분석

- 요청 기준 노출률: 해당 지도명을 요청한 모든 **정상 완료 응답**에서의 등장률. 답변이 적거나 '접근 불가'라고 정상 답한 경우도 완료 응답으로 보존하되 별도 유형으로 나눈다.
- 근거 확인 노출률: 식당의 지정 지도 상세 내용을 실제로 확인한 것으로 검수된 응답만 별도 집계한다. 출처 기준 변경으로 분모가 달라진다는 사실을 명시한다.
- 출처 준수율: 지정 지도 상세 열람·지도 스니펫·다른 사이트 대체·출처 미검증 비율. 실패·빈 결과·정상 완료·본문 미열람을 섞지 않는다.
- 같은 질문 반복의 등장률·상위 3곳·평균 순위와 모델별 차이. 반복 응답 수를 독립 식당 수로 계산하지 않는다.
- 주요 모형은 식당·질문/응답 반복을 반영한 규제/혼합효과 로지스틱 회귀. 플랫폼별로 분석하고 공통 필드는 비교한다. 식당/브랜드 그룹으로 학습·평가를 분리하며 날짜가 늘면 미래 날짜도 분리한다.
- XGBoost는 충분한 독립 식당과 실제 작성 특징이 쌓인 뒤 예측 비교에 사용한다. 중요도·SHAP은 연관성이다. 리뷰·사진·인지도만으로 작성 방식이 좋다고 결론 내리지 않는다.
- 소개문 정비의 원인은 이후 동의받은 식당에서 같은 사실을 구체화하는 정비를 하고 비교 식당을 둔 전후 측정으로 확인한다. 이번 단계에서 외부 가게 정보를 수정하지 않는다.

## 공식 필드 기준

- 네이버는 상세 설명·대표키워드·사진·메뉴/가격·영업시간 등 등록 필드를 안내한다. [네이버 스마트플레이스 도움말](https://help.naver.com/service/30026/contents/20366?lang=ko&osType=COMMONOS)
- 카카오는 메뉴·영업시간·예약·배달·소식·후기 답글 등을 관리할 수 있다고 안내한다. [카카오 매장관리](https://business.kakao.com/info/mystore/)
- 구글은 지역 검색에서 관련성·거리·인지도와 정보 완성도를 설명한다. 이는 구글 지도 자체의 검색 기준이며 CLI 추천 기준의 증거로 사용하지 않는다. [Google 공식 도움말](https://support.google.com/business/answer/7091?hl=ko)
