## 관찰된 패턴

1. **자주 나오는 식당에는 반복성이 있다.** 같은 질문의 두 응답에서 평균 Codex 2.64/5곳, Gemini 3.09/5곳이 겹쳤다. 두 모델끼리의 겹침은 2.11/5곳이었다. 매번 목록은 바뀌지만 일부 식당이 반복 등장한다.
2. **모델별 차이가 크다.** 아래 차이는 같은 기존 식당 표본을 각 모델의 해당 지역 성공 응답 수로 나눈 값이다. 모델 차이를 평균 하나로 가리지 않고 따로 분석해야 한다.

| 상호 | Codex | Gemini | 차이 Codex-Gemini |
|---|---:|---:|---:|
| 명동함흥면옥 | 75.0% | 5.0% | +70.0%p |
| 일등식당 | 10.0% | 35.0% | -25.0%p |
| 명동정 | 22.5% | 2.5% | +20.0%p |
| 미성옥 | 52.5% | 72.5% | -20.0%p |

3. **홈페이지 보유만으로 높은 노출을 설명하지 못했다.** 일반 질문에서 지역을 맞춘 기존 표본의 홈페이지 보유-미보유 평균 차이는 -13.7%p였다. 탐색적 지역 내 순열검정 p=0.505, 비교 식당 20곳이다. 홈페이지가 불리하다는 결론은 아니다. 선정 표본이 작고 메뉴·인지도 등이 통제되지 않았다. 자체 사이트와 가격 공개를 확인한 하수오곰탕·고시레의 실제 등장률은 위 표에 기록했다.
4. **한 번 발견한 후보가 계속 추천되는 것은 아니다.** 새 후보 132개 중 추가 측정에서 다시 등장한 후보는 77개, 등장하지 않은 후보는 55개였다. 후보 일부의 상호·지점 동일성은 미검수여서 실제 식당의 재추천 비율로 확정하지 않는다.
5. **기존 표본의 미노출 사례도 남겼다.** 기존 30곳 중 현재 전체 측정에서 9곳이 한 번도 언급되지 않았다. 폐업·이전 여부를 뜻하지 않는다.

**후속 검증 가설:** 대표 메뉴의 명확성, 공식 관광·독립 가이드의 식당별 소개, 리뷰·운영 이력 등 축적된 외부 정보가 함께 작용하는지 비교한다. 명동교자·하동관의 가이드 소개, 소문난성수감자탕의 관광 소개는 확인했지만, 미노출 식당도 같은 기준으로 조사하기 전에는 효과 크기를 계산할 수 없다. 현재 리뷰 수·별점 효과는 판단하지 않는다.

## 전처리 완료 항목

- 유효 응답 240개, 추천 슬롯 1200개, 식당×응답 행 12,960개.
- 식당×모델 후속 집계 324행. 324행은 162개 후보의 두 모델 관측이며 독립 식당 324곳이 아니다.
- 상호·별칭 정규화, 미매칭 검수 목록, 상호 언급/원본 주소 일치 구분, 완료된 응답의 미언급 0 처리.
- 메뉴군 통합, 확인 가격 숫자화, 결측 표시, 향후 리뷰 수 log1p 변환, 식당 그룹 분리.
- AI 추천 이유·반환 가격·출처 URL은 학습 입력에서 제외. 미수집 리뷰·별점은 0으로 채우지 않음.
- 고정 후보와 매칭하지 못한 추가·모호한 추천 54슬롯은 `unmatched_review_queue.csv`에 보존. 후보 목록을 후속 응답으로 다시 늘리지 않음.
- 공개 URL 258개 자동 점검: 본문 접근 211개. 자동 접근·제목 일치는 식당 검증 또는 학습 특징 확인과 다름.
- 외부 메뉴 분류 확보 36/162개, 홈페이지 조사값 31/162개, 정확한 대표 가격 6/162개. 전체 후보의 특징 수집은 미완료.

## 분석 방법과 다음 데이터

지역·질문·모델별 빈도와 반복 안정성을 먼저 보고, 외부 특징을 동일 기준으로 수집한 후 규제 회귀를 기준 모델로 사용한다. 이후 얕은 XGBoost를 식당 그룹을 분리해 검증하고, 검증 성능이 개선될 때 폴드별 중요도·SHAP을 확인한다. SHAP은 예측 연관성을 설명한다. 정보 정비의 효과는 비교 식당을 둔 전후 실험으로 확인한다.

**현재 XGBoost 학습은 수행하지 않았다.** 현재 특징 수집은 기존 표본의 홈페이지·메뉴군에 집중돼 있고 리뷰·사진·최근성 등 주요 값은 미수집이다. 검토 표본의 준비 확인 결과: 35개 상호 그룹, 학습 준비=False. 기존 30곳의 과거 조사 자료와 새 후보 5개의 외부 상호·주소 대조를 사용한 값이며 현장 영업 검증 수가 아니다. 환경 의존성과 상세 이유는 `model_readiness.json`에 기록했다.

상세 방법·수집 기준·재실행 명령은 [분석방법_전처리.md](./분석방법_전처리.md)에 있다. 추가 표본은 AI 추천 결과를 보지 않고 외부 목록에서 지역·메뉴군별로 선정해 지속 미노출 식당을 포함해야 한다.

## 실행 조건과 검수

- Codex 120/120, Gemini/Antigravity 120/120. 계획은 2개 모델×12개 한국어 질문×10회=240개 응답이다.
- 요청 모델은 Codex gpt-6.1-sol, Antigravity Gemini 3.8 Flash (Low). 현재 위치를 통제하지 않은 CLI 결과이며 소비자 앱으로 일반화하지 않음.
- 매 실행 새 세션에서 실제 웹 검색. 가게 이름·목록·프로젝트 파일을 질문에 제공하지 않음.
- Gemini CLI 자체의 UNSUPPORTED_CLIENT 오류는 별도 기술 실패. Gemini 측정은 Antigravity를 사용함.
- Codex 사용량 제한과 네트워크 오류는 미노출로 집계하지 않고 재시도. 원문 로그와 시도 기록 보존.
- 후보 목록 해시·중복 행·실행 분모·결측·그룹 분리와 소비자 CSV 해시를 검수. `validation.json`은 자료 무결성 검수이며 현장 영업 검증이 아님.
