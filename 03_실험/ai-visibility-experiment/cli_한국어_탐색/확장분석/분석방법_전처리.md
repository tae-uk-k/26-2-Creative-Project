# 식당 추천 패턴 분석과 학습 데이터 사용법

이번 데이터로 먼저 확인할 것은 **어느 식당이 어떤 질문·모델에서 반복 등장하는가**다. 이후 외부에서 수집한 식당 특징으로 등장률을 예측한다. 예측에 도움이 되는 특징과 노출을 높이는 원인은 구분한다.

## 이번 표본의 구조

- 기존 비교 표본 30곳은 지역별로 미리 선정한 식당이다. 무작위 표본이 아니다.
- 추가 후보 132곳은 앞선 120개 응답에서 발견했다. 후보 목록을 고정한 뒤 **추가 반복 6~10회에서만** 특징과 노출을 비교한다. 발견에 사용한 응답을 새 후보의 평가 데이터로 다시 쓰지 않는다.
- 162개는 고정한 상호 후보 수다. 모두 다른 실제 지점으로 검수한 162개 식당을 의미하지 않는다. 동명이점·오타·분점·간판 변경은 검수 대상이다.
- 기존 표본의 전체 10회 결과와 새 후보의 후속 5회 결과를 같은 분모로 비교하지 않는다. `ranking_prospective_all_candidates.csv`는 모두 후속 측정만 사용해 비교한다.
- 반복 측정은 추천의 변동과 등장률을 더 정확히 보기 위한 것이다. 240개 응답이나 12,960개 식당×질문 행을 독립 식당 표본 수로 계산하지 않는다.
- 소비자 웹 실험, 미국 환경 실험, 이번 한국어 CLI 실험은 합산하지 않는다.

## 분석 순서

| 단계 | 방법 | 확인하는 내용 |
|---|---|---|
| 1 | 지역·모델·질문별 등장률, 상위 3위 비율, 평균 역순위 | 어떤 가게가 자주 나오고 어느 질문에 적합한가 |
| 2 | 동일 질문의 추천 집합 겹침, 전반·후반 Spearman 순위 상관 | 추천 목록과 자주 등장하는 가게가 얼마나 안정적인가 |
| 3 | 같은 지역·메뉴군 안의 특징 비교, 식당 단위 재표집 | 홈페이지·가격 공개 등 특징과 등장률의 연관성 |
| 4 | 규제한 로지스틱/이항 회귀 또는 단순 등장률 회귀 | 적은 표본에서도 해석 가능한 기준 모델 |
| 5 | 얕은 XGBoost + 식당을 분리한 검증 | 특징의 비선형 관계와 조합이 예측을 개선하는가 |
| 6 | 검증 폴드별 중요도·SHAP 및 제거 실험 | 예측에 일관되게 기여하는 특징은 무엇인가 |
| 7 | 정보 개선 대상과 비교 식당의 전후 측정 | 실제 정보 개선이 노출을 높이는가 |

홈페이지 비교는 일반 질문의 등장률을 사용하고, 지역별 집단 차이를 따로 확인한다. 기존 명동·성수 표본에 홈페이지 유무가 모두 있고 망원 표본에는 없는 것으로 기록돼 있어, 망원 안에서 유무 효과를 비교할 수 없다. 현재 탐색적 순열 검정은 명동·성수 안에서만 홈페이지 라벨을 섞는다. 식당 선정 방식과 메뉴·인지도 등의 교란이 있어 인과 검정이 아니다.

일반 질문도 지역과 식사 형태를 요구한다. 조건이 있는 질문을 모두 섞으면 ‘혼밥 질문에 적합한 식당’, ‘가격 상한에 맞는 식당’을 AI 노출 특징으로 오해하기 쉽다. 주 분석은 `general_appearance_rate`, 조건형 분석은 `query_outcomes.csv`와 별도 적합성 검수를 사용한다.

## 수행한 전처리

1. 성공한 실행 ID를 한 번씩 선택했다. 앞선 120회는 고정했고 후속 반복은 첫 유효 응답을 사용한다. 원본 재시도·시간 초과 로그는 보존한다. 공급자 완료 표식과 실제 검색·5개 추천이 확인된 응답은 프로세스 종료 상태와 구분한다.
2. Unicode·공백·기호를 정규화하고 검토한 별칭으로 상호를 대조했다. 본점·지점 접미사를 제한적으로 처리한다. 모호한 후보와 새 상호는 검수 목록에 남긴다.
3. 성공한 지역별 응답마다 해당 지역의 고정 후보를 모두 펼쳤다. 언급은 1, 완료된 응답에서 미언급은 0이다. 실행 오류를 0으로 채우지 않는다.
4. 상호 기준 언급과 원본 표본 주소 일치 언급을 구분했다. 주소 미확인은 빈값이다. 주소 대조는 실제 이전·폐업 판정이 아니다.
5. 원화 가격을 수동 확인 자료에서 숫자로 추출했다. ‘1만원대’는 임의로 10,000원으로 바꾸지 않았다. 가격은 해당 자료의 대표 메뉴 가격이며 1인 평균 지출이 아니다.
6. 메뉴 설명을 `category_codebook.csv`의 넓은 메뉴군으로 통합했다. 복합 메뉴는 대표 메뉴 기준을 명시했다. 지나치게 세분화된 메뉴 설명은 식당 이름처럼 작동할 수 있어 기본 학습 입력에서 제외했다.
7. 확인하지 못한 특징은 빈값과 결측 표시로 남겼다. 확인된 없음과 미수집을 구분했다. 리뷰·사진 수는 향후 수집 시 `log1p` 변환한다.
8. AI 답변의 추천 이유·가격·음식 종류·반환 출처는 관찰 자료에만 남겼다. 학습용 식당 특징으로 쓰지 않는다. 기존 예상 노출 구간·상호·ID·표본 구분도 기본 예측 변수에서 제외했다.
9. 식당별 모델별 후속 등장률을 만들고 같은 브랜드의 행이 검증 폴드 양쪽에 들어가지 않도록 그룹을 지정했다. 결측 대체·범주 인코딩은 향후 각 훈련 폴드에서만 학습한다.
10. 후보 목록 해시, 실행 수, 원문 존재, 중복 키, 분모, 폴드 분리, 소비자 결과 파일 보존을 검수한다.

## XGBoost 전에 더 수집할 값

같은 기준과 출처로 노출·미노출 식당 모두 조사한다. AI가 반환한 링크의 개수나 검색 가능 여부를 그대로 특징으로 넣지 않는다.

| 특징 | 수집·코딩 기준 |
|---|---|
| 메뉴·대표 가격 | 업체 또는 식당정보 페이지; 확인 날짜와 메뉴명 기록 |
| 홈페이지 | 자체 사이트 존재와 접근 확인을 구분; 기존 조사 시점도 보존 |
| 공식 관광·독립 가이드 소개 | 개별 식당 페이지 유무; 현재 여부와 과거 태그 구분 |
| 리뷰 수·별점 | Google과 Naver를 분리; 서로 다른 서비스의 숫자를 합산하지 않음 |
| 사진 수·최근 리뷰 | 출처 플랫폼을 고정; 수집일 기준 경과 일수 |
| 혼밥·예약·영업시간 | 실제 공개 설명 확인; 후기의 혼밥 태그를 1인석으로 바꾸지 않음 |
| 상호·주소 일관성 | 동일 지점의 공식·지도·관광 자료를 대조; 미확인은 결측 |
| 구조화 데이터 | 자체 사이트의 Restaurant/LocalBusiness 표기 확인; 접근 실패는 없음으로 처리하지 않음 |
| 운영 이력 | 확인 가능한 개업 연도; 오래된 유명 가게라는 AI 설명은 사용하지 않음 |

`verified_features.csv`는 식당 ID·특징·값·출처 URL·확인일·설명을 가진 수동 확인표다. 원본 `feature_checks.csv`와 함께 전처리에 반영한다. 지원하는 특징명은 `prepare.py`에 정의돼 있다. 신규 후보의 외부 상호·지점 검수가 끝나면 `verified_entities.csv`에 `entity_id,identity_reference_checked,source_url,checked_date,note`를 기록한다. 웹 자료 대조는 현장 영업 확인과 별개다.

현재 리뷰 수·별점·사진 수·최근성·주소 일관성·구조화 데이터는 미수집이다. 외부 페이지 자동 점검 결과 `source_screening.csv`는 검수 보조이며 바로 학습에 넣을 수 있는 특징이 아니다.

다음 표본은 AI 추천 여부를 보지 않고 외부 식당 목록에서 지역·메뉴군을 나눠 추출하는 편이 좋다. 실무 출발점으로 독립 식당 100~200곳을 목표로 하되, 필요한 수는 관찰되는 차이·특징 수·결측률·검증 오차에 따라 정한다. 현재 발견 후보만 계속 늘리면 AI가 한 번도 추천하지 않는 가게를 놓칠 수 있다.

## 검증과 원인 확인

- 같은 식당을 훈련·평가 데이터에 나눠 넣는 행 단위 무작위 분할을 피한다. [scikit-learn GroupKFold 설명](https://scikit-learn.org/stable/modules/cross_validation.html).
- 다른 식당에서의 예측 성능과 반복 6~10회에서의 재현성을 따로 본다. 이후 다른 날짜 측정, 지역 하나 제외, 모델별 분석을 추가한다.
- 등장률 회귀는 MAE·RMSE와 단순 평균 예측 대비 개선을 확인한다. 개별 언급 여부 분류는 log loss·Brier score·PR-AUC·보정 상태를 확인한다. 지역별 추천 수가 제한되므로 정확도만 보고 판단하지 않는다.
- 결측 대체와 인코딩을 전체 데이터에 먼저 맞추지 않는다. [scikit-learn 데이터 누출 설명](https://scikit-learn.org/stable/common_pitfalls.html).
- XGBoost는 작은 깊이와 강한 규제로 시작한다. 결측은 결측으로 유지하고 범주 인코딩을 훈련 폴드 안에서 맞춘다. [XGBoost 범주형 자료 설명](https://xgboost.readthedocs.io/en/stable/tutorials/categorical.html).
- SHAP은 예측이 왜 그렇게 나왔는지를 보여준다. 노출이 증가한 인과적 이유를 입증하지 않는다. [SHAP의 인과 해석 주의 설명](https://shap.readthedocs.io/en/latest/example_notebooks/overviews/Be%20careful%20when%20interpreting%20predictive%20models%20in%20search%20of%20causal%20insights.html).
- 원인을 확인하려면 일부 식당의 가격·주소·대표 메뉴 등 정보를 정비하고 비슷한 비교 식당은 같은 기간에 유지한다. 같은 질문·모델로 전후 측정하며, 변화 차이를 비교한다. 무작위 배정이 가능하면 우선하고, 불가능하면 차이의 차이 분석 가정과 동시 홍보·리뷰 변화 등을 기록한다.

## 실행 방법

프로젝트 루트의 PowerShell에서 실행한다. 전처리·기술통계·검수는 기존 Python으로 실행 가능하다.

```powershell
$studyDir = '.\03_실험\ai-visibility-experiment\cli_한국어_탐색\확장분석'
$studyPython = '.\04_MVP\hanoon-mvp\.venv\Scripts\python.exe'
& $studyPython "$studyDir\analyze.py"
& $studyPython "$studyDir\validate.py" --require-complete
& $studyPython "$studyDir\train_models.py"
```

`train_models.py`의 기본 동작은 준비 상태 확인이다. 모델을 학습하지 않는다. 학습 환경에 pandas·numpy·scikit-learn·xgboost가 있고, 식당 검수 및 특징 수집이 끝난 뒤 `--run --cohort reviewed-expanded`로 평균 예측·규제 회귀·XGBoost의 식당 분리 검증을 실행할 수 있다. 현재 제공된 학습 코드는 등장률 회귀용이다. 로지스틱/이항 회귀와 SHAP 산출은 다음 분석 단계다.

독립 식당 50곳 이상, 변동 있는 외부 특징 3개 이상이 80% 이상 수집됐는지 보는 기본 실행 제한은 작은 자료로 곧바로 모델을 만드는 것을 막기 위한 작업 기준이다. 통계적 충분성을 보장하는 수치는 아니다.
