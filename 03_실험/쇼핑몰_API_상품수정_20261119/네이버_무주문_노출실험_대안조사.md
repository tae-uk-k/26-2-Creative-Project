# 네이버 무주문 노출 실험 대안 조사

조사·검사일: 2026-11-19. 기존 seelo 스마트스토어를 대상으로 한다. 카페24 보류를 유지한다.

**2026-11-23 후속 결과:** 사용자 승인 후 재고 1개·최소 구매수량 2개를 SALE·전시중으로 적용했다. PC·모바일 크기의 정상 구매 경로에서 최소수량 또는 재고 부족으로 차단됨을 확인했다. 공개 구조화 데이터는 InStock이며 네이버쇼핑 등록 설정도 켰다. [최신 실행 결과](무주문환경_실행결과_20261123.md)를 현재 상태로 사용한다. 아래 미검증 표시는 11월 19일 조사 당시 기록이다.

## 결과

**우선 검증 후보는 `재고 1개 + 최소 구매수량 2개` 조합이다.**
본인 실험 상품에서 이 조합의 API 저장·재조회를 확인했다. 검사 중 판매와 전시는 모두 중지했다.
공개 판매중에서의 화면·주문 차단·검색 및 AI 수집은 아직 검사하지 않았다.
설정 저장 성공을 주문 차단 성공으로 판단하지 않는다.

## 비교

| 후보 | 확인한 사실 | 판정 |
|---|---|---|
| 재고 1개·최소 구매수량 2개 | 공식 API에 두 필드가 있다. 판매중지·전시중지 상태에서 HTTP 200으로 저장되고 재조회 값도 일치했다. | 우선 검증 후보. 판매중에서 조합 유지·구매자 주문 차단은 미검증 |
| 최소 2개·최대 1개 또는 최대 0개 | 최소·최대 구매수량 기능은 있다. 모순된 조합 저장이나 0의 차단 의미는 확인하지 않았다. | 적용하지 않음. 0을 주문 차단값으로 추정하지 않음 |
| 쇼핑윈도 결제여부 ‘설정안함’ | 구매하기 버튼을 없애는 공식 기능이다. 이 설정에서는 스마트스토어 채널 선택이 불가하다. 기존 결제상품을 결제불가 상품으로 바꿀 수도 없다. | 현재 스마트스토어 상품에 적용 불가. 쇼핑윈도 입점 조건도 별도 |
| 알림받기 고객 전용상품 | 알림받기를 진행한 고객은 구매 가능하다. | 전체 주문 차단 수단이 아님 |
| 라운지 전용상품·상품정보 공개용 | 미가입자도 스토어 홈에서 상품을 확인할 수 있으나 상세 진입 시 구매가 제한된다. 브랜드스토어 권한이 필요하다. | 일반 스마트스토어에 바로 적용 불가. 가입자 주문 차단 기능도 아님 |
| 미래 판매기간·판매대기 | 공식 구매자 표시 흐름에서 판매중·품절 외 상태는 미노출이다. | 공개 상품 발견 실험에 부적합 |
| 휴무·배송지연 | 공식 안내는 휴가 중에도 신규 주문 처리를 요구한다. | 주문 차단 기능이 아님 |
| 이미지에 구매 금지 안내 | 고객 안내는 가능하나 주문 기능은 그대로다. 이미지 내용을 이해하는 AI도 있다. | 보조 안내로만 사용. AI가 읽지 못한다는 전제로 사용하지 않음 |
| 주문 후 취소 | 취소는 가능하다. 품절 취소는 페널티 대상이다. 실제 사유와 다른 취소나 구매자 동의 없는 임의 취소는 별도 조치 대상이다. | 주문·결제 발생을 막지 못하므로 기본 방식으로 선택하지 않음 |
| API 테스트 환경 | 커머스API 운영자는 별도 테스트 환경을 제공하지 않는다고 안내했다. 독립몰 Npay 샌드박스는 현재 스마트스토어 결제를 바꾸는 기능이 아니다. | 현재 스토어의 공개 무결제 모드로 사용하지 않음 |

## 실제 API 검사

원상품번호: `13821774578`. 채널 상품번호: `13883527217`.

1. 공식 GET으로 정확한 상품명·번호 매핑·품절·재고 0을 확인했다.
2. 단일 PUT으로 판매중지·전시중지·네이버쇼핑 미등록·재고 1·최소 2개·1회/1인 최대 2개를 전송했다.
3. HTTP 200을 받았다. 재조회에서 요청한 상태와 수량을 확인했다.
4. 원래 품절·재고 0·전시중 상태와 구매수량 설정을 복구했다.
5. 복구 후 API 응답이 검사 전 원본과 **정확히 일치**했다. 본문과 보호 필드도 일치했다.

공개 판매중 또는 결제 가능 상태는 요청하지 않았다. 주문·정산·고객정보 API 권한도 추가하지 않았다.
요약 증거: [구매수량 조합 검사](증거/10_구매수량_조합검사.json).
원본 응답과 요청: Git 제외 폴더 `.local/runs/20261119T100025_693200_no_order_quantity/`.

## 공개 적용 전에 남은 확인

1. 구매자 화면을 확인할 수 있는 연결을 확보한다. 이번 공개 URL 조회 도구에서는 페이지에 접근하지 못했다.
2. 재고 1·최소 2개 조합을 판매중으로 바꿔도 조건이 유지되는지 확인한다.
3. 로그인 전후와 PC·모바일에서 품절 표시·상품 상태·수량 조건을 확인한다.
4. 1개는 최소수량, 2개는 재고 조건으로 주문서 진입이 각각 차단되는지 확인한다. 실제 결제는 진행하지 않는다.
5. 장바구니·바로구매·선물 등 존재하는 주문 경로를 확인한다. 화면만의 제한과 서버의 주문 거부를 구분한다.
6. 주문 경로가 남거나 품절로 바뀌면 원래 재고 0·품절 상태로 복구한다.
7. 주문 차단 확인 후 공개 페이지의 수집·정보 추출·검색 출처를 기록한다.

이 단계들은 아직 실행하지 않았다. URL을 지정한 정보 확인과 URL 없는 자연 발견은 별도로 기록한다.
