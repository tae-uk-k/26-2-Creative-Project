# 쇼핑몰 상품 등록·API 수정 실험

기준일: 2026-11-19. 대상: 본인 소유 카페24·스마트스토어 각 1개.

## 실험 상품

최종 상품은 **아카시아 벌꿀 500g**이다. 스마트스토어 분류는 `식품 > 건강식품 > 꿀`이다.
건강식품을 요청한 사용자 지시에 따라 선정했다. 일반식품이며 건강기능식품 인증·기능성 문구를 만들지 않는다.

상품은 실험용 가상 자료다. `상품기준.json`이 사양의 기준이다. 가격 14,900원도 시험 입력값이다.
실물 제조업체·소비기한·인증 정보는 미확인이다. 필요한 실물 정보가 없으면 실제 판매 등록을 완료했다고 기록하지 않는다.

## 순서와 완료 기준

1. **접속**: 가입한 두 계정에서 대상 스토어 이름을 확인한다.
2. **상품 준비**: 같은 상품명·코드·대표이미지·A안 본문을 준비한다.
3. **상품 저장**: 주문을 차단하고 저장한다. 상품번호를 받으면 다시 열어 저장 결과를 확인한다. 임시저장과 정식 상품 등록을 구분한다.
4. **API 권한**: 관리자 로그인과 별도로 앱 인증을 설정한다.
5. **원본 읽기**: API로 상품번호·본문·가격·재고·판매/전시 상태를 조회한다. 인증정보를 제외한 상품 응답은 로컬 전용 폴더에 백업한다.
6. **변경 준비**: A안에서 B안으로 바뀔 본문과 원본 해시를 저장한다. 수정 직전 재조회해 원본 일치를 확인한다.
7. **쓰기**: 실험 상품 한 개의 본문만 수정한다. 쓰기 타임아웃은 재조회로 판정하고 자동 재전송하지 않는다.
8. **검증**: API 재조회에서 B안 일치를 확인한다. 가격·재고·상태를 대조한다. 관리자 PC·모바일 미리보기를 따로 확인한다.
9. **복구**: 현재 본문이 실험에서 쓴 B안과 일치할 때만 원본 본문을 복구한다. 재조회로 A안 복구를 확인한다.

| 항목 | 카페24 | 스마트스토어 |
|---|---|---|
| 가입 | 사용자 완료 보고. 관리자 로그인에서 확인 | seelo 스토어 가입 승인·관리자 접속 확인 |
| 수동 관리자 권한 | 대표운영자 또는 부운영자 | 통합매니저 또는 별도 매니저 |
| 실험용 API | 개발자 앱 → 테스트몰 설치 → OAuth | 본인 소유 스토어 전용 개발계정 → 내 스토어 앱 |
| 최소 그룹 | 상품 읽기·쓰기 | 상품/N배송 그룹 |
| 인증 | mall.read_product, mall.write_product | SELF. 본인 소유 실험 스토어에서만 사용 |
| 수정 | PUT /api/v2/admin/products/{product_no} | PUT /external/v2/products/origin-products/{originProductNo} |
| 수정 필드 | description | originProduct.detailContent |
| 주문 차단 | 판매 안함·진열 안함 | 재고 0·전시중지·네이버쇼핑 미등록 |

**본인 실험과 외부 고객 연동을 구분한다.** 스마트스토어 SELF 앱은 이 계정의 자체 검증에만 사용한다. 외부 고객의 SELF 앱 키를 받는 서비스 흐름으로 바꾸지 않는다. 외부 고객 연결은 기존 공식 SELLER/대행 경로를 따른다.

## 범위

본문 저장·재조회·화면 표시·복구를 검증한다. 스토어 테마·전체 디자인·관리자 계정·결제·배송 정책은 수정 실험 대상이 아니다.
카페24의 요약·모바일 설명·SEO는 본문 왕복 시험 이후 별도 필드로 시험한다. 스마트스토어 기존 스마트에디터 문서의 변환은 새 HTML 실험 상품 검증과 구분한다.
이 실험은 기술 검증이다. AI 추천 효과 실험은 상품 공개·검색 접근·관측 질문·기준선이 준비된 뒤 별도로 설계한다.

## 증거와 보관

- `실행결과.md`: 실제 완료·미완료·필요 조치.
- `.local/`: 토큰·비밀 설정·상품 원본. Git에서 제외한다.
- `증거/`: 개인정보를 담지 않은 상품 설정·미리보기 화면.
- `상세설명_A.html`, `상세설명_B.html`: 플랫폼 편집기에 넣을 HTML 조각. 스크립트·외부 폰트·외부 링크 없이 구성한다.
