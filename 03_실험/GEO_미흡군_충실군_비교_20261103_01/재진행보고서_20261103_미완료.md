기준 시각: 2026-11-03 04:05 KST. **연구는 미완료다. 브라우저 지도 조사는 복구됐으나 고정 CLI의 지도 상세 본문 접근 실패가 계속됐고, 표본·집단 확정과 90회 추천 측정은 완료되지 않았다.** 기존 결과를 합산하지 않았다.

검색 카드 수는 서로 다른 질문의 중복 매장을 포함한다. 지도 간 연결은 이름 부분 일치·주소 일치로 만든 **검수용 후보**이며, 동명 매장·다른 층·다른 지점을 포함할 수 있다. 자동 연결을 표본 선정이나 동일 지점 확인으로 사용하지 않았다.

일반 음식점 질의 3개에서 양 지도 첫60위, 음식별 확대 질의 12개에서 첫30위까지 수집했다. 실제 결과가 적으면 적은 수 그대로 남겼다. 화면에서 추가로 관측된 31위 이후 카드는 보존했지만, 사전 1·2차 검색 범위에 자동 편입하지 않았다. 3차 31~60위 확대와 역명 앵커 확대는 아직 완료하지 않았다. 따라서 **후보가 전부 부족하다는 결론이나 적합한 짝이 존재하지 않는다는 결론을 내리지 않는다.**

## ① 두 집단의 기본 검색 노출 수준은 얼마나 비슷한가?

집단과 짝이 확정되지 않아 비교할 수 없다. 후보 단계의 지도 순위·Google 평점·리뷰 수는 [사전 범위를 적용한 검색 카드](analysis/음식별확대_v3_사전범위적용/native_cards.csv)와 [미확정 후보표](analysis/재접근_상세검수_20261103_01/후보_조사표_미확정.csv)에 저장했다. 가격·판매 단위·기본 정보량까지 검수한 최종 매칭표는 아직 없다.

순위는 같은 지역·같은 검색어의 자연 검색 위치이며 서로 다른 검색어의 순위를 합산하지 않았다. 카카오 정확도순, Google 기본 관련성순, 추가 필터 없음이다. 실제 운영은 공개 영업 안내를 조사한 것이며 현장 운영을 확인한 것은 아니다.

## ③ 추천 등장률은 각각 얼마였는가?

**A 산출 불가 / B 산출 불가 / B-A 산출 불가.** 유효 식당 추천 응답의 분모가 0이다. A 0% VS B 0%로 표시하지 않는다.

고정 설정은 Codex CLI `0.166.0-alpha.5.1`, 요청 모델 `gpt-6.1-sol`, 내장 live web search, reasoning low, read-only, ephemeral, ignore-user-config, 프로젝트 지시 파일 길이 0이다. 모델 내부 스냅샷 ID는 확인되지 않았다. 질문·90셀 순서·독립 빈 작업 폴더 실행 방식은 기존 고정 설정을 유지했다.

이번에 추가한 두 점검은 식당을 추천하게 한 호출이 아니다. 서울특별시청이라는 중립 장소를 사용했다.

| 이번 중립 점검 | 실제 결과 |
|---|---|
| 2026-11-03 03:56:42 KST 시작·일반 지도 접근 | 프로세스는 종료 코드 0. 지도 `open_page` 결과 2개 모두 `Internal Error`. 지도 본문 확인 없음 |
| 2026-11-03 03:58:21 KST 시작·실제 상세 URL 직접 제공 | 프로세스는 종료 코드 0. 지도 `open_page` 결과 2개 모두 `Internal Error`. 지도 본문 확인 없음 |

두 지도 상세 URL을 직접 지정한 점검에서도 같은 문제가 나타났다. 반면 조사용 브라우저에서는 실제 지도 상세를 열어 주소·영업시간을 읽었다. 따라서 **브라우저 복구를 CLI 검색 경로의 접근 복구로 간주할 수 없다.** 정확한 내부 오류 원인은 확인되지 않았다.

모델이 마지막 답변에 접근 실패라고 쓴 내용만 믿지 않고, 수정하지 않은 JSONL 안의 실제 도구 결과를 검수했다. [중립 점검 원시 이벤트 검수](analysis/재접근_상세검수_20261103_01/CLI_중립점검_원시이벤트검수.json), [실제 중립 시도 목록](analysis/재접근_상세검수_20261103_01/CLI_중립점검_시도목록.csv).

## ④ 추천 답변은 어떤 정보를 근거로 삼았는가?

식당 추천 원문이 없어 판정할 수 없다. 조사 세션이 읽은 메뉴·시간·공식 안내를 CLI 추천 모델이 사용한 근거라고 바꾸어 기록하지 않았다. 추천 순서·출처 사용률·사실 오류·조건 누락·매장쌍 차이도 아직 계산할 자료가 없다. 중립 점검의 실패 응답은 추천 자료에 합치지 않았다.

## ⑤ 어떤 정보부터 정비할 필요가 있는가?

이번 조사에서 확인된 **정보 검수 순서**는 제시할 수 있지만, 추천 등장률 개선에 효과적인 순서를 검증한 것은 아니다.

1. 같은 지점의 실제 전화·영업시간·휴게시간과 공식 연결을 대조한다. 서로 다른 값을 발견하면 실제 적용 범위를 확인한다.
2. 실제 판매하는 대표 메뉴의 가격과 인원·개수·중량 단위를 같은 항목에 연결한다. 증량분 60g 같은 추가 구성량을 메뉴 전체 중량으로 잘못 기록하지 않는다.
3. 실제 제공하는 리필·구성·선택·계절 메뉴·최소 주문 조건을 해당 메뉴·서비스에 연결한다. 공식 페이지에 이미 있는 안내를 누락으로 채점하지 않는다.
4. 사진 메뉴판과 등록 텍스트의 가격·제공 여부가 다르면 확인 시점과 작성 출처를 남긴다. 사진에만 있는 내용을 텍스트에 없다는 이유로 부재라고 판단하지 않는다.

남은 일은 3차 후보 확대·필수 상세 검수·12쌍 구성, 집단·점수 동결, CLI 지도 본문 접근 정상 확인, 독립 새 세션 90회 실행, 출처·지점 검수와 등장률 분석이다. **최종 비교나 발표용 등장률 문장을 작성할 실측 결과는 아직 없다.** 실제 정보 정비를 하지 않았으므로 정비 전후 개선 효과도 측정하지 않았다.
