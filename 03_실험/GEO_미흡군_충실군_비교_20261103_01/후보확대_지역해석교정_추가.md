# 후보 확대: 지도 UI의 지역 해석 교정

2026-11-03 04:22 KST, 추천 결과를 전혀 측정하지 않은 시점에 기록한다. 표본·집단·점수는 아직 동결하지 않았다.

실제 카카오 검색 화면에서 `서울 명동 돈까스`가 **서울특별시 주변 명동 돈까스**로 해석되는 것을 확인했다. 따라서 타 지역의 상호에 명동이 들어간 매장이 섞였다. 해당 화면이 제공하는 `'서울 명동' 주변 '돈까스' (으)로 재검색` 링크를 클릭하면 실제 검색 안내가 **서울 중구 명동 주변 돈까스 검색결과**로 바뀐다.

이는 상위60위 조사 범위를 바꾸거나 추천 결과에 맞춘 표본 변경이 아니다. 잘못 해석된 지역 조건을 UI로 교정하는 후보 확대 단계다. 기존 조사 결과를 삭제하거나 기존 순위와 교정 후 순위를 합치지 않는다.

적용 규칙:

1. 원래 3개 지역·음식점/돈까스/국수/파스타/백반 질의를 동일하게 사용한다. 카카오가 지역과 키워드를 다르게 해석하면 실제 화면에 표시된 지역 재검색 링크로 교정한다. 교정 링크가 없거나 이미 맞는 지역이면 실제 안내를 기록한다.
2. 새 검색 조건 ID는 `region_v1`이다. 원래 관측에는 `default`를 적용한다. 같은 쌍은 같은 조건 ID·같은 검색어·같은 지도별 정렬에서만 비교한다.
3. 카카오는 실제 교정 후 표시 안내를 기록하고 정확도순·추가 필터 없음을 유지한다. Google은 같은 한국어 검색어로 다시 검색하고 기본 관련성순을 유지한다. 각 지도 첫60개 자연 검색 결과를 조사하며 결과가 적으면 실제 수를 기록한다.
4. 두 지도 모두 주소로 실제 지역과 동일 지점을 별도 확인한다. 이름 부분 일치나 같은 건물 주소만으로 동일 지점이라고 확정하지 않는다.
5. A 0~3/B 5~6/4·필수미확인 제외, 가격·순위·평점·리뷰·기본정보량 매칭 수치, 한국어 추천 질문, 모델·측정 도구 설정은 바꾸지 않는다.
6. 이전 단계와 교정 단계는 별도 층으로 남기고 최종 선정 근거에 어떤 검색 조건을 썼는지 명시한다. 최종 동결 시 이 문서도 해시 대상에 포함한다.

이 단계의 후보 조사와 고정 CLI의 지도 접근 장애는 별도다. CLI가 본문을 열지 못한 시도를 실제 추천 유효 응답으로 바꾸지 않는다.
