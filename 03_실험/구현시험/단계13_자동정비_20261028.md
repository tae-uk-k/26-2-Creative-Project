### W-09-5 Google·공통

**가짜 화면** `integration/test_w_09_5.py` 9개
- 승인한 칸만 order_no 순으로 쓴다. 칸마다 읽기 → 쓰기 → 다시 읽기 → applied.
- **before_value·attempt가 쓰기보다 먼저 커밋된다.** `FakeMapAdmin.before_write`가 쓰기 직전에 다른 연결로 DB를 읽어 확인한다.
- 다시 읽은 값이 다르거나 "검토 중"이면 pending_reflection.
- 차단(가게 열기, 첫 쓰기):
  - 재시도 0번
  - 그 칸과 남은 칸 모두 manual_required(`automation_blocked`, `error_code` = 사유)
  - 관리자 메일 1통(dedupe `manual_required:plan:{id}:blocked`)
- 일시 오류는 1번 다시 해서 성공한다(`before_value`는 처음 읽은 값 그대로).
- 두 번 모두 실패하면 그 칸만 write_failed(`transient`)이고 다음 칸은 계속한다. 저장 실패는 메일 1통으로 묶는다.
- 쓸 수 없는 칸(셀렉터가 없는 칸 등) → 그 칸만 write_failed(`unsupported_field`).
- 가게가 안 보이면 권한 회수(E18): 연결 revoked, 남은 칸 disconnected, 쓰기 0번.
- 정비안이 승인 전이거나 연결이 끊겼으면 화면을 열지 않는다.
- 정비 완료(remeasure_scheduled) 뒤 다시 불러도 쓰기 0번.
- 실제 연동인데 셀렉터 파일이 비어 있으면 브라우저를 열지 않고 남은 칸 모두 수동 처리(`selectors_missing`).

**로컬 HTML** `integration/test_browser_google.py` 10개(Playwright, 흉내 낸 관리 화면)
- 목록에서 이름으로 가게 찾기, 정보 화면 주소에서 식별값 뽑기.
- 읽기 → 쓰기 → 다시 읽기. "검토 중" 표시 → `pending_review`.
- 셀렉터가 없는 칸(영업시간·메뉴·편의 정보)은 `FieldWriteFailed`.
- 로그인 화면(불러온 뒤 로그인으로 이동)·보안 확인 문구·캡차·예상 밖 화면 → 즉시 멈춤, 저장 0번.
- 가게 없음 표시·목록에 없음 → `StoreNotVisible`. "인증 필요" → `AttentionNeeded`.
- 실제 `selectors/google.yaml`(빈 파일)이면 화면을 열지 않는다.
- `applyFix`를 이 화면 엔진으로 끝까지 돌림: 소개·전화는 applied(before_value 저장), 영업시간은 그 칸만 수동.

**API 모드** `unit/test_gbp_api.py` 17개(httpx MockTransport)

- `updateMask`에 승인한 칸 하나만, 본문도 그 필드만. `GBP_VALIDATE_ONLY` → `validateOnly=true`.

## Compose 확인

**설정**
- 정비 워커 이미지(`Dockerfile.fix`, Playwright 1.64.1 기반, 4.48GB)를 처음 빌드해 `--profile fix`로 띄웠다.
- 로컬 `.env`는 그대로 두고, 확인용 덮어쓰기 파일로 api·worker-main·worker-fix에만 `AUTO_FIX_ENABLED=true`를 줬다(`FAKE_EXTERNALS=true`).
- 끝난 뒤 원래 설정(수동 모드, 정비 워커 없음)으로 되돌렸다.

**자동 모드**(신청 4번, 가짜 관리 화면)
1. [초대했어요] → 관리자 [연결 확인](본문 없음 → 202).
2. 정비 워커가 `verifyConnection`을 돌려 connected(`fake-google-12`).
3. 지금 값 읽기(fix 큐) → 정비안 생성 → awaiting_approval(편의 정보 칸 1개).
4. 승인 → `applyFix`(fix 큐, `lock fix:google`) → 칸 applied(method browser, attempt 1, applied_at·verified_at).
5. `finalizeFix`(plan 큐) → 사장님 홈 `remeasure_waiting`(재측정 11-12 KST), 관리자 상세 예약 scheduled.
6. 작업 5개 모두 succeeded: verifyConnection·readCurrentValues·applyFix는 fix 큐, generateFixPlan·finalizeFix는 plan 큐.

**차단 재현**(신청 5번, 정비 워커만 `FAKE_MAP_BEHAVIOR=block`)
- 승인 → 첫 쓰기에서 보안 확인 → 재시도 없이 칸 manual_required(`automation_blocked`, `error_code security_check`, attempt 1).
- 사장님 화면 "seelo 팀 처리 중", 홈 `manualInProgress`.
- 관리자 대표 상태 `manual_required`, 수동 칸 "편의 정보 / automation_blocked".
- 관리자 메일은 `.env`의 `ADMIN_NOTIFY_EMAILS`가 비어 받을 사람이 없어 기록되지 않았다(테스트에서는 메일 1통 확인).
- 이것은 가짜 화면의 재현이다. 실제 화면 차단 재현은 PoC 뒤에 한다.
