## 재개 시 확인 순서

- 사용자 요청으로 현재 대화에 5분 간격 자동 재시도를 활성화했다. 자동화 ID: `seelo-a1`, 이름: `seelo 무료 A1 서버 확보`.
- 매 실행 전 기존 서버·진행 중 요청과 무료 잔여량·네트워크를 확인한다. 가용성 보고서가 OUT_OF_HOST_CAPACITY이면 생성을 생략하고, AVAILABLE일 때만 중복 여부를 다시 확인한 뒤 생성 요청을 최대 한 번 실행한다. 네트워크·키를 중복 생성하지 않는다.
- 429 시 10분→20분→최대 60분으로 대기 시간을 늘린다. 동일한 용량 부족은 조용히 기록하고 새 오류·로그인 필요·확보 성공 시 보고한다.
- RUNNING 상태와 공인 IP 확인 후 자동 재시도를 비활성화한다. 스케줄 등록은 서버 확보 완료를 뜻하지 않는다.
- 최근 자동 확인: 2026-10-30 20:33:14 KST. 서버·부트/블록 볼륨 없음 및 기존 서브넷 AVAILABLE를 확인했다. A1 2 OCPU·12GB 가용성 보고서는 OUT_OF_HOST_CAPACITY였다. 생성 요청은 생략하고 동일 상태 알림 없이 5분 간격 확인을 유지한다.

1. 기존 Oracle 콘솔·Cloud Shell을 재사용한다. 브라우저 제어와 사용자 로그인은 복원됐다. 추후 세션 만료 시에만 다시 로그인한다.
2. 저장된 자원 식별자를 사용한다. VCN·게이트웨이·서브넷·SSH 키·Resend 키를 중복 생성하지 않는다.
3. `seelo-prod` 인스턴스 존재 여부를 먼저 조회한다. 이미 생성된 경우 생성 명령을 다시 실행하지 않고 상태·공인 IP를 확인한다.
4. 아직 없다면 승인한 A1 2 OCPU·12GB·100GB만 제한적으로 재시도한다. 429 또는 가용 용량 부족을 유료 사양 전환으로 해결하지 않는다.
5. 생성 성공 뒤 SSH와 디스크·네트워크 규칙을 검증하고 DNS·HTTPS 단계로 진행한다.
