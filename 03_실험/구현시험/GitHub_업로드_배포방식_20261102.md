- 저장소: https://github.com/tae-uk-k/26-2-Creative-Project
- 작업 브랜치: `backend-0-13`. 기존 백엔드 0~13단계 커밋에 후속 14~16단계·운영 구성·문구 수정·조사·로고 자료를 추가한다.

- 실제 운영 환경 파일·키·개인키·DB 덤프는 저장소 밖 보호 폴더에 보관한다. 업로드 대상의 자격증명 형식 검사와 보호 설정의 실제 비밀 값 12개 대조에서 발견 사항이 없었다.
- 현재 백엔드 ruff·OpenAPI 계약 검사·단위 테스트 463개 통과. 이전 통합/실제 공급자 검증 범위는 날짜별 구축 기록을 따른다.

## 현재 배포 흐름

`로컬 수정·검증 → 변경 패키지 생성 → SSH/SCP로 VM 전달 → Docker 이미지 빌드 → 릴리스/이미지 태그 변경 → Docker Compose 서비스 갱신 → HTTPS health 확인`

- GCP Compute Engine의 서울 `seelo-prod` VM에서 실행한다. 고정 IP `34.64.188.249`, 도메인 `https://seelo.site`.
- `nginx`가 80/443과 TLS를 처리하고 FastAPI·PostgreSQL·작업 큐 워커가 내부 Docker 네트워크에서 실행된다.
- 운영 구성은 `docker-compose.prod.yml` + `docker-compose.local-ai.yml`. `/usr/local/sbin/seelo-compose`가 두 파일과 `/etc/seelo/production.env`를 고정해 실행한다.
- `/opt/seelo/current`는 버전별 `/opt/seelo/releases/...`를 가리킨다. 기존 이미지·릴리스·운영 환경 파일 백업을 보존해 롤백 경로를 유지한다.
- AI는 VM에서 기존 SSH private Unix socket을 통해 사용자 PC의 Codex CLI를 호출한다. PC가 꺼지거나 SSH 연결이 끊기면 이 AI 경로를 사용할 수 없다.
- 인증서 갱신은 Certbot, DB 백업은 systemd timer로 별도 운영한다. 일반 메일 큐·자동 지도 쓰기는 꺼져 있다.
- **GitHub push로 서버가 자동 배포되지는 않는다.** 현재 seelo 백엔드의 GitHub Actions/자동 배포 파이프라인은 없다. 이번 요청에서는 GitHub 업로드만 수행하며 운영 배포·DB 마이그레이션은 실행하지 않는다.

## 확인 결과와 배포 차이

- GCP API에서 VM `RUNNING`·기존 고정 IP를 확인했다. 실제 도메인의 HTTPS health는 HTTP 200, `status=ok`, `db=ok`다.
- SSH는 연결 시간 초과로 현재 컨테이너 내부 상태를 재확인하지 못했다. 마지막 배포 기록(2026-10-31)의 이미지는 `seelo-backend:gcp-cli-report-d253f1c6eb09`다.
- 보고서·메일의 자동 면책 문구 제거는 이번 업로드 소스에 포함되지만 해당 변경의 운영 배포는 아직 하지 않았다.
