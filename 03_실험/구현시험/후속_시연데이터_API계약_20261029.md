- 시연 보고서는 고정 ID의 fixture를 복사하지 않고 실제 `build_report`로 현재 행 ID를 넣어 생성한다.

## Compose 확인

- `docker compose --profile dev up -d --build`. 개발 가짜 모드·수동 정비 설정 확인. `.env`는 바꾸지 않았다.
- `python scripts/seed_demo.py --scenarios` 첫 실행: 기존 계정 17개 유지, 시연 상태 15개 생성. 기존 가게 18개 행은 그대로였고 새 가게 16개가 생겼다(가게 변경 시나리오의 이전 가게 1개 포함).
- 두 번째와 후속 실행: 생성 0·기존 유지 15·보호 0. 가게가 더 늘지 않았고 기존 행을 덮어쓰지 않았다.
- nginx 경유 사장님 계정 16개의 로그인·홈 확인. 진단은 고쳐야 할 점 수 5·주변 가게 5·등장률 30%, 정비안은 칸 3개·확인 필요·민감 칸·증거, 보고서는 14일·질문 3개·20%p를 확인했다. revoked 계정은 Google 권한 회수 표시가 나온다.
- 기존 `nostore` 계정에는 이번 시드 전에 무료 사용 이력이 있어 `no_store` 대신 `free_used_store_changed`가 나온다. 이력을 보존했다. 새 DB의 `no_store`는 통합 시험에서 확인했다.
- PostgreSQL 직접 확인: 새 가게 19~34의 `job_links` 0개, 관련 `procrastinate_jobs` 0개, `email_logs` 0개. 측정 18개는 completed 14·failed 2·running 2인 정지 상태 예시다. 보고서 5는 가게 33·completed.
- 확인 스크립트는 저장소 밖 `%TEMP%/seelo-followup-tools-20261029/verify_demo.py`. 비밀번호는 `DEMO_PASSWORD`를 import했고 값·쿠키·토큰을 출력하지 않았다.
- 초기 시드에서 이번에 생성한 수동 완료 로그 9~12는 처리자·시각을 보완했다. 정확한 가게·로그 ID와 `evidence.demo=true`를 확인한 뒤 관리자 ID·정비 완료 시각으로 맞췄다. 기존 가게 1~18과 상태 값은 바꾸지 않았다. 수정된 팩토리는 새 DB에서 이 값을 바로 생성하며 재실행은 계속 기존 행을 보존한다.

## 남은 것

1. 실제 지도·AI 키·모델·단가, 지인 가게 동의·연결·관리 화면 PoC.
2. 실제 SMTP와 받은편지함 확인, VM·도메인·인증서·외부 감시·배포 인수 시험.
3. 시드는 읽기용 카드 예시다. 진행 중 상태는 주기 작업에 바뀔 수 있다. 버튼 이후 전체 흐름은 기존 인수 시험으로 검증한다.

- 커밋·푸시·DB 초기화·파일 삭제는 하지 않았다. React 구현은 기존 범위대로 남겼다.
