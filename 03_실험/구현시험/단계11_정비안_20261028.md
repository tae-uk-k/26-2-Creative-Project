**칸 사전**
- 이름·주소·업종 칸이 없다. 이 칸들은 사장님 직접 안내(`ownerOnlyFields`)로 보낸다.
- `validate_value`가 내는 결과: too_long, bad_format, too_many, placeholder_left.
- `same_value`는 정규화해서 비교한다.

**사실 목록**
- 출처 우선순위대로 만든다.
- AI 웹 검색 사이트 값은 2곳 이상이 같을 때만 쓴다.
- 네이버 값과 카카오 로컬 API 값은 넣지 않는다.

**칸 만들기**
- 근거(finding)가 있는 칸만 만들고, finding 우선순위 순으로 놓는다.
- 사실이 없을 때:
  - 영업시간·메뉴·편의 → `needs_owner_input`
  - 웹사이트·링크 → 칸을 만들지 않는다.
- 지금 값과 같고 확인이 필요 없는 칸은 지운다.

**글(LLM)**
- 한 번 호출하고 사실만 넣는다. 카카오·네이버 값은 넣지 않는다.
- 글자 수를 넘으면 그 칸만 1번 더 짧게 만든다. 그래도 넘으면 문장 단위로 줄인다.

- 카카오 지금 값은 `evidence`에 넣지 않고 `current_value`에만 둔다.

**지금 값 읽기**(E13)

**관리자 다시 생성**(E23)

### W-09-4 조회·승인

테스트: `integration/test_w_09_4.py` 14개

**조회**
- 상세에 문제 목록과 칸, 칸에 연결된 문제(`itemId`), `ownerOnlyFields`, `mapNotFound`가 나온다.
- generating 정비안은 칸이 빈 목록이다.
- 남의 정비안·한 번도 연결되지 않은 지도는 404.
- 관리자는 읽기 전용으로 본다(`readOnly`).

**승인 검사**
- 오류 순서: NEEDS_OWNER_INPUT(해당 칸 전부) → SENSITIVE_NOT_CONFIRMED → FIELD_INVALID(첫 칸).
- 오류가 있으면 아무것도 저장하지 않는다.
- 칸 목록이 다르면 `ITEMS_MISMATCH`.

**승인 결과**
- 수동 모드(`AUTO_FIX_ENABLED=false`): 모든 칸이 `manual_required`(`automation_disabled`)가 된다. 이어서 관리자 메일 `manual_required`가 나가고 `finalizeFix`가 등록된다.
- 자동 모드: 칸이 browser 또는 api로 queued가 되고 `applyFix`가 등록된다.
  - api 모드에서 지원하지 않는 칸은 `api_unsupported`.
  - 카카오이고 `KAKAO_FIX_ENABLED=false`면 `kakao_fix_disabled`.
- 동시 승인 2개 중 1개만 성공하고 `applyFix`는 1번만 등록된다.
- 연결이 끊긴 지도는 409 `CONNECTION_NOT_CONNECTED`.
- 신청이 remeasure_scheduled면 fixing으로 돌아가고 예약은 canceled.
- 쓸 수 없는 신청 상태면 409.

## [기획 확인] 수동 모드의 카카오 정비안은 칸이 없다

**현상**
- `AUTO_FIX_ENABLED=false`(지금 기본)에서는 카카오 지금 값을 읽지 않는다. 그래서 정비안 단계 판정(08 6.5 P5~P7)을 건너뛴다.
- 진단 단계에서 카카오는 기본정보만 판정한다(08 6.1). 그래서 카카오 칸에 연결될 finding이 거의 없다.
- 결과: 카카오 정비안은 칸 0개로 awaiting_approval이 된다. 승인하면 바로 `finalizeFix`.
- 테스트 `test_kakao_plan_empty_in_manual_mode`가 이 동작을 고정한다.

**M2 영향**
- 지인 가게 시연에서 카카오는 고칠 칸이 나오지 않는다.

**고를 것(추론)**
1. 그대로 둔다. 카카오는 자동화를 켠 뒤에만 정비안이 생긴다.
2. 수동 모드에서도 관리자가 카카오 파트너센터 값을 직접 보고 넣게 한다. 이렇게 하면 지금 값이 생겨 P5~P7이 돈다. 관리자 입력 API가 하나 더 필요하다.
3. 수동 모드에서는 카카오 칸을 근거 없이도 사전 전체로 만든다. 다만 "근거 없는 칸은 만들지 않음"(09 6.3 4번) 원칙과 어긋난다.

Google도 같은 이유로 진단 finding이 있는 칸만 나온다. 수동 모드에서는 소개(`description`) 칸이 나오지 않는다(P1·P3 건너뜀).

## 남은 것

**12단계**
- `finalizeFix` 본문, 관리자 manual-items·manual-done, `remeasure_schedules` 생성, 메일 `fix_completed`.
- `fix_logs` 생성과 메일 `manual_required`는 11단계 승인에서 이미 만들었다.
- 그때 정할 것: `finalizeFix`의 실행 큐. 지금은 fix 큐(06 4장)라 수동 모드 compose에서는 돌지 않는다. DB만 쓰는 작업이므로 기본 워커 큐로 옮기는 안(추론)이 있다.

**13단계**
- `applyFix`, 실제 브라우저로 지금 값 읽기(google_admin·kakao_partner).

**설정**
- 로컬 `.env`의 `ADMIN_NOTIFY_EMAILS`·`SEELO_GOOGLE_ACCOUNT_EMAIL`·`SEELO_KAKAO_ACCOUNT_ID`가 비어 있다.
- 메일 `manual_required`가 관리자에게 가려면 `ADMIN_NOTIFY_EMAILS`가 필요하다.

**정리**
- 개발 DB의 옛 `readCurrentValues` 작업 1건은 `docker compose --profile dev down -v` 또는 DB 초기화 때 사라진다.

**컨테이너**
- 실행 중: db·api·web·worker-main·worker-ai-openai·worker-ai-gemini·mailpit.
- 끄려면 `docker compose --profile dev down`.
