## 완료

- 아이콘 저장은 사용자가 직접 눌러도 Failed to fetch가 발생해 재시도를 종료했다.
- 카카오 공식 문서에 따라 인가 요청의 scope를 생략해 앱에 설정된 동의항목을 사용하도록 수정했다. 비즈 앱 전용 account_email 강제 요청을 제거했다. Google의 openid email profile·state·정확한 콜백·클라이언트 시크릿은 유지했다.
- 카카오 로그인 ON·OIDC OFF·추가 개인정보 동의항목 미사용을 확인했다. 다른 앱·지도 무료 쿼터·유료 API는 변경하지 않았다.
- Windows OAuth 단위 테스트 10개와 ruff 통과. 별도 내부 전용 Docker 네트워크·PostgreSQL에서 같은 운영 코드의 OAuth 단위/통합 테스트 26개 통과. 테스트 DB는 운영 DB와 분리했고 종료 상태로 보존했다.
- 운영 환경은 KAKAO_OAUTH_CLIENT_ID·KAKAO_OAUTH_CLIENT_SECRET·SEELO_IMAGE_TAG 세 항목만 변경했다. 지도용 KAKAO_REST_API_KEY는 공란, 일일 AI 예산은 0이다.
- 기존 릴리스·이미지·root 0600 환경 파일을 보존하고 API만 갱신했다. DB 마이그레이션·웹 재배포·워커 시작은 하지 않았다.

## 남은 조건

- 운영 DB 집계는 users=0·auth_identities=0·pending_signups=2·email_logs=0이다. 제공자 콜백을 최종 가입·로그인 세션 성공으로 기록하지 않는다.
- 가입 약관·카카오 이메일 입력 UI는 미배포 상태다. 카카오 이메일은 별도로 입력하고 인증해야 한다. 회원번호를 이메일로 취급하거나 이메일 검증을 생략하지 않았다.
- 실제 메일 수신·AI 예산/모델·Gemini·OpenAI 잔액·전체 진단 인수·정기 외부 백업·외부 장애 알림이 남는다.
- 아이콘 등록·비즈 앱 전환은 현재 기본 로그인 연동을 막는 조건이 아니다. 앞선 기록의 해당 선행 조건 판단은 이 문서로 정정한다.
- 보호 자원 JSON과 기존 배포 묶음을 포함한 일괄 기록 갱신 명령은 자동 승인 검토에서 blocked by policy로 거부됐다. 이 문서는 보호 파일을 읽거나 덮어쓰지 않는 별도 결과 기록이다. 보호 자원 JSON에는 이전 상태가 남아 있을 수 있으므로 현재 운영 상태는 이 기록과 실제 서버를 기준으로 확인한다.
